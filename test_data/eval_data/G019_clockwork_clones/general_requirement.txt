## 1. 定位与完整流程 [S01–S06]

- S01 类型：3D 单人录制-回放协作解谜。本测例包含的能力：三房冻结布局、≤15 秒动作录制、时影分身回放、双压板/时序开关/驻守供电三类同步机关、房级重置、超时判负、开场/首次协作/结算视频。
- S02 核心循环一句话：录制本体动作 → 回放生成分身 → 本体与分身同场协作 → 同步触发机关 → 房间完成。
- S03 流程：房1 单分身基础（双压板同踩）→ 房2 双机关时序（间隔同步）→ 房3 往返接力（分身驻守供本体通行）→ 结算。
- S04 最低完整流程：开始界面、录制/回放操作、三房目标判定、结算、房级重置、重开必须全部存在且有真实入口。
- S05 失败恢复入口：软锁不可存在（红线：任何时刻可房级重置恢复）；超时判负可重开；Esc 暂停。
- S06 本局耦合边速览：本体录制序列决定分身回放行为（录制系统→回放系统）；分身与本体同步触发决定机关开闭（分身行为→机关系统）。

## 2. 完整核心循环与阶段 [S06–S10]

完整循环：启动与开始界面 → 房1 双压板 → 房2 时序开关 → 房3 往返接力 → 结算 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与开始界面
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且场景加载完成
  - state_change：进入「开始界面」状态；首次进入按 §10 C01 触发开场视频
  - feedback：界面按 §9 F10 呈现（三房任务简报）
  - next_actions：进入「房1」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 房1 单分身基础
  - input：WASD 移动、F 录制、G 生成分身、R 重置、Esc 暂停（触发方：玩家）
  - precondition：开始界面已完成（房1 默认解锁）
  - state_change：载入房1 冻结布局；录制档案与分身初始为空
  - feedback：录制时间线、分身齿轮与残影表现按 §9 F05 呈现
  - next_actions：双压板同承重开门并抵达出口 →「房2 解锁」
  - outcome：房1 完成标记局内保留（V04）
- S08 房2 双机关时序
  - input：同 S07（触发方：玩家）
  - precondition：房1 出口达成
  - state_change：载入房2 冻结布局；时序开关 A/B 可用
  - feedback：同步间隔提示（HUD 计时差）
  - next_actions：A/B 间隔 ≤0.5 秒同步开门并抵达出口 →「房3 解锁」
  - outcome：房2 完成标记局内保留
- S09 房3 往返接力
  - input：同 S07（触发方：玩家）
  - precondition：房2 出口达成
  - state_change：载入房3 冻结布局；驻守开关＋升降台可用
  - feedback：驻守供电指示与升降台运行表现
  - next_actions：分身驻守供电、本体乘升降台抵达出口 →「结算」（先播 C03）
  - outcome：按 V01 结算
- S10 结算
  - input：Enter＝重开 / Esc＝返回开始界面（触发方：玩家）
  - precondition：三房出口全部达成（V01）
  - state_change：进入「结算」状态；场景冻结
  - feedback：结算面板显示用时、重置次数、录制总时长
  - next_actions：重开（全量清空）或返回
  - outcome：无跨局写入

## 3. 数值口径与全局规则 [G01–G07]

- G01 统一刻度：时间为毫秒；距离为米；房号与档案为整数。
- G02 录制与分身（本包冻结值）：本体自按下录制起动作自动记录，单次录制上限 **15 秒**；分身上限 **1**；回放自分身生成时刻起精确重演录制序列；本体可在分身回放期间自由行动。
- G03 同步机关（本包冻结值）：房1 双压板需同时承重（本体＋分身）→ 门开启；房2 时序开关 A/B 触发间隔 ≤**0.5 秒**判同步；房3 分身驻守开关持续供电本体通行升降台。承重与间隔判定为确定规则。
- G04 回放复现与 oracle：录制-回放 diff=0——本体录制「直行 3 米→左转→踩压板」序列后，分身回放动作事件流与录制逐帧 diff=0；时序 oracle 数例：A 于 t＝5.000 秒触发、B 于 t＝5.300 秒触发 → 间隔 0.300 秒 ≤0.5 → 判同步开门；任何偏离即 FAIL。
- G05 超时、重置与随机（本包冻结值）：每房限时 **120 秒**（超时判负可重开）；R 房级重置（清空该房录制档案与机关）；fixed_seed=1019 冻结三房布置；Esc 暂停冻结回放与计时；窗口失焦自动暂停。
- G06 分身语义与录制内容（本包冻结值）：录制内容＝本体移动输入流（WASD 位移）与机关接触事件的毫秒时间戳序列，不录制镜头视角与 UI 输入；分身为半透明「时影」回放体——不阻挡也不被阻挡（与本体、货箱式障碍、机关碰撞体互不推挤，可穿行），但可触发压板/时序开关/驻守开关；同帧本体与分身接触同一机关时按「本体优先、分身随后」串行记录时间戳；回放为确定性重演（deterministic replay，diff=0）。
- G07 录制失败、回放失败与重置（本包冻结值）：录制中再按 F＝停止并保存；录制达 15 秒自动停止保存；时长 <0.5 秒的档案视为空档案，按 G 生成无效并提示「档案为空」；回放期间按 R＝房级重置（分身与档案即时清空、机关回初始）；回放本身无失败态（分身不被伤害、不可被清除，仅被 R 或重新生成覆盖）；暂停冻结录制与回放计时，恢复后从暂停点继续。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：WASD＝移动；F＝开始/停止录制；G＝生成分身回放；E＝交互（压板自动触发无需按键）；R＝房级重置；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：录制中按 G 先终止录制再生成；已有分身时按 G 重新生成（覆盖旧分身）；未录制或空档案时按 G 无效；暂停/结算期间输入无效。
- I03 鼠标可选（第三人称视角水平旋转），全部操作可键盘完成。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入；同帧多输入按录制停止→生成分身顺序结算。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：房号、剩余时限、录制时间线（录制中显示已录时长/15 秒上限，回放中显示回放进度）、分身状态（在场/回放中/驻留）、同步间隔提示；HUD 对照见 rubric。
- I07 输入延迟目标：移动按键到画面反馈 ≤ 80 毫秒；录制/生成按键反馈 ≤ 100 毫秒。

## 6. 机制系统 [M01–M04]

- M01 动作录制
  - input：F 开始/停止
  - precondition：处于房内游玩状态且当前未在回放生成流程中
  - state_change：本体移动/机关接触序列按毫秒时间戳记录（≤15 秒，G06 内容口径）；达上限自动停止
  - observable：`record_start`/`record_stop` 事件与录制档案（动作序列流水）
  - invalid_case：时长 <0.5 秒 → 空档案（按 G 生成无效并提示）
  - recovery：R 房级重置清空档案
- M02 分身回放（主机制）
  - input：G 生成
  - precondition：存在非空录制档案
  - state_change：分身按录制序列精确重演（diff=0）；分身为时影回放体（G06：不阻挡不被阻挡、可触发机关）；回放结束后驻留末位姿态
  - observable：回放动作事件流与录制档案逐帧 diff=0（断言）
  - invalid_case：空档案按 G 无效；已有分身时重新生成覆盖旧分身
  - recovery：R 重置或再次生成覆盖
- M03 同步机关
  - input：本体/分身踩踏压板与时序开关（系统）
  - precondition：对象与机关触发体接触（分身穿行同样触发）
  - state_change：双压板同承重 → 门开；时序间隔 ≤0.5 秒 → 判同步；驻守开关供电升降台
  - observable：机关触发事件（含触发方 ID 与双方时间戳、间隔）
  - invalid_case：承重/间隔不满足保持关闭
  - recovery：离开/超时回落，可重新触发
- M04 循环重置
  - input：R／超时（系统）
  - precondition：处于房内
  - state_change：房级重置清空录制档案、分身与机关状态回初始；镜头回出生点
  - observable：`room_reset` 事件（清空差分断言）
  - invalid_case：重置不影响其他房完成标记
  - recovery：超时判负后一键重开

系统耦合边（玩法必需、可复现）：

- E01 from_system=录制系统 → to_system=分身回放系统；changed_state=本体录制序列决定分身逐帧行为（协作成立前提）；验证方式=探针录制固定序列后生成回放，state_before（录制事件流）与 state_after（回放事件流）diff=0 对照。
- E02 from_system=分身行为 → to_system=机关系统；changed_state=分身踩踏与本体触发的时间间隔/同承重决定机关开闭；验证方式=分身在场/不在场两态下机关 state_before/after 对照。

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：三房机关全部按规则触发并抵达各房出口 → 结算（显示用时与重置次数）。
- V02 失败条件：任一房 120 秒超时 → 判负结算；软锁不可达为缺陷红线（记 FAIL 非玩家失败）。
- V03 恢复语义：R 房级重置（清录制/分身/机关）；判负后一键重开；空档案/无效生成不产生副作用。
- V04 persistent_state：无（重开全量清空；房内录制档案仅局内保留，房级重置即清）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（房完成标记）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设永久软锁——R 房级重置为最终恢复出路；空档案提示不阻断流程。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：发条与齿轮驱动的架空年代；老城钟楼下的「辰枢坊」是大钟的机枢工坊，今夜整点报时机枢停摆，天亮前必须修复。
- W02 场景所在地：辰枢坊内部三间实验房——基础间、时序间、驻守间，均以黄铜齿轮墙与悬摆装饰。
- W03 玩家身份与当前任务：玩家是钟表匠学徒「阿枢」；当前任务：使用师父留下的「时影装置」录制自身动作、生成时影分身，独自完成需要两人协作的机关修复。
- W04 失败代价与结局表达：超时＝天亮前来不及上弦，大钟停摆一日（结算文案）；完成则 C03 呈现大钟重新走时、全城钟声齐鸣。
- W05 叙事来源：时影装置＝师父的未竟发明（分身因此为半透明时影）；双压板/时序开关/驻守开关＝机枢检修流程中需要双人配合的工序；升降台＝齿轮配重升降检修台。全部原创。
- W06 视觉风格与色彩材质：风格化蒸汽钟表风；主色＝黄铜金（#B08D4F 系）＋深胡桃木（#5A4632 系）＋时影青蓝（#57B8C9 半透明）；材质以黄铜、胡桃木、磨砂玻璃为主。
- W07 环境氛围与声音语言：深夜工坊的滴答与齿轮低鸣——常驻发条环境声；音效语言为「发条上弦＋齿轮咔哒＋时影嗡鸣」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代停摆与装置 → 首次协作视频（C02）作为能力获得节点 → 结算视频（C03）收束；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：第三人称斜后方跟随（距离 4 米、高度 2.2 米），鼠标水平旋转视角（±180°），俯仰不可用；镜头跟随平滑插值 0.1 秒；镜头边界＝房间墙体的相机碰撞体（不穿墙）；R 房级重置后镜头回该房出生点冻结初始角。
- F02 关键操作镜头变化：分身生成瞬间镜头轻微推近 5%（0.5 秒）后回位；同步开门瞬间镜头轻微震动 0.15 秒；无慢动作。
- F03 输入与延迟：见 I07。
- F04 环境常驻效果：悬摆缓慢摆动、齿轮墙缓慢旋转、时影装置待机微光；不遮挡机关判定区。
- F05 事件反馈表（事件 → 表现 → 结束条件，全部为冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 开始录制 | 本体边缘亮起描边＋HUD 时间线启动 | 上弦咔哒声 | 停止即灭 |
| 停止录制 | 描边熄灭＋时间线定格 | 弹簧回位声 | 定格即停 |
| 生成分身 | 齿轮展开光环＋时影淡入（0.4s）＋残影拖尾 | 时影嗡鸣 | 淡入完成常驻微光 |
| 回放中 | 分身半透明＋移动残影（0.3s 渐隐） | 低频回放嗡声（回放期间循环） | 回放结束即停 |
| 分身触发机关 | 机关亮起「时影青」色环 | 齿轮咔哒 | 机关状态变化即停 |
| 同步成功 | 门缝透光＋HUD 间隔数字定格绿色 | 谐和确认音 | 开门完成 |
| 同步失败 | 间隔数字红闪 | 短促否定音 | 0.4s 结束 |
| 驻守供电 | 供电线路流光连至升降台 | 电流嗡声（供电期间循环） | 离开驻守即停 |
| 房间完成 | 门开启＋房间灯组亮起 | 上扬提示音 | 进入下一房即淡出 |
| 超时判负 | 灯光骤暗＋HUD 变灰 | 低沉钟声 | 进入判负面板即停 |
| 空档案生成 | 装置红光一闪＋「档案为空」文字 | 短促否定音 | 0.4s 结束 |

- F06 关键音效清单：上弦咔哒、弹簧回位、时影嗡鸣、回放嗡声、齿轮咔哒、确认音、否定音、电流嗡声、上扬提示音、低沉钟声；环境音：发条滴答＋齿轮低鸣（常驻循环，暂停静音）；循环音开始/结束：环境声随房载入开始、随结算淡出 0.5s；回放嗡声/电流嗡声仅在对应状态期间循环；无配音需求。
- F07 VFX 信息性与遮挡约束：分身青蓝半透明与描边承担「时影身份」信息；供电线路流光承担驻守状态信息；残影与齿轮粒子单帧 ≤ 30，不遮挡压板与开关判定区。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：2 个（text-to-3D 0，image-to-3D 2）；object 任务资产为：apprentice_clockmaker, chrono_echo_device。每项只允许一个物体；组合物必须拆成独立任务。
- motion：3 个；覆盖动作：idle, walk, plate_press。
- video/audio/mechanic/UI：分别为 3/8/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

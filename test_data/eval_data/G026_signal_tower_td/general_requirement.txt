- 作品名：《峡谷信号塔的固定路防守》；版本：mechanics-v3（2026-10-11 完整性修订：吸收 ydg 反馈——T10 塔防口径全套、缓速塔 1.0 秒单体、L02 精确 20 格、射程 3.0/3.1 边界探针、出售后格空可再建断言；补世界设定、镜头输入、演出反馈、过场视频与正向范围清单）；运行引擎：**Three.js（WebGL）**——选择理由：单屏俯视塔防以浏览器即开即玩交付，格点建造与波次逻辑以 Three.js 场景图＋DOM/HUD 实现开销可控；摄像机：斜俯视约 50°（支持平移缩放）；输入：键鼠（点击放置/出售）；构建启动：Three.js 工程构建为静态 Web 页面（Vite/ESBuild 打包或单文件 HTML），本地静态服务器或直接打开 index.html 运行。

## 1. 定位与完整流程 [S01–S05]

- S01 类型：单固定路线塔防。
- S02 核心循环一句话：波前布塔 → 塔自动交战 → 金币结算 → 补强布防 → 守至终波。
- S03 流程：开始 → 波前建造期 → 敌波行进（塔自动交战）→ 波次结算（金币奖励）→ 下一波 → 第 5 波清空 → 胜利结算。
- S04 最低完整流程：建造界面、战斗、波次结算、胜负结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：基地生命归零 → 失败结算一键重开（塔布局/金币/波次全量重置）；Esc 暂停。

## 2. 完整核心循环与阶段 [S06–S13]

完整循环：主菜单 → 开始对局 → 建造期 ⇄ 敌波行进 → 波次结算（共 5 波，波间回到建造期）→ 胜利结算；任意玩法阶段可 Esc 暂停；基地生命归零即时进入失败结算。每阶段六要素如下（引用本 spec §3–§7 对应规则）：

- S06 主菜单
  - input：系统启动，玩家确认进入
  - precondition：程序启动完成
  - state_change：显示主菜单（开始/退出）
  - feedback：主菜单界面
  - next_actions：玩家点击「开始」→ S07
  - outcome：无状态副作用
- S07 开始对局
  - input：玩家点击「开始」
  - precondition：主菜单已显示
  - state_change：对局初始化：金币 100、基地生命 3、波号 1
  - feedback：HUD 显示初始值（金币/波号/基地生命，见 §4 I06）
  - next_actions：进入 S08 建造期
  - outcome：进入首波建造期；无跨局状态（见 §7 V05）
- S08 建造期（每波前）
  - input：玩家建塔/出售（按 §4 I01/I02 键位）；Space 提前开波；倒计时归零（系统）
  - precondition：波号已确定；上一波已结算（首波为对局初始化）
  - state_change：进入建造期，倒计时 20 秒（见 §3 G06）；建塔/出售即时生效
  - feedback：HUD 显示建造期倒计时、下一波敌数与单只 HP（见 §4 I06）
  - next_actions：Space 或倒计时归零 → S09；Esc → S11
  - outcome：塔布局保留至本局结束
- S09 敌波行进
  - input：系统波调度（fixed_seed=1026 出生序列，每 1.0 秒出生一只）；塔自动交战；玩家仍可建塔（不暂停敌人）
  - precondition：建造期结束（Space 或倒计时归零）
  - state_change：敌人沿固定路线行进；塔按 §3 G04 交战；漏怪（抵达基地）→ 基地生命 −1
  - feedback：命中反馈与特效（见 §9 F05/F06）；漏怪基地红闪＋屏幕边缘红晕
  - next_actions：波内敌人清空或全部抵达基地 → S10；基地生命归零 → S13；Esc → S11
  - outcome：击杀金币入账；漏怪扣基地生命
- S10 波次结算
  - input：系统结算
  - precondition：波内敌人清空或全部抵达基地
  - state_change：波奖励 +40（见 §3 G03）；波号 +1
  - feedback：金币数字跳动（见 §9 F05）
  - next_actions：波号 < 5 → 回 S08；波号 = 5 → S12
  - outcome：进度推进；状态保留
- S11 暂停
  - input：玩家按 Esc
  - precondition：处于 S08/S09 任意玩法阶段
  - state_change：冻结敌人、塔、波调度、倒计时与时间倍率（见 §3 G05）
  - feedback：暂停菜单（继续/重开/返回菜单）
  - next_actions：Esc 或「继续」→ 返回原阶段；「重开」→ S07；「返回菜单」→ S06
  - outcome：恢复后一切计时从冻结点继续，无副作用
- S12 胜利结算
  - input：系统结算
  - precondition：第 5 波结束且基地生命 > 0（见 §7 V01）
  - state_change：显示胜利结算（剩余基地生命与金币）
  - feedback：胜利全屏特效（见 §9 F05）
  - next_actions：Enter 重开 → S07；返回菜单 → S06
  - outcome：按 §7 V01/V03 判定并结算
- S13 失败结算
  - input：系统结算
  - precondition：基地生命归零（任意波中即时判负，见 §7 V02）
  - state_change：显示失败结算
  - feedback：失败反馈
  - next_actions：Enter 一键重开 → S07；返回菜单 → S06
  - outcome：按 §7 V02/V03 判定并结算（全量重置）

## 3. 数值口径与全局规则 [G01–G06]

- G01 统一刻度：金币/HP 为整数；塔射程按格计，射程判定按格中心欧氏距离 ≤ 射程；时间用游戏模拟秒（暂停冻结）。
- G02 塔表（本包冻结值）：箭塔（造价 50、攻 10、射程 3、间隔 1.0 秒）；炮塔（造价 80、攻 30、射程 2、间隔 2.5 秒、溅射同格）；缓速塔（造价 40、攻 0、射程 2、间隔 1.0 秒、单体命中、命中后敌方移速 −50% 持续 2 秒）。
- G03 敌波表（本包冻结值）：5 波峡谷爬行者——数量 6/8/10/12/14，单只 HP 40/60/80/100/120，移速 1 格/秒（缓速后 0.5）；同波敌人每 1.0 秒出生一只。击杀金币 10/只；每波通关奖励 +40；初始金币 100；基地生命 3，每漏 1 敌 −1。
- G04 交战规则（本包冻结值）：塔默认攻击「最接近基地」的射程内敌人；炮塔溅射对同格额外半伤（15）；缓速不叠加只刷新；伤害即时结算（命中帧生效，弹道飞行仅为表现层，不影响结算时间戳）。DPS oracle 数例：箭塔 10/1.0＝**10/秒**；炮塔 30/2.5＝**12/秒**；箭塔单杀首波敌（HP 40）需 4 发共 4 秒。
- G05 暂停、倍率与随机：Esc 暂停冻结敌人、塔、波调度与全部计时；T 键切换时间倍率 ×1/×2，倍率统一作用于敌人移速、塔攻击间隔、建造期倒计时与状态持续时间（暂停优先于倍率）；fixed_seed=1026 冻结波内敌人出生序列与出生点；伤害为确定公式。
- G06 建造期规则（本包冻结值）：每波前建造期 20 秒倒计时，可按 Space 提前开波；建造期 HUD 显示下一波敌数与单只 HP；倒计时归零自动开波。

## 4. 操作与输入 [I01–I06]

- I01 键鼠：点击建造格＋塔型按钮＝建塔；点击已有塔＝查看/出售（返还 60%）；1/2/3＝快捷选塔型；Space＝建造期提前开波；T＝时间倍率 ×1/×2 切换；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：金币不足建塔无效；占位格重复建造无效；战斗中可随时建塔（不暂停敌人）；暂停/结算期间玩法输入无效。
- I03 无手柄需求。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入（沿用原 I02 口径）；同帧多输入按 §6 各机制声明的顺序结算。
- I05 焦点与点击穿透规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停，不推进游戏模拟。
- I06 UI 必须显示的状态：金币、波次号、基地生命（按 §3 G01/G03 刻度）；建造期倒计时与下一波敌数/单只 HP（见 §3 G06）；选中塔型或悬停建造格时显示射程圈与建造合法性（绿/红，见 §9 F05）；当前时间倍率（×1/×2）。
- I07 输入延迟目标：点击到画面反馈 ≤150 毫秒（WebGL 口径，P95，≥30 次采样/类别）。

## 6. 机制系统 [M01–M03]

- M01 建塔与射程（主机制）
  - input：玩家建塔/出售指令（按 §4 I01 键位）
  - precondition：建造要求金币 ≥ 造价且目标建造格为空；出售要求目标格已有本方塔
  - state_change：塔落位进入自动交战；出售后返还 60% 且格子空出可再建
  - output：按 §3 G02/G04 结算伤害与减速（公式见对应 G 条）
  - observable：建塔/出售事件（类型/位置/金额）与逐次攻击事件（目标、伤害、时间戳）
  - invalid_case：金币不足或占位格重复建造按 §4 I02 拒绝且无副作用；暂停/结算期间玩法输入无效
  - recovery：失败/中断/非法态后的恢复按 §7 V03 恢复语义与 V04 软锁处理执行，不产生冻结规则之外的副作用
- M02 金币经济
  - input：击杀/波次结算（系统）；建塔/出售（玩家）
  - precondition：击杀确认或波结算发生；建造/出售指令合法（见 M01 precondition）
  - state_change：击杀 +10、通关 +40、建塔扣费、出售返还 60%；无凭空增减
  - output：按 §3 G02/G03 数值结算
  - observable：金币流水对账（每笔收入/支出与余额）
  - invalid_case：金币不足的建造按 §4 I02 拒绝且不扣费
  - recovery：按 §7 V03/V04 执行
- M03 波次与漏怪
  - input：波调度（fixed_seed=1026 出生序列）
  - precondition：建造期结束（Space 提前开波或 20 秒倒计时归零，见 §3 G06）
  - state_change：波开始→敌序列每 1.0 秒出生一只→波内敌人清空或全部抵达基地判波结束；漏怪（抵达基地）→基地生命 −1；归零判负（即时）
  - output：按 §3 G03 结算波奖励与胜负（见 §7 V01/V02）
  - observable：wave_start/波结算/漏怪事件与基地生命流水；出生时间戳间隔 1.0 秒
  - invalid_case：建造期未结束时无敌人出生；暂停期间波调度冻结
  - recovery：按 §7 V03/V04 执行

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：第 5 波结束（波内所有敌人被击杀或已抵达基地）时基地生命 > 0 → 胜利结算（显示剩余基地生命与金币）。
- V02 失败条件：基地生命归零（累计漏 3 敌）→ 失败结算（任意波中即时判负；漏怪致基地归零与末波清空同帧时判负优先）。
- V03 恢复语义：失败/胜利结算一键重开（Enter）；塔布局、金币、波次、基地生命全量重置；局内无存档（不做整波重打）。
- V04 软锁与不可达处理：无永久软锁——关键目标均可通过正常操作达成，或触发 V02 失败路径进入结算；结算界面重开为最终恢复出路；判定不可达时按 V02 失败语义结算而非无限等待。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（金币/塔布局/基地生命/波次）局内保留、重开清空；无跨局保留（重开全量清空）。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：断讯纪元的大陆依靠峡谷信标站链维持最后的通信中继；风暴季将至，循电磁而聚的荒漠虫群开始沿峡谷迁徙，三峰中继塔是北线的最后一环。
- W02 场景所在地：干涸峡谷中的单条 S 形风蚀通道（20 格固定路），信号塔基地扼守通道尽头，12 个岩台建造格分布路侧。
- W03 玩家身份与当前任务动机：玩家是守塔工程师；风暴季前最后一次巡检中发现虫群逼近——用箭塔、炮塔与缓速塔在通道中建立防线，守住信号塔至第 5 波风暴过境。
- W04 失败代价与结局表达：信号塔失守=北线通信中断（C02 失败意象：信号熄灭）；守住 5 波=信号满格回传（C02 胜利意象：光柱冲天）。
- W05 叙事来源：峡谷爬行者=循电磁而来的荒漠甲虫（原创造型）；箭塔=岩台弩架、炮塔=配重投石机、缓速塔=冷凝雾栅；信号塔基地=三峰中继塔的信号收发站。全部原创，不用商业作品命名。
- W06 视觉风格与色彩材质：荒漠军事风；主色＝沙金 #D8B96A、岩褐 #8A7A66、信号青 #3E9C8B、警报橙 #E4762C；材质为风化岩、木制弩架、帆布与铜线。
- W07 环境氛围与声音语言：峡谷风啸为底；音效语言＝建造落位/塔击发/命中/漏怪警报/波次横幅（F06 冻结清单）；混音优先级：基地警报 ＞ 波次横幅 ＞ 命中 ＞ 建造/出售 ＞ 环境风。
- W08 故事表达方式：开场视频（C01）交代虫群来袭与守塔任务 → 过程事件（F05 特效与波次横幅）承载风暴季推进 → 结算视频（C02）双意象收束；叙事只做包装不改数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：斜俯视约 50°；WASD、方向键或鼠标贴边平移；滚轮缩放 3 档；镜头不出地图边界；F 键回到基地。

| 波开始 | 波次横幅 | wave_start | 横幅收起 |

- F06 关键音效清单（one_shot 11 条＋环境循环 1 条，全部冻结需求）：arrow_shot、cannon_fire、slow_pulse、crawler_hit、crawler_death、base_alarm、wave_start、tower_build、tower_sell、victory_sting、defeat_sting；环境循环：canyon_wind（峡谷风啸底噪；暂停静音、结算淡出 0.5 秒；恒低于警报音）。无配音需求。
- F07 VFX 信息性与遮挡约束：射程圈、放置合法性色块、溅射爆炸圈、波次横幅为信息类 VFX，必须清晰可辨（溅射圈大小＝同格溅射范围，供玩家核对）；粒子不遮挡 HUD 与基地关键目标；非结算单个全屏遮挡 ≤0.5 秒。
- F08 音画同步：击发音与弹道同帧；脉冲音与脉冲环同帧；警报音与基地红闪同帧；横幅音与横幅同帧。
- F09 屏幕震动：基地受击 0.25 秒中幅；暂停/结算取消未结束的震动与特效；设置可关闭（镜头震动开/关；伤害数字开/关）。
- F10 前端界面：标题（开始/设置/退出）→ 建造期 HUD（金币/波次/基地生命/倒计时/下一波敌数与单只 HP/时间倍率，见 I06）→ 暂停面板（继续/重开/返回/设置）→ 结算面板（剩余基地生命与金币；Enter 重开）；关键状态图标＋文字并用；窗口失焦自动暂停。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：9 个（text-to-3D 6，image-to-3D 3）；object 任务资产为：arrow_tower, canyon_crawler, signal_tower_base, cannon_tower, slow_tower, build_pad, arrow_bolt, cannon_shell, wave_gate。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：tower_build。
- video/audio/mechanic/UI：分别为 2/12/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

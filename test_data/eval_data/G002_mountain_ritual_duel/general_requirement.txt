## 1. 定位与完整流程 [S01–S05]

- S01 类型：3D 第三人称 1v1 仪式决斗，单人单局。能力：方向格挡/完美格挡/破防/反击、背靠背转身射击仪式攻击、体力经济、180s 时限、开场/仪式攻击/结算视频、打击感演出层。
- S02 核心循环一句话：观察劈砍前摇 → 方向格挡 → 抓住反击窗口 → 循环至剑士倒下。
- S03 流程：标题 → 决斗仪式（首次开始前播 C01）→ 交战 → 胜负结算（胜者插剑/败者退场，播 C02）→ 重开或返回。
- S04 最低完整流程：标题、决斗、胜利结算、失败结算、重开全部存在且有真实入口。
- S05 失败恢复入口：失败结算提供「重开本局」（全量重置）；Esc 暂停可继续/重开/返回。

## 2. 完整核心循环与阶段 [S06–S11]

- S06 启动与标题
  - input：系统加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且资源加载完成
  - state_change：进入「标题」；首次开始前按 §10 C01 播开场仪式视频
  - feedback：标题界面按 §9 F10
  - next_actions：进入「决斗」
  - outcome：无跨局状态
- S07 决斗
  - input：WASD 移动、LMB 攻击、RMB+方向 格挡、后+Space 撤步、T 仪式攻击、Esc（触发方：玩家）；剑士攻击由 seed 序列驱动（触发方：系统）
  - precondition：处于决斗状态
  - state_change：按 §6 M01–M05 结算每次输入；HP/体力/反击窗口实时更新
  - feedback：命中与格挡反馈按 §9 F05（火花/铿锵/顿帧/慢镜）
  - next_actions：任一方 HP0 →「胜负结算」；180s 超时 →「失败结算」
  - outcome：按 V01/V02 判定
- S08 胜利结算
  - input：Enter=重开 / Esc=返回（触发方：玩家）
  - precondition：V01 成立（剑士 HP0）
  - state_change：面板出现前按 §10 C02 播结算视频（每局一次）
  - feedback：结算面板显示用时、剩余 HP、完美格挡数
  - next_actions：重开或返回
  - outcome：无跨局状态
- S09 失败结算
  - input：Enter=重开 / Esc=返回（触发方：玩家）
  - precondition：V02 成立（玩家 HP0 或超时，注明原因）
  - state_change：进入失败结算；面板出现前同样播 C02 的失败变体入口（本测例 C02 胜负共用一条结算视频，内容含胜者插剑与败者退场双意象）
  - feedback：失败面板注明原因
  - next_actions：重开本局
  - outcome：全量重置
- S10 暂停
  - input：Esc（触发方：玩家）
  - precondition：处于决斗状态
  - state_change：暂停覆盖层打开，剑士攻击序列、计时、体力全部冻结
  - feedback：暂停面板（继续/重开/返回/设置）
  - next_actions：恢复回到决斗
  - outcome：恢复后与暂停前逐字段一致；窗口失焦自动暂停
- S11 设置
  - input：鼠标点击（触发方：玩家）
  - precondition：标题或暂停界面
  - state_change：打开设置面板
  - feedback：提供「镜头震动开/关」「慢镜开/关」（关闭不影响判定）
  - next_actions：返回上级

## 3. 数值口径与全局规则 [G01–G07]

- G01 统一刻度：擂台为直径 16m 圆形石台（XZ 米制，原点=台心）；状态变量=玩家 HP/体力/反击窗口计时、剑士 HP/攻击序列相位、仪式攻击状态、180s 倒计时。
- G02 双方数值：玩家 HP100、体力上限 100；对手「哨卫剑士」HP150、劈砍 30、前摇预告 0.7s、出招间隔 2.5s（seed=1002 冻结序列，含攻击与短暂踱步）。
- G03 格挡与破防：方向格挡（RMB+方向键）——方向与攻击来向匹配=格挡成功（0 伤害、体力 −10）；不匹配=受击（HP −30）。受击时体力 <20 → 破防：3s 内不可格挡且受伤 ×1.5（=45）。
- G04 体力经济：体力回复 15/s（停止格挡/攻击 1s 后起，上限 100）；撤步（后+Space）体力 10。
- G05 反击窗口：格挡成功后 0.8s 内 LMB=反击 45 伤害；窗口外 LMB=普通攻击 20。oracle：格挡成功 → 0 伤害、体力 100→90；格挡后 0.5s 反击 → 剑士 150→105；体力 15 时受击 → 破防 −45。
- G06 暂停与模拟时间：Esc 暂停冻结剑士序列/倒计时/体力；失焦自动暂停；结算与视频不推进计时。
- G07 优先级与同帧裁决：同帧「格挡指令按下 0.15s 内的攻击命中」按 M04 完美格挡结算；反击窗口最后一帧与下一剑士攻击同帧 → 玩家动作先结算；180s 归零瞬间已有判定帧在飞 → 该帧结算后再判超时。

## 4. 操作与输入 [I01–I07]

- I01 键位：WASD=移动；LMB=攻击/反击；RMB（按住）+方向键=格挡；后+Space=撤步；T=仪式特殊攻击；Esc=暂停；Enter=确认/重开。
- I02 输入语义边界：破防期按格挡被拒绝且无副作用；仪式攻击条件不满足时 T 无效；反击窗口外 LMB 走普通攻击；面板期玩法键一律拒绝。
- I03 键盘+鼠标为完整输入方式。
- I04 输入优先级：暂停/结算阻断玩法输入；同帧顺序=暂停 > 格挡 > 撤步 > 攻击 > 仪式。
- I05 焦点与失焦：点击捕获；失焦自动暂停。
- I06 UI 必显状态：玩家 HP、体力条、剑士 HP、反击窗口提示（可用/剩余）、180s 倒计时、仪式攻击可用（每局 1 次）。
- I07 输入延迟目标：≤50 毫秒（格斗类口径；慢镜不改变 I07 计时）。

## 6. 机制系统 [M01–M05]

- M01 方向格挡
  - input：RMB 按住 + 方向键（触发方：玩家）
  - precondition：非破防期；处于决斗状态
  - state_change：格挡方向与攻击来向匹配 → 0 伤害、体力 −10、开启 0.8s 反击窗口；不匹配 → 按攻击伤害受击
  - observable：`block(dir)` / `block_fail` 事件与体力快照
  - invalid_case：破防期格挡被拒绝；体力不足格挡仍可按（消耗后可能触发破防条件）
  - recovery：松开 RMB 结束格挡姿态
- M02 破防
  - input：受击时判定（触发方：系统）
  - precondition：受击瞬间体力 <20
  - state_change：破防 3s（不可格挡、受伤 ×1.5）；剑士获得「抓住破绽」追击表现
  - observable：`guard_break` 事件
  - invalid_case：体力 ≥20 受击不触发
  - recovery：3s 后自动解除
- M03 反击窗口
  - input：LMB（触发方：玩家）
  - precondition：格挡成功后 0.8s 内
  - state_change：反击命中 → 剑士 −45；窗口外 LMB → 普通攻击 −20
  - observable：`counter(t)` / `attack(t)` 事件与剑士 HP 流水
  - invalid_case：窗口结束后按键走普通攻击
  - recovery：每次格挡成功刷新一次窗口
- M04 完美格挡（新增）
  - input：格挡指令按下后 0.15s 内的攻击命中（触发方：系统判定）
  - precondition：格挡姿态已建立
  - state_change：完美格挡=0 体力消耗、0.35s 顿帧、0.25s 慢动作、剑士短硬直 0.5s（可接反击）
  - observable：`perfect_parry` 事件
  - invalid_case：超过 0.15s 的命中按普通格挡结算
  - recovery：无额外恢复——窗口与反击规则同 M03
- M05 背靠背转身射击仪式攻击（新增）
  - input：T（触发方：玩家发起，后续由系统驱动）
  - precondition：每局 1 次；体力 ≥30；与剑士距离 ≤3m
  - state_change：双方背靠背锁定（触发瞬间按 §10 C03 播放仪式攻击视频，每局一次，播放期间倒计时冻结）→ 3 步踱步（每步 1s，共 3s）→ 第 3 步落地开启 0.5s 转身射击窗口 → 窗口内 LMB：命中=直接获胜；未中=剑士反击 45 伤害；仪式期间玩家免受普通攻击
  - observable：`ritual_start` / `ritual_step(1..3)` / `ritual_window` / `ritual_hit` / `ritual_miss` 事件；C03 播放起止事件
  - invalid_case：踱步中 Esc=取消仪式（消耗 10 体力）；窗口内未按 LMB=未中
  - recovery：每局仅一次；取消后本局不可再发起
- M06 剑士攻击（系统）
  - input：seed 序列驱动（触发方：系统）
  - precondition：决斗状态、非硬直、非仪式
  - state_change：按 G02 前摇 0.7s（可辨预告动作）→ 判定帧（30 伤害，受 G03 格挡裁决）→ 间隔 2.5s
  - observable：`windup` / `strike` 事件
  - invalid_case：完美格挡硬直 0.5s / 破防追击期间序列暂停
  - recovery：硬直结束后恢复序列

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：剑士 HP0（含仪式射击命中直接获胜）→ 胜利结算，显示用时/剩余 HP/完美格挡数。
- V02 失败条件：玩家 HP0 或 180s 超时 → 失败结算并注明原因。
- V03 恢复语义：重开=全量重置（HP/体力/序列相位/仪式次数/计时）；Esc 暂停可继续。
- V04 persistent_state：无跨局状态。
- V05 persistent_state 生命周期：动作级即时；局内保留；重开清空。
- V06 软锁与不可达处理：不设软锁——破防 3s 自动解除；仪式取消仍有正常取胜路径。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：云海之上的高山哨所时代——各代守台人以决斗传承哨位。
- W02 场景所在地：云岭哨台，直径 16m 的圆形石台与祭坛铜钟，云海翻涌于台下。
- W03 玩家身份与当前任务动机：玩家是挑战者，以老哨约之名挑战现任哨卫剑士；胜者守台、败者下山。
- W04 失败代价与结局表达：失败=让出哨位传承；结局表达见 §10 C02——胜者插剑立台、钟声送败者退场。
- W05 叙事来源：仪式攻击（背靠背转身射击）=老哨约最后的「火与剑」之约；铜钟=仪式开始与结束的见证。全部原创。
- W06 视觉风格与色彩材质：高山石质写实风；主色=花岗岩灰 #8E8A82、仪式红 #9E3B32、冷金 #C9A876、云白 #E8E6E0；材质为风化花岗岩、粗麻旗布、黄铜。
- W07 环境氛围与声音语言：高山风环境声为底；音效语言=剑刃轨迹+金属铿锵+钟声；关键声音优先级：剑士前摇 > 钟声 > 风。
- W08 故事表达方式：开场视频（C01）交代仪式 → 仪式攻击视频（C03）与攻防事件承载过程 → 结算视频（C02）收束；故事只做包装不改数值。

## 10. 过场视频 [C01–C03]

- C01 仪式开场（Opening，8 秒，1280×720@24fps）
  - 触发时机：首次由标题进入决斗之前，每局一次
  - 内容与角色场景：云岭哨台晨光，祭坛铜钟被敲响三声；决斗者拾阶登台，与哨卫剑士相对行礼，拔刀出鞘映出云海
  - 资产对应：决斗者、剑士、石台、铜钟与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入决斗；自然播完 → 进入决斗
  - 状态一致：播放期间不推进计时
- C02 哨台易主（Ending，10 秒，1280×720@24fps）
  - 触发时机：胜负结算面板出现之前，每局一次（胜负共用，内容含双意象）

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：6 个（text-to-3D 4，image-to-3D 2）；object 任务资产为：duelist, sentinel_swordsman, ritual_flintlock, altar_bell, duel_banner, spare_longblade。每项只允许一个物体；组合物必须拆成独立任务。
- motion：9 个；覆盖动作：draw_sword, slash_combo, block_stance, counter_thrust, ritual_pace_turn, victory_sheathe, windup_slash, stagger_break, swordfall。
- video/audio/mechanic/UI：分别为 3/11/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

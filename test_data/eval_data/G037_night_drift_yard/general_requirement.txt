## 1. 定位与完整流程 [S01–S05]

- S01 类型：3D 单车限时漂移计分（雨夜封闭工业货场）。
- S02 核心循环一句话：入弯侧滑起漂 → 计分累积 → 连段保持 → 应对积水/碰撞中断 → 结算评级。
- S03 流程：开始界面 → C01 开场 → 3 秒倒计时 → 90 秒限时漂移 → 结算（总分/评级）→ 重开。
- S04 最低完整流程：开始界面、可操作驾驶、计分 HUD、结算界面、重开必须全部存在且有真实入口。
- S05 失败恢复入口：结算界面一键重开（即时段重开）；R 即时段重开；Esc 暂停。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：主菜单 → 倒计时 → 限时漂移（起漂→连段→中断/积水应对）→ 结算 → 重开/返回菜单；任意漂移阶段可 Esc 暂停。每阶段六要素如下（引用本 spec §3–§7 对应规则）：

- S06 主菜单
  - input：系统启动，玩家确认进入
  - precondition：程序启动完成（C01 可在首次入局前播放）
  - state_change：显示主菜单（开始/退出）
  - feedback：主菜单界面（F10）
  - next_actions：点击「开始」→ S07
  - outcome：无状态副作用
- S07 倒计时
  - input：玩家点击「开始」后系统进入
  - precondition：主菜单已完成、C01 播完或跳过
  - state_change：3-2-1 倒计时（3 秒）；倒计时内车辆锁定（G04/I02）
  - feedback：倒计时数字＋雨夜环境（F04/F06）
  - next_actions：倒计时归零 → S08
  - outcome：倒计时结束瞬间开始 90 秒计分计时
- S08 限时漂移（主玩法阶段）
  - input：玩家驾驶（按 §4 I01 键位：油门/转向/手刹）
  - precondition：倒计时结束
  - state_change：侧滑角 ≥15° 时按 G02 采样计分；连段计时累积倍率；碰撞/断漂按 M02–M04 结算；驶入积水洼临时降抓地
  - feedback：胎烟/湿痕/水花/连段横幅（F05），HUD 见 I06
  - next_actions：90 秒耗尽 → S09 或 S10；Esc → S11
  - outcome：总分与最大倍率累积（V01/V02 判据）
- S09 达标结算
  - input：系统结算（90 秒耗尽且总分 ≥5000）
  - precondition：V01 成立
  - state_change：显示总分、最大倍率、碰撞次数、达标评级
  - feedback：C03 结算视频（胜利意象）＋结算面板
  - next_actions：Enter 重开 → S06；返回菜单 → S06
  - outcome：按 V01 判胜结算
- S10 未达标结算
  - input：系统结算（90 秒耗尽且总分 <5000）
  - precondition：V02 成立
  - state_change：显示总分与差距
  - feedback：C03 结算视频（失败意象）＋结算面板
  - next_actions：Enter 重开 → S06；返回菜单 → S06
  - outcome：按 V02 判负结算
- S11 暂停
  - input：玩家按 Esc
  - precondition：处于 S07–S10 之外的全部计时阶段
  - state_change：冻结车辆、计时与采样（G04）
  - feedback：暂停菜单（继续/重开/返回菜单）
  - next_actions：Esc/继续 → 返回原阶段；重开 → S06
  - outcome：恢复后 90 秒计时从冻结点连续累计，无漂移

## 3. 数值口径与全局规则 [G01–G04]

- G01 统一刻度：时间为秒（毫秒精度）；侧滑角为度；车速为米/秒；分数为整数。
- G02 得分公式（本包冻结值）：每 0.1 秒采样一次，仅当侧滑角 ≥15° 记分；单次采样得分＝round(侧滑角 × 车速 / 40)。连贯倍率＝1.0＋0.5×floor(连续漂移秒数 / 2)，上限 **4.0**；倍率作用于后续每次采样得分。独立 oracle 数例：θ＝30°、v＝20 米/秒 → 每次采样 round(30×20/40)＝**15 分**（150 分/秒）；连漂 6 秒后倍率＝1.0＋0.5×3＝**2.5**（375 分/秒）。
- G03 判定（本包冻结值）：限时 **90 秒**；目标分 **5000**（达标判胜）；碰撞（撞墙/撞货箱）→ 本段倍率归 1.0、连续漂移计时清零、本次碰撞不扣分；湿地抓地系数 **0.7**（更易起漂）。
- G04 暂停与随机：Esc 暂停冻结车辆、计时与采样；窗口失焦自动暂停；fixed_seed=1037 冻结货箱布置、8 盏路灯位置与 3 处积水洼位置；本作无概率判定。
- G05 手感冻结（本包冻结值）：手刹（Space）按下时后轮抓地 −50%（起漂辅助），松开即时恢复 0.7；积水洼内湿地抓地 0.7→**0.55**（驶离即恢复）；反打修正——侧滑角 >45° 时松油门＋反向转向 1.0 秒内车辆恢复可控（抓地恢复事件）；碰撞后 0.5 秒内油门/转向响应即时恢复（碰撞不清空操控）；输入到可见转向反馈 ≤100 毫秒（I07）。

## 4. 操作与输入 [I01–I07]

- I01 键位：W/S＝油门/刹车；A/D＝转向；Space＝手刹起漂；R＝即时段重开；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：暂停/结算期间驾驶输入无效；被拒输入不产生状态变化；R 即时段重开清空全部计分状态。
- I03 鼠标仅用于菜单，非冻结需求。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入；同帧多输入按 §6 各机制声明的顺序结算。
- I05 焦点与点击穿透规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停（G04）。
- I06 UI 必须显示的状态：总分、当前倍率、连漂计时（当前段连续漂移秒数）、剩余时间、碰撞次数、当前侧滑角（起漂阈值 15° 参照）。
- I07 输入延迟目标：按键到可见转向/车辆反馈 ≤100 毫秒（桌面 P95，每类输入 ≥30 次采样）。

## 6. 机制系统 [M01–M04]

- M01 侧滑角计分（主机制）
  - input：驾驶操作（转向＋油门/手刹，玩家）
  - precondition：处于 S08 计分阶段（非暂停/结算）
  - state_change：侧滑角与车速 → 每 0.1 秒按 G02 公式计分（仅侧滑角 ≥15°）
  - output：按 G02 累积总分
  - observable：侧滑采样与得分流水（含 θ、v、单次得分字段）
  - invalid_case：θ<15° 的采样不计分且不中断连段（连段中断规则见 M02）；暂停期间采样冻结
  - recovery：断漂后重新起漂即重新累积（连段从 0 起）
- M02 连贯倍率
  - input：持续不中断漂移（系统计时）
  - precondition：当前段处于漂移状态（θ≥15°）
  - state_change：连续漂移每满 2 秒倍率 +0.5，上限 4.0；漂移中断（角度跌破 15° 或松油门）→ 倍率归 1.0、连漂计时清零
  - output：倍率作用于后续采样得分（G02）
  - observable：倍率状态事件与连漂计时
  - invalid_case：非漂移期间不累积连漂计时
  - recovery：中断后重新起漂，倍率从 1.0 重新爬升
- M03 碰撞中断与湿地摩擦
  - input：碰撞检测（系统）；湿地接触（全场地基）
  - precondition：车辆处于行驶状态
  - state_change：碰撞 → 本段倍率归 1.0、连漂清零、不扣分、0.5 秒内操控即时恢复；湿地抓地系数 0.7 持续作用于转向/制动
  - output：按 G03 结算中断
  - observable：碰撞事件（含位置与对象）与摩擦参数差分
  - invalid_case：碰擦计为碰撞（速度 >2 m/s 的接触）；静止接触不触发中断
  - recovery：碰撞后立即可控（G05），重新起漂即恢复计分
- M04 积水洼与手刹
  - input：驶入/驶离积水洼（系统触发体）；按下/松开手刹（玩家）
  - precondition：车辆处于行驶状态
  - state_change：积水洼内抓地 0.7→0.55（驶离恢复）、水花溅起；手刹按下时后轮抓地 −50%（起漂辅助）、松开恢复
  - output：按 G05 改变车辆物理参数
  - observable：积水洼进入/离开事件、水花事件、手刹状态与抓地参数差分
  - invalid_case：积水洼判定体半径 4 米（seed 冻结），边界采样可复核；手刹在直线高速时仅提供制动不主动起漂
  - recovery：驶离积水洼或松手刹即时恢复原抓地

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：90 秒内累计得分 ≥5000 → 结算判胜（显示总分、最大倍率、碰撞次数、评级）。
- V02 失败条件：90 秒耗尽且得分 <5000 → 结算判负（显示差距）；无车辆损毁态。
- V03 恢复语义：R 即时段重开（清空得分、计时、倍率、碰撞计数）；结算界面一键重开。
- V04 persistent_state：无（重开全量清空）。
- V04 软锁与不可达处理：不设永久软锁——达标可通过正常漂移达成，或触发 V02 失败路径进入结算；结算界面重开为最终恢复出路。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（分数/倍率/计时）局内保留、重开清空；跨局状态无（S 档：重开全量清空）。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：港口城「灰潮市」的雨季——独立改装厂「夜鸥工坊」每在暴雨夜租下闲置的集装箱货场，做封闭漂移调校测试；雨夜湿滑地面是它们天然的调校台。
- W02 场景所在地：灰潮市 7 号货运堆场——150×100 米围场，集装箱与轮胎障错落围出漂移区，8 盏高架路灯切出光池，3 处积水洼映着灯光；铁皮围墙为硬边界。
- W03 玩家身份与当前任务动机：玩家是夜鸥工坊的调校车手，驾驶后驱漂移轿跑在 90 秒封闭测试里跑出 5000 分以上的调校报告。
- W04 失败代价与结局表达：未达标＝「调校失败」——工坊雨棚灯熄灭（C03 失败意象）；达标＝工坊灯全亮、白板上写下新纪录（C03 胜利意象）。
- W05 叙事来源：漂移车＝夜鸥工坊自制的后驱轿跑；货箱/轮胎障＝堆场遗留的货运物资；路灯＝港口高架钠灯；积水洼＝排水不畅的低洼。全部原创，不用商业作品命名。
- W06 视觉风格与色彩材质：雨夜工业风；主色＝铁青 #2E3A43、钠灯橙黄 #F0B24A、水膜反光青 #4B7C8C、警示橙 #E4762C；材质为湿混凝土、锈蚀集装箱、水洼镜面与轮胎橡胶。
- W07 环境氛围与声音语言：持续降雨与远处港机低鸣为底；音效语言＝引擎、轮胎摩擦、水花、碰撞、连段提示（F06 冻结清单）；混音优先级：倒计时/结算 ＞ 连段提示 ＞ 碰撞 ＞ 轮胎 ＞ 引擎 ＞ 雨环境。
- W08 故事表达方式：C01 开场交代雨夜测试任务 → 过程中连段横幅与胎痕水雾承载调校推进 → C03 结算双意象收束；叙事只做包装不改数值。

- F04 环境常驻效果：持续中雨与地面雨点涟漪、湿混凝土全图反光、路灯锥形光池与雨丝显形、远处港机剪影；均为纯表现层。

| 结算 | C03 播放（双意象）＋结算面板 | victory_sting / defeat_sting | 进入结算面板 |

- F06 关键音效清单（one_shot 9 条＋环境循环 3 条，全部冻结需求）：countdown_beep、start_release、combo_up、drift_break、collision_crash、puddle_splash、handbrake_click、victory_sting、defeat_sting；环境循环：rain_night_loop（雨夜底噪）、drift_engine（引擎随速变调）、tire_skid_loop（侧滑摩擦随 θ 强度）。无配音需求。
- F07 VFX 信息性与遮挡约束：连段横幅、倍率数字、侧滑角参照为信息类 VFX，必须清晰可辨；胎烟/水花不得遮挡 HUD 与前方障碍；雨丝密度不得遮蔽路灯光池边界；非结算单个全屏遮挡 ≤0.5 秒。
- F08 音画同步：起漂音与胎烟同帧；倍率音与数字跳动同帧；碰撞音与火花同帧；水花音与溅起同帧。
- F09 屏幕震动：碰撞 0.3 秒中幅（幅度 6 px 等效）；积水洼 0.1 秒轻微；暂停/结算取消未结束的震动；设置可关闭（镜头震动开/关、伤害数字同义开关保留给分数飘字）。
- F10 前端界面：标题（开始/设置/退出）→ 漂移 HUD（总分/倍率/连漂计时/剩余时间/碰撞数/侧滑角，见 I06）→ 暂停面板（继续/重开/返回/设置）→ 结算面板（总分、达标差距、最大倍率、碰撞次数、评级；Enter 重开）；关键状态图标＋文字并用；窗口失焦自动暂停。

## 10. 过场视频 [C01–C03]

- C01 雨夜货场（Opening，6 秒，1280×720@24fps）
  - 触发时机：首次由标题点击「开始」后、倒计时之前，每局一次
  - 内容与角色场景：暴雨中的 7 号堆场俯瞰、路灯一盏盏亮起、集装箱间隙里漂移车驶出工坊雨棚，镜头绕场一周停在起点
  - 资产对应：漂移车、货箱障碍、路灯与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入倒计时；自然播完 → 进入倒计时
  - 状态一致：跳过与自然播完后初始状态一致；播放期间不推进任何游戏计时
- C02 漂移连段（Event，5 秒，1280×720@24fps）
  - 触发时机：本局首次连段倍率达到 2.0 时插入一次（画中画、不打断操作），每局最多一次
  - 内容与角色场景：低机位贴地跟拍轮胎在湿地上划出的水痕弧线、胎烟掠过镜头、路灯光池被车影劈开
  - 资产对应：漂移车与湿地面材质同源
  - 可跳过：Esc/Enter 跳过 → 立即返回行驶视角；自然播完 → 自动返回
  - 状态一致：不打断驾驶控制权；播放期间游戏计时正常推进（不暂停、不加成）
- C03 分数结算（Ending，6 秒，1280×720@24fps，双意象共用条目）
  - 触发时机：V01/V02 成立、结算面板出现之前，每局一次
  - 内容与角色场景：胜利意象＝工坊雨棚灯全亮、白板写下新纪录、车手比出手势；失败意象＝雨棚灯熄灭、白板分数被雨冲淡、车影停在光池边
  - 资产对应：漂移车与工坊场景元素同源
  - 可跳过：Esc/Enter 跳过 → 直接进入对应结算面板；自然播完 → 进入对应结算面板
  - 状态一致：仅在真实 V01/V02 后触发；播放期间不推进任何游戏计时

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：9 个（text-to-3D 6，image-to-3D 3）；object 任务资产为：night_drift_car, freight_cargo_container, tire_stack_barrier, concrete_curb_barrier, metal_safety_rail, yard_street_lamp, yard_wall_section, puddle_pool, drift_scoreboard。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：handbrake_drift。
- video/audio/mechanic/UI：分别为 3/12/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

## 0. 标题、版本与使用说明

- 作品名：《湿地动物迁徙的摄影调查》；版本：mechanics-v3（2026-10-11 完整性修订：补焦距、照片质量档、样本去重、行为时间表、惊扰回归与隐蔽规则、世界设定、演出反馈、视频与正向范围清单）；运行引擎：**Three.js（WebGL）**（spec、rubric 与 asset 任务 JSONL 引擎字段保持一致）；输入方式：键盘与鼠标。
- 原创边界：本作全部名称、动物、场景、文案与美术必须原创，不使用任何商业作品的物种设计、名称或造型。
- 规则优先级：本文件全局数值与规则 ＞ 机制章节 ＞ 区域实例 ＞ 生成器自由补充；未指定数值可作为明确标注的配置默认值。

## 1. 定位与完整流程 [S01–S06]

- S01 类型：单区域观察拍摄＋证据判定调查。本测例包含的能力：三物种行为循环、双档焦距取景、拍摄有效性判定、照片质量分级、样本去重、潜行隐蔽、惊扰回归、证据组合与二选一结论、开场/结算视频。
- S02 核心循环一句话：观察行为 → 构图拍摄 → 证据入册 → 组合提交 → 结论分支。
- S03 流程：进入湿地 → 蹲点观察 → 拍摄三个调查对象 → 证据入册 → 提交证据组合 → 结论分支结算。
- S04 最低完整流程：可探索湿地、取景拍摄、证据册界面、提交判定、结论结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：结论不成立可续拍再提交（快门重置）；快门耗尽自动重开；结算界面一键重开。
- S06 与种子卡差异：种子卡 persistent_state 为「证据册（区域内持久）」；本包冻结为仅局内保留，重开全量清空（P0）。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：启动与标题 → 湿地探索与蹲点 → 取景拍摄 → 证据入册 → 提交判定 → 结论结算 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且湿地按 seed=1052 生成完成
  - state_change：进入「标题」状态；首次进入按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10 呈现（任务简报：判定停歇地或过境通道）
  - next_actions：进入「湿地探索」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 湿地探索与蹲点
  - input：WASD 移动、Shift 蹲伏靠近、右键取景（触发方：玩家）
  - precondition：标题已完成
  - state_change：进入可操作探索；动物按行为时间表活动
  - feedback：芦苇风、水面涟漪、动物行为图标按 §9 F05 呈现
  - next_actions：接近目标并进入「取景拍摄」
  - outcome：惊扰状态与位置结算
- S08 取景拍摄
  - input：滚轮切换焦距、左键拍摄、行为标签选择（触发方：玩家）
  - precondition：处于取景模式且快门 >0
  - state_change：按 G02 判定表生成照片有效性 → 有效入册（去重）/无效丢弃
  - feedback：取景框、对焦标记、判定弹窗按 §9 F05
  - next_actions：集齐目标组合进入「提交判定」
  - outcome：证据册条目推进
- S09 证据入册与整理
  - input：Tab 打开证据册（触发方：玩家）
  - precondition：存在至少一张有效照片
  - state_change：证据册按「物种×行为」去重登记并显示质量档
  - feedback：条目卡片与质量徽标
  - next_actions：勾选组合 →「提交判定」
  - outcome：待提交组合确定
- S10 提交判定
  - input：提交界面勾选＋确认（触发方：玩家）
  - precondition：证据组合已勾选
  - state_change：按 G03 判定表评估证据集 → 成立/不成立
  - feedback：判定结果弹窗；不成立提示续拍
  - next_actions：成立 →「结论结算」（先播 C02）；不成立 → 快门重置续拍
  - outcome：按 V01 出分支
- S11 结论结算
  - input：Enter＝重开 / Esc＝返回标题（触发方：玩家）
  - precondition：成立结论已触发
  - state_change：进入「结算」状态；区域冻结
  - feedback：结论报告页（结论、有效照片数、质量分布、快门余量）
  - next_actions：重开或返回
  - outcome：无跨局写入

## 3. 数值口径与全局规则 [G01–G09]

- G01 统一刻度：快门次数、有效照片数、证据编号为整数；距离为米。
- G02 拍摄与快门（本包冻结值）：快门上限 **24 张**（提交失败续拍时重置）；三个调查对象——白鹭（觅食行为）、苇莺（停歇鸣唱）、水獭（巢穴栖息）；拍摄有效性判定表（本包冻结值）：距离 ≤15 米、目标在取景框内、无遮挡、行为状态与所选标签一致 → 照片有效；任一不满足 → 无效（耗快门但不入册）。
- G03 证据组合与结论（本包冻结值）：结论分支二选一——「迁徙停歇地」需 ≥2 种行为证据（各 ≥1 张有效照片）；「过境通道」需 1 种行为证据＋1 张栖息环境照片。提交时按判定表出成立/不成立；不成立可续拍（快门重置）。
- G04 结果状态 oracle：给定输入状态（距离 12 米、无遮挡、白鹭处于觅食行为、标签选「觅食」）拍摄 → 照片必然入册为有效证据；同一局面但距离 20 米 → 必然无效且不入册；任何偏离即 FAIL。Esc 暂停冻结动物行为与快门；fixed_seed=1052 冻结动物初始位置与巡游路线及行为循环相位。
- G05 焦距与取景（本包冻结值）：取景模式下滚轮切换焦距 2 档（1×/3×）；1× 视场 40°、3× 视场 15°；焦距只改变取景画面与目标占比，有效性判定的距离上限仍为实际 15 米；HUD 取景框旁显示当前焦距（图标＋文字「1×/3×」）与实际距离。
- G06 照片质量档（本包冻结值）：有效照片分三档——高质量（距离 ≤8 米且目标占取景框 ≥60%）、合格（满足 G02 判定表）、无效；质量档写入证据册条目并显示于结算报告；质量不改变 G03 结论判定，仅作报告分级展示。
- G07 样本去重（本包冻结值）：每种「物种×行为」组合的有效照片仅首张计入证据册条目；后续同组合照片存档但不重复入册；证据册条目数＝去重后的组合数（结算按条目数与质量分布展示）。
- G08 动物行为时间表（本包冻结值）：白鹭＝觅食→梳理→起飞（每状态 20 秒循环）；苇莺＝停歇→鸣唱→隐蔽（每状态 15 秒循环）；水獭＝巡游→栖息→入水（每状态 25 秒循环）；行为循环相位由 seed=1052 冻结；标签必须与拍摄瞬间动物实际状态一致才算有效。
- G09 惊扰与回归（本包冻结值）：跑动进入动物 8 米范围 → 当次行为中断并离开当前观测点，被惊扰动物 60 秒不回归该点，HUD 提示「目标受惊，建议转移观测点」（图标＋文字）；蹲伏且位于芦苇丛内 → 惊扰判定半径缩至 4 米；蹲伏移动本身不触发惊扰。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：WASD＝移动；Shift＝蹲伏靠近（降低惊扰）；右键＝取景；滚轮＝切换焦距；左键＝拍摄；Tab＝证据册；E＝提交界面；Esc＝暂停；结算 Enter＝重开。
- I02 输入语义边界：快门为 0 时拍摄无效；未取景时左键无效；提交界面外按 E 无效；暂停/结算期间输入无效。
- I03 无手柄需求。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；取景模式下移动键降速生效、标签选择优先于拍摄。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：快门余量、当前焦距与距离、取景框、行为标签选择、证据册条目与质量、惊扰提示；HUD 对照见 rubric。
- I07 输入延迟目标：移动/蹲伏按键到画面反馈 ≤ 80 毫秒；快门反馈 ≤ 100 毫秒。

## 5. 区域与内容清单 [L01–L04]

- L01 生成对象：调查员角色 1（人形）、三个调查对象（白鹭/苇莺/水獭，原创造型）、观测点 3、芦苇丛隐蔽区 3、相机 UI（取景框/焦距/距离）；湿地装饰为表现层。
- L02 区域：单湿地区域（芦苇带、浅滩、水道），动物初始位置、巡游路线、行为相位与芦苇丛由 seed=1052 冻结；惊扰半径 8 米（蹲伏芦苇丛内 4 米）。
- L03 目标物/交互物/场景/UI 对象：本 spec §3–§9 引用的界面元素（标题/取景 UI/证据册/结算/暂停/视频播放层）与交互物逐类存在且运行时可进入；数量与属性以 L01/L02 与 G 系为准。
- L04 冻结需求 vs 实现默认 vs 生成自由度：本 spec 明确写出的数值与数量为冻结需求；§9 未冻结的装饰造型与配色为生成自由度，不得评估为缺失；实现默认值必须明确标注且符合核心机制。

## 6. 机制系统 [M01–M05]

- M01 拍摄条件（主机制）
  - input：取景＋左键拍摄（含行为标签选择）
  - precondition：快门 >0 且处于取景模式
  - state_change：按 G02 判定表生成照片有效性 → 有效入册（G07 去重）/无效丢弃
  - observable：每张照片的判定字段（距离/遮挡/行为/质量/结果）与快门消耗流水
  - invalid_case：任一判定项不满足 → 无效；快门 0 → 拒绝
  - recovery：续拍重置快门
- M02 证据组合
  - input：提交界面勾选证据组合
  - precondition：至少存在待提交条目
  - state_change：按 G03 判定表评估证据集 → 成立/不成立
  - observable：提交判定事件（含证据编号与结论）
  - invalid_case：组合不成立 → 提示缺项并允许续拍
  - recovery：快门重置为 24、证据册保留
- M03 结论分支
  - input：提交成立组合
  - precondition：组合按 G03 成立
  - state_change：按证据构成触发「迁徙停歇地」或「过境通道」结论 → 结算
  - observable：分支触发事件与结算面板
  - invalid_case：证据构成与结论不匹配的提交 → 判不成立
  - recovery：续拍重提交
- M04 焦距与取景
  - input：滚轮切换焦距
  - precondition：处于取景模式
  - state_change：视场 40°↔15° 切换；HUD 焦距与距离更新
  - observable：焦距状态事件与取景画面变化
  - invalid_case：非取景状态滚轮无效
  - recovery：无副作用
- M05 惊扰与回归
  - input：跑动进入惊扰半径（系统）
  - precondition：动物在该观测点处于活动中
  - state_change：行为中断 → 离开观测点 → 60 秒不回归该点；蹲伏芦苇丛内半径缩至 4 米
  - observable：`flee` 事件（含物种与点位）与回归计时
  - invalid_case：蹲伏移动不触发
  - recovery：60 秒后或转移观测点

系统耦合边（玩法必需、可复现）：

- E01 from_system=潜行系统 → to_system=动物行为系统；changed_state=蹲伏且芦苇丛内使惊扰半径 8→4 米，可接近至 4–8 米内拍摄（G06 高质量距离档由此可达）；验证方式=蹲伏芦苇丛内/外分别跑动接近的 flee 事件边界对照（state_before/after）。
- E02 from_system=动物行为时间表 → to_system=拍摄判定系统；changed_state=标签与动物瞬时状态一致/不一致直接决定照片有效/无效（G02 第四判定项）；验证方式=同一位置不同行为状态两次拍摄的判定对照。

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：提交成立证据组合 → 结论分支结算（显示结论、有效照片数、质量分布、快门余量）。
- V02 失败条件：结论不成立（可续拍重提交）；快门耗尽自动重开；无角色死亡态。
- V03 恢复语义：不成立续拍时快门重置为 24、证据册保留；快门耗尽/手动重开 → 证据册与快门全量清空。
- V04 persistent_state：无（重开全量清空；证据册仅局内保留，见 §1 与种子卡差异）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（证据册/快门）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设永久软锁——快门可续拍重置、行为循环必然复现，任意时刻可完成或重开。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：现代生态保护时代；「芦鸣湿地」正处候鸟迁徙季，保护站需要在两周窗口内完成一份迁徙调查报告。
- W02 场景所在地：芦鸣湿地——芦苇带、浅滩觅食区、水道獭巢三大观测点由步道串联。
- W03 玩家身份与当前任务：玩家是野生动物调查员「苇」；当前任务：潜行拍摄白鹭、苇莺、水獭的行为证据，判断湿地是「迁徙停歇地」还是「过境通道」。
- W04 失败代价与结局表达：快门耗尽＝本季样张不足需重新布点（自动重开文案）；成功则 C02 呈现报告封页与结论递交场面。
- W05 叙事来源：三个物种即湿地的指示物种；观测点＝保护站既设的蹲点位；芦苇丛＝天然隐蔽掩体；相机与长焦＝保护站调查装备。全部原创。
- W06 视觉风格与色彩材质：风格化写实湿地；主色＝苇绿（#7FA05A 系）＋浅滩米（#D8CFA8 系）＋水色青蓝（#5C8FA3 系）；材质以芦苇、湿泥、羽色为主，光线为清晨柔光。
- W07 环境氛围与声音语言：清晨湿地的生机——常驻虫鸣与水声、物种鸣叫（白鹭短唳/苇莺啭鸣/水獭低咕）；音效语言为「快门轻响＋对焦提示＋惊飞振翅」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代调查任务 → 取景-入册-提交过程承载调查节奏 → 结算视频（C02）收束报告；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：第三人称跟随（距离 3.5 米、高度 2 米），平滑插值 0.08 秒；取景模式切换为相机取景框画面（保留肩后视角叠加）；镜头边界＝湿地步道与可涉区外框；受惊失败时镜头短暂跟随惊飞方向 0.5 秒。
- F02 关键操作镜头变化：3× 焦距时取景画面轻微缩放稳定（减抖动 50%）；惊扰瞬间镜头轻微晃动 0.15 秒；无慢动作。
- F03 输入与延迟：见 I07。
- F04 环境常驻效果：芦苇风摆、水面涟漪与晨雾、玩家泥滩脚印（留痕 45 秒渐隐）、远处飞鸟剪影；不遮挡取景判定框。
- F05 事件反馈表（事件 → 表现 → 结束条件，全部为冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 进入取景 | 取景框展开＋焦距/距离显示 | 相机开镜声 | 退出取景 |
| 切换焦距 | 视场缩放动画 0.2s＋档位标签跳动 | 变焦轻响 | 完成 |
| 对焦锁定 | 目标描边微亮＋对焦标记 | 对焦提示音 | 目标离开或拍摄 |
| 拍摄有效 | 闪光禁用快照框＋照片飞入证据册＋质量徽标弹出 | 快门轻响＋入册叮声 | 完成 |
| 拍摄无效 | 灰色快照框＋失效原因文字（距离/遮挡/标签） | 快门轻响＋短促提示音 | 0.5s |
| 重复样本 | 照片存档不入册＋「重复样本」提示 | 存档沙沙声 | 0.5s |
| 惊扰触发 | 动物急速逃离＋羽毛/水花粒子＋HUD 受惊提示 | 惊飞振翅声＋动物鸣叫 | 离开视野 |
| 蹲伏隐蔽 | 角色压低姿态＋芦苇半掩描边＋「隐蔽」图标 | 衣料摩擦声 | 状态常驻 |

- F06 关键音效清单：开镜、变焦、对焦提示、快门轻响、入册叮、失效提示、存档沙沙、振翅、动物鸣叫（三种）、衣料摩擦、翻页、盖章、上扬音、回卷、低提示音；环境音：虫鸣＋水声（常驻循环）＋晨风拂苇；循环音开始/结束：环境声随区域载入开始、随结算淡出 0.5s；无配音需求。

- F09 屏幕震动：惊扰瞬间 0.15 秒小幅；设置界面提供「镜头震动开/关」（关闭不影响判定）。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：4 个（text-to-3D 2，image-to-3D 2）；object 任务资产为：wildlife_surveyor, egret_heron, reed_warbler, ripple_otter。每项只允许一个物体；组合物必须拆成独立任务。
- motion：3 个；覆盖动作：idle, walk, crouch_sneak。
- video/audio/mechanic/UI：分别为 2/9/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

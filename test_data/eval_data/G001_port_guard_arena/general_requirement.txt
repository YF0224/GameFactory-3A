## 1. 定位与完整流程 [S01–S05]

- S01 类型：3D 第三人称近战攻防，单人单场地。本测例包含的能力：三段轻击与取消、闪避无敌、体力经济、机械守卫 AI（前摇预警/硬直/倒地）、两阶段训练流程、计时结算、开场/阶段升级/结算视频、打击感演出层。
- S02 核心循环一句话：观察守卫前摇 → 走位贴近 → 三段连击 → 闪避取消后摇 → 循环输出至守卫倒地。
- S03 流程：标题界面 → 进入训练场（首次进入前播 C01）→ 训练阶段一（单守卫）→ 阶段升级（全守卫激活）→ 胜利/失败结算（胜局面板前播 C02）→ 重开或返回标题。
- S04 最低完整流程：标题、训练场、胜利结算、失败结算、重开全部存在且有真实入口。
- S05 失败恢复入口：失败/超时结算界面提供「重开本局」（全量重置，含守卫复活与计时重置）；任意时刻 Esc 暂停可继续/重开/返回标题。

## 2. 完整核心循环与阶段 [S06–S12]

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且资源加载完成
  - state_change：进入「标题」状态；首次开始时按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10 呈现
  - next_actions：进入「训练阶段一」
  - outcome：无跨局状态写入
- S07 训练阶段一（单守卫热身）
  - input：WASD 移动、LMB 轻击、Space 闪避、Esc 暂停（触发方：玩家）
  - precondition：阶段一开始，场内 1 号守卫激活，2/3 号守卫待机桩态
  - state_change：按 §6 M01–M05 结算每次输入；体力、连击段、守卫 HP 实时更新
  - feedback：命中反馈按 §9 F05（顿帧/震动/闪白/火花/击退）；蓄力预警按 F05 预警行
  - next_actions：1 号守卫 HP0 → training_phase_up 事件 →「训练阶段二」
  - outcome：守卫倒地后保持倒地模型，不再复活
- S08 训练阶段二（三守卫同场）
  - input：同 S07（触发方：玩家）；守卫 AI 由系统驱动
  - precondition：training_phase_up 已触发，2/3 号守卫激活并恢复巡逻
  - state_change：三守卫独立结算；全场守卫 HP 归零前阶段保持
  - feedback：training_phase_up 瞬间按 §10 C03 播放阶段升级视频（每局一次），随后场地警示灯变绿；其余同 S07
  - next_actions：全部守卫 HP0 →「胜利结算」；玩家 HP0 或 180s 超时 →「失败结算」
  - outcome：按 §7 V01/V02 判定，同帧冲突按 §3 G07
- S09 胜利结算
  - input：Enter=重开 / Esc=返回标题（触发方：玩家）
  - precondition：V01 成立（三守卫全倒）
  - state_change：进入「胜利结算」；面板出现前按 §10 C02 播放结算视频（每局一次）
  - feedback：结算面板显示用时、剩余 HP、最高连击段
  - next_actions：重开（全量重置）或返回标题
  - outcome：不写入跨局状态
- S10 失败结算
  - input：Enter=重开 / Esc=返回标题（触发方：玩家）
  - precondition：V02 成立（HP0 或超时，面板注明原因）
  - state_change：进入「失败结算」，玩法冻结
  - feedback：失败面板注明「体力耗尽被击倒」或「训练超时」
  - next_actions：重开本局
  - outcome：本局状态清空，无跨局副作用
- S11 暂停
  - input：Esc（触发方：玩家）
  - precondition：处于训练场状态
  - state_change：暂停覆盖层打开，守卫 AI、体力回复、倒计时全部冻结
  - feedback：暂停面板（继续/重开/返回标题/设置）
  - next_actions：Esc 或「继续」→ 回到训练场
  - outcome：恢复后状态与暂停前逐字段一致（§3 G05）；窗口失焦自动暂停
- S12 设置
  - input：鼠标点击（触发方：玩家）
  - precondition：标题或暂停界面
  - state_change：打开设置面板
  - feedback：提供「镜头震动开/关」「顿帧开/关」（关闭不影响任何判定数值）
  - next_actions：返回上级界面

## 3. 数值口径与全局规则 [G01–G07]

- G01 统一刻度：场地为 XZ 平面米制、原点=场地中心；状态变量=玩家 HP/体力/连击段、每守卫 HP/AI 相位、训练阶段、倒计时。HUD 状态见 I06。
- G02 角色数值：玩家 HP100、ATK100、DEF20、移速 4.0 m/s、体力上限 100；守卫×3（同规格）：HP120、ATK80、DEF10、移速 3.2 m/s、攻击系数 0.8。
- G03 伤害公式：伤害 = max(1, round(ATK × 系数 × 100/(100+DEF)))。oracle：轻击一段（0.7）对守卫 = 64；三段（1.2）对守卫 = 109；守卫攻击（0.8）对玩家 = 53。
- G04 连击与取消：轻击三段系数 0.7/0.85/1.2、出招间隔 0.38/0.42/0.62s、判定半径 2.5/2.5/3.0m、命中朝向余弦 ≥0.3；距上一段 >0.9s 回一段；后摇开始 0.15s 起可按 Space 闪避取消。连击衰减：同一守卫 2s 窗口内第 n 次命中伤害 ×0.85^(n−1)，下限 ×0.5；oracle：三段二连 = round(109×0.85)=93、三连 = 79。
- G05 暂停与模拟时间：Esc 暂停冻结全部玩法模拟与 180s 倒计时；结算/菜单/视频播放期间不推进；窗口失焦自动暂停；恢复后无状态漂移。
- G06 状态转移 oracle（独立可复核）：初始玩家 HP100/守卫 HP120；输入 [LMB] 命中一段 → 事件流 `hit(player→guard, dmg=64)`、守卫 120→56；若守卫处于前摇，同时产生 `interrupt(windup)`。任何偏离即 FAIL。
- G07 优先级与同帧裁决：同帧「守卫判定帧命中」与「玩家闪避无敌帧」并存时，按判定帧先结算、闪避无敌使伤害=0（G08）；玩家 HP 与第 3 名守卫 HP 同帧归零 → 判负优先（先失败后成功）；倒计时归零瞬间若最后一击已在判定帧 → 该击仍结算后再判超时。

## 4. 操作与输入 [I01–I07]

- I01 键位：WASD=移动；LMB=轻击（连按推进三段）；Space=闪避；Esc=暂停/关闭面板；Enter=确认/重开。
- I02 输入语义边界：超出判定半径/朝向余弦不足的攻击=挥空（有挥击动画与拳风音、无命中反馈、不计连击推进）；体力不足时闪避被拒绝且无位移；面板打开时玩法键一律拒绝且无副作用。
- I03 键盘+鼠标为完整输入方式；菜单可仅用键盘或仅用鼠标操作。
- I04 输入优先级：暂停/结算状态阻断玩法输入；同帧多输入顺序=暂停 > 闪避 > 攻击。
- I05 焦点与失焦：点击画布捕获输入焦点；窗口失焦自动暂停（不依赖 G06）。
- I06 UI 必显状态：玩家 HP、体力条、当前连击段（1/2/3）、每守卫 HP、训练阶段（一/二）、倒计时（180s 倒数）。
- I07 输入延迟目标：按键到画面反馈 ≤100 毫秒（顿帧属于表现层，不改变 I07 计时口径）。

## 6. 机制系统 [M01–M06]

- M01 轻击三段与取消（主机制）
  - input：LMB（触发方：玩家）
  - precondition：处于训练场状态且非面板期；距上一段 ≤0.9s 才推进段位
  - state_change：命中判定（半径 2.5/2.5/3.0m、朝向余弦 ≥0.3）成立时按 G03 结算伤害并按 G04 计连击衰减；后摇 0.15s 起可被 Space 取消
  - observable：`swing(seg)` / `hit(seg, dmg)` / `whiff(seg)` 事件与守卫 HP 快照
  - invalid_case：半径外或朝向不足 → `whiff`，无伤害无连击推进
  - recovery：中断 >0.9s 自动回一段；挥空不中断已推进段位
- M02 闪避与无敌帧
  - input：Space（触发方：玩家）
  - precondition：体力 ≥15
  - state_change：位移 4m（0.3s 内完成）、体力 −15、前 300ms 无敌（期间受击伤害=0）
  - observable：`dodge` 事件与位移轨迹
  - invalid_case：体力不足 → 拒绝，无位移无扣减
  - recovery：体力 12/s 回复（攻击/闪避后 0.5s 起，上限 100）
- M03 机械守卫 AI
  - input：系统每帧驱动（触发方：系统）
  - precondition：守卫存活且已激活
  - state_change：与玩家距离 ≤2m 进入攻击序列：前摇 0.6s（蓄力光锥+蓄力音，见 F05）→ 判定帧 → 后摇 0.4s；受击硬直 0.3s（打断前摇/后摇、不打断判定帧）；HP0 → 倒地并从 AI 列表移除
  - observable：`windup(g)` / `strike(g, dmg=53)` / `stagger(g)` / `down(g)` 事件
  - invalid_case：玩家在判定帧时已离开 2m → 本次攻击落空
  - recovery：倒地守卫不再复活；待机守卫在 training_phase_up 后激活
- M04 训练阶段流转
  - input：1 号守卫 HP0（触发方：系统）
  - precondition：当前为阶段一
  - state_change：触发 `training_phase_up`；2/3 号守卫激活并进入巡逻；触发瞬间按 §10 C03 播放阶段升级视频（每局一次，播放期间倒计时冻结）
  - observable：事件流与场地警示灯变绿（F05）；C03 播放起止事件
  - invalid_case：重复触发被拒绝（每局仅一次）
  - recovery：重开时回阶段一
- M05 体力经济
  - input：闪避/攻击消耗（触发方：玩家操作触发）
  - precondition：处于训练场状态
  - state_change：闪避 −15；攻击不耗体力（本测例冻结口径）；0.5s 空闲起回复 12/s
  - observable：体力条 HUD 与 `stamina_change` 事件
  - invalid_case：体力 <15 时闪避拒绝
  - recovery：自然回复至上限 100
- M06 胜负与重开
  - input：三守卫全倒 / 玩家 HP0 / 180s 超时（触发方：系统判定）
  - precondition：处于训练场状态
  - state_change：V01/V02 判定进入对应结算；同帧冲突按 G07
  - observable：`win` / `lose(reason)` 事件
  - invalid_case：结算后再触发判定被拒绝（每局一次）
  - recovery：重开=全量重置（玩家/守卫/阶段/计时/连击）

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：三名守卫全部 HP0 → 胜利结算，显示用时、剩余 HP、最高连击段。
- V02 失败条件：玩家 HP0（注明「体力耗尽被击倒」语义）或 180s 超时（注明超时）→ 失败结算；与胜利同帧按 G07 判负优先。
- V03 恢复语义：结算界面一键重开=全量重置（守卫复活到初始位、阶段回一、计时回 180s、连击清零）；Esc 暂停可继续；一切恢复不需要读档。
- V04 persistent_state：无（重开全量清空，无跨局解锁与收集品）。
- V05 persistent_state 生命周期：动作级状态即时结算；局内状态（HP/体力/阶段/计时）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设永久软锁——守卫不会卡死不可攻击；玩家被围时可正常闪避脱离；判定不可达时按 V02 语义结算而非无限等待。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：风暴纪元后的第七年，锈港——一座被放弃的深水码头。远方的侵蚀舰队曾触怒此地沉睡的机械守卫，如今守卫将一切靠近者视为来犯之敌。
- W02 场景所在地：锈港集装箱训练场，四周为龙门吊剪影与围墙，海雾常年不散。
- W03 玩家身份与当前任务动机：玩家是港口旧主的领土捍卫者传人，回到锈港夺回领土；必须先通过机械守卫训练场的试炼，证明自己配得上这片土地。
- W04 失败代价与结局表达：失败=未能守住领土传承，训练中断；结局表达见 §10 C02——守卫全倒后，警示灯转绿，捍卫者在场地中央收拳立誓。
- W05 叙事来源：机械守卫=港口旧自动化防卫体系觉醒后的形态；训练场=旧主为传人留下的考验；集装箱与木桩=港口遗留物资。全部原创，不使用商业作品命名或造型。
- W06 视觉风格与色彩材质：写实偏风格的工业废土；主色=锈红 #8C4A3C、海军灰 #5A6672、钨钢 #B8B2A6、警示黄 #E4B33C、海雾蓝 #6E8FA3；材质为锈蚀金属、集装箱彩钢、湿滑混凝土。
- W07 环境氛围与声音语言：海雾弥漫的黄昏训练场——常驻海风环境声；音效语言为「金属打击+机械伺服+海浪衬底」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代捍卫者身份与来敌 → 阶段升级视频（C03）承载「守卫全阵唤醒」的过程叙事 → 结算视频（C02）收束；故事只做包装与节奏，不改变任何机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：第三人称肩后跟随；FOV 60–90 可调（默认 70）；镜头平滑跟随（阻尼 0.15s）；边界=场地外接矩形 +8% 余量。
- F02 关键操作镜头变化：命中瞬间镜头轻微内推 2%（0.1s）；守卫倒地镜头短暂下沉 0.5s；无持续震动。
- F03 输入与延迟：见 I07；顿帧不改变 I07 计时口径。
- F04 环境常驻效果：海雾粒子、龙门吊剪影轮廓光、警示灯旋转光锥（阶段一黄、阶段二绿）。常驻效果纯表现层，不参与判定。
- F05 事件反馈表（事件 → 画面表现 → 音效 → 结束条件，全部冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 轻击命中 | 顿帧 60–100ms（三段逐段加重）＋镜头微震＋守卫闪白 0.1s＋火花＋击退 0.4m | 金属清脆撞击＋低频闷响（打断前摇的命中音调更高） | 顿帧结束即恢复 |
| 挥空 | 拳风轨迹 | 挥拳风声（无命中音） | 动作结束 |
| 守卫蓄力攻击预警 | 前摇 0.6s 全程蓄力光锥（警示黄）＋守卫胸口聚能 | 低频蓄力音渐强 | 判定帧触发即停 |
| 玩家受击 | 屏幕边缘红晕 0.3s＋受击方向指示 | 闷响受击音 | 红晕淡出 |
| 守卫硬直 | 守卫电弧短路粒子 | 金属刮擦 | 0.3s 结束 |
| 守卫倒地 | 倒地动画＋尘土＋部件弹落 | 重物倒地＋机械故障音 | 动画到位即停 |
| 阶段升级 | 全场警示灯黄转绿＋短促横幅 | 上扬提示音一次 | 2s 后横幅淡出 |
| 胜利 | 结算光效 | 胜利音一次 | 进入面板 |
| 失败 | 画面降饱和 | 低沉提示音 | 进入面板 |

- F06 关键音效清单（one_shot）：拳风、金属撞击、低频闷响、蓄力预警、守卫倒地、胜利音、失败音；环境循环：海风+远浪（常驻，暂停静音、结算淡出 0.5s）；无配音需求（对白以文本呈现）。
- F07 VFX 信息性与遮挡约束：蓄力光锥与受击红晕承担玩法信息（预警/伤害方向）；火花与尘土单帧粒子 ≤40，不遮挡 HUD 与判定主体；击退方向与伤害来源一致。
- F08 音画同步：命中音与命中事件同帧起止；蓄力音与前摇同帧开始、判定帧结束；顿帧期间音效正常播放。
- F09 屏幕震动：命中 0.1s 小幅、守卫倒地 0.2s 中幅；设置提供「镜头震动开/关」（关闭不影响判定与数值）。
- F10 前端界面：标题（开始/设置/退出）→ 训练 HUD（I06 全项）→ 胜利结算（用时/剩余 HP/最高连击段/重开/返回）→ 失败结算（原因/重开/返回）→ 暂停面板（继续/重开/返回/设置）；关键状态附图标+文字（阶段一/二、连击段、蓄力预警），不只靠颜色区分；窗口失焦自动暂停（与 I05 一致）。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：6 个（text-to-3D 4，image-to-3D 2）；object 任务资产为：guard_trainer, mechanical_guard, port_container, dock_crane, training_post, warning_beacon。每项只允许一个物体；组合物必须拆成独立任务。
- motion：7 个；覆盖动作：jab_l1, jab_l2, jab_l3, dodge_roll, hit_react, windup_charge, knockdown。
- video/audio/mechanic/UI：分别为 3/9/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

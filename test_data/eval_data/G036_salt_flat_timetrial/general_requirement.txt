## 1. 定位与完整流程 [S01–S05]

- S01 类型：3D 单车两圈检查点计时赛（含 1 处双路线分岔）。
- S02 核心循环一句话：驾驶 → 过计时门 → 计时累积 → 选择路面与路线 → 完成圈数 → 结算最好成绩。
- S03 流程：开始界面 → C01 开场 → 倒计时起步 → 两圈行驶（过 8 检查点/圈＋分岔选择）→ 终点结算（评级/最好成绩）→ 重开。
- S04 最低完整流程：开始界面、可操作驾驶、检查点计时门序列、终点结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：R 复位回最近检查点（计时继续、+3 秒罚时）；总时限超时判负结算；结算界面一键重开；Esc 暂停（计时暂停）。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：主菜单 → 倒计时起步 → 两圈行驶（每圈 8 座分段计时门＋1 处分岔）→ 终点结算 → 重开/返回菜单；任意行驶阶段可 Esc 暂停。每阶段六要素如下（引用本 spec §3–§7 对应规则）：

- S06 主菜单
  - input：系统启动，玩家确认进入
  - precondition：程序启动完成（C01 可在首次入局前播放）
  - state_change：显示主菜单（开始/退出）
  - feedback：主菜单界面（F10）
  - next_actions：点击「开始」→ S07
  - outcome：无状态副作用
- S07 倒计时起步
  - input：玩家点击「开始」后系统进入；油门可预压
  - precondition：主菜单已完成、C01 播完或跳过
  - state_change：3-2-1 倒计时（3 秒）；倒计时内车辆锁定（G04/I02）
  - feedback：倒计时数字＋发车音效（F05/F06）
  - next_actions：倒计时归零 → S08
  - outcome：起步瞬间开始计时（G01/G02）
- S08 两圈行驶（主玩法阶段）
  - input：玩家驾驶（按 §4 I01 键位）
  - precondition：起步完成
  - state_change：按序过 8 座分段计时门（每圈）；第 4–5 门之间选择主线/外线（M04）；出界、漏点、复位按 M01–M03 结算
  - feedback：分段计时门横幅、胎痕/尘土/风（F04/F05），HUD 见 I06
  - next_actions：完成两圈 → S09；总时限 720 秒耗尽 → S10；Esc → S11
  - outcome：计时累积、复位罚时计入总成绩（G02）
- S09 终点结算
  - input：系统结算（跨过终点计时门）
  - precondition：两圈全部按序完成（V01）
  - state_change：显示两圈分段、总成绩、评级（金 480/银 540/铜 600）、复位次数
  - feedback：C03 冲线结算视频＋结算面板（F05/F06）
  - next_actions：Enter 重开 → S06；返回菜单 → S06
  - outcome：按 V01 判定并结算
- S10 超时判负结算
  - input：系统结算（总时限 720 秒耗尽，V02）
  - precondition：S08 中未完成两圈且超时
  - state_change：显示超时判负结算（当前圈数/门数/已用时间）
  - feedback：超时警报＋C03 失败意象（F05/F06）
  - next_actions：Enter 重开 → S06；返回菜单 → S06
  - outcome：按 V02 判负结算
- S11 暂停
  - input：玩家按 Esc
  - precondition：处于 S07–S10 之外的全部行驶/倒计时阶段
  - state_change：冻结车辆与计时（G04）
  - feedback：暂停菜单（继续/重开/返回菜单）
  - next_actions：Esc/继续 → 返回原阶段；重开 → S06
  - outcome：恢复后计时从冻结点连续累计，无漂移

## 3. 数值口径与全局规则 [G01–G05]

- G01 统一刻度：时间精确到毫秒；分段/单圈/总成绩均为累计计时；复位次数为整数；车速 km/h、距离米。
- G02 计时公式与 oracle（本包冻结值）：单圈用时＝该圈末计时门时间戳 − 该圈首计时门时间戳；总成绩＝两圈之和＋Σ复位罚时（每次 **+3 秒**）。独立 oracle 数例：8 个分段各 30.000 秒 → 单圈 240.000 秒；两圈各 240 秒＋1 次复位 → 总成绩 **483.000 秒**。评级带宽（冻结）：金牌 ≤480 秒、银牌 ≤540 秒、铜牌 ≤600 秒，超铜牌仅显示完赛无评级。
- G03 车辆与路面参数（本包冻结值）：极速 200 km/h；常规加速 0–100 km/h 用时 4 秒；转向无漂移辅助，转向灵敏度＝基准×(1−0.5×v/200)（v 为 km/h，即 100 km/h 时 75%、200 km/h 时 50%）；主路面（压实盐板）抓地系数 1.0，100 km/h 制动距离 40 米；盐晶酥松带抓地系数 0.75、制动距离 ×1.3（100 km/h → 52 米）、急转打滑风险显著提高。赛道全长约 4 千米，每圈 8 座分段计时门（起点拱门兼主计时门）。
- G04 暂停与随机：Esc 暒停冻结车辆与计时；窗口失焦自动暂停；fixed_seed=1036 冻结赛道布置（检查点位置、分岔口、酥松带范围、地标）；本作无概率判定（风为表现层，见 F04）。
- G05 超时（本包冻结值）：全程总时限 **720 秒**（自起步倒计时归零起算，暂停不计入）；超时 → 超时事件 → 判负结算（V02）。

## 4. 操作与输入 [I01–I07]

- I01 键位：W/S＝油门/刹车；A/D＝转向；R＝复位回最近已过计时门；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：暂停/结算期间驾驶输入无效；起步倒计时 3 秒内油门可预压但车辆锁定；被拒输入不产生状态变化。
- I03 鼠标仅用于菜单与镜头辅助（可选），非冻结需求。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入；同帧多输入按 §6 各机制声明的顺序结算。
- I05 焦点与点击穿透规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停（G04）。
- I06 UI 必须显示的状态：当前圈数（1–2）、单圈计时、总计时、已过门数（x/8）、复位次数、本圈分段用时（过门时刷新）、超时倒计时（剩余总时限）。
- I07 输入延迟目标：按键到画面可见反馈 ≤100 毫秒（桌面 P95，每类输入 ≥30 次采样）。

## 5. 赛道与内容清单 [L01–L04]

- L01 生成对象：原创试验车 1、分段计时门拱门 8（兼起终点主计时门）、遥测站 1、盐晶岩地标 2、风向袋 3；装饰非冻结需求。
- L02 赛道（冻结布局）：全长约 4 千米封闭环线；8 座计时门位置由 seed=1036 冻结；边界白线外为出界判定区；第 4–5 门之间设 1 处双路线分岔——主线（压实盐板，长 500 米）与外线（盐晶酥松带，长 450 米、抓地 0.75）在分岔口汇合，两侧均设检查点判定；酥松带另在赛道两处弯道外侧延伸为漂移带。
- L03 目标物/交互物/场景/UI 对象：本 spec §3–§7 引用的界面元素（菜单/HUD/结算面板）与交互物（计时门触发体、出界判定体、复位点）逐类存在且运行时可进入；计时门判定体由引擎触发器构建，装饰拱门模型不得替代判定体；数量与属性以对应 G·M 条目为准。
- L04 冻结需求 vs 实现默认 vs 生成自由度：本 spec 明确写出的数值与数量为冻结需求；未给数值的表现层（装饰造型、配色、粒子参数、音色）为生成自由度，不得评估为缺失；实现默认值必须明确标注且符合核心机制。音效为冻结需求（F06 清单逐条交付，缺失按 FAIL 计）。

## 6. 机制系统 [M01–M04]

- M01 顺序计时门（主机制）
  - input：穿越判定（系统触发器，毫秒时间戳）
  - precondition：车辆处于可计时的行驶状态（非暂停/结算）
  - state_change：计时门必须按 1→8 序通过；漏门（越序或跳越）→ 该圈不计成绩并触发漏门警告
  - output：按 G02 结算分段与单圈用时
  - observable：计时门序列事件（含编号与毫秒时间戳）、lap_complete 事件、漏门警告事件
  - invalid_case：越序穿门不计入且出漏门警告（无副作用）；暂停/结算期间触发体冻结
  - recovery：漏门后须按 R 复位回最近已过门重新按序通过，或继续完成本圈但成绩按 V02 标记 invalid
- M02 防抄近路
  - input：出界检测（系统，边界白线外判定区）
  - precondition：车辆处于行驶状态
  - state_change：离开赛道边界 → 计时继续、车辆减速，该圈成绩有效性标记 invalid（除非按 R 复位回检查点后重新按序通过剩余计时门）
  - output：按 G02 结算成绩有效性
  - observable：出界事件与成绩有效性标记
  - invalid_case：分岔两侧均为合法路线（L02），出界判定不误伤分岔区；误判出界的样本须可回放复核
  - recovery：出界后按 R 复位恢复有效性（+3 秒罚时）
- M03 复位
  - input：R 键或翻车自动
  - precondition：车辆处于行驶状态或翻车态
  - state_change：回最近已过计时门、车头朝向重置为赛道行进方向、计时继续、复位计数 +1 并罚 +3 秒
  - output：按 G02 计入罚时
  - observable：reset 事件（含门号与罚时）与计时连续性
  - invalid_case：结算/暂停期间 R 无效
  - recovery：复位本身即恢复入口；结算界面一键重开为最终出路（V03）
- M04 路面与路线分岔
  - input：驶入分岔口选择主线/外线（驾驶）；持续接触酥松带（系统）
  - precondition：处于第 4–5 门之间分岔区或酥松带延伸区
  - state_change：外线里程短但抓地 0.75（转向与制动衰减、打滑风险）；主线长但抓地 1.0；路线记录事件（圈号、所选路线、分段用时）
  - output：按 G03 抓地/制动口径改变车辆物理参数
  - observable：路线记录事件与两线分段用时差分（同 seed 同操作可复现）
  - invalid_case：分岔区两侧均为合法赛道（M02 不判出界）
  - recovery：误入外线可正常跑完，或 R 复位回第 4 门重选

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：按序完成两圈并跨越终点主计时门 → 结算（显示两圈分段、总成绩、评级与复位次数）。
- V02 失败条件：总时限 720 秒耗尽未完成两圈 → 超时判负结算（G05）；作弊标记未消除的完赛 → 成绩显示 invalid（不授评级）。
- V03 恢复语义：R 复位回最近计时门（计时继续、+3 秒罚时）；出界后须复位恢复有效性；超时判负或结算后一键重开。
- V04 persistent_state：无（重开全量清空；最好成绩仅本次会话内显示，不要求跨会话保存）。
- V04 软锁与不可达处理：不设永久软锁——关键目标均可通过正常操作达成，或触发 V02 失败路径进入结算；结算界面重开为最终恢复出路；判定不可达时按 V02 失败语义结算而非无限等待。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（计时/门序/复位计数）局内保留、重开清空；跨局状态无（S 档：重开全量清空）。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：近未来「白蚀盐原」上的民间测速纪元——大地测量局每年开放干涸盐湖试车场一周，供独立车队挑战公开计时纪录；盐板之下是未干透的卤水层，酥松盐晶带随时可能让轻率的车手付出圈速代价。
- W02 场景所在地：白蚀盐湖试车场——白色盐板主环线（4 千米）＋外围酥松盐晶带；远处低山、遥测站与维护棚屋点缀地平线；8 座分段计时门与起终点拱门由 seed 冻结。
- W03 玩家身份与当前任务动机：玩家是独立车队「灰隼小队」的试车手，驾驶自制原型试验车挑战本赛季公开圈速纪录——两圈之内跑进金标 480 秒。
- W04 失败代价与结局表达：超时或成绩无效＝「测速失败」——车队纪录墙留空（C03 失败意象）；跑进评级带宽＝纪录上墙、遥测站灯带亮起（C03 胜利意象）。
- W05 叙事来源：试验车＝封闭座舱低重心原型车；分段计时门＝测量局的标准龙门架遥测门；酥松带＝盐晶卤水析出带；遥测站＝大地测量局观测塔。全部原创，不用商业作品命名。
- W06 视觉风格与色彩材质：高对比白盐工业风；主色＝盐白 #F2F4EF、石墨灰 #3A3F45、遥测青 #2FA8C7、警示橙 #E4762C；材质为盐板反光地面、石墨车漆、金属龙门架与褪色安全条带。
- W07 环境氛围与声音语言：干燥风啸与盐面尘雾为底；音效语言＝引擎、轮胎、过门提示、倒计时、结算（F06 冻结清单）；混音优先级：倒计时/过门提示 ＞ 漏门警告 ＞ 引擎 ＞ 轮胎 ＞ 风环境。
- W08 故事表达方式：C01 开场交代测速周与车队目标 → 过程中分段计时门横幅与尘雾表现承载推进 → C03 结算双意象收束；叙事只做包装不改数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：第三人称追车镜头，跟随距离 6 米、高度 2.2 米、FOV 60°；镜头平滑跟随（位置阻尼 0.12）；C 键复位镜头到正后方；镜头不出赛道边界；1920×1080 下 HUD 不遮挡赛道关键门位，1280×720 保持可读（I06）。
- F02 关键操作镜头变化：高速段（≥150 km/h）镜头 FOV +8°（速度感）；碰撞/出界 0.3 秒中幅震动；复位瞬间镜头快速回正；设置里可关闭震动（F09）。
- F03 输入与延迟：见 I07（≤100ms P95）；顿帧不改变计时口径。
- F04 环境常驻效果：盐面热浪扭曲、恒向风线与尘雾飘移（风向袋指示风向）、胎痕渐隐（30 秒）、遥测站顶灯呼吸；风为纯表现层，不参与车辆物理判定（G04）。
- F05 事件反馈表（事件 → 画面表现 → 音效 → 结束条件，全部冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 倒计时起步 | 3-2-1 数字放大 | countdown_beep×3＋start_release | 起步瞬间 |
| 过分段计时门 | 门上灯带闪青＋分段时间横幅 1.5 秒 | gate_pass | 横幅收起 |
| 漏门警告 | 屏幕边缘橙框＋「MISS GATE」提示 | gate_miss | 玩家过下一合法门或复位 |
| 出界 | 尘土爆起＋画面去饱和 20%（2 秒） | offroad_rumble | 回到界内 |
| 驶入酥松带 | 车身扬起盐晶尘雾、胎痕颜色变浅 | tire_salt_loop | 离开酥松带 |
| 高速直线（≥150） | 尾迹拉长＋镜头 FOV +8° | engine_high（音调随速） | 速度跌破 150 |
| 复位 | 车辆淡出淡入回检查点＋镜头回正 | reset_woosh | 复位完成 |
| 超时 | 画面暗角＋「TIME OUT」横幅 | timeout_alarm | 进入判负结算 |
| 冲线结算 | C03 播放（双意象）＋结算面板 | victory_sting / defeat_sting | 进入结算面板 |

- F06 关键音效清单（one_shot 9 条＋环境循环 2 条，全部冻结需求）：countdown_beep、start_release、gate_pass、gate_miss、offroad_rumble、reset_woosh、timeout_alarm、victory_sting、defeat_sting；环境循环：salt_flat_wind（恒向风啸）、prototype_engine（引擎，随速变调）。无配音需求。
- F07 VFX 信息性与遮挡约束：分段横幅、漏门橙框、出界去饱和为信息类 VFX，必须清晰可辨；尘雾与尾迹不得遮挡 HUD 与前方计时门；非结算单个全屏遮挡 ≤0.5 秒。
- F08 音画同步：过门音与门灯带闪青同帧；倒计时音与数字同帧；冲线音与终点横幅同帧。
- F09 屏幕震动：碰撞/出界 0.3 秒中幅（幅度 6 px 等效）；暂停/结算取消未结束的震动；设置可关闭（镜头震动开/关）。
- F10 前端界面：标题（开始/设置/退出）→ 行驶 HUD（圈数/单圈/总计时/已过门/复位数/分段/剩余总时限，见 I06）→ 暂停面板（继续/重开/返回/设置）→ 结算面板（分段表、总成绩、评级、复位数；Enter 重开）；关键状态图标＋文字并用；窗口失焦自动暂停。

## 10. 过场视频 [C01–C03]

- C01 测速周开幕（Opening，6 秒，1280×720@24fps）
  - 触发时机：首次由标题点击「开始」后、倒计时起步之前，每局一次
  - 内容与角色场景：白色盐湖全景、遥测站灯带依次点亮、灰隼试验车驶出维护棚，镜头掠过分段计时门停在起跑拱门
  - 资产对应：试验车、计时门、遥测站与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入倒计时起步；自然播完 → 进入倒计时起步
  - 状态一致：跳过与自然播完后初始状态一致；播放期间不推进任何游戏计时
- C02 高速赛段（Event，5 秒，1280×720@24fps）
  - 触发时机：本局首次速度达到 ≥180 km/h 时插入一次（不打断操作，画中画或瞬时可跳），每局最多一次
  - 内容与角色场景：追车镜头贴地掠过盐板、尾迹与尘雾拉长、外线酥松带反光一闪
  - 资产对应：试验车与赛道材质同源
  - 可跳过：Esc/Enter 跳过 → 立即返回行驶视角；自然播完 → 自动返回
  - 状态一致：不打断驾驶控制权；播放期间游戏计时正常推进（不暂停、不加成）
- C03 冲线与测速结果（Ending，6 秒，1280×720@24fps，双意象共用条目）
  - 触发时机：V01/V02 成立、结算面板出现之前，每局一次
  - 内容与角色场景：胜利意象＝冲线横幅、遥测站灯带全亮、纪录墙上墙；失败意象＝超时暗角、车队纪录墙留空、车影停在盐面
  - 资产对应：试验车、遥测站与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入对应结算面板；自然播完 → 进入对应结算面板
  - 状态一致：仅在真实 V01/V02 后触发；播放期间不推进任何游戏计时

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：6 个（text-to-3D 4，image-to-3D 2）；object 任务资产为：salt_flat_prototype_car, checkpoint_gate_kit, telemetry_station, salt_crystal_rock, wind_sock_set, maintenance_shed。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：drift_recovery。
- video/audio/mechanic/UI：分别为 3/11/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

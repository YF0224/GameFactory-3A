## 0. 标题、版本与使用说明

- 作品名：《海岸灯塔的棱镜校准》；版本：mechanics-v3（2026-10-11 完整性修订：冻结三组固定布局与坐标、颜色符号标签、组推进规则、演出反馈、视频与正向范围清单）；运行引擎：**Godot 4.x（Windows 桌面构建）**（spec、rubric 与 asset 任务 JSONL 引擎字段保持一致）；输入方式：键盘与鼠标。
- 原创边界：光路反射属公有领域机制；本作全部名称、场景、文案与美术必须原创，不使用任何商业作品的角色、关卡集或造型。
- 规则优先级：本文件全局数值与规则 ＞ 机制章节 ＞ 谜题实例 ＞ 生成器自由补充；未指定数值可作为明确标注的配置默认值。
- 本文件用于游戏生成模型；文档存在不等于玩法完成，静态页面或演示视频不能单独证明可玩。

## 1. 定位与完整流程 [S01–S05]

- S01 类型：单屏光路解谜（镜面旋转＋颜色合成＋遮挡）。本测例包含的能力：三组冻结布局谜题、45° 离散旋转、双色合成、遮挡控制、即时预览、组级重置、组间推进、开场与结算视频。
- S02 核心循环一句话：观察光路 → 旋转镜面/开合遮挡 → 预览校验 → 全接收器点亮 → 下一组。
- S03 流程：标题 → 组1（教学）→ 组2（合成）→ 组3（三镜链）→ 完成结算；每组可一键重置；已完成组可重玩。
- S04 最低完整流程：标题、三组谜题、完成结算、组级重置、重开必须全部存在且有真实入口。
- S05 失败恢复入口：谜题组级一键重置（R）；无失败态、无生命/计时；结算界面可重开。
- 与种子卡差异：种子卡 persistent_state 为「已解组进度」；本包冻结为仅当前会话内推进，重开全量清空（P0），不要求跨会话保存。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：启动与标题 → 组1 → 组2 → 组3 → 完成结算 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且资源加载完成
  - state_change：进入「标题」状态；首次进入按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10 呈现
  - next_actions：进入「组1」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 组1（教学·单束直线）
  - input：Tab/WASD/点击＝选中镜面；Q/E＝旋转；R＝重置；Esc＝暂停（触发方：玩家）
  - precondition：标题已完成（组1 默认解锁）
  - state_change：进入「组1」状态，载入 L02 组1 冻结布局
  - feedback：光束、旋转与遮挡反馈按 §9 F05/F06 呈现
  - next_actions：R1 点亮 →「组2 解锁」
  - outcome：组1 完成标记局内保留（见 V04）
- S08 组2（双色合成）
  - input：同 S07（触发方：玩家）
  - precondition：组1 全部接收器点亮（组推进规则 G05）
  - state_change：进入「组2」状态，载入 L02 组2 冻结布局
  - feedback：同上；合成节点双色汇流表现
  - next_actions：R2 点亮 →「组3 解锁」
  - outcome：组2 完成标记局内保留
- S09 组3（三镜链＋双遮挡）
  - input：同 S07（触发方：玩家）
  - precondition：组2 全部接收器点亮
  - state_change：进入「组3」状态，载入 L02 组3 冻结布局
  - feedback：同上
  - next_actions：R3 点亮 →「完成结算」
  - outcome：组3 完成 → 触发 C02 → 结算面板
- S10 完成结算
  - input：Enter＝重开 / Esc＝返回标题（触发方：玩家）
  - precondition：三组全部接收器同时点亮过（V01）
  - state_change：进入「完成结算」状态；谜题冻结
  - feedback：结算面板显示总旋转次数与误操作次数
  - next_actions：重开（全量清空）或返回标题
  - outcome：按 V01 结算，无跨局写入
- S11 暂停
  - input：Esc（触发方：玩家）
  - precondition：处于任一谜题组
  - state_change：暂停覆盖层打开，交互与光路状态冻结
  - feedback：暂停面板（继续/重置本组/返回标题/设置）
  - next_actions：Esc 或「继续」→ 回到当前组
  - outcome：恢复后光路状态与暂停前一致（G04）

## 3. 数值口径与全局规则 [G01–G06]

- G01 统一刻度：格坐标（列,行），原点 (0,0) 位于左上；镜面角度离散 **45°/次**，合法角度 0°–315°（8 档），每面镜在 UI 显示「角度值＋反射映射标签」（如 E→S）；光束颜色＝红 R、蓝 B、黄 Y（原色，几何图标：R 三条纹、B 水波纹、Y 星芒）与紫 P、橙 O、绿 G（次色，P 三角徽、O 方徽、G 圆徽）——颜色同时有字母与图标，不只靠颜色区分（F10）。
- G02 颜色合成表（本包冻结值）：红＋蓝＝紫；红＋黄＝橙；蓝＋黄＝绿；同色叠加不产生新色。接收器要求特定颜色（组1 任意色、组2 紫 P、组3 绿 G）。
- G03 光束传播规则（本包冻结值）：光束自光源沿直线逐格传播；遇当前角度的镜面按「反射映射标签」转向 90°；遇关闭的遮挡板即阻断；两束异原色汇交于合成节点产次色并沿合成节点出口方向继续；同帧重算全光路（无传播延迟）。
- G04 结果状态 oracle：给定组2 冻结初始布局（光源东向、镜 A/B 初始角、遮挡板 P2 关闭），输入序列〔旋转镜 A 至 E→S → 开启遮挡板 P2 → 旋转镜 B 至 E→N〕后，最终接收器状态唯一确定为「紫色接收器点亮且仅其点亮」；任何偏离即 FAIL。fixed_seed=1017 冻结三组初始布局。
- G05 组推进规则（本包冻结值）：组 N 的全部接收器点亮后「下一组」按钮才激活；组间推进只解锁顺序下一组；已完成组可随时重玩且不影响进度标记；组推进事件 `group_unlocked` 必须可观测。
- G06 暂停与随机：Esc 暂停冻结交互与光路；窗口失焦自动暂停；fixed_seed=1017 仅用于表现层随机流，不影响谜题规则。

## 4. 操作与输入 [I01–I07]

- I01 键位：Tab/WASD 或点击＝选中镜面/遮挡板；Q/E＝左旋/右旋 45°；Space＝开合选中遮挡板；R＝组级重置；Esc＝暂停；Enter＝确认/下一组。
- I02 输入语义边界：未选中对象时旋转/开合无效；暂停/结算期间输入无效；被拒输入不改变光路、不计入误操作数。
- I03 鼠标可选；全部操作可仅用键盘完成。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入；同帧多输入按选中→旋转→开合顺序结算。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：当前组号、本组旋转次数、全局面板中三组完成标记、选中对象的当前角度与反射映射标签；HUD 对照见 rubric。
- I07 输入延迟目标：按键到光路重算画面反馈 ≤ 100 毫秒（WebGL/HTML5 环境目标 ≤ 150 毫秒）。

## 6. 机制系统 [M01–M05]

- M01 镜面旋转（主机制）
  - input：Q/E（选中镜面）
  - precondition：处于谜题组状态且有选中镜面
  - state_change：角度按 45° 离散步进（0°–315° 循环）→ 反射映射标签更新 → 光路即时重算（G03）
  - observable：镜面角度状态与 `light_recompute` 事件（含角度前后值）
  - invalid_case：未选中时 Q/E 无事件副作用；暂停/结算期间拒绝
  - recovery：R 组级重置（见 M05）
- M02 颜色合成
  - input：两束异原色光汇交于合成节点（系统）
  - precondition：两束原色光同帧到达同一合成节点
  - state_change：按 G02 合成表产生次色光束；接收器仅当光色与需求色（含图标/字母标签）匹配时点亮
  - observable：`synth` 事件（含两原色与产物色字段）与接收器匹配断言
  - invalid_case：同色叠加无新色（不产生合成事件）；色不匹配不点亮
  - recovery：遮挡断路即可复位
- M03 遮挡
  - input：Space 开合选中遮挡板
  - precondition：有选中遮挡板
  - state_change：关闭 → 光路断路（下游全灭）；开启 → 恢复
  - observable：`shutter` 事件（开/闭）与下游接收器熄灭/重亮联动
  - invalid_case：未选中遮挡板按 Space 无效
  - recovery：再按 Space 恢复
- M04 即时预览
  - input：任意旋转/开合操作
  - precondition：处于谜题组状态
  - state_change：预览渲染与光路结算同帧完成
  - observable：预览状态＝最终状态断言（采样对比，容差 0）
  - invalid_case：无独立失败态
  - recovery：—
- M05 组级重置与全局重开
  - input：R（组级）/ 结算或标题「重新开始」（全局）
  - precondition：R 在谜题组内可用；全局重开在结算/标题可用
  - state_change：组级重置＝当前组镜角/遮挡板/接收器回 L02 初始值（已点亮接收器熄灭），其余组与完成标记不变；全局重开＝三组全量清空回组1
  - observable：`group_reset`/`full_reset` 事件（含重置范围字段）
  - invalid_case：组级重置不得清空其他组进度
  - recovery：两级恢复语义见 V03

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：三组谜题的全部接收器按各自需求色点亮 → 完成结算（显示总旋转次数与误操作次数）。
- V02 失败条件：无失败态、无生命与计时（误操作只计数不惩罚）。
- V03 恢复语义：R＝当前组一键重置（该组镜角/遮挡/接收器回初始值，完成标记保留）；结算界面「重新开始」＝全局全量清空——两级恢复语义互不混淆。
- V04 persistent_state：无（重开全量清空；已解组进度仅会话内推进，见 §1 与种子卡差异）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（组完成标记/旋转计数）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设永久软锁——任意误操作状态可经 R 组级重置恢复；关键目标均可用正常操作达成。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：架空的「雾潮湾」海岸线，蒸汽与光学并存的年代；百年灯塔「白汐塔」的棱镜阵列因海雾侵蚀而失准，夜间航线面临危险。
- W02 场景所在地：白汐塔顶层的棱镜校准室——三组棱镜阵列（教学组/合成组/主镜链组）沿塔室环形排布。
- W03 玩家身份与当前任务：玩家是守塔人学徒「汀」；当前任务：在夜幕降临前校准全部棱镜，让白汐塔重新亮起。
- W04 失败代价与结局表达：本作无失败态；若放弃校准（返回标题），结算文案表达「塔灯仍暗」；完成校准则 C02 呈现海岸重新亮灯。
- W05 叙事来源：镜面＝塔内黄铜校准镜；遮挡板＝防潮闸门；合成节点＝塔心的水晶棱柱；接收器＝航标灯座。全部物件与人物原创。
- W06 视觉风格与色彩材质：风格化低多边形＋手绘质感；主色＝暮色蓝灰（#3E5C76 系）＋黄铜金（#C9A227 系）；光束为高饱和发光材质；材质以黄铜、湿岩、玻璃为主。
- W07 环境氛围与声音语言：海雾弥漫的黄昏塔室——常驻海浪与雾号环境声；音效语言为「机械咔哒＋玻璃谐音＋航标确认音」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代灯塔来信与任务 → 三组谜题难度递进承载过程 → 结算视频（C02）与结算面板收束；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：固定正交俯视（90°），当前组整组布局同屏全部可见；滚轮两档缩放（1.0×/1.35×），缩放以谜题组中心为锚；无平移；镜头边界＝当前组网格外接矩形外加 8% 余量；缩放不改变判定。
- F02 关键操作镜头变化：组完成瞬间镜头轻微拉远 5%（1.5 秒）后回位；无震动类镜头。
- F03 输入与延迟：见 I07。
- F04 环境常驻效果：塔室尘埃微粒、窗外海雾流动（低频循环，不遮挡光路格与 HUD）。
- F05 事件反馈表（事件 → 表现 → 结束条件，全部为冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 镜面旋转 | 镜框高亮＋角度标签跳动 | 黄铜咔哒声 | 旋转到位即停 |
| 光束通/断 | 光束辉光即时延伸/截断，断点冒细小光尘 | 通光低鸣（通路段常驻）/断路静音 | 与光路状态同帧 |
| 遮挡开合 | 闸门落下/抬起 0.3s 动画 | 闸门机械声 | 动画完成 |
| 合成成功 | 双色汇流旋转粒子＋次色标签弹出 | 玻璃谐音 | 光束离开节点即淡出 |
| 接收器点亮 | 对应色环点亮＋字母/图标徽记弹出 | 航标确认音 | 常亮至状态变化 |
| 色不匹配 | 接收器灰环闪烁 1 次 | 短促否定音 | 0.3s 结束 |
| 组完成 | 全组光带亮起＋「下一组」按钮点亮 | 上扬提示音 | 进入下一组即淡出 |
| 全局完成 | 塔灯光柱冲天粒子 | 结算音 | 进入结算即停 |

- F06 关键音效清单：咔哒、闸门、谐音、确认音、否定音、组完成音、结算音；环境音：海浪（常驻循环）＋雾号（每 45 秒一次）；循环音开始/结束：海浪随标题进入开始、随结算淡出 0.5s；无配音需求。
- F07 VFX 信息性与遮挡约束：光束颜色/粗细与接收器徽记承担玩法信息；尘埃与汇流粒子单帧 ≤ 30，不遮挡镜面角度标签与光路格。
- F08 音画同步：光束通断与光路结算同帧；接收器确认音在点亮事件帧触发；闸门音与动画同步起止。
- F09 屏幕震动：无震动需求（静谜题）；设置界面提供「镜头震动开/关」占位不适用，不设该项。
- F10 前端界面：标题（开始/设置/退出）→ 组选择面板（三组卡片＋完成标记＋锁定态）→ HUD（当前组号、旋转次数、选中对象角度与映射标签）→ 完成结算（总旋转次数/误操作次数/重开/返回标题）；关键状态附图标＋字母文字（颜色标签、组完成标记），不只靠颜色区分；Esc 暂停面板（继续/重置本组/返回标题/设置）；窗口失焦自动暂停。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：3 个（text-to-3D 2，image-to-3D 1）；object 任务资产为：brass_mirror, prism_node, receiver_lamp。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：prism_rotate_align。
- video/audio/mechanic/UI：分别为 2/7/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

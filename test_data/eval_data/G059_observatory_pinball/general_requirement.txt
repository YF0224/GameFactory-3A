## 1. 定位与完整流程 [S01–S06]

- S01 类型：单台物理弹珠街机。本测例包含的能力：冻结台面布局、三组机关链与倍率、多球状态与球标识、同帧出界合并结算、连续碰撞稳定、双档镜头、开场/多球/结算视频。
- S02 核心循环一句话：发射弹射 → 挡板控制 → 机关触发 → 倍率累积 → 多球管理 → 出界回收 → 结算。
- S03 流程：单球热身段（倍率起步）→ 机关链段（按序提倍率）→ 多球高潮段（解锁多球）→ 球数耗尽结算。
- S04 最低完整流程：发射、左右挡板、机关靶标、倍率显示、出界回收、结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：单球落袋且仍有发球机会→自动发新球继续；球数耗尽一键重开；Esc 暂停。
- S06 本局耦合边速览：机关顺序系统→倍率计分系统（按序提倍率、乱序重置组链）；多球状态系统→出界回收系统（多球下逐球回收、同帧出界合并耗 1 机会）。

## 2. 完整核心循环与阶段 [S06–S10]

完整循环：启动与标题 → 单球热身 → 机关链 → 多球高潮 → 球数耗尽结算 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且台面按 seed=1059 冻结
  - state_change：进入「标题」状态；首次进入按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10 呈现（达标线 10000 目标）
  - next_actions：进入「单球热身段」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 单球热身段
  - input：Space 蓄力发射、左/右 Shift 挡板、滚轮缩放、Esc 暂停（触发方：玩家）
  - precondition：发球机会 >0 且场上无球
  - state_change：发射入台；倍率从 ×1 起步；A/B/C 组链可用
  - feedback：星光尾迹与撞击反馈按 §9 F05 呈现
  - next_actions：按序完成任一组 → 倍率 +1 →「机关链段」节奏
  - outcome：分数与倍率局内累计
- S08 机关链段
  - input：挡板控制（触发方：玩家）
  - precondition：球在场
  - state_change：A1→A2→A3 / B1→B2 / C1→C2→C3 按序推进；乱序重置该组链（倍率不回退）
  - feedback：组链进度灯与倍率跳变反馈
  - next_actions：完成 C 组 → 解锁多球 →「多球高潮段」（先播 C02）
  - outcome：倍率与分数持续累计
- S09 多球高潮段
  - input：挡板控制（触发方：玩家）
  - precondition：C 组完成，+2 球入场
  - state_change：各球独立物理与计分；逐球回收带球标识；同帧多球出界按 G07 合并结算
  - feedback：多球星光与机台灯光全亮
  - next_actions：机会归零 →「结算」（先播 C03）
  - outcome：按 V01/V02 判定
- S10 结算
  - input：Enter＝重开 / Esc＝返回标题（触发方：玩家）
  - precondition：发球机会归零
  - state_change：进入「结算」状态；物理冻结
  - feedback：结算面板显示总分、最高倍率、多球时长
  - next_actions：重开（全量清空）或返回
  - outcome：无跨局写入

## 3. 数值口径与全局规则 [G01–G07]

- G01 统一刻度：分数按点、倍率按倍数、球按颗计；时间用游戏模拟秒（暂停冻结）。
- G02 弹珠台与物理（本包冻结值）：单张天文台弹珠台（倾斜台面、原创造型）；左右挡板各 1、顶部发射弹射轨道；弹珠直径 2.7 cm 等比；重力沿台面分量固定。高速碰撞可靠性红线：任意速度下弹珠不得穿模穿透挡板/靶标/边墙（碰撞采样导出，零穿模事件）；单物理步内连续碰撞 ≥3 次仍须稳定结算（采用连续碰撞检测或子步进，采样导出零穿模零卡死）。
- G03 机关顺序与倍率（本包冻结值）：3 组机关——A 行星轨道（靶标 A1→A2→A3 按序）、B 星图（B1→B2 按序）、C 彗星（C1→C2→C3 按序）；任一组按序完成 → 倍率 +1（上限 ×5）；组内乱序命中 → 该组链重置（倍率不变）；完成 C 组 → 解锁多球（+2 球）。
- G04 计分（本包冻结值）：每次靶标命中得基础 100 ×当前倍率；完成组链瞬间另加 500 ×当时倍率；返回通道射入 250 ×倍率；总分＝事件加权和，对账容差 0；达标线 10000 分。
- G05 球数与出界（本包冻结值）：初始发球机会 3 次；单球落袋（场上无其他球）→ 机会 −1；多球下逐球出界仅回收该球、不耗机会；机会归零且分数未达标 → 失败结算。
- G06 判定与独立 oracle（本包冻结值）：计分 oracle——按序命中 A1→A2→A3（倍率 ×1 期）：100×3＝300 分，完成链另加 500 → 总 800 分且倍率升 ×2，之后每次命中按 ×2 计；对账任何偏离即 FAIL。多球 oracle——双球在场时 1 球落袋（预期发球机会不变、另一球继续）；单球落袋（预期机会 −1）。发射弹射由 Space 蓄力（蓄力 0.5–1.0 秒线性映射弹射力度）。Esc 暂停冻结物理与计时；fixed_seed=1059 冻结台面扰动序列（可复现弹射）；窗口失焦自动暂停。
- G07 同帧多球出界（本包冻结值）：同一物理步内多球同时出界——逐球回收并各自记录回收事件（含球标识）；若该步后场上无球且发球机会 >0 → 本步出界合并视为一次「落袋事件」，仅耗 1 次发球机会（不按球数扣减）；oracle：双球同帧出界且无第三球在场 → 机会 −1（非 −2）；任意时刻机会不为负。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：左 Shift／Z＝左挡板；右 Shift／／＝右挡板；Space＝发射蓄力；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：无球在发射轨道时蓄力无效；暂停/结算期间输入无效；挡板键为按住状态语义。
- I03 无手柄需求；分数、倍率、剩余发球机会、组链进度、场上球数须常驻显示。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；同帧左右挡板同时有效；发射仅在发射轨道有球时可用。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：分数、倍率、发球机会、组链进度（A/B/C 三组）、场上球数；HUD 对照见 rubric。
- I07 输入延迟目标：挡板按下到抬起反馈 ≤ 30 毫秒（弹珠手感关键）；发射蓄力采样 ≤ 50 毫秒。

## 6. 机制系统 [M01–M05]

- M01 挡板与碰撞（主机制）
  - input：左右挡板键
  - precondition：处于游玩状态（非暂停/结算）
  - state_change：挡板抬升改变碰撞反弹；高速碰撞不穿透；单步连续碰撞 ≥3 次稳定结算（G02）
  - observable：碰撞采样流（含球标识、速度、法线、接触点；零穿模事件）
  - invalid_case：暂停期间挡板冻结
  - recovery：—
- M02 机关顺序与倍率
  - input：弹珠命中靶标（系统）
  - precondition：球与靶标碰撞体接触
  - state_change：组内按序推进、乱序重置；完成组链倍率 +1（≤×5）
  - observable：机关序事件（含球标识与靶标 ID）与倍率状态变更
  - invalid_case：乱序命中不加分不提倍率
  - recovery：该组链重新按序完成
- M03 多球状态
  - input：完成 C 组机关（系统）
  - precondition：C 组链完成且未处于多球中
  - state_change：+2 球入场，各球独立物理、独立计分、独立球标识
  - observable：多球计数与逐球回收事件（带球标识）
  - invalid_case：重复完成 C 组不重复加球（倍率期外）
  - recovery：逐球回收直至单球/零球
- M04 出界与计分
  - input：球落袋／球数耗尽（系统）
  - precondition：球越过出界判定线
  - state_change：逐球回收；单球落袋耗发球机会；同帧多球出界按 G07 合并耗 1 机会；机会归零结算
  - observable：计分流水（事件加权和）与发球机会流水（含同帧合并事件字段）
  - invalid_case：机会为 0 时不再发球
  - recovery：判负一键重开
- M05 镜头与取景
  - input：滚轮缩放（玩家）
  - precondition：处于游玩状态
  - state_change：1.0×/1.3× 两档缩放（台面中心为锚）；台面边界外不可平移；多球期间保持台面全览（不跟随单球）
  - observable：缩放档位事件；全览断言（多球时四角可见）
  - invalid_case：缩放不改变判定与物理
  - recovery：—

系统耦合边（玩法必需、可复现）：

- E01 from_system=机关顺序系统 → to_system=倍率计分系统；changed_state=按序完成组链使倍率 +1，随后每次命中按新倍率计分；乱序重置组链但不回退倍率；验证方式=机关序事件→倍率状态→计分流水三联对照（state_before/after）。
- E02 from_system=多球状态系统 → to_system=出界回收系统；changed_state=场上球数 ≥2 时落袋仅回收该球且发球机会不变，单球落袋才机会 −1，同帧多球出界合并耗 1（G07）；验证方式=多球/单球/同帧三种落袋场景的发球机会流水对照。

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：球数耗尽时总分 ≥10000 → 胜利结算（显示总分、最高倍率、多球时长）。
- V02 失败条件：发球机会归零且总分 <10000 → 失败结算。
- V03 恢复语义：单球落袋且有剩余机会 → 自动发新球继续（倍率与分数保留）；判负一键重开全量重置（seed 复现）。
- V04 persistent_state：局内（倍率/球数/分数局内保留；重开全量清空）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设软锁——发球机会耗尽必然结算；球卡死（速度近零且非判定区）超 5 秒自动微扰复位（缺陷容错，采样记录）。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：架空的黄铜天文时代；「星穹观测台」的老匠人把一生观测的星图搬进了一台弹珠机，让访客用弹珠「运行」他的星空。
- W02 场景所在地：星穹观测台的展示厅——单张天文台主题弹珠台（倾斜台面、星轨灯带、黄铜挡板）。
- W03 玩家身份与当前任务：玩家是观测台的访客；当前任务：按序点亮行星轨道、星图与彗星三组机关，解锁「群星多球」，冲击观测记录 10000 分。
- W04 失败代价与结局表达：机会耗尽未达标＝「记录未破」（判负文案）；达标则 C03 呈现群星灯带全亮与观测记录题名。
- W05 叙事来源：三组机关＝老匠人的三段观测笔记（行星轨道/星图/彗星）；多球＝「群星同辉」时刻；返回通道＝回廊巡星。全部原创。
- W06 视觉风格与色彩材质：黄铜与深蓝星空的机台风；主色＝黄铜金（#B08D4F 系）＋星空深蓝（#1D2B4A 系）＋彗星青白（#9FD8E8 系）；材质以黄铜、发光灯带、深色台面为主。
- W07 环境氛围与声音语言：安静展厅中的机台低鸣——常驻展厅环境声；音效语言为「弹射砰＋撞击铛＋靶标叮＋多球合鸣」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代观测台与弹珠机 → 多球视频（C02）在首次解锁多球时呈现「群星同辉」→ 结算视频（C03）收束观测记录；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：侧视固定台面全览（正面视角，台面四角可见）；滚轮两档缩放（1.0×/1.3×，台面中心为锚）；镜头边界＝台面外框，不可平移；多球期间保持全览（防漏球）；重开后镜头复位默认档。
- F02 关键操作镜头变化：完成组链瞬间轻微震动 0.1 秒；多球入场时机台灯带全亮＋镜头轻微拉远 5%（0.4 秒）后回位；无慢动作。
- F03 输入与延迟：见 I07（挡板 ≤30 毫秒）。
- F04 环境常驻效果：星轨灯带缓转、台面星尘微粒、挡板黄铜反光；不遮挡靶标与出界判定线。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：3 个（text-to-3D 2，image-to-3D 1）；object 任务资产为：star_pinball, planet_target_bank, brass_flipper_pair。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：ball_launch。
- video/audio/mechanic/UI：分别为 3/11/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

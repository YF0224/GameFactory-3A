## 1. 定位与完整流程 [S01–S06]

- S01 类型：3D 第三人称抓钩摆荡攀爬，单人单局，单条峡谷巡检线。本测例包含的能力：抓钩检测/连接两段范围、绳长约束摆荡、动量继承平抛、空中微调、阵风带推力、四检查点（首点自动激活）、坠落复位与 240 秒限时、开场/风场事件/结算视频、抓钩手感演出层。
- S02 核心循环一句话：寻找合法锚点 → 连接摆荡积累动量 → 在正确时机释放平抛 → 落点/着陆 → 激活检查点推进巡检线。
- S03 流程：开始界面 → 进入峡谷（首次进入前播 C01）→ 教学段（1 检查点，首点自动激活）→ 长摆荡段（2 检查点＋阵风带）→ 精密落点段（1 检查点）→ 抵达终点塔顶 → 结算（面板前播 C03）→ 重开或返回。
- S04 最低完整流程：开始界面、可操作巡检、结算界面、重开必须全部存在且有真实入口。
- S05 失败恢复入口：坠落回最近已激活检查点（清绳与速度）；第 6 次坠落或 240 秒超时判负；结算界面一键重开；游玩中 Esc 暂停。
- S06 本局系统耦合边速览：动量系统 → 飞行着陆系统（E01）、检查点系统 → 坠落复位系统（E02）、阵风带 → 摆荡/飞行系统（E03），详见 §6。

## 2. 完整核心循环与阶段 [S07–S12]

- S07 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且资源加载完成
  - state_change：进入「标题」状态；首次开始时按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10 呈现
  - next_actions：进入「教学段」
  - outcome：无跨局状态写入
- S08 教学段（检查点 1，首点自动激活）
  - input：WASD 移动、右键发射/锚定、左键或再按右键释放、E 激活交互、Esc 暂停（触发方：玩家）；锚点由 seed 冻结（触发方：系统）
  - precondition：处于巡检状态且非暂停/结算/视频
  - state_change：按 §6 M01–M04 结算每次输入；速度、绳长、坠落计数、检查点实时更新
  - feedback：按 §9 F05（绳索张力、摆荡风声、连接火花、落点尘土）
  - next_actions：通过教学段 →「长摆荡段」；坠落 → M04 复位
  - outcome：按 §7 V01/V02 判定
- S09 长摆荡段（检查点 2、3＋阵风带）
  - input：同 S08（触发方：玩家/系统）
  - precondition：教学段已通过
  - state_change：大跨度锚点与阵风带（E03）把速度、高度与落点选择连成链条；首次进入阵风带按 §10 C02 播放风场事件视频
  - feedback：同 S08；风带内绳索加大摆动与持续风声
  - next_actions：通过长摆荡段 →「精密落点段」
  - outcome：局内状态演进
- S10 精密落点段（检查点 4）
  - input：同 S08（触发方：玩家/系统）
  - precondition：长摆荡段已通过
  - state_change：小锚点与窄平台要求精密释放与空中微调；通过后抵达终点塔顶
  - feedback：同 S08
  - next_actions：抵达塔顶 →「结算」
  - outcome：按 §7 V01 判定
- S11 结算
  - input：Enter=重开 / Esc=返回（触发方：玩家）
  - precondition：V01 或 V02 成立
  - state_change：进入对应结算；面板出现前按 §10 C03 播放结算视频（每局一次，胜负共用双意象）
  - feedback：胜利面板显示用时与坠落次数；失败面板注明「坠落超限」或「超时」
  - next_actions：重开（全量重置）或返回标题
  - outcome：无跨局状态写入
- S12 暂停
  - input：Esc（触发方：玩家）；窗口失焦自动触发（触发方：系统）
  - precondition：处于巡检状态
  - state_change：暂停覆盖层打开，摆荡、风场推力、坠落与 240 秒计时全部冻结
  - feedback：暂停面板（继续/重开/返回/设置）
  - next_actions：恢复回到巡检
  - outcome：恢复后状态逐字段一致

## 3. 数值口径与全局规则 [G01–G07]

- G01 统一刻度：距离为米；速度为米/秒；时间用游戏模拟秒（暂停冻结）。
- G02 基础运动（本包冻结值＋AUD11）：地面移速 4 米/秒；无独立跳跃输入（本题唯一位移进阶为摆荡）；空中微调水平加速度上限 2 米/秒²。
- G03 抓钩检测与连接（zkx 裁决修正，AUD10）：右键发射锚点；**12 米为目标检测距离**（HUD 标记范围内的候选锚点）；**实际可连接距离 ≤8 米**且俯仰角限制 15°–75°；连接时绳长＝当前距离（不瞬移、不自动缩绳），此后以锚点为圆心摆荡；超距/超角目标不可锚定（非法锚点拒绝且不消耗、不中断当前摆荡）。
- G04 动量继承与 oracle（本包冻结值＋AUD11）：释放瞬间速度向量先整体限幅 15 米/秒，再完全继承为飞行初速；此后受重力 10 米/秒² 平抛直到着陆或坠落。独立 oracle 数例：高度差 5 米处以水平速度 10 米/秒释放 → 飞行时间 t＝sqrt(2×5/10)＝1 秒 → **落点距释放点 10 米**；oracle 在释放后无输入条件下运行，时间容差 0.02 秒、距离容差 0.05 米；任何超出容差的偏离即 FAIL。
- G05 坠落、检查点与限时（本包冻结值＋AUD12）：4 个检查点（教学段 1、长摆荡段 2、精密段 1），**首点自动激活**；坠落回最近已激活检查点（清绳与速度、计数 +1）；坠落上限 5 次（第 6 次判负）；单局限时 240 秒；240 秒归零与抵达塔顶同帧 → 判负优先。
- G06 暂停与随机：Esc 暂停冻结摆荡、风场与计时；fixed_seed=1013 冻结锚点分布、巡检点位与阵风带位置；物理为确定公式，无概率判定。
- G07 阵风带（v3 新增冻结值）：长摆荡段内设 2 处阵风带（位置由 seed=1013 冻结，范围以地面标记与持续风声可辨，F05/F07）；风带内角色与绳索受沿风向 1.5 米/秒² 的持续推力（空中飞行与挂绳摆荡均生效），挂绳时绳索呈现加大摆动的视觉反馈；G04 抛体 oracle 在风带外运行，风带内落点按推力叠加计算——独立 oracle 数例：高度差 5 米、水平速度 10 米/秒、顺风 1.5 米/秒²、飞行 1 秒 → 落点 ≈ **10.75 米**（10 + 0.5×1.5×1²），容差同 G04。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：WASD＝地面移动/空中微调（≤2 m/s²）；右键＝发射/锚定抓钩；左键或再按右键＝释放；E＝检查点交互激活；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：超距/超角锚点请求拒绝且不中断当前摆荡；未锚定时按释放无效；暂停/结算期间输入无效且无副作用。
- I03 鼠标控制镜头（第三人称跟随）；点击画布捕获鼠标焦点。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；同帧互斥动作按 I01 列举顺序取首个。
- I05 焦点与失焦：点击画布捕获输入焦点；窗口失焦自动暂停。
- I06 UI 必显状态：当前重力/摆荡状态、速度表（m/s）、检测到的候选锚点标记（12m 内）、当前连接距离与绳长、坠落计数（0–5）、已激活检查点（0–4）、剩余时间（240s 倒数）。
- I07 输入延迟目标：按键到画面反馈 ≤100 毫秒（P95，≥30 次采样/类别）。

## 6. 机制系统 [M01–M04]

- M01 锚点检测与连接
  - input：右键指向锚点（触发方：玩家）
  - precondition：目标在 12 米检测范围内可标记；实际连接需距离 ≤8 米且俯仰 15°–75°（AUD10）
  - state_change：命中合法锚点 → 挂钩连接、绳长＝当前距离（不瞬移、不自动缩绳）并以锚点为圆心摆荡；检测到但超距/超角 → 拒绝且不消耗、不中断当前摆荡
  - observable：anchor_detected（候选标记，含距离/角度字段）、anchor_hit/anchor_reject 事件与绳长参数
  - invalid_case：未锚定时按释放无效；面板期输入拒绝
  - recovery：拒绝后可继续当前摆荡或重新瞄准
- M02 动量继承（主机制）
  - input：释放键（触发方：玩家）
  - precondition：处于挂绳摆荡状态
  - state_change：释放瞬间速度向量先整体限幅 15 m/s 再完全继承为飞行初速 → 平抛至着陆/坠落；空中可微调（≤2 m/s²，G02）
  - observable：release 事件（含限幅后速度向量）、landing 事件（含落点）；释放点-落点配对流水按 G04 oracle（10m/容差）与风带内 10.75m 例核对
  - invalid_case：风带外无输入 oracle 超出容差即 FAIL
  - recovery：坠落走 M04
- M03 检查点与限时
  - input：E 激活检查点（触发方：玩家）；首点自动激活（触发方：系统）
  - precondition：处于检查点交互范围内（或局开始自动激活首点）
  - state_change：激活后记录位置；240 秒倒计时独立推进；首点自动激活不要求交互
  - observable：checkpoint_active 事件（含 ID 与时间戳）
  - invalid_case：已激活检查点重复激活无副作用
  - recovery：无失败态
- M04 坠落复位
  - input：坠出安全区（触发方：系统）
  - precondition：处于巡检状态
  - state_change：清绳与速度 → 回最近已激活检查点（AUD12）、坠落计数 +1；第 6 次坠落或 240 秒超时 → 判负结算
  - observable：fall_reset 事件（含检查点 ID 与计数）
  - invalid_case：结算后坠落不再触发复位
  - recovery：结算界面重开为最终出路

系统耦合边（玩法必需、可复现）：

- E01 from_system=动量系统 → to_system=飞行着陆系统；changed_state=释放时刻速度向量决定飞行抛物线与落点；验证方式=探针记录 state_before（释放点与速度向量）→ 预测落点 → 对照 state_after（实际着陆点），按 G04 oracle（10 米配对，容差 0.02s/0.05m）核对。
- E02 from_system=检查点系统 → to_system=坠落复位系统；changed_state=最近激活检查点决定复位位置与后续路线；验证方式=激活不同检查点后坠落，state_before（最近激活 ID）与 state_after（复位位置）逐项对照。
- E03 from_system=阵风带 → to_system=摆荡与飞行系统；changed_state=进入风带后角色与绳索受 1.5 m/s² 沿风向推力，摆荡与抛体轨迹随之改变；验证方式=同一释放条件在风带外（落点 10m）与顺风风带内（落点 ≈10.75m）对照，容差同 G04。

## 7. 成功、失败与恢复 [V01–V06]

- V01 成功条件：依次激活 4 检查点（首点自动）并抵达终点塔顶 → 结算（显示用时与坠落次数）。
- V02 失败条件：坠落计数达 6 次或 240 秒超时 → 失败结算（注明原因）；240 秒与抵达塔顶同帧 → 判负优先（AUD12）。
- V03 恢复语义：单次坠落回最近已激活检查点继续（计数保留、清绳与速度）；判负/通关后一键重开。
- V04 persistent_state：无（重开全量清空；检查点进度仅局内保留）。
- V05 persistent_state 生命周期：动作级即时结算；局内状态（检查点/计数/计时）局内保留、重开清空；无跨局保留。
- V06 软锁与不可达处理：不设永久软锁——检测范围可标记全部候选锚点，任何位置可回最近检查点重试；判定不可达时按 V02 失败语义结算而非无限等待。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：风塔巡检日志——峡谷风塔群逐座失联，风暴季的风口让巡检成为只有老巡检员敢接的差事。
- W02 场景所在地：单条峡谷巡检线（教学崖壁、长摆荡风口、精密落点塔群），塔间以环形机械锚点相连，峡谷底部是翻涌的云雾坠落带。
- W03 玩家身份与当前任务动机：玩家是风塔巡检员，携抓钩装置沿巡检线恢复四个检查点的信号，最终登上终点塔顶重启信标。
- W04 失败代价与结局表达：失败=坠落云雾或超时未归，巡检日志记为未完成（C03 失败意象）；胜利=塔顶信标重新亮起，全线风塔回归在线（C03 胜利意象）。
- W05 叙事来源：锚点=风塔检修桥的旧挂环；检查点=巡检信号桩（首桩自动在线）；阵风带=峡谷风口的季节性穿堂风；坠落带=峡谷积云。全部原创。
- W06 视觉风格与色彩材质：峡谷荒原＋机械风塔的写实风格化；主色=岩褐 #8A7A66、塔钢青 #4A6F8C、信号橙 #E4762C、绳索麻灰 #B8B2A6、云雾白 #DCE6EA；材质为风化钢、绳缆、岩石与信号灯。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：第三人称跟随（鼠标控制）；FOV 70（可调 60–80）；摆荡时镜头平滑跟随并轻微滞后（阻尼 0.1s）；镜头边界=巡检线包围盒。

- F03 输入与延迟：见 I07（≤100ms P95）；顿帧不改变计时口径。
- F04 环境常驻效果：峡谷云雾流动、塔身旗帜翻卷、锚点锈光、检查点信号灯呼吸。纯表现层，不参与判定。

- F07 VFX 信息性与遮挡约束：候选锚点描边与距离标记、检查点信号柱、阵风带地面标记为信息类 VFX，必须清晰可辨（检测≠连接以颜色区分）；绳索弧线不遮挡准星与落点预测；坠落带云雾不泄露复位位置（隐藏信息不外泄）；粒子不遮挡 HUD。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：6 个（text-to-3D 4，image-to-3D 2）；object 任务资产为：wind_inspector, grapple_anchor, checkpoint_flag, tower_top_platform, wind_gust_marker, wind_tower。每项只允许一个物体；组合物必须拆成独立任务。
- motion：6 个；覆盖动作：run, swing_pose, release_jump, air_adjust, landing, fall_reset_pose。
- video/audio/mechanic/UI：分别为 3/14/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

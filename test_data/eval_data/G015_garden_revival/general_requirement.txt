## 1. 定位与完整流程 [S01–S07]

- S01 类型：横版平台探索长流程（能力解锁驱动），单人单局，有界互联地图三区单向深入＋捷径反向连通。本测例包含的能力：基础跳跃与三项能力（冲刺/二段跳/抓壁）、三类能力门禁、旧区回访开捷径、区间容错与第 4 次区间重置、会话内存档与暂停 Load、只读结算快照、开场/能力/捷径/结算视频、复苏手感演出层。
- S02 核心循环一句话：探索 → 遇门禁 → 获得新能力 → 解锁通路 → 回访旧区开捷径 → 深入下一区。
- S03 流程：标题 → 进入园区（首次进入前播 C01）→ 区域一（地面层）→ 能力节点一（冲刺）→ 区域二（藤蔓层）→ 能力节点二（二段跳）→ 能力节点三（抓壁）→ 区域三（根系深处）→ 最深处终点 → 复苏结算（面板前播 C04）→ 重开或返回。
- S04 最低完整流程：探索移动、能力节点交互、门禁通过、捷径开启、存档点存读档、终点结算、暂停 Load/重开必须全部存在且有真实入口。
- S05 失败恢复入口：三级恢复——①区间内回检查点（容错 3 次）；②暂停菜单 Load 最近存档快照；③结算界面 Enter 重开（全量清空）；任意可操作阶段提供暂停 Load/重开（AUD13）；Esc 暂停。
- S06 本局耦合边速览：能力系统→门禁系统（持能力改变门禁可通行性）；能力系统→捷径系统（新能力在旧区开启捷径）；见 §6 M01–M03。
- S07 跨阶段结构与状态保留：三区顺序推进；能力、门禁状态、收集、地图标记、捷径状态跨区持久；存档点保存上述全部状态，读档全量恢复；检查点区间坠落容错计数区间内有效（跨区状态不回退，AUD13）。

## 2. 完整核心循环与阶段 [S08–S15]

- S08 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且资源加载完成
  - state_change：进入「标题」状态；首次开始时按 §10 C01 播放开场视频
  - feedback：标题界面按 §9 F10 呈现
  - next_actions：进入「区域一」
  - outcome：无跨局状态写入
- S09 区域一（地面层）
  - input：W/A/S/D＝移动、Space＝跳、E＝交互、Esc＝暂停（触发方：玩家）；门禁由能力状态判定（触发方：系统）
  - precondition：处于游玩状态且非暂停/结算/视频
  - state_change：按 §6 M01–M04 结算每次输入；能力集、收集、检查点、容错计数实时更新
  - feedback：按 §9 F05（门禁符号提示、收集光尘、检查点亮起）
  - next_actions：能力节点一交互 →「区域二」；坠落 → M04 区间恢复
  - outcome：按 §7 V03 三级恢复语义
- S10 能力节点一（冲刺）
  - input：E 交互能力节点（触发方：玩家）
  - precondition：抵达能力节点交互范围
  - state_change：获得冲刺 → 指令集扩大（Shift 冲刺可用）；能力获得落盘进会话存档状态（AUD12）
  - feedback：能力绽放 VFX（F05）＋C02 视频触发点（每局首次）
  - next_actions：区域一冲刺裂隙门禁可过 → 推进区域二
  - outcome：能力跨区持久
- S11 区域二（藤蔓层）
  - input：同 S09＋Shift＝冲刺（获得后）（触发方：玩家）
  - precondition：区域一推进完成
  - state_change：冲刺裂隙/二段跳高台门禁按持有能力判定；回访区域一可用二段跳开捷径门
  - feedback：同 S09；捷径开启时按 §10 C03 触发捷径视频（每局首次）
  - next_actions：能力节点二/三 →「区域三」
  - outcome：收集与检查点进度跨区保留
- S12 区域三（根系深处）
  - input：同 S11＋Space×2＝二段跳、贴壁自动抓壁（获得后）（触发方：玩家）
  - precondition：区域二推进完成
  - state_change：三类能力门禁组合可过；根系深处检查点激活
  - feedback：同 S09
  - next_actions：最深处终点 →「复苏结算」
  - outcome：按 §7 V01 判定
- S13 复苏结算
  - input：Enter=重开 / Esc=返回（触发方：玩家）
  - precondition：V01 成立（集齐三项能力并抵达最深处终点）
  - state_change：进入「复苏结算」；结算仅保留**只读快照**（能力/收集/捷径/耗时展示，AUD12）；面板出现前按 §10 C04 播放结算视频（每局一次）
  - feedback：结算面板显示总收集件数、路线耗时、捷径开启数
  - next_actions：Enter 重开（全量清空）或返回标题
  - outcome：重开前快照只读不回写
- S14 坠落与区间恢复
  - input：坠出安全区（触发方：系统）
  - precondition：处于游玩状态
  - state_change：普通坠落也回当前检查点、区间容错计数 +1（AUD13）；计数达 4 → 额外重置该区间临时机关/敌障并清零容错计数，跨区能力与收集**不回退**
  - feedback：检查点亮起＋复位淡入（F05）
  - next_actions：复位后继续探索
  - outcome：不存在自动全局局败（AUD13）
- S15 暂停与 Load
  - input：Esc（触发方：玩家）；窗口失焦自动触发（触发方：系统）
  - precondition：任意可操作阶段
  - state_change：暂停覆盖层打开，模拟时间冻结；暂停菜单提供「继续 / Load 最近存档 / 重开 / 设置」（AUD13）
  - feedback：暂停面板显示最近存档快照摘要
  - next_actions：Load → 恢复最近存档快照（能力/收集/门禁/捷径/检查点全量，AUD12）；继续 → 回到游玩
  - outcome：Load 后状态与存档时 diff=0

## 3. 数值口径与全局规则 [G01–G07]

- G01 统一刻度：距离按米、时间用游戏模拟秒（暂停冻结）；收集按件；评级为整数。
- G02 基础移动（zkx 裁决冻结，AUD10）：**统一 2.5D 侧视**；基础移速 4 米/秒；基础跳跃峰高 1.5 米、总时长 0.8 秒；平跳最大水平 3.2 米；站立碰撞高 1.8 米。三项能力（本包冻结值）：冲刺（位移 4 米，冷却 0.8 秒）、二段跳（第二跳相对高度 2.5 米）、抓壁（贴壁缓降并可蹬壁跳 3 米）；获得前对应指令无效。
- G03 门禁依赖（本包冻结值＋AUD10/11）：冲刺裂隙（从边缘安全起跳标记到对侧落脚判定点计 **4 米**，提供 0.1 米落脚容差，需冲刺渡过——基础跳最大 3.2 米不可越，普通跳不能绕过）；二段跳高台（高 4 米两段——首跳峰 1.5 米＋首跳顶点触发二段跳 2.5 米可达 4 米高台，落脚容差 0.1 米）；抓壁光壁（高 6 米光滑壁面——须**两次交替壁面蹬跳**，每次 ≤3 米；场景必须提供可接触对侧壁，离壁后不可无限凭空续跳）。未持对应能力接触门禁 → 不可通过并提示所需能力。
- G04 收集与捷径（本包冻结值）：光合晶 12 件（每区 4，唯一 ID）；旧区设 3 处反向捷径门（区域一 1 处需二段跳、区域二 2 处需抓壁），用后区能力回访开启后大幅缩短跨区路径；捷径开启状态永久保留（会话内，AUD12）。
- G05 坠落、检查点与区间重置（本包冻结值＋AUD13）：每检查点区间坠落/陷阱容错 **3 次**；普通坠落回当前检查点且容错计数 +1；**第 4 次额外重置该区间临时机关/敌障并清零容错计数**（跨区能力与收集不回退）；全图检查点 8 个（每区至少 2）；不存在自动全局局败。
- G06 保存语义（zkx 裁决冻结，AUD12）：能力/收集/已开门禁/捷径/检查点及区间容错计数**只在当前运行会话保存**；存档点交互（6 个）保存全部上述状态；暂停菜单 Load 恢复最近存档快照；结算界面保留只读快照，Enter 重开才清空；退出进程不承诺保存。存读档 oracle——存档后读档，前后状态快照 **diff＝0**。
- G07 判定与独立 oracle（本包冻结值＋AUD10/11）：门禁 oracle——未持冲刺接触 4 米裂隙必坠落回检查点且不可通过；持冲刺同门必出渡过事件（位移 4 米±0.1 米容差）；二段跳 oracle——首跳顶点触发二段跳可达 4 米高台（1.5＋2.5）；蹬跳 oracle——6 米光壁两次交替蹬跳（每次 ≤3 米）可登顶、第三次续跳不可达。fixed_seed=1015 冻结收集品与检查点布位；物理为确定公式，无概率判定。Esc 暂停冻结全部模拟计时（含能力冷却与区间容错）；窗口失焦自动暂停。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：W/A/S/D＝移动；Space＝跳；Shift＝冲刺（获得后）；Space×2＝二段跳（获得后）；贴壁自动抓壁（获得后）；E＝能力节点/存档点/捷径门交互；Esc＝暂停（含 Load/重开菜单）；结算界面 Enter＝重开。

- I04 输入优先级：暂停与结算状态阻断全部玩法输入；同帧互斥动作按 I01 列举顺序取首个；跳跃与下蹲互斥。
- I05 焦点与失焦：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停（桌面窗口失焦口径）。

## 6. 机制系统 [M01–M04]

- M01 能力解锁（主机制）
  - input：到达能力节点并按 E（触发方：玩家）
  - precondition：处于能力节点交互范围且该节点尚未获得
  - state_change：获得冲刺/二段跳/抓壁之一 → 可行动指令集扩大（获得前后指令集差分落盘）
  - observable：能力获得事件（ability_id）与移动指令集差分流水
  - invalid_case：已获得节点重复交互无副作用；未获得能力时对应指令无效
  - recovery：无失败态；能力获得后落盘，区间重置不清除（AUD13）
- M02 门禁依赖（主机制）
  - input：接触门禁（触发方：系统）
  - precondition：处于游玩状态
  - state_change：未持能力 → 不可通过并提示所需能力（不传送）；持能力 → 按对应动作参数通过（G03 几何与容差）
  - observable：门禁状态与通过/拒绝事件（含所需能力标识 gate_lock_symbol）；渡过/登顶事件含位移与容差字段
  - invalid_case：普通跳越过 4m 裂隙不可达（基础平跳 3.2m 上限）；离壁后无限续跳不可达
  - recovery：未通过走 M04 区间恢复
- M03 旧区回访与捷径（主机制）
  - input：用新能力在旧区交互捷径门（触发方：玩家）
  - precondition：持有对应后区能力且处于捷径门交互范围
  - state_change：捷径开启 → 跨区路径缩短、地图标记更新；开启状态会话内永久保留（AUD12）
  - observable：捷径开启事件（shortcut_id）与路径耗时差分
  - invalid_case：未持对应能力的捷径门交互无效
  - recovery：无失败态
- M04 坠落、区间容错与存读档（主机制）
  - input：坠出安全区 / 存档点交互 / 暂停菜单 Load / 结算 Enter（触发方：系统/玩家）
  - precondition：处于游玩状态（存读档可在任意可操作阶段经暂停菜单发起）
  - state_change：坠落 → 回当前检查点、容错 +1；第 4 次坠落 → 重置该区间临时机关/敌障并清零容错，跨区能力/收集/捷径不回退；存档 → 快照全部持久字段（能力/收集/门禁/捷径/检查点/容错）；Load → 恢复最近快照（diff=0）
  - observable：fall_reset 事件（checkpoint_id 与容错计数）、zone_reset 事件、save/load 事件与前后快照
  - invalid_case：结算只读快照不可回写；退出进程不承诺保存
  - recovery：三级恢复（区间检查点 → 存档 Load → 全量重开，S05）

跨阶段后果表（至少 1 条显式 A→B→C 链，早期状态在后续阶段仍可观察）：

- K01 阶段A（区域一末获得冲刺，能力事件落盘）→ 阶段B（区域二入口的冲刺裂隙由不可通过转为可通行，门禁通过事件）→ 阶段C（区域三入口的冲刺＋二段跳组合门可过、最深处终点路线可达）；验证方式=跨阶段回溯探针：阶段 A 结束时记录能力集快照 → 阶段 B 检查对应门禁通过事件 → 阶段 C 检查组合门状态与终点可达。
- K02 阶段A（区域一收集光合晶并首次存档）→ 阶段B（区域二、三继续收集，计数跨区累计）→ 阶段C（最深处终点结算显示总收集件数与通关路线耗时，回访捷径使同段路径耗时差分可测）；验证方式=终点结算对账＋捷径开启前后耗时对照；Load 后 K01/K02 状态仍成立（G06 oracle）。

## 7. 成功、失败与恢复 [V01–V06]

- V01 成功条件：集齐三项能力并抵达最深处终点 → 复苏结算（显示总收集件数、路线耗时、捷径开启数；结算仅保留只读快照，AUD12）。
- V02 失败条件：本作无自动全局死亡终局——坠落仅回检查点（容错 +1）、第 4 次坠落重置区间（AUD13）；仅当玩家在结算界面主动 Enter 重开才全量清空。
- V03 恢复语义：三级恢复——①区间内回检查点（容错 3 次，第 4 次区间重置清零）；②暂停菜单 Load 最近存档快照（全量状态恢复，任意可操作阶段可用）；③一键重开（全量清空，seed 复现）。
- V04 persistent_state：会话内跨区持久（能力、门禁状态、收集、地图标记、捷径）；存档点存读档；跨进程不承诺保存（AUD12）；重开全量清空。
- V05 persistent_state 生命周期：动作级即时结算；局级状态（能力/收集/捷径/检查点）会话内跨区保留；结算界面只读快照；Enter 重开清空。
- V06 软锁与不可达处理：不设永久软锁——三类门禁几何在能力参数边界内可达（AUD10/11）；第 4 次区间重置清除临时机关卡点；暂停 Load 与重开为兜底恢复出路；不得把恢复入口缺失解释为正常失败。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：地下植物园复苏记录——封存的地下植物园因供电衰减根系通路逐渐枯死，复苏计划只剩最后一个维护窗口。
- W02 场景所在地：地下植物园三层园区（地面层花圃平台、藤蔓层悬吊栈道、根系深处黑暗溶腔），层间以能力门禁与捷径暗道相连。
- W03 玩家身份与当前任务动机：玩家是植物园维护研究员，携带复苏工具箱下潜；动机是找回三项维护能力（冲刺靴/二段跳簧/抓壁爪），在最深处终点重启生长核心，让花园重新复苏。
- W04 失败代价与结局表达：无全局死亡——坠落只打断节奏；放弃或重开=复苏记录中止（C04 失败意象）；成功=生长核心重启、复苏波沿园区扩散（C04 胜利意象）。
- W05 叙事来源：能力节点=封存的维护装备舱；三类门禁=裂隙封印/高台封印/光壁封印（对应能力符号）；光合晶=植物储能结晶；存档终端=园区记录仪；检查点=生长灯标；捷径=后区能力打开的检修暗道。全部原创。
- W06 视觉风格与色彩材质：地下生态暖光风；主色=生长绿 #7FBF6A、晶蓝 #7FD8E8、岩褐 #8A7A66、灯标橙 #E4762C、深腔紫 #4A4E6F；材质为藤蔓、湿岩、发光苔藓与玻璃晶格。
- W07 环境氛围与声音语言：植物呼吸与水滴为底；音效语言为「能力绽放＋封印提示＋冲刺风切＋蹬壁抓附＋捷径开启＋复苏波」，全部音效按 §9 F06 冻结清单交付；混音优先级：区间重置与复苏波 ＞ 能力/门禁反馈 ＞ 收集 ＞ 环境底噪。
- W08 故事表达方式：开场视频（C01）交代枯萎园区与复苏目标 → 能力获得视频（C02）承载装备重启节拍 → 捷径视频（C03）承载回访叙事 → 结算视频（C04）收束；叙事提示不阻断控制、不改变数值。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：7 个（text-to-3D 5，image-to-3D 2）；object 任务资产为：garden_researcher, ability_node_pod, sealed_gate_frame, photo_crystal, save_terminal, garden_checkpoint_lamp, shortcut_door。每项只允许一个物体；组合物必须拆成独立任务。
- motion：7 个；覆盖动作：run, jump, double_jump, dash, wall_climb, interact, fall_reset。
- video/audio/mechanic/UI：分别为 4/13/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

## 1. 定位与完整流程 [S01–S06]

- S01 类型：俯视移动部署护卫塔防。
- S02 核心循环一句话：载具行进 → 路段遭遇预告 → 停车限区内部署 → 交战回收 → 继续行进。
- S03 流程：平原路段（轻遭遇）→ 峡谷路段（中遭遇）→ 渡口路段（重遭遇）→ 抵达终点结算。
- S04 最低完整流程：部署操作、遭遇预告、交战、回收、耐久显示、胜负结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：失败结算提供「重打本段 / 全量重开」两个入口——段落重打从该段起点、载具耐久回进段时值；Esc 暂停。
- S06 本局耦合边速览：载具位置决定可部署区（载具→部署合法性）；回收与收入决定下一路段资源（回收/收入→资源）。

## 2. 完整核心循环与阶段 [S07–S15]

完整循环：主菜单 → 开始对局 → 路段行进 ⇄ 遭遇预告 → 遭遇交战 → 清空后行进与回收窗口（三段循环）→ 抵达终点胜利结算；任意玩法阶段可 Esc 暂停；载具耐久归零即时进入失败结算。每阶段六要素如下（引用本 spec §3–§7 对应规则）：

- S07 主菜单
  - input：系统启动，玩家确认进入
  - precondition：程序启动完成
  - state_change：显示主菜单（开始/退出）
  - feedback：主菜单界面
  - next_actions：玩家点击「开始」→ S08
  - outcome：无状态副作用
- S08 开始对局
  - input：玩家点击「开始」
  - precondition：主菜单已显示
  - state_change：对局初始化：篷车耐久 100、资源 200、路段=平原
  - feedback：HUD 显示初始值（耐久/资源/路段进度，见 §4 I06）
  - next_actions：进入 S09 路段行进
  - outcome：无跨局状态（见 §7 V05）
- S09 路段行进
  - input：系统驱动篷车自动行进（0.5 格/秒，不可操控）；玩家圈内部署/回收（按 §4 I01/I02 键位）
  - precondition：本路段已进入且未触发遭遇预告
  - state_change：篷车沿路线前进；部署圈随车平移
  - feedback：部署圈光环随车移动（见 §9 F05）；HUD 路段进度更新
  - next_actions：到达遭遇触发点 → S10；抵达段末 → 段末检查点事件（记录段末耐久/资源）→ 下一路段 S09 或终点 → S14；Esc → S13
  - outcome：段末检查点记录；状态局内保留
- S10 遭遇预告
  - input：系统（篷车到达遭遇触发点）
  - precondition：路段行进中
  - state_change：篷车停车；5 秒倒计时开始；屏幕边缘显示来袭方向箭头（左/右/前）
  - feedback：遭遇预告特效（见 §9 F05）
  - next_actions：倒计时归零 → S11；Esc → S13
  - outcome：篷车静止，部署圈定界
- S11 遭遇交战
  - input：系统遭遇调度（敌人从路段两侧固定点按 1.0 秒间隔出生，布位由 seed=1029 冻结）；塔自动交战；玩家仍可部署/回收（不暂停）
  - precondition：遭遇预告倒计时归零
  - state_change：敌人冲向篷车并接触扣耐久；箭塔按 §3 G03 交战；击杀 +5/只
  - feedback：命中反馈与治疗光丝（见 §9 F05/F06）
  - next_actions：遭遇敌人清空 → S12；篷车耐久归零 → S15；Esc → S13
  - outcome：击杀收入入账；耐久变动
- S12 清空后行进与回收窗口
  - input：篷车继续自动行进（系统）；玩家手动回收（按 §4 I01）
  - precondition：遭遇敌人清空
  - state_change：篷车恢复行进；10 秒回收窗口开始——窗口内手动回收返还 60%；超时未收装置随圈平移，出圈后转为远离件（回收 30%）
  - feedback：回收光点飞回篷车、资源数字跳动（见 §9 F05）
  - next_actions：行进至下一遭遇触发点 → S10；抵达段末 → 段末检查点（每通过一段 +60）→ 下一路段 S09 或终点 → S14；Esc → S13
  - outcome：回收与过段收入入账
- S13 暂停
  - input：玩家按 Esc
  - precondition：处于 S09–S12 任意玩法阶段
  - state_change：冻结篷车、敌人、装置、遭遇计时与全部计时
  - feedback：暂停菜单（继续/重开/返回菜单）
  - next_actions：Esc 或「继续」→ 返回原阶段；「重开」→ S08；「返回菜单」→ S07
  - outcome：恢复后一切计时从冻结点继续，无副作用
- S14 胜利结算
  - input：系统结算
  - precondition：篷车穿越三路段抵达终点（见 §7 V01）
  - state_change：显示胜利结算（剩余耐久与资源）
  - feedback：胜利 Ending CG 与全屏特效（见 §9 F05 与 §10 C04）
  - next_actions：Enter 全量重开 → S08；返回菜单 → S07
  - outcome：按 §7 V01/V03 判定并结算
- S15 失败结算
  - input：系统结算
  - precondition：篷车耐久归零（任意时刻即时判负，见 §7 V02）
  - state_change：显示失败结算，含「重打本段（R）」与「全量重开（Enter）」两个入口
  - feedback：失败台词（见 §9 F05 与 W08 配音节点）
  - next_actions：R 重打本段 → 该段起点（耐久回进段时值、装置与资源回段初）；Enter 全量重开 → S08；返回菜单 → S07
  - outcome：按 §7 V02/V03 判定并恢复

## 3. 数值口径与全局规则 [G01–G06]

- G01 统一刻度：耐久/资源为整数；距离按格计；装置射程按格中心欧氏距离 ≤ 射程判定；时间用游戏模拟秒（暂停冻结）。
- G02 载具与耐久（本包冻结值）：迁徙篷车耐久 100（上限 100）、移速 0.5 格/秒、随路线自动行进（不可操控）；遭遇预告开始时停车，遭遇清空后继续行进；敌人接触篷车每次 −10（同一敌 1 秒冷却）；耐久归零判负。
- G03 装置表（本包冻结值）：箭塔（造价 50、耐久 30、攻 12、射程 3、间隔 1.0 秒、优先攻击离篷车最近的射程内敌人）；路障（造价 30、耐久 40、**阻挡不可通行**——敌人不可越过，无减速；被阻挡的敌人转而攻击该路障）；治疗桩（造价 40、篷车在其 3 格内时 +2/秒；不占格、不被攻击，由引擎基础几何＋绿色光效呈现）。箭塔与路障均**占格阻挡**并可被敌人摧毁（敌人接触阻挡装置每 1 秒 −10 耐久，摧毁后继续冲向篷车）。初始资源 200。
- G04 移动部署区（本包冻结值）：仅可部署于篷车周围 **半径 8 格**内（部署区随篷车实时移动）；篷车移动使边缘装置出圈后保留生效但不可再获回收（远离件）；圈外部署一律非法拒绝。
- G05 回收折损（本包冻结值）：交战中或遭遇清空后 10 秒回收窗口内手动回收 → 返还造价 **60%**（折损 40%）；超时未收的装置在篷车行进使其出圈后转为远离件，远离件回收返还减半（30%）；回收资源入账可再部署；回收对账流水守恒（无凭空增减）。
- G06 路段、遭遇与经济（本包冻结值）：三路段固定遭遇脚本由 seed=1029 冻结——平原 6 敌（HP 40）、峡谷 10 敌（HP 60）、渡口 14 敌（HP 80），移速均 1 格/秒；遭遇开始后敌人从路段两侧固定点按 1.0 秒间隔出生（布位由 seed 冻结）；敌人目标＝篷车，行进被己方箭塔/路障占格阻挡时先攻击该装置（每 1 秒 −10 耐久）直至摧毁后继续冲向篷车；接触篷车后贴车按 1 秒冷却扣血；击杀 +5/只、每通过一段 +60；每段结束自动检查点（段末耐久记录）。伤害即时结算（命中帧生效，弹道仅为表现层）。部署合法性/回收/收入 oracle：①篷车移动前圈内部署成功、出圈后同格再部署非法；②50 造价箭塔回收入账 30、远离件回收 15；③收入对账：初始 200、击杀 +5/只、过段 +60——经济推演：平原段击杀 6 只 +30 与过段 +60，到峡谷段可用资源不低于 200−部署＋90，同理推演到渡口段资源足以部署「1 箭塔＋1 路障」以上防线（第三段可完成）；任何偏离即 FAIL。

## 4. 操作与输入 [I01–I06]

- I01 键鼠：点击圈内格＋装置＝部署；点击己方装置＋回收钮＝回收；1/2/3＝快捷选装置；Esc＝暂停；胜利结算 Enter＝全量重开；失败结算 R＝重打本段、Enter＝全量重开。
- I02 输入语义边界：圈外部署非法拒绝且不扣资源；资源不足部署无效；交战中可随时部署/回收；暂停/结算期间输入无效。
- I03 无手柄需求。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入（沿用原 I02 口径）；同帧多输入按 §6 各机制声明的顺序结算。
- I05 焦点与点击穿透规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停，不推进游戏模拟。
- I06 UI 必须显示的状态：耐久（上限 100）、资源、路段进度（按 §3 G01 刻度）；遭遇预告 5 秒倒计时与来袭方向（左/右/前）；部署圈边界可视（冻结要求）；悬停圈内格显示射程圈与合法性（绿/红，见 §9 F05）。
- I07 输入延迟目标：点击到画面反馈 ≤100 毫秒（桌面口径，P95，≥30 次采样/类别）。

## 6. 机制系统 [M01–M04]

- M01 移动部署区（主机制）
  - input：部署指令（系统实时判定圈界）
  - precondition：目标格在篷车周围半径 8 格内且为空；资源 ≥ 装置造价
  - state_change：圈内落位生效；篷车移动使部署区整体平移；出圈装置保留但进入远离态
  - output：按 §3 G03/G04 结算装置效果与部署合法性
  - observable：deploy/deploy_reject 事件（含距篷车格数）与圈界状态
  - invalid_case：圈外部署、资源不足按 §4 I02 拒绝且无副作用；暂停/结算期间玩法输入无效
  - recovery：失败/中断/非法态后的恢复按 §7 V03 恢复语义与 V04 软锁处理执行，不产生冻结规则之外的副作用
- M02 临时防线与回收
  - input：手动回收（玩家，交战中或遭遇清空后 10 秒窗口内）
  - precondition：目标为圈内己方装置（远离件按 30% 口径）
  - state_change：装置移除并按 §3 G05 返还（60%／远离 30%）；超时未收装置出圈转远离件
  - output：按 §3 G05 结算返还
  - observable：recycle 事件与资源流水对账（含超时转远离件事件）
  - invalid_case：无装置可回收时指令无效；远离件按 30% 而非 60% 返还
  - recovery：按 §7 V03/V04 执行
- M03 护送耐久
  - input：敌人接触篷车（系统）；治疗桩驻圈（系统）
  - precondition：敌人与篷车接触（每敌 1 秒冷却）；篷车在某治疗桩 3 格内
  - state_change：每次接触 −10；治疗 +2/秒（不超上限 100）；归零判负
  - output：按 §3 G02/G03 结算耐久
  - observable：caravan_hit/heal 事件与耐久流水
  - invalid_case：同一敌 1 秒冷却内重复接触不扣；篷车不在治疗桩 3 格内不回复
  - recovery：按 §7 V03/V04 执行
- M04 路段遭遇
  - input：路线进度（系统）
  - precondition：篷车到达遭遇触发点（行进中）
  - state_change：篷车停车＋5 秒预告（含方向）→ 敌人从路段两侧固定点按 1.0 秒间隔出生并冲向篷车；段末检查点记录
  - output：按 §3 G06 结算遭遇与收入（击杀 +5、过段 +60）
  - observable：segment_start/encounter_warning（含方向）/checkpoint 事件与遭遇序列、击杀与过段收入流水
  - invalid_case：遭遇未开始时无敌人出生；暂停期间遭遇调度冻结
  - recovery：按 §7 V03/V04 执行

系统耦合边（玩法必需、可复现）：

- E01 from_system=篷车位置系统 → to_system=部署合法性系统；changed_state=篷车坐标实时决定部署圈界与合法性；验证方式=探针在篷车移动前后同格部署，state_before/after（合法/非法）对照。
- E02 from_system=回收与收入系统 → to_system=资源系统；changed_state=回收折损返还与击杀/过段收入决定下一路段可部署规模；验证方式=回收/收入前后资源流水与再部署规模对照。

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：篷车穿越三路段安全抵达终点（耐久 > 0）→ 结算（显示剩余耐久与资源）。
- V02 失败条件：篷车耐久归零 → 失败结算（任意时刻即时判负）。
- V03 恢复语义：失败结算两个入口——「重打本段」从该段起点恢复（耐久回进段时值、装置与资源回段初）；「全量重开」清空全部进度；局内无存档。
- V04 软锁与不可达处理：无永久软锁——关键目标均可通过正常操作达成，或触发 V02 失败路径进入结算；结算界面重开/重打为最终恢复出路；判定不可达时按 V02 失败语义结算而非无限等待。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（耐久/装置/资源/路段进度）局内跨段保留、重开清空；无跨局保留（重开全量清空）。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：旱季将尽的大迁徙纪元——部落的种子与水源装在风帆篷车上，必须在河水封冻前从平原经峡谷赶到南岸渡口，错过封冻整个部落将无种可播。
- W02 场景所在地：单条三段迁徙路线——平原段（轻遭遇）、峡谷段（中遭遇）、渡口段（重遭遇），各段 20 格，遭遇布位由 seed 冻结。
- W03 玩家身份与当前任务动机：玩家是护卫长；长老阿岩托付种子与水，斥候先行探路——在移动的部署圈内布设箭塔、路障与治疗桩，护送篷车穿越三段荒野。
- W04 失败代价与结局表达：篷车倾覆=种子与水尽失（C04 失败意象＋失败台词）；抵达渡口=渡河开往新牧场（C04 胜利意象）。
- W05 叙事来源：迁徙篷车=风帆木车；平原劫掠者/峡谷伏击者=循水汽而来的荒野流寇（两套人形按段换色）；箭塔=车载弩架、路障=沙石拒马、治疗桩=净水石桩；长老阿岩与斥候为剧情人物。全部原创，不用商业作品命名。
- W06 视觉风格与色彩材质：荒野迁徙风；主色＝篷帆米白 #E8DFC8、峡谷赭 #A9744F、河渡青 #5B8A8F、警报红 #C0392B；材质为风帆帆布、木质车架、沙岩。
- W07 环境氛围与声音语言：风沙与车轮辘辘为底；音效语言＝部署/回收/遭遇方向警报/车轮与木屑（F06 冻结清单）；混音优先级：遭遇警报 ＞ 篷车受击 ＞ 战斗命中 ＞ 部署/回收 ＞ 环境风。
- W08 故事表达方式：开场视频（C01）交代出发与封冻期限 → 过程视频（C02/C03）承载斥候伏兵报告与渡口日落 → 结算视频（C04）双意象收束；叙事节点台词每节点 ≤2 句、可跳过、剧情界面打开时游戏暂停；故事只做包装不改数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：斜俯视约 50°；镜头自动跟随篷车，按住中键可临时拖动，松开后回弹；滚轮缩放 3 档。
- F02 关键操作镜头变化：篷车受击 0.25 秒中幅震动；其余事件不震；设置里可关闭（见 F09）。
- F03 输入与延迟：见 I07（≤100ms 桌面 P95）；顿帧不改变计时口径。
- F04 环境常驻效果：风沙飘移、篷车帆布鼓动、车轮尘迹、路旁枯草。纯表现层，不参与判定。
- F05 事件反馈表（事件 → 画面表现 → 音效 → 结束条件，全部冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 装置部署 | 地面光环随车移动、边缘渐隐；部署落地展开扬尘＋回弹 0.2 秒 | deploy | 落位完成 |
| 圈外部署拒绝 | 红色格子闪烁提示 | deploy_reject | 提示 0.4 秒 |
| 装置回收 | 光点飞回篷车、资源数字跳动 | recycle | 0.4 秒结束 |
| 远离件 | 灰化、虚线连回篷车 | （常驻视觉，无音效） | 持续 |
| 箭塔击发 | 弩箭拖尾＋命中木屑＋受击闪白 0.08 秒＋伤害飘字 | arrow_shot / raider_hit | 每发即时 |
| 敌人死亡 | 流寇倒地消散 | raider_death | 消散完成 |
| 装置被摧毁 | 碎裂崩散 | roadblock_hit | 碎裂结束 |
| 治疗桩回复 | 绿色光丝连到篷车 | heal_pulse | 持续回复期间 |
| 篷车受击 | 木屑飞溅、红闪＋0.25 秒中幅震动 | wagon_hit | 闪烁结束 |
| 遭遇预告 | 来袭方向箭头在屏幕边缘闪烁＋5 秒倒计时 | encounter_warning | 倒计时归零 |
| 段末检查点 | 旗帜光效＋过段奖励飘字 | checkpoint | 光效结束 |
| 胜负结算 | 全屏特效（双意象见 C04） | victory_sting / defeat_sting | 进入结算面板 |

- F06 关键音效清单（one_shot 12 条＋环境循环 1 条，全部冻结需求）：deploy、deploy_reject、recycle、arrow_shot、roadblock_hit、raider_hit、raider_death、heal_pulse、wagon_hit、encounter_warning、checkpoint、victory_sting、defeat_sting；环境循环：wagon_rolling（车轮辘辘与风沙底噪；篷车行进时循环、停车时降低、暂停静音、结算淡出 0.5 秒）。配音：长老阿岩/斥候 5 条（W08 节点，每条 ≤2 句）。
- F07 VFX 信息性与遮挡约束：部署圈边界、射程圈、合法性色块、遭遇方向箭头为信息类 VFX，必须清晰可辨；粒子不遮挡篷车与 HUD 关键目标；非结算单个全屏遮挡 ≤0.5 秒。
- F08 音画同步：弩箭音与拖尾同帧；警报音与方向箭头同帧；回收音与光点同帧；受击音与红闪震动同帧。
- F09 屏幕震动：篷车受击 0.25 秒中幅；暂停/结算取消未结束的震动与特效；设置可关闭（镜头震动开/关；伤害数字开/关）。
- F10 前端界面：标题（开始/设置/退出）→ 护送 HUD（耐久/资源/路段进度/遭遇预告含方向/部署圈状态，见 I06）→ 暂停面板（继续/重开/返回/设置）→ 结算面板（胜利：剩余耐久与资源；失败：「重打本段（R）/全量重开（Enter）」两入口）；关键状态图标＋文字并用；窗口失焦自动暂停。

## 10. 过场视频 [C01–C04]

- C01 出发（Opening，8 秒，1280×720@24fps）
  - 触发时机：首次由标题进入对局（平原段行进）之前，每局一次
  - 内容与角色场景：晨光中长老阿岩将种子袋交上篷车、护卫队收起营火、风帆张满，篷车驶出绿洲边缘
  - 资产对应：迁徙篷车、护卫队员与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入平原段行进；自然播完 → 进入平原段行进
  - 状态一致：跳过与自然播完后初始状态一致；播放期间不推进任何游戏计时
- C02 峡谷伏兵（Transition，5 秒，1280×720@24fps）
  - 触发时机：首次进入峡谷段之前，每局一次
  - 内容与角色场景：斥候登高远眺、峡谷岩脊上伏兵剪影绰绰，斥候向篷车方向打出手势警报
  - 资产对应：护卫队员、劫掠者剪影与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入峡谷段行进；自然播完 → 进入峡谷段行进
  - 状态一致：播放期间不推进任何游戏计时
- C03 渡口日落（Transition，5 秒，1280×720@24fps）
  - 触发时机：首次进入渡口段之前，每局一次
  - 内容与角色场景：夕阳下的河湾渡口、渡船泊在浅滩、河面浮冰漂近——最后一段路在暮色里展开
  - 资产对应：迁徙篷车与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入渡口段行进；自然播完 → 进入渡口段行进
  - 状态一致：播放期间不推进任何游戏计时
- C04 渡河（Ending，8 秒，1280×720@24fps，双意象共用条目）
  - 触发时机：V01/V02 成立、结算面板出现之前，每局一次
  - 内容与角色场景：胜利意象=篷车驶上渡船、河对岸绿意隐现；失败意象=篷车倾覆、种子袋散落风沙
  - 资产对应：迁徙篷车与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入对应结算面板；自然播完 → 进入对应结算面板
  - 状态一致：仅在真实 V01/V02 后触发；播放期间不推进任何游戏计时

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：3 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：6 个（text-to-3D 4，image-to-3D 2）；object 任务资产为：sail_wagon, plains_raider, portable_arrow_tower, roadblock, escort_guard, canyon_ambusher。每项只允许一个物体；组合物必须拆成独立任务。
- motion：12 个；覆盖动作：move, attack, hit, death, move, attack, hit, death, move, attack, hit, death。
- video/audio/mechanic/UI：分别为 4/19/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

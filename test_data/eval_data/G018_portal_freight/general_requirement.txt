## 1. 定位与完整流程 [S01–S06]

- S01 类型：3D 单人传送门解谜搬运。本测例包含的能力：三室冻结布局、双门投放与动量映射、三类货箱搬运、压板联动、卡物自动恢复、双区状态同步、结算幂等、开场/首次运输/结算视频。
- S02 核心循环一句话：规划门位 → 投放传送门 → 搬运对象/自身 → 完成目标。
- S03 流程：室1 单室基础搬运（2 箱）→ 室2 压板联动（3 箱＋1 压板）→ 室3 动量搬运（跨沟抛箱 2 箱）→ 结算。
- S04 最低完整流程：开始界面、三门投放与搬运操作、三室目标判定、结算、室级重置、重开必须全部存在且有真实入口。
- S05 失败恢复入口：无步数失败态（每室 60 步带宽仅提示）；R 室级一键重置；卡物 3 秒自动弹回；结算界面重开；Esc 暂停。
- S06 本局耦合边速览：入口动量经映射公式决定出口运动（映射系统→动量系统）；压板承重决定门/升降台开启（压板系统→门禁系统）。

## 2. 完整核心循环与阶段 [S06–S10]

完整循环：启动与开始界面 → 室1 基础搬运 → 室2 压板联动 → 室3 动量搬运 → 结算 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与开始界面
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始任务」
  - precondition：构建可启动且场景加载完成
  - state_change：进入「开始界面」状态；首次进入按 §10 C01 触发开场视频
  - feedback：界面按 §9 F10 呈现（任务简报：三室目标箱数）
  - next_actions：进入「室1」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 室1 单室基础搬运
  - input：WASD 移动、左/右键投门、E 抱放、Q 抛箱、R 重置、Esc 暂停（触发方：玩家）
  - precondition：开始界面已完成（室1 默认解锁）
  - state_change：载入室1 冻结布局；2 只标准箱 S 待运
  - feedback：传送残影/吸入/落地/重量反馈按 §9 F05 呈现
  - next_actions：室1 全部 delivered →「室2 解锁」
  - outcome：室1 完成标记局内保留（V04）
- S08 室2 压板联动
  - input：同 S07（触发方：玩家）
  - precondition：室1 全部货箱 delivered
  - state_change：载入室2 冻结布局；3 箱（S×2＋H×1）与压板联动门禁可用
  - feedback：压板承重与门开闭状态同步显示（HUD 小地图）
  - next_actions：室2 全部 delivered →「室3 解锁」
  - outcome：室2 完成标记局内保留
- S09 室3 动量搬运
  - input：同 S07（触发方：玩家）
  - precondition：室2 全部货箱 delivered
  - state_change：载入室3 冻结布局；跨沟动量搬运（L×1＋S×1）
  - feedback：抛箱轨迹与出口动量继承表现
  - next_actions：室3 全部 delivered →「结算」（先播 C03）
  - outcome：按 V01 结算
- S10 结算
  - input：Enter＝重开 / Esc＝返回开始界面（触发方：玩家）
  - precondition：三室全部货箱 delivered（V01）
  - state_change：进入「结算」状态；场景冻结
  - feedback：结算面板显示总步数、用时、delivered 清单
  - next_actions：重开（全量清空）或返回
  - outcome：无跨局写入

## 3. 数值口径与全局规则 [G01–G08]

- G01 统一刻度：距离为米；速度为米/秒；步数与箱数为整数。
- G02 传送门（本包冻结值）：蓝/橙两枚，仅可投放于专用门墙面（白色面板），门面为成对椭圆（半径 1.2 m）；门位可随时改投；玩家与货箱均可穿越。
- G03 映射公式与冷却（本包冻结值）：出口速度大小＝入口速度大小（守恒）；出口方向＝入口方向按两门法线夹角旋转（角度容差 ±2°）；传送后 0.3 秒冷却（冷却中同门不可再穿，防无限往返）。动量映射 oracle 数例：以 6 米/秒水平进入门 A（法线水平朝内）、两门法线夹角 90° → 出口速度大小 **6 米/秒**、方向沿门 B 法线朝外旋转 90°；任何偏离（超 ±2° 或模长变化）即 FAIL。
- G04 压板与重量（本包冻结值）：压板承重 ≥1 单位（任何箱型或玩家均计 1）触发对应门/升降台开启，离开即回落；升降台承载玩家与箱垂直移动 3 米/秒。
- G05 步数与卡物（本包冻结值）：每室 60 步带宽（步＝一次门投放或一次搬运位移指令批次，超带宽仅提示不判负）；货箱卡入门缘/夹缝 → 3 秒自动弹回卡住前 1 秒位置（卡物自动恢复，软锁视为缺陷红线）；fixed_seed=1018 冻结三室布置；Esc 暂停冻结物理与计时；窗口失焦自动暂停。
- G06 货物规格与目标（本包冻结值）：箱型三类——标准箱 S（1×1×1 m，重 40，棕色标签）、重箱 H（1×1×1 m，重 80，深灰标签）、长箱 L（2×1×1 m，占 2 格，重 60，蓝色标签）；每室分布＝室1 S×2、室2 S×2＋H×1、室3 L×1＋S×1（共 7 箱）；目标位按箱型标色＋字母标签（S/H/L），只有箱型匹配的目标位计入完成；货箱不可叠放、不可旋转（放置吸附世界轴）。
- G07 传送映射与顺序（本包冻结值）：出口点＝入口点按门面局部二维坐标（u,v）一一映射至对面门同（u,v）位置且法线翻转；同帧多对象到达门面按接触先后串行结算（先到先出）；门位改投瞬间正在穿越的对象按旧门完成本次传送（传送不中断、对象不消失）。
- G08 双区同步与结算幂等（本包冻结值）：压板/升降台/门状态为两区共享状态（任一区改变，另一区 HUD 与判定同帧一致）；`delivered` 事件对每箱只发一次（首次到达匹配目标位）；货箱搬离目标位再搬回不重复计数（幂等）；进度＝已 delivered 箱数/7。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：WASD＝移动；左键＝投蓝门；右键＝投橙门；E＝抱起/放下货箱；Q＝抛出所抱货箱（出口动量继承）；R＝室级重置；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：非门墙面投放无效；未抱箱时 Q 无效；冷却中穿越不触发传送（沿门面滑过）；暂停/结算期间输入无效；被拒输入不计步。
- I03 鼠标控制视角（第一人称，见 F01）。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入；同帧多输入按投门→抱放→抛出顺序结算。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：当前室号、步数带宽提示、所抱箱型与重量条、进度（delivered/7）、小地图（两区布局＋门位连线＋压板/门状态）；HUD 对照见 rubric。
- I07 输入延迟目标：移动/投门按键到画面反馈 ≤ 80 毫秒；抱箱/抛箱交互反馈 ≤ 100 毫秒。

## 5. 货运室与内容清单 [L01–L04]

- L01 生成对象：调度员（玩家，第一人称手部可见）、标准箱 S×4、重箱 H×1、长箱 L×1、蓝橙传送门、压板 1、升降台 1、门 2、目标位 7（按箱型标记）；空间站装饰为表现层。
- L02 货运室：三间单屏货运室（约 20×12 米），沟壑与门墙面布置由 seed=1018 冻结；每室目标区有箱型匹配标识（颜色＋字母标签）。
- L03 目标物/交互物/场景/UI 对象：本 spec §3–§9 引用的界面元素（开始界面/HUD/结算/暂停/视频播放层）与交互物逐类存在且运行时可进入；数量与属性以 L01/L02 与 G 系为准。
- L04 冻结需求 vs 实现默认 vs 生成自由度：本 spec 明确写出的数值与数量为冻结需求；§9 未冻结的装饰造型与配色为生成自由度，不得评估为缺失；实现默认值必须明确标注且符合核心机制。

## 6. 机制系统 [M01–M05]

- M01 位置与方向映射（主机制）
  - input：穿越传送门（玩家/货箱）
  - precondition：对象与门面接触且不在 0.3 秒冷却内
  - state_change：入口位置与速度向量 → 出口位置（按 G07 的 (u,v) 映射与法线翻转）与旋转后速度向量（G03 公式）
  - observable：`portal_transit` 事件（含入口/出口位置与速度向量、角度差）；出口速度按重量不影响（动量守恒适用全部箱型）
  - invalid_case：冷却中接触 → 不传送（沿门面滑过）；非接触状态无事件
  - recovery：卡物按 M04 自动恢复
- M02 传送冷却与顺序
  - input：传送完成（系统）
  - precondition：传送事件刚发生
  - state_change：0.3 秒冷却内同门穿越不触发传送；同帧多对象按 G07 接触先后串行结算
  - observable：`cooldown` 事件与穿越流水（含对象 ID 与顺序）
  - invalid_case：门位改投时正在穿越的对象按旧门完成传送（不中断）
  - recovery：—
- M03 压板与重量
  - input：货箱/玩家置于压板
  - precondition：对象与压板碰撞体接触
  - state_change：承重 ≥1 → 对应门/升降台开启；离开回落；状态为双区共享（G08）
  - observable：`plate` 事件（承重值、开关状态）与两区 HUD 同步
  - invalid_case：承重 0 时门禁保持关闭
  - recovery：移开对象即回落
- M04 卡物恢复
  - input：货箱卡入门缘/夹缝（系统检测）
  - precondition：货箱速度低于阈值且位于门缘/夹缝碰撞体
  - state_change：3 秒后弹回卡住前 1 秒位置
  - observable：`stuck_recover` 事件（含位置前后对照）
  - invalid_case：正常移动不触发
  - recovery：超时未恢复记缺陷红线（FAIL 而非玩家失败）
- M05 结算幂等
  - input：货箱置于匹配目标位（系统检测）
  - precondition：箱型与目标位标签匹配且静止
  - state_change：首次达成 → `delivered` 事件＋progress+1；搬离再搬回不重复计数（幂等）；三室全部 delivered → 触发结算
  - observable：`delivered` 事件流水（含箱 ID、箱型、目标位）与 progress 状态
  - invalid_case：箱型不匹配的目标位不计入（提示「目标位不匹配」）
  - recovery：可自由搬离重摆，进度不回退

系统耦合边（玩法必需、可复现）：

- E01 from_system=门映射系统 → to_system=动量搬运系统；changed_state=入口速度经守恒与法线旋转决定出口运动与落点（跨沟抛箱成立的前提）；验证方式=探针以固定 6 米/秒穿门，state_before（入口向量）与 state_after（出口向量）按 G03 oracle 核对。
- E02 from_system=压板系统 → to_system=门禁系统；changed_state=承重值决定门/升降台开闭与通行路径（双区共享状态）；验证方式=空板/放箱/站人三态下门开闭的 state_before/after 对照。

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：三室全部 7 箱按箱型匹配 delivered → 结算（显示步数与用时）。
- V02 失败条件：无步数失败态；卡物 3 秒未恢复视为缺陷（红线记 FAIL 而非玩家失败）。
- V03 恢复语义：R 室级一键重置（该室箱位/门位/机关回初始，delivered 与其他室进度保留）；卡物自动弹回；结算界面重开全局。
- V04 persistent_state：无（重开全量清空；室内机关状态仅局内保留）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（delivered 进度/室完成标记）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设永久软锁——卡物自动恢复＋室级重置双保险；关键目标均可通过正常操作达成。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：近未来的深空物流时代，环轨货运枢纽「枢纽七号」负责中转殖民地补给；今夜自动分拣臂故障停机，滞留货物必须在天亮班次前人工归位。
- W02 场景所在地：枢纽七号的 B 区货运甲板——三间串联货运室（基础舱/联动舱/跨沟舱），门外是舷窗中的星空与港口灯。
- W03 玩家身份与当前任务：玩家是夜班货运调度员；当前任务：使用便携式成对传送门，把 7 件滞留货物全部送回对应泊位。
- W04 失败代价与结局表达：本作无失败态；放弃任务（返回开始界面）表达为「班次延误」的结算文案；完成则 C03 呈现货舱灯次第点亮的出港景象。
- W05 叙事来源：标准箱 S＝殖民城市口粮周转箱；重箱 H＝工业机床件（压板联动因它而设）；长箱 L＝跨班次联运长件（占双格）；传送门＝枢纽配备的「配对裂隙装置」，蓝橙成对。全部原创。
- W06 视觉风格与色彩材质：风格化科幻工业风；主色＝冷白合金（#B8C4CC 系）＋门橙蓝辉光（#E8722A/#2A7FE8）；材质以哑光合金、警示条纹、发光门面为主；目标位用箱型色＋字母标签。
- W07 环境氛围与声音语言：低重力感的寂静甲板——常驻气密舱低鸣与通风声；音效语言为「液压＋传送嗡鸣＋落地闷响（按重量分档）」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代故障与任务 → 首次成功运输视频（C02）作为正反馈节点 → 结算视频（C03）收束；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：第一人称；鼠标控制偏航/俯仰（俯仰 ±80°）；无镜头自动回正；抱重箱时镜头下沉 5°（模拟重量，见 F05）；摄像机边界＝货运室墙体碰撞体（不可穿出）；R 室级重置后镜头回该室出生点朝向冻结初始角。
- F02 关键操作镜头变化：穿门瞬间 FOV 由 75° 快速扩张至 85° 并在 0.3 秒内回弹（传送失重感）；抛箱命中目标位时镜头轻微上扬 2°；无慢动作。
- F03 输入与延迟：见 I07。
- F04 环境常驻效果：舷窗星光缓慢流动、通风口气流丝、目标位常亮标签；不遮挡门墙面与压板。
- F05 事件反馈表（事件 → 表现 → 结束条件，全部为冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 投放传送门 | 门面涟漪展开 0.3s＋对应色辉光 | 门锚定嗡声 | 展开完成即常驻 |
| 穿越传送门 | 传送残影（0.4s 渐隐）＋门面吸入涟漪；FOV 变化 | 传送嗡鸣（与穿门同帧） | 对象离开门面即停 |
| 抱起货箱 | 箱体升起至胸前＋HUD 重量条弹出 | 液压举升声 | 抱持状态常驻 |
| 抱重箱移动 | 镜头下沉 5°＋移速按箱型减慢（H×0.6、L×0.75） | 脚步声变沉 | 放下即恢复 |
| 放置落地 | 落点尘环（大小按重量分档）＋箱子轻微下压回弹 | 落地闷响（S/H/L 三档音量） | 回弹完成即停 |

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：4 个（text-to-3D 1，image-to-3D 3）；object 任务资产为：crate_std, crate_heavy, crate_long, portal_device。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：portal_open_close。
- video/audio/mechanic/UI：分别为 3/9/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

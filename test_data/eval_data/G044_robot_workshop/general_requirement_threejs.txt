## 0. 标题、版本与使用说明

- 作品名：《维修机器人车间的生产编排》；版本：mechanics-v3（2026-10-11 完整性修订：吸收 yyy 反馈——P0 三项冻结：①提供不依赖隐藏技巧的有效 witness 布局（10 槽 ≤14、稳态 ≥1 台躯干/12 秒，600 秒 ≥20 台存在 ≥2 倍裕量）与吞吐推演；②冻结合流（≤2 输入向、同刻顺时针优先）、分流格（逐件轮转＋单侧背压）、设备 tick 顺序（行主序）与删除带物料设备（销毁入损耗台账）四条路由规则；③新增局部堵塞诊断（单格 20 秒无移动＋输出侧积压 → 高亮格坐标与原因），全局停止 60 秒恢复手段保持有界可复现；另补世界设定、固定镜头、事件反馈表、音效冻结清单、过场视频与参考图绑定）；运行引擎：**Three.js（WebGL）**——选择理由：网格编排、物流状态可视化与调试 UI 比高保真渲染更重要，Web 交付便于诊断；**启动入口冻结：Three.js 构建为自包含静态 Web 页面，以本地静态服务器在桌面 Chrome/Edge 最新稳定版运行，画布 1920×1080、最低可用 1280×720**；摄像机：固定正交俯视（12×8 网格全境可见，不可旋转/缩放）；输入：鼠标（左键放置/选中、点击带段转向、右键删除）；构建启动：Three.js 工程构建为静态 Web 页面（Vite/ESBuild 打包或单文件 HTML）后按上述入口运行。

## 1. 定位与完整流程 [S01–S06]

- S01 类型：俯视产线编排模拟。不是开放工厂自由建造、不是回合制桌游、不是剧情经营。
- S02 核心循环一句话：下指令排产 → 物流转运 → 监控堵塞 → 调整编排 → 交付结算。
- S03 流程：准备编排（不计时）→ 启运（600 秒计时开始）→ 生产运行（单线启运→双线扩产→瓶颈重构的推进由玩家自由选择）→ 600 秒交付结算。
- S04 最低完整流程：放置/转向/删除指令、物流运转、诊断提示、交付口计数、结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：堵塞用指令重排或「清空下游缓冲」解除（冷却 30 秒）；产线级重置；判负一键重开；Esc 暂停。
- S06 本局耦合边速览：配方系统→物流系统（投入按配方系数转换为产出且守恒）；物流堵塞系统→产能交付系统（阻塞停产使产能归零，解除后恢复）。

## 2. 完整核心循环与阶段 [S07–S12]

完整循环：主菜单 → 准备编排 → 启运 → 生产运行（监控/调整/堵塞处理）→ 600 秒交付结算 → 重开/返回菜单；生产阶段可 Esc 暂停。每阶段六要素如下（引用本 spec §3–§7 对应规则）：

- S07 主菜单
  - input：系统启动，玩家点击「开工」
  - precondition：程序启动完成（C01 可在首次开工前播放）
  - state_change：初始化车间（指令槽 14 空、交付计数 0、损耗台账空）
  - feedback：主菜单界面（F10）
  - next_actions：点击「开工」→ S08
  - outcome：无状态副作用
- S08 准备编排（不计时）
  - input：玩家放置设备与带格、设定配方与转向（I01）
  - precondition：主菜单已完成、C01 播完或跳过
  - state_change：槽位占用按 G05 口径消耗；采矿口与交付口按冻结位置/规则可用
  - feedback：网格预览、槽位计数、合法性提示（F05/F10）
  - next_actions：点击「启运」→ S09（也可不搭建直接启运）
  - outcome：布局为启运初始状态
- S09 生产运行（600 秒计时）
  - input：玩家持续放置/转向/删除；系统按 seed 派生采矿节奏与物流 tick
  - precondition：启运完成
  - state_change：采矿口产料 → 带格转运（合流/分流按 G05 规则）→ 组装台按配方转换 → 交付口入账；堵塞按 G05 诊断与恢复；指令槽增减
  - feedback：物料流动、堵塞高亮、产能曲线、HUD（I06）
  - next_actions：600 秒耗尽 → S10；Esc → S12；红线死锁（不可恢复）→ S10 判负
  - outcome：交付计数与堵塞时长累积为结算依据
- S10 交付结算
  - input：系统结算（600 秒到时或红线死锁）
  - precondition：生产阶段结束
  - state_change：交付口累计 ≥20 台躯干 → V01 判胜；不足 → V02 判负；红线死锁直接判负
  - feedback：C03 结算视频（双意象）＋结算面板（产能曲线/堵塞总时长/损耗台账，F05/F06）
  - next_actions：Enter 重开 → S07；返回菜单 → S07
  - outcome：按 V01/V02 判定并结算
- S11 产线级重置
  - input：玩家点击「重置产线」（暂停菜单或 HUD）
  - precondition：生产阶段进行中
  - state_change：清空全部带段与设备缓冲、保留已放布局、交付计数与计时不回退（冷却 30 秒与「清空下游缓冲」共用）
  - feedback：重置提示与曲线中断标记（F05）
  - next_actions：继续生产
  - outcome：堵塞状态清零、进度保留
- S12 暂停
  - input：玩家按 Esc
  - precondition：处于 S08–S09 阶段
  - state_change：冻结物流模拟与 600 秒计时（G06）
  - feedback：暂停面板（继续/重置产线/重开/返回菜单）
  - next_actions：Esc/继续 → 返回原阶段；重开 → S07
  - outcome：恢复后计时从冻结点连续累计，无漂移

## 3. 数值口径与全局规则 [G01–G06]

- G01 统一刻度：物料按件计、指令按槽计；时间用游戏模拟秒（暂停冻结）。
- G02 车间与节点（本包冻结值）：车间网格 12×8（列 1–12、行 1–8）；节点类型——采矿口（**固定 2 个：M1 (1,2)、M2 (1,6)，输出向固定向东，各产铁屑 1 件/2 秒，不占指令槽**）、传送带（每格 1 槽）、分流格（每格 1 槽，见 G05）、组装台（每台 1 槽）、**交付口（玩家放置、占 1 槽，接收相邻流入的躯干入账）**；组装台输入缓冲 4 件、输出缓冲 2 件。
- G03 三级配方（本包冻结值）：R1 齿轮＝2 铁屑 →1 齿轮（加工 2 秒/件）；R2 轴承＝1 齿轮＋1 铁屑 →1 轴承（3 秒/件）；R3 机器人躯干＝2 轴承＋1 齿轮 →1 躯干（5 秒/件）。
- G04 判定与独立 oracle（本包冻结值）：配方守恒 oracle——投入 10 铁屑经 R1 必然产出恰 5 齿轮、无凭空增减；5 齿轮＋5 铁屑经 R2 必然产出恰 5 轴承；4 轴承＋2 齿轮经 R3 必然产出恰 2 躯干；任何对账偏离即 FAIL。
- G05 指令槽、路由与 witness（本包冻结值，P0 修复）：
  - **指令槽 14**——组装台每台 1 槽、传送带与分流格每格 1 槽、交付口 1 槽；采矿口不占槽；槽满不可再放、删除即回收。
  - **合流**：每带格最多接受 2 个输入向；同一 tick 多件同刻到达时按顺时针优先序（北→东→南→西）取先到者，其余停留原格等待下一 tick。
  - **分流格**：单输入向、2 输出向（直行＋侧向）；物料按「逐件轮转」交替发往两输出向；某输出向下游满载时该侧暂停（物料滞留分流格，容量 2），另一侧继续；两侧均满则整格满载、上游堵塞。
  - **设备接收与输出**：相邻带格/采矿口的物料若为当前配方所需且输入缓冲未满 → 立即吸入（1 件/次），否则物料在边界滞留；加工完成后输出件移入输出向相邻格（带格/分流格/设备/交付口），该格满载则暂存输出缓冲（容量 2），输出缓冲满则暂停加工。
  - **tick 顺序**：全局按行主序结算（行 1→8、行内列 1→12 逐格），每格每 tick 至多移出 1 件。
  - **删除带物料的设备/带格**：其上与缓冲内物料全部销毁并计入「损耗台账」（诊断可查），槽位回收。
  - **witness 布局（10 槽 ≤14，不依赖隐藏技巧）**：G1＝R1 组装台 (2,2)（铁屑来自 M1 东向相邻直供）；S＝分流格 (2,3)（输入北＝G1 南向输出；输出南→R2、东→(3,3)）；R2＝R2 组装台 (2,4)（北入齿轮、南入铁屑——铁屑线＝(2,6) 东向＋(2,5) 北向接自 M2）；T＝R3 组装台 (4,3)（西入齿轮经 (3,3) 东向、南入轴承经 (3,4) 东向＋(4,4) 北向接自 R2 东向输出）；D＝交付口 (5,3)（T 东向相邻）。槽位计数＝设备 4（G1/R2/T/D）＋带格 6（S、(3,3)、(2,6)、(2,5)、(3,4)、(4,4)）＝**10 ≤14**。吞吐推演：瓶颈＝G1 齿轮产能（M1 铁屑 0.5 件/秒 ÷2 铁屑/齿轮 ×3 齿轮/躯干）→ 稳态 ≥1 台躯干/12 秒；计入约 30 秒爬坡后 600 秒内产出 ≥20 台存在 ≥2 倍裕量。**该 witness 需运行可达性验证；若运行复算不可达，应修正规则或阈值，不得在实现阶段放宽。**
  - **失败判定**：时限 **600 秒**内交付 ≥**20 台躯干**判胜；不足判负；全局死锁（全部带段与设备停止 60 秒且「清空下游缓冲/产线重置」冷却中不可用）为红线判负；**局部堵塞诊断**——单格或设备连续 20 秒无物料移动且其输出侧有积压 → HUD 高亮（格坐标＋原因：下游满载/下游需求停止）。
- G06 随机与暂停：fixed_seed=1044 冻结采矿口产出节奏与派发事件；Esc 暂停冻结物流模拟与 600 秒计时，UI 过渡不推进游戏状态；**物流全量 trace 可导出**（每件物料的产生/移动/入设备/出设备/交付/销毁事件与 tick 序号）。

## 4. 操作与输入 [I01–I06]

- I01 键鼠：左键点击网格＋设备钮＝放置（放置时可选配方与输出向）；点击带格/分流格＝转向或切换分流输出向（4 向循环）；右键＝删除回收槽位（物料入损耗台账）；Esc＝暂停；结算界面 Enter＝重开；HUD「重置产线」钮。
- I02 输入语义边界：槽满放置被拒且不消耗；重叠放置被拒；暂停/结算期间输入无效；「清空下游缓冲/产线重置」冷却期内不可用。
- I03 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入；同帧多输入按 §6 各机制声明的顺序结算。
- I04 焦点与点击穿透规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停（G06）。
- I05 无手柄需求；触控为表现层扩展，不进入验收分母。
- I06 UI 必须显示的状态：剩余指令槽（14 上限与已用）、剩余时间（600 秒）、交付口累计躯干数（x/20）、堵塞高亮格坐标与原因、当前产能（台/分钟或最近 60 秒交付数）、损耗台账入口、采矿口节奏提示。

## 5. 车间与内容清单 [L01–L04]

- L01 生成对象：采矿口 2（冻结位置）、传送带格（直通/分流两型）、组装台、交付口、协会订单板 1（C01/W04 结算意象）、三种物料（铁屑/齿轮/轴承）与躯干成品（原创造型）、诊断面板、产能曲线面板。
- L02 关卡（冻结布局）：单间车间 12×8 网格；采矿口固定于左缘 (1,2) 与 (1,6)、输出向东；其余布局由玩家编排（交付口玩家放置）。
- L03 目标物/交互物/场景/UI 对象：本 spec §3–§7 引用的界面元素（菜单/HUD/诊断面板/产能曲线/结算面板）与交互物（网格放置判定、带格转向体、分流配置体、删除回收体）逐类存在且运行时可进入；配方转换与路由由引擎物流状态机驱动，装饰模型不得替代判定；数量与属性以对应 G·M 条目为准。
- L04 冻结需求 vs 实现默认 vs 生成自由度：本 spec 明确写出的数值与数量为冻结需求；未给数值的表现层（装饰造型、配色、粒子参数、音色）为生成自由度，不得评估为缺失；实现默认值必须明确标注且符合核心机制。音效为冻结需求（F06 清单逐条交付，缺失按 FAIL 计）。

## 6. 机制系统 [M01–M04]

- M01 配方与物流（主机制）
  - input：指令编排（放置/转向/删除/配方与输出向设定）
  - precondition：槽位充足、目标格空（放置）
  - state_change：采矿口产料→带格转运（合流/分流按 G05）→组装台按配方转换→交付口入账
  - output：按 G03/G04 转换与守恒
  - observable：物料流水（件数对账、tick 序号）与配方守恒事件；物流 trace 可导出
  - invalid_case：槽满/重叠放置拒绝且不消耗；配方输入不符的物料在设备边界滞留
  - recovery：删除重排；产线级重置清缓冲保留布局与进度
- M02 堵塞诊断
  - input：物流饱和（出口满/缓冲满/下游需求停止，系统）
  - precondition：生产阶段
  - state_change：出口阻塞→上游带段停产→20 秒无移动且输出侧积压 → 高亮（格坐标＋原因）；全局停止 60 秒 → 提供恢复手段
  - output：按 G05 记堵塞时长与诊断
  - observable：堵塞事件（格坐标、原因、起止 tick）与诊断定位事件
  - invalid_case：局部高亮不自动改线（仅提示）；恢复动作仍有界（冷却 30 秒）
  - recovery：重排解除；「清空下游缓冲」；产线级重置；红线死锁判负为最终出路
- M03 有限指令槽
  - input：放置/删除指令
  - precondition：按 G05 槽位口径
  - state_change：槽位占用/回收；槽满限制扩张
  - output：按 G05 槽位语义
  - observable：槽占用状态（14 上限）与拒绝事件
  - invalid_case：槽满放置被拒且不消耗；删除带物料设备销毁入损耗台账
  - recovery：删除即回收槽位
- M04 多解权衡与产能
  - input：编排方案（紧凑单线／冗余双线／witness 布局等）
  - precondition：生产阶段
  - state_change：不同方案产出不同产能曲线与堵塞时长
  - output：按 G05 判定 600 秒 ≥20
  - observable：交付口按秒聚合产能曲线与方案标记（AB_PAIRED 差分）
  - invalid_case：witness 复算不可达时修正规则而非放宽（G05）
  - recovery：方案中途可改（受槽位与冷却约束）

系统耦合边（玩法必需、可复现）：

- E01 from_system=配方系统 → to_system=物流系统；changed_state=组装台按配方系数消耗输入并转换为输出沿带下行（10 铁屑→5 齿轮守恒），上游供料节奏直接决定下游可转换量；验证方式=组装台投入/产出对账流水（state_before/after 物料总量差分=0）。
- E02 from_system=物流堵塞系统 → to_system=产能交付系统；changed_state=出口阻塞使上游停产、交付口产能降为 0，重排或清空缓冲后恢复；验证方式=堵塞/解除事件与产能曲线差分对照。

## 7. 成功、失败与恢复 [V01–V04]

- V01 成功条件：600 秒到时交付口累计 ≥20 台躯干 → 胜利结算（显示产能曲线与堵塞总时长）。
- V02 失败条件：到时不足 20 台 → 失败结算；出现不可恢复死锁（带段与设备停止 60 秒且恢复手段冷却中不可用）为红线判负。
- V03 恢复语义：堵塞可经重排/「清空下游缓冲」（30 秒冷却）解除；产线级重置清空带段与设备缓冲、保留已放布局、交付计数与计时不回退；判负后一键重开全量重置。
- V04 persistent_state：局内（产线布局/物料/交付计数局内保留；重开全量清空）；无跨局持久。
- V04 软锁与不可达处理：不设永久软锁——局部堵塞可诊断、可重排、可有界恢复；红线死锁路径可达且判负结算；结算界面重开为最终恢复出路。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（布局/物料/交付计数/损耗台账）局内保留、重开清空；跨局状态无（M 档：重开全量清空）。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：原创后工业小镇「铆钉湾」——维修机器人是镇上每户的帮手，镇口的老车间接下机器人协会的整备订单，600 秒一班的产能就是车间的口碑。
- W02 场景所在地：铆钉湾维修车间——12×8 网格车间地面、左侧矿料输送墙（两个采矿口）、顶部吊灯与工具墙；窗外是雨后小镇天际线。
- W03 玩家身份与当前任务动机：玩家是车间的新任排产工程师，要在这一班内用有限的 14 个指令槽交付 20 台躯干，保住车间的协会认证。
- W04 失败代价与结局表达：产能不足或红线死锁＝吊灯熄灭、协会徽章收回（C03 失败意象）；达标＝传送带满载躯干列队出库、协会徽章点亮（C03 胜利意象）。
- W05 叙事来源：铁屑/齿轮/轴承＝矿料到成件的三级工艺；躯干＝维修机器人的核心骨架订单；采矿口＝墙上矿料滑槽。全部原创，不用商业作品命名。
- W06 视觉风格与色彩材质：清爽工程网格风；主色＝钢蓝 #4A6B8A、车间灰 #8A9098、安全黄 #E8C84B、警示红 #D9553F；材质为哑光钢、传送带橡胶、矿料颗粒与成品金属。
- W07 环境氛围与声音语言：车间底噪与远处雨声为底；音效语言＝放置/删除、加工步进、完成、堵塞警报、恢复、交付计数（F06 冻结清单）；混音优先级：堵塞警报 ＞ 恢复/交付 ＞ 加工步进 ＞ 车间环境。
- W08 故事表达方式：C01 接单开线交代车间与目标 → 过程中堵塞/扩产/重构反馈承载编排节奏 → C03 结算双意象收束；叙事只做包装不改数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：固定正交俯视，12×8 网格全境可见；镜头不可旋转缩放；1920×1080 下每格与高亮清晰可辨，1280×720 保持可读（I06）。
- F02 关键操作镜头变化：无镜头运动需求（固定机位）；放置/删除时目标格短暂高亮 0.3 秒。
- F03 输入与延迟：点击到网格可见反馈 ≤100 毫秒（桌面 P95，每类输入 ≥30 次采样）；顿帧不改变计时口径。
- F04 环境常驻效果：吊灯微晃、传送带辊轮常动（空载慢转/满载快转）、窗外天际线雨痕、矿料滑槽落料粒子；均为纯表现层。
- F05 事件反馈表（事件 → 画面表现 → 音效 → 结束条件，全部冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 放置设备/带格 | 落位闪光＋槽位计数刷新 | place_part | 闪光收束 |
| 删除设备/带格 | 拆解碎屑＋损耗台账角标＋1 | delete_part | 碎屑收束 |
| 加工步进 | 组装台火花迸溅 | assemble_step | 步进结束 |
| 配方完成 | 成品亮起弹跳 | assemble_complete | 物品离台 |
| 物料入交付口 | 计数滚动＋躯干入库滑轨 | deliver_tick | 动画收束 |
| 局部堵塞高亮 | 目标格红色脉冲＋原因浮标（20 秒判据） | jam_alert | 堵塞解除或保持提示 |
| 恢复指令可用 | 「清空下游缓冲」钮亮起 | recovery_flush | 执行或再次冷却 |
| 产线重置 | 全带段清空闪光＋曲线中断标记 | recovery_flush（重置档） | 重置完成 |
| 红线死锁 | 全屏红框＋判负结算入口 | defeat_sting（死锁档） | 进入判负结算 |
| 达标结算 | C03 胜利意象＋结算面板 | victory_sting | 进入结算面板 |
| 产能不足结算 | C03 失败意象＋结算面板 | defeat_sting | 进入结算面板 |

- F06 关键音效清单（one_shot 9 条＋环境循环 2 条，全部冻结需求）：place_part、delete_part、assemble_step、assemble_complete、deliver_tick、jam_alert、recovery_flush、victory_sting、defeat_sting；环境循环：workshop_amb_loop（车间底噪与远处雨声）、conveyor_hum_loop（传送带运转嗡鸣，随负载音量两档）。无配音需求。
- F07 VFX 信息性与遮挡约束：堵塞高亮、槽位计数、产能曲线为信息类 VFX，必须清晰可辨；火花与碎屑不得遮挡网格放置判定与高亮；非结算单个全屏遮挡 ≤0.5 秒。
- F08 音画同步：放置音与落位闪光同帧；加工步进音与火花同帧；交付音与计数滚动同帧；堵塞警报音与红色脉冲同帧。
- F09 屏幕震动：本作无震动需求（俯视编排固定机位）；表现层自由，不设冻结项。
- F10 前端界面：标题（开工/设置/退出）→ 编排 HUD（I06 全项＋设备钮盘）→ 诊断面板（堵塞列表/损耗台账）→ 产能曲线面板 → 暂停面板（继续/重置产线/重开/返回）→ 结算面板（交付数/产能曲线/堵塞总时长/损耗台账；Enter 重开）；关键状态图标＋文字并用；窗口失焦自动暂停。

## 10. 过场视频 [C01–C03]

- C01 接单开线（Opening，5 秒，1280×720@24fps）
  - 触发时机：首次由标题点击「开工」后、准备编排之前，每局一次
  - 内容与角色场景：铆钉湾雨后清晨、车间吊灯依次亮起、矿料滑槽落料、第一台组装台就位、订单板亮出「20 台躯干」

- C02 扩产与瓶颈事件（Event，5 秒，1280×720@24fps）
  - 触发时机：本局首次发生局部堵塞高亮时插入一次（画中画、不打断操作），每局最多一次
  - 内容与角色场景：传送带物料堆积、红色高亮沿上游蔓延、工程师俯身改线、分流格落位后物料恢复流动

  - 可跳过：Esc/Enter 跳过 → 立即返回生产视角；自然播完 → 自动返回
  - 状态一致：不打断操作；播放期间游戏计时正常推进
- C03 交付结算（Ending，6 秒，1280×720@24fps，双意象共用条目）
  - 触发时机：V01/V02 成立、结算面板出现之前，每局一次
  - 内容与角色场景：胜利意象＝传送带满载躯干列队出库、协会徽章点亮；失败意象＝吊灯熄灭、协会徽章收回、车间归于安静
  - 资产对应：躯干成品、车间与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入对应结算面板；自然播完 → 进入对应结算面板
  - 状态一致：仅在真实 V01/V02 后触发；播放期间不推进任何游戏计时

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：9 个（text-to-3D 7，image-to-3D 2）；object 任务资产为：conveyor_splitter_module, raw_iron_scrap_chips, finished_gear, bearing_ring, robot_torso_chassis, mine_chute_node, assembly_bench_station, delivery_port_station, workshop_order_board。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：assembly_weld。
- video/audio/mechanic/UI：分别为 3/11/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

## 1. 定位与完整流程 [S01–S05]

- S01 类型：3D 第一人称撤离射击，单人单局。能力：步枪射击与部位伤害、搜刮与背包负重、巡逻/精锐守卫 AI、撤离倒计时、深区失压与负重噪声、撤离结算、开场/深区失压/结局视频、射击手感演出层。
- S02 核心循环一句话：搜刮容器 → 管理负重与噪声 → 击退或避开守卫 → 在气闸开启窗口撤离。
- S03 流程：标题 → 进入轨道站（首次进入前播 C01）→ 浅区/实验舱搜刮 → 深区高风险搜刮（首次触发安保警报；首个失压周期播 C04）→ 气闸 240s 开启倒计时 → 撤离交互 → 结算（撤离成功播 C02 / 死亡或超时播 C03）→ 重开或返回。
- S04 最低完整流程：标题、轨道站、撤离成功结算、失败结算、重开全部存在且有真实入口。
- S05 失败恢复入口：死亡/超时结算提供「重开本局」（全量重置）；Esc 暂停可继续/重开/返回标题。

## 2. 完整核心循环与阶段 [S06–S12]

- S06 启动与标题
  - input：系统加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且资源加载完成
  - state_change：进入「标题」；首次开始前按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10
  - next_actions：进入「浅区搜刮」
  - outcome：仓库净值（V04）延续上一局
- S07 浅区与实验舱搜刮
  - input：WASD/LMB/R/E/Tab/X（触发方：玩家）
  - precondition：处于轨道站游玩状态
  - state_change：开箱按 §6 M04 结算物品入包；负重与噪声按 M05 更新
  - feedback：拾取闪光与音效按 §9 F05；背包 HUD 按 I06
  - next_actions：进入深区 →「深区搜刮」；返回撤离区等待 →「撤离阶段」
  - outcome：物品进入背包，超时/死亡不丢弃（V02 例外见后）
- S08 深区搜刮
  - input：同 S07（触发方：玩家）；首次进入触发安保警报（触发方：系统）
  - precondition：首次跨越深区门
  - state_change：全体巡逻守卫移速 +25%；深区失压计时器启动（M07）
  - feedback：警报红光与广播音（F05）
  - next_actions：离开深区 → 失压计时暂停；持续搜刮 → 风险累计
  - outcome：深区收益与风险并存
- S09 撤离阶段
  - input：玩家到达开放撤离点并按 E（触发方：玩家）；倒计时由系统驱动
  - precondition：气闸 240s 开启倒计时归零（HUD 全程显示）或持有门禁卡使用维修井
  - state_change：撤离交互 3s（气闸）/4s（维修井）完成 → V01 胜利；600s 硬上限到 → V02 失败
  - feedback：倒计时最后 10s 紧迫音效（UI/音效/状态数据三处可验证）
  - next_actions：撤离成功 →「胜利结算」；HP0/超时 →「失败结算」
  - outcome：按 V01/V02/V03 结算
- S10 胜利结算
  - input：Enter=重开 / Esc=返回标题（触发方：玩家）
  - precondition：V01 成立
  - state_change：面板出现前按 §10 C02 播撤离成功视频（每局一次）
  - feedback：结算面板显示净值、物品清单、用时
  - next_actions：重开或返回
  - outcome：仓库净值入账（V04）
- S11 失败结算
  - input：Enter=重开 / Esc=返回标题（触发方：玩家）
  - precondition：V02 成立（HP0 或 600s 超时，注明原因）
  - state_change：面板出现前按 §10 C03 播失败视频（每局一次）
  - feedback：失败面板注明「阵亡」或「撤离窗口关闭」；本局物品丢失
  - next_actions：重开本局
  - outcome：仓库净值回退至本局开始前（V03）
- S12 暂停
  - input：Esc（触发方：玩家）
  - precondition：处于游玩状态
  - state_change：暂停覆盖层打开，守卫 AI、失压计时、撤离倒计时全部冻结
  - feedback：暂停面板（继续/重开/返回/设置）
  - next_actions：恢复回到游玩
  - outcome：恢复后状态逐字段一致（G06）；窗口失焦自动暂停

## 3. 数值口径与全局规则 [G01–G08]

- G01 统一刻度：站点为线性三区布局（米制，沿主走廊坐标 s∈[0,240]）；状态变量=玩家 HP/背包占用/武器弹药/失压计时/撤离倒计时/守卫状态/警报等级。
- G02 玩家与武器：玩家 HP100、移速 5.0；步枪弹匣 30/初始备弹 90/射速 6 发每秒/装填 2.0s；守卫死亡掉落弹药 +30 备弹。部位伤：躯干 12、头部 24（×2.0）。
- G03 敌人数值：巡逻守卫 HP60（躯干 5 枪/头 3 枪）、精锐 HP120（10/5）；守卫攻击：巡逻 6 伤害每 0.8s、精锐 10；视锥半角 50°、视距 14m；巡逻移速 3.0/战斗 4.5；曝露 1.0s→锁定→战斗；脱视 8s→回巡逻。
- G04 背包与负重：容量 10 格；tier1/2 占 1 格、tier3 占 2、tier4 占 3；满包拾取无效。负重移速 = max(2.5, 5.0×(1−0.10×tier3 数−0.20×tier4 数))。物品价值：tier1=20、tier2=50、tier3=120、tier4=300；净值=Σ(携带物品价值)。
- G05 容器分布：浅区柜 ×6（70% tier1/30% tier2）、实验舱柜 ×6（60% tier2/40% tier3）、深区柜 ×5（60% tier3/40% tier4）；深区库房固定门禁卡 ×1（必刷）。fixed_seed=1010 冻结容器序列。
- G06 暂停与模拟时间：Esc 暂停冻结守卫/失压/撤离倒计时；失焦自动暂停；结算与视频播放不推进计时；恢复无漂移。
- G07 状态转移 oracle（独立可复核）：初始（弹匣 30/备弹 90）对巡逻守卫头部命中 2 次 → 事件流 `hit(head,24)`×2、守卫 60→36→12→？——预期第三次任意部位命中后 `down`；弹匣 30→28→26…；任何偏离即 FAIL。
- G08 优先级与同帧裁决：撤离交互完成的瞬间与玩家 HP0 同帧 → 判撤离成功优先（先完成撤离）；600s 超时判定在最后一帧动作结算之后执行。

## 4. 操作与输入 [I01–I07]

- I01 键位：WASD=移动；鼠标=视角；LMB=射击（按住连发至弹匣空）；R=装填；E=开箱/撤离交互；Tab=背包（查看/丢弃）；X=丢弃手持位物品；Esc=暂停；Enter=确认/重开。
- I02 输入语义边界：弹药 0 时射击有空仓咔哒反馈且不消耗备弹；备弹 0 时 R 无效；装填中再按 R 无副作用；满包拾取被拒绝并提示；交互被打断（移动/受击）时无副作用。
- I03 键盘+鼠标为完整输入方式。
- I04 输入优先级：暂停/结算阻断玩法输入；同帧多输入顺序=暂停 > 交互 > 装填 > 射击。
- I05 焦点与失焦：点击捕获；失焦自动暂停。
- I06 UI 必显状态：HP、弹匣/备弹、背包占用与负重档、携带净值、撤离倒计时（240s 窗口开启前显示「未开启」）、失压状态、警报等级。
- I07 输入延迟目标：≤100 毫秒。

## 6. 机制系统 [M01–M08]

- M01 射击与部位伤害
  - input：LMB（触发方：玩家）
  - precondition：弹匣 >0；目标在射界内
  - state_change：命中按 G02 结算部位伤害；击杀守卫掉落弹药 +30
  - observable：`fire`/`hit(part,dmg)`/`kill` 事件
  - invalid_case：弹药 0 → 空仓咔哒、不消耗备弹
  - recovery：R 装填 2.0s（可被再次 R 重置为完整 2.0s）
- M02 守卫感知
  - input：系统每帧驱动（触发方：系统）
  - precondition：守卫存活
  - state_change：玩家进入视锥且曝露 1.0s → 锁定进入战斗；脱视 8s → 返回巡逻
  - observable：`spot(g)`/`lose(g)` 事件与守卫状态快照
  - invalid_case：蹲伏不在本测例范围（本档无蹲伏键）
  - recovery：脱离视锥等待衰减
- M03 撤离窗口
  - input：倒计时由系统驱动（触发方：系统）
  - precondition：本局开始
  - state_change：240s 气闸开启（HUD 全程倒计时）；开启瞬间广播 →+2 增援守卫且全体巡逻 +25% 移速
  - observable：`airlock_open` 事件与倒计时状态
  - invalid_case：窗口开启前气闸交互被拒绝
  - recovery：600s 硬上限前撤离点保持可用
- M04 搜刮与背包
  - input：E（触发方：玩家）
  - precondition：贴近容器且未满包
  - state_change：开箱按 G05 序列获得物品、占用背包格；净值更新
  - observable：`open(container, item)` 事件
  - invalid_case：满包拾取被拒绝；交互中断无副作用
  - recovery：Tab/X 丢弃腾格后可继续
- M05 负重与噪声（新增）
  - input：移动（触发方：玩家）
  - precondition：处于游玩状态
  - state_change：脚步噪声半径按负重档位 4m（基础档，占用≤4 格）/6m（5–7 格）/8m（8–10 格）；噪声半径内守卫被吸引前往声源调查
  - observable：`noise(level, pos)` 事件与守卫调查行为
  - invalid_case：静止不产生噪声事件
  - recovery：离开声源后守卫 8s 衰减回巡逻
- M06 负重移速
  - input：移动（触发方：玩家）
  - precondition：背包占用变化
  - state_change：按 G04 公式重算移速（2.5 下限）
  - observable：移速 HUD 与 `speed_change` 事件
  - invalid_case：无
  - recovery：丢弃重物立即重算
- M07 深区失压（新增）
  - input：系统计时（触发方：系统）
  - precondition：首次进入深区后启动
  - state_change：每 60s 失压 10s：期间玩家 HP −2/s、移速 −30%；离开深区暂停计时；每局首次失压开始时按 §10 C04 播放深区失压事件视频（每局一次，播放期间失压与撤离计时冻结）
  - observable：`depressurize(start/end)` 事件与 HUD 警示；C04 播放起止事件
  - invalid_case：浅区不触发
  - recovery：离开深区或等待 10s 结束恢复
- M08 胜负与重开
  - input：撤离交互完成 / HP0 / 600s（触发方：系统判定）
  - precondition：处于游玩状态
  - state_change：V01/V02 判定进入对应结算；同帧按 G08
  - observable：`win(net)`/`lose(reason)` 事件
  - invalid_case：结算后重复判定被拒绝
  - recovery：重开=全量重置（HP/弹药/背包/计时/守卫/警报）

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：到达任一开放撤离点并完成交互（气闸 3s/维修井 4s）→ 撤离成功结算，显示净值、物品清单、用时。
- V02 失败条件：HP0（阵亡，含失压扣血）或 600s 超时（撤离窗口关闭）→ 失败结算并注明原因；本局物品丢失。
- V03 恢复语义：失败后仓库净值回退至本局开始前；重开=全量重置；Esc 暂停可继续。
- V04 persistent_state：仓库净值（历史累计）跨局持久；其余（背包/HP/计时/守卫）重开清空。
- V05 persistent_state 生命周期：动作级即时结算；局内状态局内保留；仓库净值跨局保留且只在 V01 时入账。
- V06 软锁与不可达处理：不设永久软锁——弹药耗尽可靠近撤离点等待窗口；门禁卡必刷保证维修井路线可达；600s 上限兜底结束。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：近未来轨道商业化时代，「环枢七号」研究站因深区一次失败的样品实验与地面失联。
- W02 场景所在地：环枢七号——浅区气闸室、实验舱群、深区库房的三段线性结构；舷窗外地球始终可见。
- W03 玩家身份与当前任务动机：玩家是受雇的回收撤离者，趁 station AI 维护窗口潜入搜刮高价值样件，并在轨道站再入大气层前的撤离窗口离开。
- W04 失败代价与结局表达：失败=阵亡于站内或随站体再入焚毁；结局表达见 §10 C02/C03——逃生舱脱离与地球背景为成功意象，警报红光中的失压走廊为失败意象。
- W05 叙事来源：守卫=站内安保自动化系统在失联后转入的敌对协议；深区危险=样品实验破坏了舱段密封；门禁卡=库房主管的遗留权限。全部原创。
- W06 视觉风格与色彩材质：硬科幻工业风；主色=舷窗蓝 #2E5E8C、舱壁灰 #9AA3AB、警示红 #D64541、核心辉金 #FFC46B、深区紫黑 #1B1626；材质为拉丝金属、聚合物面板、结霜管路。
- W07 环境氛围与声音语言：低鸣空气循环 + 电子提示音；关键声音优先级：撤离倒计时、失压警报、脚步方位必须可辨（见 F07）。
- W08 故事表达方式：开场视频（C01）交代接驳与任务 → 深区失压事件视频（C04）与警报/气闸事件承载过程叙事 → 结局视频（C02/C03）收束；故事只做包装不改数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F06 关键音效清单：枪声、弹壳、命中、爆头、击杀、装填、空仓、翻找、高稀有拾取、脚步（轻/重两档）、失压警报、泄压、广播、滴答；环境循环：空气循环低鸣（常驻，暂停静音）；无配音需求。
- F07 VFX 信息性与遮挡约束：hit marker、倒计时、失压警示为信息性 VFX 必须可辨；环境音不得掩盖脚步方位与倒计时滴答（关键声音优先级：倒计时>警报>脚步>环境）；粒子不遮挡准星。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：10 个（text-to-3D 7，image-to-3D 3）；object 任务资产为：patrol_guard, elite_guard, core_vault_workbench, storage_cabinet, airlock_pod, maintenance_well, orbital_rifle, door_keycard, ammo_pickup, sample_canister。每项只允许一个物体；组合物必须拆成独立任务。
- motion：7 个；覆盖动作：patrol_walk, alert_aim, combat_fire, hit_react, search_scan, heavy_advance, knockdown。
- video/audio/mechanic/UI：分别为 4/15/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

## 0. 标题、版本与使用说明

- 作品名：《风暴岛屿的方块求生》；版本：mechanics-v3（2026-10-11 完整性修订：补日夜循环、风暴预警、安全区重生、世界设定、演出反馈、视频与正向范围清单；难度 S→M 复核升档，理由见 §13）；运行引擎：**Unity 2022.3（URP 渲染管线）**（spec、rubric 与 asset 任务 JSONL 引擎字段保持一致）；输入方式：键盘与鼠标。

## 1. 定位与完整流程 [S01–S06]

- S01 类型：有界体素采集建造求生。本测例包含的能力：六类方块采集与合成、有顶庇护所建造、昼夜循环与风暴预警、篝火求救判定、安全点重生、局内检查点存档、开场/风暴/结算视频。
- S02 核心循环一句话：采集 → 制作工具 → 建造庇护所 → 达成求救条件。
- S03 流程：空降海滩 → 徒手采集原木/石块 → 制作木板与石斧 → 建造有顶庇护所 → 在庇护所内点燃信号篝火 10 秒 → 求救成功结算。
- S04 最低完整流程：可采集方块、合成配方界面、建造放置、求救判定、结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：HP 归零 → 重生于最近安全点（海滩落点或最近庇护所门口，取最近者）并丢失携带栏 50% 物品（放置方块保留）；超时 → 失败结算重开；F5 局内存档（检查点式，见 V04）；Esc 暂停。
- S06 本局耦合边速览：制作系统→采集系统（石斧使采集耗时减半）；建造系统→生存系统（庇护所顶盖使风暴伤害降为 0）。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：启动与标题 → 空降海滩 → 采集与制作 → 建造庇护所 → 篝火求救 → 结算 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且体素地形按 seed=1046 生成完成
  - state_change：进入「标题」状态；首次进入按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10 呈现（任务简报：600 秒内点燃信号篝火）
  - next_actions：进入「空降海滩」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 空降海滩
  - input：WASD 移动、空格跳、左键采集、右键放置、1–9 快捷栏、C 合成、F5 存档、Esc 暂停（触发方：玩家）
  - precondition：地形载入完成；玩家位于海滩落点
  - state_change：进入可操作生存状态；安全点记录＝海滩落点
  - feedback：昼夜与风暴状态按 §9 F05/F04 呈现
  - next_actions：采集资源进入「制作」
  - outcome：世界修改即时落盘（局内）
- S08 采集与制作
  - input：左键采集／C 打开合成（触发方：玩家）
  - precondition：目标方块在可及范围；合成材料满足配方
  - state_change：方块入库存；按配方消耗材料产出成品（守恒 G03）
  - feedback：采集进度环、拾取图标飞入、合成完成弹窗
  - next_actions：攒足材料进入「建造庇护所」
  - outcome：工具/库存状态局内保留
- S09 建造庇护所
  - input：右键放置选中方块（触发方：玩家）
  - precondition：放置目标在世界界内且不与玩家/方块重叠；库存有对应方块
  - state_change：方块写入世界；庇护所判定（G04 几何）即时更新；建成庇护所自动登记为安全点
  - feedback：放置吸附高亮、庇护所成立提示（「庇护所已成形」）
  - next_actions：在庇护所内点燃信号篝火进入「求救」
  - outcome：世界修改与安全点局内保留
- S10 篝火求救
  - input：右键放置并点燃信号篝火（庇护所内）（触发方：玩家）
  - precondition：玩家与篝火均在庇护所判定范围内；篝火材料满足配方
  - state_change：点燃后开始 10 秒持续判定（离开范围中断计数）
  - feedback：篝火火光、烟柱、求救进度条
  - next_actions：10 秒达成 →「结算」（先播 C03）
  - outcome：按 V01 判定
- S11 结算与判负
  - input：Enter＝重开 / Esc＝返回标题（触发方：玩家）；600 秒超时（触发方：系统）
  - precondition：V01 达成（结算）或 V02 达成（判负）
  - state_change：进入「结算/判负」状态；模拟冻结
  - feedback：结算面板显示用时、剩余 HP、死亡次数；判负面板注明「超时未求救」
  - next_actions：重开（全量清空）或返回标题
  - outcome：无跨局写入

## 3. 数值口径与全局规则 [G01–G07]

- G01 统一刻度：世界为 32×32×16 体素界；物品按组计（快捷栏 9 格，每组上限 **99**）；HP 与时间为整数。
- G02 生存数值（本包冻结值，v3 按昼夜分档修订）：HP 100；风暴每 30 秒席卷一次——昼段露天每次 −4 HP、夜段露天每次 **−6 HP**、处于有顶庇护所内为 0；进食浆果 +10 HP（浆果丛可重复采收，每 60 秒刷新）；单局限时 **600 秒**（超时判负）。
- G03 采集与合成（本包冻结值）：徒手采集 2 秒/方块、石斧 1 秒/方块；配方——木板×4←原木×1；石斧×1←木板×2＋燧石×1；信号篝火×1←木板×4＋石块×4。资源守恒 oracle：合成 1 把石斧必消耗 2 木板＋1 燧石且不可重复消耗；数例：采集 3 原木＋1 燧石 → 可合成 12 木板、1 石斧，余 0 原木。
- G04 求救判定（本包冻结值）：庇护所＝以信号篝火为中心 5×5 水平范围内任意实体方块构成顶盖、玩家处于顶盖下方；在庇护所内点燃篝火持续 **10 秒** → 判胜；判定在每次方块变化后即时更新。
- G05 暂停与随机：Esc 暂停冻结风暴、采集、昼夜与倒计时；窗口失焦自动暂停；fixed_seed=1046 冻结岛屿地形与资源分布（同 seed 双跑布置 diff=0）；本作无概率判定。
- G06 日夜循环与风暴预警（本包冻结值）：600 秒内昼夜交替——昼段 150 秒、夜段 150 秒（0–150 昼、150–300 夜、300–450 昼、450–600 夜）；夜段最大自然能见度 12 米（篝火/庇护所内照明范围不受限）、移动速度 ×0.9；每次夜段开始前 **10 秒** HUD 显示「风暴将至」预警（图标＋文字），环境风声渐强；风暴席卷瞬间伴随小幅屏幕震动 0.1 秒。
- G07 安全点重生（本包冻结值）：安全点集合＝海滩落点＋每个已建成庇护所门口；HP 归零后 3 秒重生于**最近**安全点（距离取直线最近），重生保留世界修改与放置方块、丢失携带栏 50% 物品（每组按数量减半向下取整，清单事件可核）；F5 局内存档为检查点，读档回到存档时刻全量状态。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：WASD＝移动；空格＝跳；左键＝采集/攻击；右键＝放置选中方块；1–9＝快捷栏选择；C＝合成界面；F5＝局内存档；F9＝读档；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：材料不足时合成/放置无效；超出世界边界放置无效；快捷栏空格右键无效；暂停/结算期间输入无效。
- I03 无手柄需求。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；合成界面打开时玩法键不串入；同帧多输入按采集→放置顺序结算。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：HP、昼夜图标与时段剩余、风暴预警、快捷栏与物品数、合成界面、倒计时；HUD 对照见 rubric。
- I07 输入延迟目标：移动/采集/放置按键到画面反馈 ≤ 80 毫秒；界面操作 ≤ 100 毫秒。

## 5. 岛屿与内容清单 [L01–L04]

- L01 生成对象：六类方块（原木/石块/木板/叶片/燧石/浆果丛）、石斧 1 种工具、3 条配方、信号篝火 1、重生海滩落点 1、庇护所门口安全点（动态）；生物与非冻结装饰不做。
- L02 岛屿：32×32×16 有界体素世界（海滩、林地、岩区），地形与资源分布由 seed=1046 冻结；四周边界不可放置/采集。
- L03 目标物/交互物/场景/UI 对象：本 spec §3–§9 引用的界面元素（标题/HUD/合成/结算/判负/暂停/视频播放层）与交互物逐类存在且运行时可进入；数量与属性以 L01/L02 与 G 系为准。
- L04 冻结需求 vs 实现默认 vs 生成自由度：本 spec 明确写出的数值与数量为冻结需求；§9 未冻结的装饰造型与配色为生成自由度，不得评估为缺失；实现默认值必须明确标注且符合核心机制。

## 6. 机制系统 [M01–M05]

- M01 采集与放置（主机制）
  - input：左键采集／右键放置
  - precondition：目标方块在可及范围内（放置格不与玩家碰撞体重叠、在世界界内）
  - state_change：方块从世界移入库存（耗时按工具效率：徒手 2 秒/石斧 1 秒）；放置消耗库存并写入世界；放置后庇护所判定即时重算
  - observable：方块增减事件（含类型与坐标）与库存流水
  - invalid_case：边界外放置、重叠放置、库存空放置 → 拒绝且无副作用
  - recovery：F9 读档或死亡重生恢复
- M02 合成配方
  - input：C 界面点击配方
  - precondition：材料满足配方且库存可容纳成品
  - state_change：按 G03 配方消耗材料产出成品（资源守恒，不可重复消耗）
  - observable：合成事件（材料/成品数量对照）
  - invalid_case：材料不足拒绝且不部分消耗
  - recovery：补齐材料重试
- M03 昼夜与庇护所防护
  - input：昼夜计时（系统）／建造放置（玩家）
  - precondition：处于游玩状态
  - state_change：按 G06 切换昼夜（能见度/移速/伤害分档）；风暴每次判定玩家露天或庇护所内 → 伤害按 G02 昼夜分档（昼 −4/夜 −6/庇护 0）；庇护所判定按 G04 几何规则即时更新
  - observable：`storm_tick` 事件（含时段、伤害字段、玩家位置状态）、昼夜切换事件
  - invalid_case：庇护所破坏后顶盖不满足 → 重新判定为露天
  - recovery：补建顶盖即恢复防护
- M04 求救与安全点重生
  - input：篝火点燃（庇护所内）／HP 归零（系统）
  - precondition：篝火点燃需材料与位置满足 G04；重生需 HP 归零
  - state_change：持续 10 秒 → 判胜结算；死亡 → 3 秒后重生于最近安全点、丢失携带栏 50% 物品
  - observable：`beacon_lit`/`win` 事件、`death`/`respawn` 事件（含丢失物品清单与安全点 ID）
  - invalid_case：篝火中断（离开范围/顶盖破坏）计数作废重计
  - recovery：重生后流程可继续
- M05 检查点存档
  - input：F5 存档／F9 读档
  - precondition：处于游玩状态
  - state_change：存档保存世界体素、库存、HP、昼夜与安全点全量状态；读档恢复
  - observable：存读档前后快照 diff=0
  - invalid_case：无存档时 F9 无效
  - recovery：读档即恢复

系统耦合边（玩法必需、可复现）：

- E01 from_system=制作系统 → to_system=采集系统；changed_state=合成石斧后同种方块采集耗时 2 秒→1 秒（效率状态传递）；验证方式=同方块徒手/持斧各采一次的耗时流水（state_before/after）。
- E02 from_system=建造系统 → to_system=生存系统；changed_state=建成 5×5 顶盖庇护所后风暴判定伤害由 −4/−6（昼夜）→0（防护状态传递，求救判定的前提）；验证方式=露天/顶盖下两态 storm_tick 伤害对照。

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：在庇护所内点燃信号篝火持续 10 秒 → 求救成功结算（显示用时、剩余 HP、死亡次数）。
- V02 失败条件：600 秒超时判负；HP 归零非终局（进入安全点重生流程），死亡不限次数。
- V03 恢复语义：死亡重生于最近安全点（G07），保留世界修改与放置方块、丢失携带栏 50% 物品；F5/F9 局内检查点存读档；失败结算一键重开。
- V04 persistent_state：无（重开全量清空；世界修改、安全点与存档均为局内检查点语义，见 §1 与种子卡差异）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（世界/库存/昼夜）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设永久软锁——资源可重复采集、死亡重生不删进度、关键目标均可正常操作达成；判定不可达时按 V02 失败语义结算。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：现代近海航运时代；货轮「灰鸥号」在风暴季失事，幸存者漂流到无人小岛「灰鸥岛」，必须在风暴季的窗口期内发出求救信号。
- W02 场景所在地：灰鸥岛——南部海滩（落点）、中部林地（原木/浆果）、北部岩区（石块/燧石），全岛受周期性风暴带影响。
- W03 玩家身份与当前任务：玩家是灰鸥号幸存船员；当前任务：采集、制作、搭建有顶庇护所，并在庇护所内点燃信号篝火坚持 10 秒，引来救援船。
- W04 失败代价与结局表达：超时＝风暴季窗口关闭、救援无望（判负文案）；HP 归零＝短暂昏迷后于安全点苏醒（非终局）；成功则 C03 呈现救援船破浪而来的场面。
- W05 叙事来源：六类方块＝岛上可利用的自然资源；石斧＝船舱工具箱遗失后的手工替代品；信号篝火＝船员求生的最后手段；庇护所＝抵御风暴带的必要工事。全部原创。
- W06 视觉风格与色彩材质：风格化卡通体素；主色＝海雾蓝绿（#5E8C7A 系）＋风暴雨灰（#6B7280 系）＋篝火暖橙（#E8935A 系）；材质以哑光木纹、粗岩、叶片为主，昼夜光照差异明显。
- W07 环境氛围与声音语言：风暴带海岛——昼段海鸟与浪声、夜段风声渐强；音效语言为「方块碎裂＋放置闷响＋风暴呼啸＋篝火噼啪」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代海难与落岛 → 风暴视频（C02）在首场夜段风暴前强化威胁 → 结算视频（C03）收束；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：第一人称；鼠标偏航 ±180°、俯仰 ±85°；无镜头自动回正；摄像机边界＝体素世界外墙；死亡与读档后镜头回安全点/存档点冻结朝向。
- F02 关键操作镜头变化：风暴席卷瞬间小幅震动 0.1 秒；夜段进入时镜头轻微下沉变冷色；被雷击照亮瞬间短暂曝光提升；无慢动作。
- F03 输入与延迟：见 I07。
- F04 环境常驻效果：昼段海面反光与云影流动；夜段风线粒子与远处闪电（低频率，仅表现）；篝火火光与烟柱常驻；庇护所内暖光。
- F05 事件反馈表（事件 → 表现 → 结束条件，全部为冻结需求）：

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：2 个（text-to-3D 1，image-to-3D 1）；object 任务资产为：stone_axe, signal_bonfire。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：bonfire_ignite。
- video/audio/mechanic/UI：分别为 3/10/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

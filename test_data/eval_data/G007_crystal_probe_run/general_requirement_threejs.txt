## 0. 标题、版本与使用说明

- 作品名：《微观晶体中的探测艇》；版本：mechanics-v3（2026-10-11 完整性修订：新增低速精确模式与 graze→清屏补充联动两机制、世界设定 W01–W08、演出反馈 F01–F10、开场/累计奖励/结算视频 C01–C03、正向范围清单 N01–N06、参考图绑定 A01–A02；并修正旧版 oracle ②「4 像素命中」与 ≤2 命中阈值自相矛盾的数例，改为 1 像素命中＋3 像素擦弹边界例，命中 ≤2 / 擦弹 ≤8 阈值本身不变）。
- 运行引擎：**Three.js（WebGL）**（本 spec、rubric 与 asset 任务 JSONL 中的 mechanic/ui/pipeline 任务引擎字段保持一致，引擎唯一冻结）。选择理由：GPU 粒子与自定义渲染适合高密度弹幕、擦弹火花、清屏冲击波等 VFX 需求；3D 模型（探测艇、晶柱、晶脉节点）与 2D 逻辑判定混排的纵版卷轴以正交相机实现成熟，GLB 导入链路稳定（射击与动作逻辑保持轻量，不扩展联机与高密度 VFX）。平台：桌面浏览器（Chrome/Edge 最新稳定版），1280×720 画布（可全屏）。摄像机：主相机为正交相机、固定不跟随（见 §9 F01），3D 场景件沿 Z 轴分层形成视差。输入：键盘（见 §4）。构建启动方式：Three.js 工程构建为静态 Web 页面（Vite/ESBuild 打包或单文件 HTML）→ 本地静态服务器或直接打开 index.html 运行进入标题；验证要求：构建产物须在目标平台复测 §4 I07 输入延迟（≤50ms）与 fixed_seed 复现（G02/G09），3D 资产导入检查按 rubric §六执行。
- 原创边界：本作全部名称、机体、弹幕、场景、文案与美术必须原创，不使用任何商业作品的名称、机体或造型（探测艇「尘针号」、星髓晶、谐振脉冲均为本测例原创词）。
- 规则优先级：本文件全局数值与规则 ＞ 机制章节 ＞ 谱面实例 ＞ 生成器自由补充；未指定数值可作为明确标注的配置默认值，不得伪装成本文既定要求。
- 本文件用于游戏生成模型，目标是输出可操作的纵版固定弹幕躲避游戏；文档存在不等于玩法完成，静态页面、类名或演示视频不能单独证明可玩。谱面为确定性时间轴（G02），任何任务关键目标均可通过正常操作达成，无随机失败导致的永久删除。

## 1. 定位与完整流程 [S01–S05]

- S01 类型：2D 纵版固定弹幕射击（纯躲避计分题），单人单屏。本测例包含的能力：90 秒单谱面三模式弹幕、擦弹计分、低速精确模式（判定点与擦弹范围显示）、清屏资源管理（初始 2 次＋graze 累计补充、存量上限 3 次）、开场/累计奖励/结算视频、微观晶体内部主题表现层。
- S02 核心循环一句话：移动微操（常速/低速切换）→ 贴弹擦弹 → 计分与清屏资源补充 → 存活推进 → 结算。
- S03 流程：标题界面 → 开场视频 C01 → 谱面开始（90 秒）→ 三模式弹幕循环推进 → 存活至终点 → 胜利结算（C02）→ 重开；生命耗尽 → 失败结算 → 重开。
- S04 最低完整流程：标题、可操作躲避、计分 HUD、胜利结算、失败结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：生命 3 耗尽 → 失败结算一键重开（全量重置，见 V03）；谱面中任意时刻 Esc 暂停并可选择重开。

## 2. 完整核心循环与阶段 [S06–S12]

完整循环：启动与标题 → 谱面开始 → 弹幕循环推进 → 存活至终点与胜利结算 → 失败结算 → 暂停 → 重开。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter 或点击「开始」
  - precondition：构建可启动且资源加载完成（rubric D3 断言）
  - state_change：游戏进入「标题」状态
  - feedback：标题界面按 §9 F10 呈现（开始/设置/退出、引擎版本号）
  - next_actions：进入「谱面开始」
  - outcome：无跨局状态写入（见 V04）
- S07 谱面开始
  - input：玩家确认开始（触发方：玩家）；系统触发开场视频 C01（触发方：系统）
  - precondition：标题界面就绪且玩家已选择开始
  - state_change：先播 C01（每次由标题进入谱面一次，见 §10）；播放完成或跳过后进入「谱面进行」初始状态——探测艇位于 (640,648)、生命 3、清屏资源 2、graze 计数 0、graze 累计 0、得分 0、谱面计时 0
  - feedback：C01 按 §10 呈现；随后 HUD 按 I06 七项就绪（§9 F10）
  - next_actions：进入「弹幕循环推进」
  - outcome：谱面计时从 0 开始推进；初始状态与 G01 冻结值一致
- S08 弹幕循环推进（核心阶段）
  - input：系统按谱面时间轴（seed 冻结，G02）生成并推进弹幕（触发方：系统）；玩家按 §4 I01 输入方向/Shift/B（触发方：玩家）
  - precondition：处于谱面进行状态且非暂停/结算
  - state_change：按 §6 M01–M06 结算——弹幕生成与移动、擦弹计分与累计、清屏消耗与 graze 补充转换、低速切换、命中与重生、谱面计时推进
  - feedback：按 §9 F05/F06 逐事件呈现（擦弹火花＋擦擦音、低速切换、命中闪白＋碎裂音、清屏冲击波＋轰鸣＋震屏等）
  - next_actions：存活至 90 秒 →「胜利结算」；生命归零 →「失败结算」；Esc →「暂停」
  - outcome：局内状态演进；无跨局写入（见 V04）；胜负同帧裁决按 G10
- S09 存活至终点与胜利结算
  - input：系统在谱面计时到达 90.0 秒时触发（触发方：系统）；玩家 Enter 确认后续操作
  - precondition：V01 成立（存活至 90 秒且生命未归零；同帧裁决按 G10 判负优先）
  - state_change：先播 C02（每局一次），随后进入「胜利结算」面板；弹幕与计时冻结
  - feedback：F05 胜利行；结算面板显示总分＝1000＋Σgraze、graze 计数、用时
  - next_actions：重开（全量重置）/ 返回标题
  - outcome：无跨局写入（见 V04）
- S10 失败结算
  - input：系统在生命归零时触发（触发方：系统）；玩家 Enter 重开
  - precondition：V02 成立（生命 3 耗尽）
  - state_change：进入「失败结算」状态；画面定格、弹幕冻结
  - feedback：F05 失败行；失败面板注明原因「能量护层耗尽」并给一键重开入口
  - next_actions：一键重开（V03 全量重置后直接进入谱面，不重播 C01）
  - outcome：本局状态清空，无跨局副作用
- S11 暂停
  - input：玩家按 Esc；窗口失焦时系统自动触发（触发方：玩家/系统）
  - precondition：处于谱面进行状态
  - state_change：暂停覆盖层打开；玩法输入、弹幕推进、谱面计时全部冻结（G08）
  - feedback：暂停面板（继续/重开/返回标题/设置，含镜头震动开关）
  - next_actions：Esc 或「继续」→ 回到谱面进行
  - outcome：恢复后逐帧状态与暂停前一致（G08 无漂移）
- S12 重开
  - input：玩家在结算或暂停面板选择重开（Enter/按钮）
  - precondition：处于胜利结算、失败结算或暂停状态
  - state_change：按 V03 全量重置（生命 3、清屏 2、graze 计数/累计、得分、谱面时间轴、艇位）后直接进入谱面进行
  - feedback：HUD 各项回到初始值；谱面按 seed 复现（G02/G09）
  - next_actions：进入「弹幕循环推进」
  - outcome：旧局数据全部清空、不串入新局（rubric D3 恢复断言）

## 3. 数值口径与全局规则 [G01–G10]

- G01 统一刻度与速度基准：逻辑分辨率 1280×720（逻辑像素），原点 (0,0) 位于左上，x 向右、y 向下。判定点＝探测艇碰撞核心，中心与艇体模型原点重合，半径 2 逻辑像素；命中判定＝弹心与判定点中心距离 ≤2 逻辑像素；擦弹窗口＝2 < 距离 ≤8 逻辑像素。探测艇常速 300 逻辑像素/秒、低速精确模式 150 逻辑像素/秒（减半）；移动无惯性（松键同帧停住，G07）。艇体可移动范围 x∈[16,1264]、y∈[64,688]（顶部 64 逻辑像素为 HUD 安全区）。初始位与重生位均为 (640,648)。分数、生命、清屏资源、graze 计数均为整数。
- G02 弹幕三模式与谱面时间轴（本包冻结值）：模式 A「晶环扩散」——每 1.2 秒自屏幕上方三点发环形 12 弹（10 秒段）；模式 B「棱线直射」——五列等速直线弹流（10 秒段）；模式 C「螺旋晶列」——双旋臂旋转弹（10 秒段）；三段按 A→B→C 循环三轮覆盖 90 秒（精确时间轴与生成参数见 §5 L02）。弹幕序列由 fixed_seed=1007 冻结：谱面生成参数为确定性公式，实现中的一切随机扰动（微抖动、装饰散布）必须由该 seed 驱动；同 seed 双跑弹幕状态逐帧 diff=0。
- G03 擦弹计分（本包冻结值）：每颗弹首次进入擦弹窗口 → graze +10 分（同一弹不重复计）；贴弹高风险高收益。HUD 得分＝局内累计分（初始 0，每 graze +10）；胜利结算总分＝存活基础 1000 ＋ Σgraze。
- G04 生命与清屏消耗（本包冻结值）：生命 3；判定点命中 → −1 生命＋重生（回 (640,648)）＋2 秒重生无敌；清屏资源初始 2 次，B 键消耗 1 次：清空全屏现存弹并给予 2 秒无敌；生命耗尽判负。清屏时弹幕消散为分数粒属表现层（F05），不改变 G03 结算公式。
- G05 graze→清屏补充联动（v3 新增冻结值）：graze 累计量（graze_meter）随每次 graze 事件 +10 同步累计；转换条件＝graze_meter ≥ 500 且清屏资源存量 < 3，满足即执行转换：graze_meter −500、清屏资源 +1，同帧重复判定直至条件不满足；存量上限 3——达到上限时转换暂停，graze_meter 继续累计不丢失，待存量因 B 消耗下降后同帧立即按同一规则补转换。转换来源仅限 graze 事件（存活基础分 1000 与其他加分不累计 meter）。
- G06 低速精确模式（v3 新增冻结值）：按住 Shift → 探测艇移速即时由 300 减半为 150 逻辑像素/秒（同帧生效、无过渡插值延迟），并同时显示判定点（2px 白点＋外圈）与擦弹范围（8px 青色圆环）；松开 Shift 即时恢复常速并隐藏上述显示。低速模式只改移速与显示，不改变命中/擦弹阈值与任何计分规则。
- G07 操作手感与输入延迟（v3 新增冻结值）：移动无惯性（按键起步与松键停住均即时，无加速/滑行曲线）；按键到对应画面反馈 ≤50 毫秒（弹幕躲避题按格斗/音游档）；低速切换即时（Shift 按下/松开当帧生效）；清屏即时生效（B 按下当帧结算，无前摇）。擦弹时连续「擦擦」扫描音与得分数字跳动；被弹时短暂全屏闪白＋碎裂音；清屏时震屏＋弹幕消散成分数粒（表现细节冻结于 §9 F05/F06/F09）。
- G08 暂停、失焦与模拟时间口径：Esc 暂停冻结弹幕推进、谱面计时与全部玩法输入；窗口失焦自动暂停；暂停、结算、视频播放期间不推进任何游戏计时；UI 过渡不触发玩法逻辑；恢复后逐帧状态与暂停前一致（无漂移）。
- G09 状态转移 oracle（独立可复核，任何偏离即 FAIL）：
  - ①擦弹边：弹心与判定点中心距离 6 像素（2 < 6 ≤ 8）掠过 → 产生 graze 事件（+10 分、graze_meter +10），无生命变化、弹道不变。
  - ②擦弹内边：距离 3 像素（2 < 3 ≤ 8）掠过 → 同样 graze +10 且不受伤。
  - ③命中边：距离 1 像素（≤2 命中判定）→ −1 生命、该弹不产生 graze、重生回 (640,648) 并 2 秒无敌。（v3 修正：旧版「距离 4 像素命中」与 ≤2 阈值矛盾，按阈值一致化改写。）
  - ④资源联动 oracle（写死）：graze 累计 500 → 清屏次数 +1，上限 3。开局清屏 2：graze_meter 达 500 → 存量 3、meter 归 0；继续累计至 500 时存量已为 3 → 不转换、meter 保留 500 待发；按 B 消耗 3→2 → 同帧补转换 2→3、meter 500→0。
  - ⑤复现：同 seed=1007 双跑至 30 秒处导出弹幕快照 → 逐帧 diff=0。
- G10 优先级与同帧裁决（v3 新增冻结值）：同帧多事件按固定顺序结算——①清屏消耗（B）先行：清屏帧上被消散的弹不再参与命中判定；②命中判定（≤2）；③graze 事件与 G05 转换（消耗后的同帧补转换在此步结算）；④终点与生命结算：谱面计时到达 90.0 秒与生命归零同帧同时成立时，判负优先（命中侧优先）。暂停与结算状态阻断全部玩法输入（I04）。

## 4. 操作与输入 [I01–I07]

- I01 键位：方向键或 WASD＝八向移动；Shift（按住）＝低速精确模式；B＝清屏（消耗 1 次资源）；Esc＝暂停/关闭面板；Enter＝确认、结算界面重开。
- I02 输入语义边界：清屏资源为 0 时按 B → 无效（无状态变化、无清屏特效，仅播放短促否定音 F05）；重生无敌期间判定点命中无效（擦弹窗口照常累计）；暂停/结算/视频播放期间玩法键一律无效且无副作用。
- I03 键盘为完整输入方式：本作全部玩法与界面操作均可仅用键盘完成。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入；同帧多输入按 §3 G10 固定顺序结算（清屏→命中→graze/转换→终点结算）。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停（与 §3 G08 口径一致，不依赖暂停键）。
- I06 UI 必须显示的状态（HUD 七项，对照 rubric）：得分（局内累计分）、graze 计数、graze→清屏累计进度（0–500 进度条）、清屏资源余量（图标＋数字）、生命（图标＋数字）、谱面进度（剩余秒数或 0–90 进度条）、低速模式指示（当前移速状态）。
- I07 输入延迟目标：按键到对应画面反馈（移动/低速切换/清屏/否定反馈）≤ 50 毫秒（G07）；设置界面须显示当前帧率，便于延迟复核。

## 5. 谱面与内容清单 [L01–L04]

- L01 生成对象：探测艇「尘针号」1（玩家机体，判定点可视；3D 模型按参考图生成、程序化刚体动画——倾侧与推进光点，骨骼动画非冻结需求）、三模式弹幕若干（A 环形 12 弹蓝白 / B 直线弹能量青 / C 螺旋弹晶紫，三模式弹体视觉可区分）、悬浮晶柱若干与晶脉脉冲节点（晶体内部背景件，3D 模型）、HUD（I06 七项）、VFX 件（擦弹火花、清屏冲击波、判定点受击闪烁、全屏闪白层、消散分数粒）、晶体内部环境共鸣场景（3D 场景资产，参考图绑定见 §12 A02）。
- L02 谱面数据（90 秒单卷轴谱面；时间 t 以谱面开始为 0，单位秒；弹速单位为逻辑像素/秒；生成参数为确定性公式，随机扰动仅可由 fixed_seed=1007 驱动）：

```text
段循环（三轮）：A[0,10) → B[10,20) → C[20,30) → A[30,40) → B[40,50) → C[50,60) → A[60,70) → B[70,80) → C[80,90]
模式 A「晶环扩散」：段内每 1.2 秒自屏幕上方三点 (320,-20)/(640,-20)/(960,-20) 同时发出环形 12 弹；弹速 120；弹体视觉直径 10。
模式 B「棱线直射」：段内每 0.4 秒五列 (128,-20)/(384,-20)/(640,-20)/(896,-20)/(1152,-20) 各发 1 直线弹；弹速 200；弹体视觉直径 8。
模式 C「螺旋晶列」：双旋臂自 (640,-20) 发射，每 0.15 秒每臂 1 弹、两臂相位差 180°；发射角自 90°（竖直向下）起每发累计旋转 +6°；弹速 160；弹体视觉直径 8。
出屏判定：弹心 y > 740 或 x ∉ [-40,1320] 即回收。
```

- L03 目标物/交互物/场景/UI 对象：本 spec §3–§9 引用的界面元素（标题/HUD/胜利结算/失败结算/暂停面板、视频播放层）与交互物（探测艇、判定点/擦弹范围显示、清屏触发、弹幕）逐类存在且运行时可进入；数量与属性以对应 G·M 条目为准。
- L04 冻结需求 vs 实现默认 vs 生成自由度：本 spec 明确写出的数值与数量为冻结需求（判定/擦弹阈值、速度、三模式参数、资源数值、视频与 F05/F06 演出清单）；§9 F04 之外的装饰造型、配色细节、粒子参数与音色选择为生成自由度，不得评估为缺失；实现默认值必须明确标注且符合核心机制。

## 6. 机制系统 [M01–M06]

- M01 固定弹幕三模式（主机制）
  - input：谱面时间轴（触发方：系统，seed 冻结）
  - precondition：处于谱面进行状态（非暂停/结算/视频）
  - state_change：按 G02/L02 三模式段循环生成弹幕并逐帧推进弹位
  - observable：逐帧弹幕状态快照；同 seed 双跑 diff=0（G09 ⑤）
  - invalid_case：暂停/结算/视频期间不生成不推进；出屏弹回收、不产生 graze 或命中
  - recovery：谱面时间轴与弹幕状态在重开后按 seed 完整复现（V03）
- M02 擦弹计分
  - input：弹心进入 2 < 距离 ≤8 的擦弹窗口（触发方：系统）
  - precondition：该弹本局内尚未计入 graze；处于谱面进行状态
  - state_change：graze +10 分（HUD 得分与 graze 计数 +1）；graze_meter +10（G05）；不改变弹道、不影响生命
  - observable：graze 事件（含弹 ID 与距离）、得分流水、擦弹火花与「擦擦」音（F05）
  - invalid_case：已计过的弹再次进入窗口不重复计；命中弹（≤2）不产生 graze；暂停期间不判定
  - recovery：无失败态；重开全量清零
- M03 清屏消耗与生命
  - input：B 键清屏（触发方：玩家）；判定点命中（触发方：系统）
  - precondition：清屏需资源存量 ≥1；命中需处于非无敌且距离 ≤2
  - state_change：清屏 → 清空全屏现存弹、资源 −1、2 秒无敌；命中 → −1 生命、重生回 (640,648)、2 秒无敌
  - observable：clear / life_lost 事件、资源与生命流水、清屏冲击波或闪白反馈（F05）
  - invalid_case：资源为 0 时 B 无副作用（仅否定音）；无敌期命中无效；暂停/结算期间 B 与移动无效
  - recovery：生命耗尽走 V02 失败结算；清屏无失败态
- M04 graze→清屏补充联动（v3 新增）
  - input：graze 事件累计触发转换（触发方：系统）
  - precondition：graze_meter ≥ 500 且清屏资源存量 < 3（G05）
  - state_change：graze_meter −500、清屏资源 +1，同帧重复判定直至条件不满足；存量达 3 时转换暂停、meter 继续累计；B 消耗使存量下降的同一帧立即执行待发转换；每局首次转换达成时按 §10 C03 播放累计奖励视频（每局一次，播放期间弹幕与谱面计时冻结）
  - observable：clear_charge_gained 事件（含转换后存量）、HUD 清屏余量 +1 闪光、graze 进度条回卷、C03 播放起止事件
  - invalid_case：非 graze 来源（存活基础 1000）不累计 meter；meter < 500 或存量已满 3 时不转换且无事件
  - recovery：无失败态；重开后 meter=0、资源回到初始 2
- M05 低速精确模式（v3 新增）
  - input：按住 / 松开 Shift（触发方：玩家）
  - precondition：处于谱面进行状态
  - state_change：按下当帧移速 300→150、显示判定点（2px 白点＋外圈）与擦弹范围（8px 青环）；松开当帧恢复常速并隐藏显示；阈值与计分规则不变（G06）
  - observable：focus_mode 事件（开/关）、HUD 低速指示、画面判定点与擦弹环显示
  - invalid_case：暂停/结算/视频期间 Shift 无玩法副作用；松开状态再松开无事件
  - recovery：重开后回到常速、隐藏显示
- M06 谱面推进与终点判定
  - input：模拟时钟推进（触发方：系统）
  - precondition：处于谱面进行状态且非暂停
  - state_change：谱面计时按真实模拟时间推进至 90.0 秒 → 触发终点判定（V01，同帧裁决按 G10）
  - observable：谱面进度（HUD）、survive 事件
  - invalid_case：暂停/结算/视频期间计时冻结；无超时失败态（谱面即总时长）
  - recovery：重开后计时归零并按 seed 复现

## 7. 成功、失败与恢复 [V01–V06]

- V01 成功条件：存活至 90 秒谱面终点（计时到达 90.0 秒且生命未归零；同帧与生命归零冲突时按 G10 判负优先）→ 胜利结算，先播 C02，面板显示总分＝1000＋Σgraze、graze 计数与用时。
- V02 失败条件：生命 3 耗尽 → 失败结算；无超时失败态（谱面即总时长）；与终点同帧按 G10 裁决。
- V03 恢复语义：失败结算一键重开；生命（3）、清屏资源（2）、graze 计数与累计（0/0）、得分、谱面时间轴与艇位全量重置；同 seed 整局可复现（G09 ⑤）。快速重开直接进入谱面、不重播 C01。
- V04 persistent_state：无（重开全量清空；无跨局解锁、无收集品、无排行）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（得分/graze/资源/生命/计时）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：无永久软锁——谱面为固定时间轴，任何时刻均可通过移动、低速、清屏继续操作或主动暂停重开；判定不可达时按 V02 失败语义结算而非无限等待；结算界面重开为最终恢复出路。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：22 世纪中叶的深空勘探时代；勘探署在陨石带发现具有异常储能特性的巨晶「星髓晶」，为弄清其内部能量结构，启动「微缩穿刺」勘测计划。
- W02 场景所在地：一块篮球场大小的星髓晶内部——晶格穹顶、悬浮晶柱、发光晶脉构成幽深的晶洞；晶体内部能量以游离的「能量珠」形式周期性脉涌，即玩家看到的弹幕；90 秒对应一次完整脉动周期，周期结束时撤离窗口开启。
- W03 玩家身份与当前任务动机：玩家驾驶微缩探测艇「尘针号」执行穿刺勘测：在一个完整脉动周期内贴近能量珠采集脉动数据（擦弹＝近距离高分辨率扫描，越近数据越值钱），在能量珠威胁艇体时释放艇载「谐振脉冲」（清屏）驱散周围能量珠，并活着等到撤离窗口开启。
- W04 失败代价与结局表达：失败＝探测艇能量护层（生命 3）耗尽、艇体在晶体内失联（失败结算画面定格）；胜利＝脉动周期结束、撤离窗口开启，「尘针号」带着采集数据驶出晶体（C02 结算视频）。
- W05 叙事来源：能量珠＝晶脉周期性脉涌的游离能量（因此持续涌来且模式随脉动相位切换）；擦弹计分＝贴近扫描获得高分辨率数据；清屏＝艇载谐振脉冲装置的一次性驱散（因此是有限资源）；低速精确模式＝关闭主推进焰、仅用姿控微喷换取扫描精度（因此显示判定点与扫描范围）；晶柱与晶脉节点＝晶洞的构造件。全部原创，不使用任何商业作品的命名或造型。
- W06 视觉风格与色彩材质：微观尺度下的晶洞壮丽感；主色＝深蓝紫底（#1B1E3C 系）＋晶蓝（#4A5FD9 系）＋能量青（#9BE8FF 系）＋数据金（#F2C14E 系）；探测艇为白色哑光合金＋金色描线；三模式弹体可区分：A 环形弹蓝白（#CFE3FF）、B 直线弹能量青（#9BE8FF）、C 螺旋弹晶紫（#B48CFF）；擦弹火花金色、清屏冲击波青白（#DFF6FF）、判定点受击闪烁红白（#FF5A5A）。
- W07 环境氛围与声音语言：晶体内部低频共鸣环境声（常驻循环）、能量珠掠过艇体的连续「擦擦」扫描声、护层碎裂音、谐振脉冲轰鸣；整体氛围「幽深的微观壮丽＋贴弹的紧张收益感」；全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频 C01（微缩穿入晶体内部）交代任务 → 累计奖励视频 C03 与局内 HUD/F05 事件反馈承载过程叙事（数据采集进度与资源状态）→ 结算视频 C02 收束；故事只做包装与节奏，不改变任何机制数值。

- F01 视角与镜头：主相机为固定正交相机（Orthographic），1280×720 游玩区全部可见，无跟随、无平移；背景 3D 场景件（晶柱、晶脉）沿 Z 轴分层布置形成视差，相机静止；镜头边界＝游玩区外接矩形；FOV 不适用（正交）。

## 10. 过场视频 [C01–C03]

- C01 缩穿晶壁（Opening，8 秒，1280×720@24fps）
  - 触发时机：每次由标题界面进入谱面之前，每局一次（失败/结算后的快速重开不重播）
  - 内容与角色场景：深空陨石带中泛着蓝紫辉光的星髓晶巨晶；勘探舱内白色探测艇「尘针号」被微缩光束逐级缩小至微尘尺度，随后高速穿入晶面；画面切入晶体内部——晶格穹顶、发光晶脉与悬浮晶柱纵深展开，能量珠如星群漂浮
  - 资产对应：探测艇「尘针号」、晶体内部场景与游戏内模型/贴图同源设计（同一套造型描述生成，见 §12 A01/A02）
  - 可跳过：Esc/Enter 跳过 → 直接进入谱面开始（S07 初始状态）；自然播完 → 进入谱面开始
  - 状态一致：播放期间不推进谱面计时与任何游戏状态；本局从初始冻结状态开始
- C02 撤离与数据回传（Ending，8 秒，1280×720@24fps）
  - 触发时机：90 秒存活胜利达成、胜利结算面板出现之前，每局一次
  - 内容与角色场景：晶体内部能量珠渐息，晶面透出撤离光门；「尘针号」拖金色扫描光尾迹穿过残余能量珠群驶向光门，出晶瞬间恢复原尺度，数据光流回传勘探舱屏幕，晶面在身后缓缓愈合
  - 资产对应：探测艇与晶体场景与游戏内资产同源
  - 可跳过：Esc/Enter 跳过 → 直接进入胜利结算面板；自然播完 → 进入胜利结算面板
  - 状态一致：仅在真实达成 V01 后触发，与真实游戏进度一致；播放期间不推进任何游戏计时
- C03 谐振储备就绪（Event，5 秒，1280×720@24fps）
  - 触发时机：每局首次 `clear_charge_gained` 事件（graze_meter 首次满 500 转换为清屏 +1）达成瞬间，每局一次
  - 内容与角色场景：画面短暂定格于探测艇「尘针号」贴弹瞬间；艇艏扫描环收拢成一道金色数据流，注入艇侧脉冲槽——脉冲槽图标由灰转亮、+1 浮动徽记跳出；背景晶脉随数据流入泛起一圈青金涟漪
  - 资产对应：探测艇「尘针号」、脉冲槽 HUD 图标与游戏内模型/UI 同源设计
  - 可跳过：Esc/Enter 跳过 → 直接恢复谱面进行（资源 +1 已生效）；自然播完 → 恢复谱面进行
  - 状态一致：仅在真实首次 graze→清屏转换后触发；播放期间弹幕推进与谱面计时冻结、玩法输入缓存清空，播放结束瞬间弹幕与计时按冻结前状态恢复

## 11. 范围与正向能力清单 [N01–N06]

- N01 本测例包含的玩法能力：90 秒纵版固定弹幕纯躲避、擦弹计分（每弹一次 +10）、低速精确模式（移速减半＋判定点/擦弹范围显示）、清屏资源管理（初始 2 次＋graze 累计每满 500 补 1 次、存量上限 3）、生命与重生无敌、谱面终点胜利结算；玩家通过纯机动（移动/低速/清屏）即可完成全部玩法目标，胜利不依赖射击或击破行为。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：3 个（text-to-3D 2，image-to-3D 1）；object 任务资产为：probe_craft, crystal_pillar, vein_pulse_node。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：probe_scan_pulse。
- video/audio/mechanic/UI：分别为 3/10/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

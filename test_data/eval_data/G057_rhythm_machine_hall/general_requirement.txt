## 1. 定位与完整流程 [S01–S06]

- S01 类型：下落式单谱面节奏游戏，单人。本测例包含的能力：三乐段谱面（热身/主题/终曲）、四轨道两型音符、判定窗口分档、连击倍率、血条胜负、音画校准、三设备统一判定管线、开场/终曲/结算视频。
- S02 核心循环一句话：音符下落 → 判定窗口输入 → 命中评级 → 连击累积 → 结算。
- S03 流程：开始界面 →（可选）校准 → 演奏单谱面 → 结算（评级/得分/最大连击）→ 重开。
- S04 最低完整流程：开始界面、演奏、结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：血条归零即刻判负并可直接重开；结算界面一键重开；游玩中 Esc 暂停。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：启动与开始界面 → 校准（可选）→ 演奏（热身/主题/终曲三段）→ 结算 → 重开。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与开始界面
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始演奏」
  - precondition：构建可启动且谱面/音频按 seed=1057 冻结加载
  - state_change：进入「开始界面」状态；首次进入按 §10 C01 触发开场视频
  - feedback：开始界面按 §9 F10 呈现（演奏/校准/设置/当前输入设备图标）
  - next_actions：进入「校准（可选）」或「演奏」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 校准（可选）
  - input：跟随 8 次提示节拍点击（触发方：玩家）
  - precondition：从开始界面进入校准
  - state_change：测得全局补偿值并即时生效（G06）
  - feedback：每次点击显示 Δt 与当前中位值
  - next_actions：返回开始界面或直接进入「演奏」
  - outcome：补偿值存入设置（非局内状态）
- S08 热身段（0–15 秒）
  - input：D/F/J/K（或触屏四分区/手柄面键）（触发方：玩家）
  - precondition：演奏开始且当前乐段＝热身
  - state_change：仅点击型音符、密度低；判定/得分/连击/血条按 G03–G05 结算
  - feedback：节拍灯与音符判定反馈按 §9 F05
  - next_actions：15 秒边界 → `section_change` →「主题段」
  - outcome：得分与连击局内累计
- S09 主题段（15–70 秒）
  - input：同 S08（触发方：玩家）
  - precondition：热身段结束
  - state_change：全型音符（点击＋长按）按谱面推进
  - feedback：齿轮转动与轨道灯光随节奏脉动
  - next_actions：70 秒边界 → `section_change`（提前 2 秒「终曲」提示）→「终曲段」
  - outcome：局内状态持续
- S10 终曲段（70 秒–曲尾）
  - input：同 S08（触发方：玩家）
  - precondition：主题段结束且终曲提示已显示
  - state_change：密度较主题段 +50%、出现双押、下落速度 ×1.15（G08）；首次进入时按 §10 C02 触发终曲演出视频（每局一次）
  - feedback：终曲灯光全亮与更强的命中反馈
  - next_actions：谱面完成 →「结算」（先播 C03）；血条归零 → 即刻判负界面
  - outcome：按 V01/V02 判定
- S11 结算与重开
  - input：Enter＝重开 / Esc＝返回开始界面（触发方：玩家）
  - precondition：V01（完成且达标）或 V02（判负/未达标）达成
  - state_change：进入「结算」状态；谱面推进冻结
  - feedback：结算面板显示评级、得分、最大连击、Perfect/Good/Miss 统计
  - next_actions：重开（谱面/血条/连击/得分全量重置，校准值保留）或返回
  - outcome：无跨局写入

## 3. 数值口径与全局规则 [G01–G08]

- G01 统一刻度：时间为毫秒；得分、连击、血条为数值；血条百分比上限 100、下限 0。
- G02 谱面与轨道：单曲 1 首（时长 90–120 秒，原创或公有领域音频）；4 条下落轨道（D/F/J/K 对应）；音符两型：点击、长按；谱面为时间轴数据（音符时间、轨道、类型、长按时长），由 fixed_seed=1057 冻结生成，同 seed 下谱面逐项可复现；音符总数 ≥ 80（建议点击 64、长按 16 分布）。
- G03 判定窗口（按时间差 Δt=输入时刻−音符时刻，经 G06 校准补偿后）：|Δt| ≤ 50 毫秒 → PERFECT；50 < |Δt| ≤ 120 毫秒 → GOOD；|Δt| > 120 毫秒或未按 → MISS。
- G04 得分与连击倍率：单次判定 PERFECT=300、GOOD=150、MISS=0；长按头、尾各一次判定、各计一次分。倍率 m = 1 + 0.02 × min(combo, 50)（上限 2.0），**按命中前当前连击数取值，命中后 combo+1；MISS 归零**。独立 oracle 数例：开局连续 10 个 PERFECT，第 k 个得分 300×(1+0.02×(k−1))，合计 300×(10+0.02×45) = **3270**，其中第 1 个为 300。结算对账：总分=逐音符加权之和，容差 0。
- G05 血条：初始 70%；PERFECT +2%、GOOD +0.5%、MISS −8%；到达上限 100 后不再增加；归零 → 即刻判负。
- G06 音画偏移校准：设置内提供校准流程——跟随 8 次提示节拍点击，取 |Δt| 中位数作为全局补偿值（默认 0）；**判定用 Δt = 原始时间差 − 补偿值**；校准值可随时重测并立即生效；校准只改判定时间差与谱面显示偏移，不改音符时刻本身。
- G07 评级与暂停：评级按得分率（总分/理论满分，理论满分=全 PERFECT 总分）：S ≥ 95%、A ≥ 85%、B ≥ 70%、C ≥ 60%，< 60% 为未达标；Esc 暂停冻结音频与谱面推进，恢复后音画同步继续；窗口失焦自动暂停。
- G08 谱面乐段（本包冻结值）：单曲三段——热身段（0–15 秒，仅点击型、密度低）、主题段（15–70 秒，全型音符）、终曲段（70 秒–曲尾，密度较主题段 +50%、出现双押、下落速度 ×1.15）；进入终曲段前 2 秒 HUD 显示「终曲」提示（图标＋文字）；段边界事件 `section_change` 可观测；乐段不改变 G03–G05 判定与计分规则。

## 4. 操作与输入 [I01–I07]

- I01 键位：D/F/J/K＝对应轨道判定（点击型按一下；长按型按住至尾）；Esc＝暂停/继续；结算界面 Enter＝重开。
- I02 输入语义边界：空轨按键不产生判定（不计 MISS、不加连击）；长按中途松开触发断连（M02）；暂停/结算期间输入无效。
- I03 无鼠标玩法需求；菜单可键盘完整操作。
- I04 输入设备与统一判定管线（本包冻结值）：键盘 D/F/J/K；触屏（HTML5 环境）四分区点击映射 D/F/J/K；手柄（可选开启）面键 A/B/X/Y 映射 D/F/J/K；三种设备汇入**同一判定管线**（同一 Δt 计算、同一窗口分档、同一连击/得分结算），设备切换即时生效并在 HUD 显示当前设备图标＋文字。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：连击数、血条、谱面进度、当前乐段名、判定反馈（P/G/M 图标＋文字）、当前输入设备；HUD 对照见 rubric。
- I07 输入延迟红线（本包冻结值）：判定输入到对应评级反馈 ≤ **50 毫秒**（音游手感红线）；设置界面显示当前音频-视频偏移补偿值；超红线记为缺陷（rubric D4 断言）。

## 5. 谱面与内容清单 [L01–L04]

- L01 生成对象：单谱面 1（时间轴数据，seed=1057 冻结）、音频 1（原创或公有领域）、音符两型（点击 ≥ 64、长按 ≥ 16）、轨道 4、机械音乐厅场景与判定线 UI、三乐段结构。
- L02 谱面结构：前 10 秒为低密度热身段（仅点击型）；谱面须通过「全 PERFECT 可达理论满分」的可解性自查；长按不与同轨其他音符重叠。
- L03 目标物/交互物/场景/UI 对象：本 spec §3–§9 引用的界面元素（开始界面/演奏 HUD/结算/暂停/视频播放层）与交互物逐类存在且运行时可进入；数量与属性以 L01/L02 与 G 系为准。
- L04 冻结需求 vs 实现默认 vs 生成自由度：本 spec 明确写出的数值与数量为冻结需求；§9 未冻结的机械厅装饰与配色为生成自由度，不得评估为缺失；实现默认值必须明确标注且符合核心机制。

## 6. 机制系统 [M01–M06]

- M01 判定窗口（主机制）
  - input：轨道键（键盘/触屏/手柄统一管线）
  - precondition：处于演奏状态且该轨存在待判定音符
  - state_change：按 G03 窗口将输入分档为 PERFECT/GOOD/MISS
  - observable：逐音符判定事件含 Δt 字段与档位、输入设备字段
  - invalid_case：空轨按键不产生判定事件
  - recovery：—
- M02 长按音符
  - input：按住对应轨道键
  - precondition：长按头部判定已成立
  - state_change：头部判定（同 G03）→ 按住期间 → 尾部判定；中途松开 → 断连（尾部记 MISS、连击归零）
  - observable：长按完成率事件、断连事件
  - invalid_case：头部 MISS 后按住不产生尾部判定
  - recovery：后续音符继续
- M03 音画偏移校准
  - input：校准流程中的 8 次点击
  - precondition：处于校准流程
  - state_change：测得补偿值 → 全局判定时间差与显示偏移生效
  - observable：校准前后同输入序列的判定差分
  - invalid_case：—
  - recovery：重测即覆盖
- M04 连击与结算
  - input：逐次判定 / 结算画面
  - precondition：处于演奏/结算状态
  - state_change：命中按 G04 计倍率与得分并累计连击；MISS 归零；结算按加权和与评级阈值出分
  - observable：连击事件、结算对账（容差 0）、评级事件
  - invalid_case：—
  - recovery：重开全量重置
- M05 血条与胜负
  - input：逐次判定
  - precondition：处于演奏状态
  - state_change：按 G05 增减血条；归零即刻判负；谱面走完 → 结算评级
  - observable：血条事件、win/lose 事件与结算面板
  - invalid_case：—
  - recovery：判负即刻重开
- M06 乐段推进
  - input：谱面时间推进（系统）
  - precondition：演奏进行中
  - state_change：按 G08 三段边界切换乐段（密度/双押/下落速度规则生效）；`section_change` 事件与「终曲」提示
  - observable：段边界事件、终曲段下落速度 ×1.15 采样、密度对照
  - invalid_case：乐段切换不重置连击/血条
  - recovery：—

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：完成整首谱面（血条未归零）且结算评级 ≥ C（得分率 ≥ 60%）。
- V02 失败条件：血条归零（即刻判负），或谱面完成但得分率 < 60%（结算显示未达标）。
- V03 恢复语义：失败/未达标即刻重开；重开后谱面、血条、连击、得分全量重置（校准值保留，因其属于设置而非局内状态）。
- V04 persistent_state：无（重开全量清空；最好成绩可作展示但不作为验收需求、不要求跨会话保存）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（得分/连击/血条）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设软锁——判负即刻重开、谱面按 seed 复现；判定输入始终可达。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：发条与蒸汽驱动的架空时代，「谐律厅」是城市的心脏——巨型机械音乐厅每晚以合奏钟声为全城报时。
- W02 场景所在地：谐律厅的独奏台——四条黄铜音轨沿齿轮墙垂落，判定线是一排待击音簧。
- W03 玩家身份与当前任务：玩家是调律师学徒「聆」；当前任务：在钟枢校准夜完成独奏，让报时大合奏如期奏响。
- W04 失败代价与结局表达：血条归零＝校准中断需重来（判负界面文案）；完成则 C03 呈现大合奏钟声齐鸣、全城灯火应和的场面。
- W05 叙事来源：四轨道＝钟枢的四根音簧；双押＝和音；终曲段＝校准夜的收束乐章；节拍灯＝音乐厅的呼吸。全部原创。
- W06 视觉风格与色彩材质：黄铜与暗木的机械美感；主色＝黄铜金（#B08D4F 系）＋暗胡桃（#4A3A2C 系）＋判定青光（#57C9B8 系）；材质以黄铜、蒸汽管、磨砂玻璃为主。
- W07 环境氛围与声音语言：齿轮低鸣的音乐厅——常驻机械运转声；音效语言为「节拍灯咔哒＋音符爆裂＋断连闷响＋终曲钟声」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代校准夜 → 终曲段视频（C02）作为高潮节点 → 结算视频（C03）收束报时；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：固定正面舞台视角（演奏 UI 全屏），无跟随；判定线轻微随低频节奏起伏（幅度 ≤4 像素，不改变判定位置）；镜头边界＝演奏 UI 外框。
- F02 关键操作镜头变化：连击达 25/50 时舞台灯光短暂扫过（0.5 秒）；终曲段进入时灯光全亮＋轻微 FOV 变化 +5°（0.5 秒）；无慢动作。
- F03 输入与延迟：见 I07（≤50 毫秒红线）；判定反馈与音符爆裂在判定帧同帧呈现。
- F04 环境常驻效果：齿轮墙缓慢转动、蒸汽微雾、节拍灯随节拍明暗；不遮挡轨道与判定线。
- F05 事件反馈表（事件 → 表现 → 结束条件，全部为冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| PERFECT | 音符青光爆裂＋判定线火花＋「P」字弹出 | 清脆爆裂音 | 0.2s |
| GOOD | 音符黄光散开＋「G」字弹出 | 较柔爆裂音 | 0.2s |
| MISS | 音符灰化坠落＋判定线红闪＋「M」字 | 低沉闷响 | 0.3s |
| 长按完成 | 尾焰沿轨道拉出光带 | 尾音清响 | 完成 |
| 长按断连 | 光带断裂灰化 | 断连闷响 | 0.3s |
| 连击档位升级 | 连击数字放大弹跳＋齿轮徽标点亮 | 连击咔哒声 | 弹跳完成 |
| 血条增减 | 血条平滑移动＋数字跳动 | 增/减微音 | 移动完成 |
| 段落切换 | 段名横幅（热身/主题/终曲）＋灯光变化 | 转段钟声短句 | 横幅结束 |
| 终曲提示 | 「终曲」图标＋文字提前 2 秒显示 | 提示钟声 | 进入终曲段 |
| 双押命中 | 双轨同步爆裂＋和音光环 | 和音爆裂音 | 0.2s |
| 判负 | 灯光骤暗＋谱面停格 | 失谐低鸣 | 进入判负界面 |
| 完成 | 谱面收束光带＋大合奏预演灯光 | 终曲钟声 | 进入结算 |

- F06 关键音效清单：爆裂音（P/G 两档）、尾音、断连闷响、连击咔哒、转段钟声、提示钟声、和音爆裂、失谐低鸣、终曲钟声；环境音：齿轮低鸣＋蒸汽嘶声（常驻循环，演奏中低音量）；循环音开始/结束：环境声随开始界面进入、随结算淡出 0.5s；无配音需求。
- F07 VFX 信息性与遮挡约束：判定反馈（P/G/M）文字＋图形双通道承担判定信息；爆裂粒子单帧 ≤ 30 且不遮挡相邻轨道与判定线。
- F08 音画同步：判定音效与判定帧同步（受 G06 补偿影响时以补偿后对齐）；转段钟声与 `section_change` 帧同步；终曲钟声与完成帧同步。
- F09 屏幕震动：MISS 0.05 秒微幅（可关闭）；设置界面提供「判定线起伏开/关」「震动开/关」（关闭不影响判定）。
- F10 前端界面：开始界面（演奏/校准/设置/退出＋当前输入设备图标）→ 演奏 HUD（连击、血条、进度、段名、判定反馈、设备图标）→ 结算（评级/得分/最大连击/P-G-M 统计/重开/返回）→ 判负界面（即刻重开）→ 暂停面板（继续/重开/设置）；关键状态附图标＋文字（P/G/M、段名、设备），不只靠颜色区分；窗口失焦自动暂停。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：2 个（text-to-3D 1，image-to-3D 1）；object 任务资产为：tuner_ling, chime_judgeline。每项只允许一个物体；组合物必须拆成独立任务。
- motion：2 个；覆盖动作：idle, strike_conduct。
- video/audio/mechanic/UI：分别为 3/11/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

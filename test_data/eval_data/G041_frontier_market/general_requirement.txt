## 1. 定位与完整流程 [S01–S05]

- S01 类型：单摊位多日经营模拟切片（营业周期上限 5 日）。不是多摊位扩张、雇佣经营或地牢采集。
- S02 核心循环一句话：进货定价 → 开门营业 → 顾客意愿判定/排队候补 → 成交或流失 → 日结对账 → 达标结算或新一天。
- S03 流程：主菜单 → 早晨进货 → 设定售价 → 开市营业（120 秒）→ 打烊 → 日结对账 → 达标胜利结算／进入下一日（上限 5 日）。
- S04 最低完整流程：进货界面、定价界面、营业场景、队列/候补表现、日结面板、重开必须全部存在且有真实入口。
- S05 失败恢复入口：日结自动重置营业态进入新一天；失败结算一键重开；Esc 暂停（模拟冻结）。

## 2. 完整核心循环与阶段 [S06–S12]

完整循环：主菜单 → 早晨进货界面 → 设定各商品售价 → 开门营业 → 打烊 → 日结对账 → 达标结算或资本滚入次日 → 重开/返回菜单；任意营业阶段可 Esc 暂停。每阶段六要素如下（引用本 spec §3–§7 对应规则）：

- S06 主菜单
  - input：系统启动，玩家点击「开始经营」
  - precondition：程序启动完成（C01 可在首次开局前播放）
  - state_change：初始化第 1 日经营状态（资金 400、库存 0、经营日数 1、失败计数 0）
  - feedback：主菜单界面（F10）
  - next_actions：点击「开始经营」→ S07
  - outcome：无状态副作用
- S07 早晨进货界面
  - input：玩家点击四商品的数量增减钮（I01）
  - precondition：主菜单已完成、C01 播完或跳过
  - state_change：资金按进货价扣减、库存累加（受容量 40 与资金约束，G02/I02）
  - feedback：资金、库存、容量占用实时刷新（F10）
  - next_actions：点击「下一步」→ S08
  - outcome：进货支出记入当日台账（G06）
- S08 设定各商品售价
  - input：玩家对四商品按 ±1/±5 调价（I01）
  - precondition：进货已完成
  - state_change：四商品售价写入（1–500 越界拒绝，I02）
  - feedback：售价与「基准价 × 建议区间」提示（F10）
  - next_actions：点击「开门营业」→ S09
  - outcome：售价为营业判定的初始快照
- S09 开门营业（主玩法阶段，120 秒/日）
  - input：系统按 seed 派生客流；玩家营业中可改价（I01）
  - precondition：定价完成
  - state_change：顾客到店 → 即时意愿判定（G03 当时售价与库存）→ 通过且队未满入队／队满入候补（G05）；柜台每 3.0 秒结算队首 1 位；候补 FIFO 20 秒未入队流失；断货流失
  - feedback：队列/候补/耐心沙漏/成交金币/流失红标（F05）、HUD（I06）
  - next_actions：120 秒耗尽 → S10；Esc → 暂停
  - outcome：逐笔成交流水与流失分类计数累积（G06/G08）
- S10 打烊
  - input：系统（120 秒到时自动）
  - precondition：营业阶段结束
  - state_change：在场顾客散场（不判流失）、柜台停止结算
  - feedback：打烊门板音与散场表现（F05）
  - next_actions：进入 S11
  - outcome：当日营业数据冻结待对账
- S11 日结对账
  - input：系统结算
  - precondition：打烊完成
  - state_change：当日收入＝逐笔成交之和（容差 0）；利润＝收入−当日进货支出；按 G06 判定达标/连负/破产/未达期
  - feedback：日结面板（收入、进货支出、利润、成交笔数、流失分类计数）；达标 → C03 胜利意象前置
  - next_actions：达标 → S12 胜利结算；未达标且未触发失败 → 资本滚入次日 S07；触发 V02 → S12 失败结算
  - outcome：失败计数/经营日数更新（G06）
- S12 结算与重开
  - input：系统结算（或玩家在结算面板点击）
  - precondition：V01 或 V02 判定成立
  - state_change：显示胜利结算（达标日明细）或失败结算（连负/破产/未达期分类）
  - feedback：C03 结算视频（双意象）＋结算面板（F05/F06）
  - next_actions：Enter 重开 → S06；返回菜单 → S06
  - outcome：按 V01/V02 判定并结算

## 3. 数值口径与全局规则 [G01–G08]

- G01 统一刻度：金币为整数；顾客与库存按件计；时间为游戏模拟秒（暂停冻结）；经营日数为整数（上限 5）。
- G02 商品与价格（本包冻结值）：四种商品——山草药（基准价 30）、陶罐（60）、粗毛毯（90）、香料（120）；进货价＝基准价 × 0.6（即 18/36/54/72）；初始资金 400；每件占 1 库位，摊位容量 40 件；售价范围 1–500，越界拒绝（I02）。
- G03 需求曲线（本包冻结值）：顾客对某商品的购买意愿 p＝clamp(1.25 − 0.75 × 售价/基准价, 0.05, 1.00)，在到店瞬间按当时售价判定。独立 oracle 数例：山草药定价 30 → p＝0.50；定价 24 → p＝0.65；定价 45 → p＝0.125；定价 60 → p＝0.05（下限）。营业中改价只影响改价后到店顾客的判定，不追溯已入队/候补顾客。
- G04 客流与节奏（本包冻结值）：每日客流 20 人，到店时刻表由 seed=1041 派生并随 trace 公布——0–60 秒 6 人、60–90 秒高峰窗 12 人、90–120 秒 2 人；每位顾客的目标商品与意愿判定随机数由同一 seed 派生（外部 oracle 可复算）。
- G05 队列与耐心（本包冻结值）：队列上限 3 位；柜台结算 1 位/3.0 秒（按入队序）；队满时意愿通过的顾客转入「候补徘徊」——候补按 FIFO 等待入队，候补耐心 20 秒，超时未入队记候补流失；意愿判定不通过的顾客到店即转身离店（不占柜台）；意愿通过但目标商品断货记断货流失。
- G06 日结与终止判定（本包冻结值，P0 修复）：利润＝当日收入 − 当日进货支出；**终止规则＝营业周期上限 5 日：任一营业日日结利润 ≥150 即「成功营业日」，触发 V01 胜利结算（结算面板提供「继续经营」可选表现层与「重开」入口，benchmark 成功判定已达成）；连续 2 日利润为负 → 经营失败（V02）；资金低于最低进货价（18）→ 破产失败（V02）；第 5 日日结仍无达标日 → 未达标失败（V02）**。
- G07 暂停与随机：Esc 暂停冻结营业模拟与计时；窗口失焦自动暂停；fixed_seed=1041 冻结客流时刻表、顾客目标商品与判定随机数；**顾客全量 trace 必须可导出（编号、到店时刻、目标商品、判定时售价、p 值、判定随机数、入队/候补/结算时刻、结果与流失原因分类）**。
- G08 判定与独立 oracle（本包冻结值）：收入对账 oracle——日结收入＝当日逐笔成交售价之和（容差 0）；流失分类 oracle——候补流失数＝高峰窗内意愿通过数 − 入队成交数 − 营业结束前入队数；任何对账偏离即 FAIL。日结后库存清空（未售出商品折损处理，简化口径）、顾客散场，资金与失败计数保留（V03）。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：鼠标点击＝进货数量增减、定价 ±1/±5、营业中实时改价、界面按钮；Esc＝暂停；结算界面 Enter＝重开。键盘 Tab/1–4 为商品快速选中辅助（非冻结需求）。
- I02 输入语义边界：资金不足时进货点击无效且不消耗；售价低于 1 或高于 500 越界拒绝；暂停/日结/结算期间营业输入无效；被拒输入不产生状态变化。
- I03 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入；同帧多输入按 §6 各机制声明的顺序结算。
- I04 焦点与点击穿透规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停（G07）。
- I05 无手柄需求；触控为表现层扩展，不进入验收分母。
- I06 UI 必须显示的状态：资金、库存（四商品分列与容量占用）、当前售价、营业剩余时间、队列人数（0–3）、候补人数、当日成交笔数、当日流失分类计数（转身离店/断货/候补超时）。
- I07 输入延迟目标：点击到界面可见反馈 ≤100 毫秒（桌面 P95，每类输入 ≥30 次采样）。

- L03 目标物/交互物/场景/UI 对象：本 spec §3–§7 引用的界面元素（菜单/进货/定价/HUD/日结/结算面板）与交互物（进货钮、调价钮、柜台结算位、队列槽、候补区）逐类存在且运行时可进入；柜台结算节奏由引擎计时器驱动，装饰模型不得替代计时逻辑；数量与属性以对应 G·M 条目为准。

## 6. 机制系统 [M01–M04]

- M01 定价与需求（主机制）
  - input：早晨设定售价＋营业中实时改价（玩家）
  - precondition：处于定价/营业阶段
  - state_change：售价 → 影响到店顾客的 p 判定（G03，仅对改价后到店者生效）
  - output：按 G03 产出意愿通过/不通过
  - observable：定价事件与顾客判定 trace（编号、售价快照、p 值、随机数、结果）
  - invalid_case：售价越界拒绝无副作用；暂停/日结期间改价无效
  - recovery：改价即时生效，无回滚需求
- M02 库存与断货
  - input：进货点击（玩家）与成交扣减（系统）
  - precondition：资金与容量充足（进货）；成交成立（扣减）
  - state_change：进货 → 资金−进货价、库存+1；成交 → 库存−1、资金+售价
  - output：按 G02/G06 记账
  - observable：库存流水与断货流失事件
  - invalid_case：资金不足/容量已满时进货拒绝；断货商品被意愿通过顾客选中 → 断货流失（不占柜台）
  - recovery：日结后库存清空重建（V03）
- M03 队列与候补耐心
  - input：顾客到店（系统，seed 派生）与柜台结算（系统，3.0 秒/位）
  - precondition：处于营业阶段
  - state_change：到店 → 意愿判定 → 入队/候补/离店；柜台每 3.0 秒结算队首 1 位；队空时腾出的位置按 FIFO 从候补补入
  - output：按 G05 记队列/候补/耐心
  - observable：入队、候补、补位、结算、候补超时流失事件（含时刻）
  - invalid_case：打烊后在场顾客散场不判流失；暂停期间耐心与柜台计时冻结
  - recovery：候补流失不可挽回（记入流失分类）；下一日重置
- M04 日结对账
  - input：打烊到时（系统）
  - precondition：营业阶段结束
  - state_change：收入=逐笔之和（容差 0）；利润=收入−进货支出；按 G06 判定达标/连负/破产/未达期；库存清空、资金与失败计数滚动
  - output：按 G06/G08 结算
  - observable：日结面板与逐笔对账流水（可导出）
  - invalid_case：日结期间不可回退当日；结算后 Enter 重开全量重置
  - recovery：日结即恢复入口；失败结算重开为最终出路（V03）

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：任一营业日日结利润 ≥150 → 成功营业日 → 胜利结算（显示当日收入/支出/利润/成交笔数与经营日数）。
- V02 失败条件：连续 2 日利润为负 → 经营失败；资金 <18 → 破产；第 5 日日结仍无达标日 → 未达标失败；三类均进入失败结算（分类显示）。
- V03 恢复语义：日结自动重置营业态（库存清空、顾客散场、资金与失败计数保留）进入新一天；失败结算一键重开全量重置（seed 复现客流）。
- V04 persistent_state：无跨局持久；资金/失败计数/经营日数局内保留（P1），重开清空。
- V04 软锁与不可达处理：不设永久软锁——正常定价策略可达 ≥150（见 G08 witness：低价高销与高峰窗容量的权衡存在可行解）；失败路径均可达；结算界面重开为最终恢复出路。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（资金/失败计数/经营日数）局内保留、重开清空；跨局状态无（S 档：重开全量清空）。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：原创边境世界「灰岩隘口」——商路穿隘而过，隘口集市是往来得益者的补给站；摊位虽小，定价与耐心决定商队的口碑。
- W02 场景所在地：灰岩隘口集市单摊位——货架四排、木质柜台、米色雨棚，背后是岩壁与风尘；顾客自隘口步道到店。
- W03 玩家身份与当前任务动机：玩家是「灰岩商队」年轻摊主，接管家族摊位的第一季——在 5 日内跑出一个利润 ≥150 的成功营业日，向商队证明自己。
- W04 失败代价与结局表达：连负/破产/未达期＝摊位雨棚收起、商队旗帜降下（C03 失败意象）；达标＝雨棚亮灯、商队旗帜升起、金币入库（C03 胜利意象）。
- W05 叙事来源：四商品（山草药/陶罐/粗毛毯/香料）＝隘口两侧山民与行商的土产；顾客＝商路旅人、背篓山民与驮队伙计的同构变体；全部原创，不用商业作品命名。
- W06 视觉风格与色彩材质：暖土色边境市集风；主色＝岩灰 #8A8578、雨棚米 #E8DFC8、商队青 #3E7C6F、陶土橙 #C9743F；材质为风化木架、粗陶、土布与岩壁。

- F01 视角与镜头：固定 45° 俯视斜视角，单屏覆盖摊位全境（货架/柜台/队列/候补区/出入口）；镜头不可旋转缩放；1920×1080 下 HUD 不遮挡柜台与队列，1280×720 保持可读（I06）。

- F03 输入与延迟：见 I07（≤100ms P95）；顿帧不改变计时口径。
- F04 环境常驻效果：隘口风尘飘移、雨棚布料微动、货架商品呼吸高亮、远处驮队剪影路过；均为纯表现层。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：9 个（text-to-3D 6，image-to-3D 3）；object 任务资产为：frontier_market_stall_kit, frontier_herb_jars, frontier_clay_pot, frontier_wool_blanket, frontier_spice_sack, stall_vendor_character, market_customer_npc, frontier_signpost, caravan_flag_pole。每项只允许一个物体；组合物必须拆成独立任务。
- motion：3 个；覆盖动作：vendor_greet_idle, customer_walk_browse, customer_walk_leave。
- video/audio/mechanic/UI：分别为 3/12/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

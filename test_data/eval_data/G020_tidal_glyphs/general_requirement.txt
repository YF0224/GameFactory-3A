## 1. 定位与完整流程 [S01–S07]

- S01 类型：第一人称跨室搜证解谜。本测例包含的能力：三室冻结遗址、六符号译义三态、跨室证据链、道具组合、节点存档、四级恢复、回声守望者恐怖事件（确定性触发）、开场/机关/深层/解封四段视频、三种结算评级表达。
- S02 核心循环一句话：搜证 → 标记译义假设 → 跨室验证 → 证实/误译回滚 → 解锁机关 → 解封逃脱。
- S03 流程与阶段关系（阶段推进条件均为确定规则）：
  - P1 进入与勘察（潮汐前厅）：进入遗址 → 发现并登记线索（A/D/F 佐证）→ 为符号赋义形成假设；
  - P2 译义与解锁（刻文内室）：解读 B/C 佐证 → 潮汐锁机关激活（P1 的 A 证实后可解）→ 组合道具 → 月门开启；
  - P3 深层与解封（封印密室）：进入深层石室 → 回声守望者事件（G07）→ E 佐证 → 六槽封印 → 逃脱结算。
  - 阶段推进链：P1 取证赋义 → P2 机关可解性翻转 → P3 封印对位（跨阶段后果见 K01/K02）。
- S04 最低完整流程：搜证交互、译义板赋义、机关交互、道具组合、节点存档、结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：误译可回滚＋节点存读档＋房间重置＋全量重开四级恢复；Esc 暂停。
- S06 本局耦合边速览：译义系统→机关系统（证实状态改变机关可解性）；道具系统→路径系统（组合道具解锁密室槽位）。
- S07 跨阶段结构与状态保留：三室顺序推进；译义假设、道具、机关状态、误译计数跨室持久；已证实符文跨阶段保留（房间重置不回退已证实符号）；节点存档全量保存上述状态并读档恢复。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：启动与标题 → 前厅勘察 → 内室译义 → 密室解封 → 逃脱结算 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「进入遗址」
  - precondition：构建可启动且场景加载完成
  - state_change：进入「标题」状态；首次进入按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10 呈现（任务简报：涨潮倒计时 3600 秒）
  - next_actions：进入「前厅」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 前厅勘察（P1）
  - input：WASD 移动、E 搜证/交互、Tab 译义板、拖拽赋义、R 回滚、Esc 暂停（触发方：玩家）
  - precondition：标题已完成（前厅默认进入）
  - state_change：载入前厅；佐证交互登记线索；赋义产生「暂定」假设
  - feedback：线索收集、错误与正确输入反馈按 §9 F05 呈现
  - next_actions：取证与赋义完成 → 前厅潮汐锁可解 →「内室」
  - outcome：假设/道具/线索跨室持久（V04）
- S08 内室译义（P2）
  - input：同 S07（触发方：玩家）
  - precondition：前厅潮汐锁开启（A 证实）
  - state_change：载入内室；B/C 佐证取证；铜镜＋刻刀→反光刻片→封印钥芯组合
  - feedback：组合与月门开启表现
  - next_actions：月门开启 →「密室」
  - outcome：已证实符号保留（S07 规则）
- S09 密室解封（P3）
  - input：同 S07（触发方：玩家）
  - precondition：月门开启（B 证实＋钥芯）
  - state_change：载入密室；C03 播完后按 G07 触发回声守望者事件；E 佐证取证；六槽封印对位
  - feedback：守望者演出（G07 时序）、符文 VFX、封印解封表现
  - next_actions：六符号全证实＋钥芯＋对位成功 →「逃脱结算」（先播 C04）
  - outcome：按 V01 结算（评级按 G08）
- S10 逃脱结算
  - input：Enter＝重开 / Esc＝返回标题（触发方：玩家）
  - precondition：V01 成立（六槽封印对位开启）
  - state_change：进入「结算」状态；场景冻结
  - feedback：结算面板显示误译次数、用时、佐证完成度、评级（纯净/常规/仓促）
  - next_actions：重开（全量清空）或返回标题
  - outcome：无跨局写入
- S11 暂停
  - input：Esc（触发方：玩家）
  - precondition：处于非结算状态
  - state_change：暂停覆盖层打开；倒计时、守望者演出计时、交互全部冻结
  - feedback：暂停面板（继续/读最近存档/房间重置/返回标题/设置）
  - next_actions：Esc 或「继续」→ 恢复
  - outcome：恢复后状态与暂停前一致（G05）

## 3. 数值口径与全局规则 [G01–G08]

- G01 统一刻度：符号/道具/槽位按件；时间用游戏模拟秒（暂停冻结）。
- G02 符号与译义（本包冻结值）：关键符号 6 个（A–F），每符真实译义唯一（潮/月/火/水/星/门）；译义板可为符号赋义形成假设；假设三态——未知→暂定（赋义）→证实（对应室证据交互验证）；赋错即误译，机关拒绝并计误译数，可回滚重置为未知。
- G03 佐证分布与映射（本包冻结值）：每条线索唯一映射一个符号，在译义板线索笔记中登记可查——前厅：潮汐壁画（A＝潮）、水痕石碑（D＝水）、门楣刻纹（F＝门）；内室：月相图（B＝月）、灯台铭文（C＝火）；密室：星穹顶图（E＝星）；佐证仅在对应房间可交互。
- G04 道具与组合（本包冻结值）：道具 5 件——潮汐罗盘、铜镜（前厅）、刻刀、月相盘（内室）、封印钥芯（组合产物）；组合规则——铜镜＋刻刀→反光刻片；反光刻片＋月相盘→封印钥芯；封印钥芯开密室封印槽。
- G05 机关依赖、时限与存档（本包冻结值）：前厅潮汐锁＝A 证实后可解；内室月门＝B 证实＋反光刻片；密室六槽封印＝六符号全部证实＋封印钥芯，六槽按真实译义对位；前驱未满足时机关拒绝并提示缺口；软锁红线——任何状态均可经回滚或读档继续；总时限 3600 秒（超时判负）；节点存档位于每室入口（自动）＋译义板（手动），共 ≥3 处；Esc 暂停冻结全部计时；窗口失焦自动暂停。
- G06 判定与独立 oracle（本包冻结值）：三态 oracle——A 赋义「潮」必转暂定；以前厅潮汐壁画交互必转证实；赋错「火」时潮汐锁机关必拒绝并计 1 次误译，回滚后重赋可再验。跨室 oracle——前厅佐证未取时内室潮汐锁机关必拒绝（前驱未满足）；取佐证并证实后同机关必开。存读档 oracle——节点存档后读档，假设/道具/机关状态快照 diff＝0。任何偏离即 FAIL。fixed_seed=1020 冻结符号真实译义与佐证布位。
- G07 回声守望者事件（本包冻结值，气氛与调查机制的一部分，非战斗）：触发条件＝「已证实符号数 ≥3」∧「玩家位于封印密室」∧「本局未触发过」三者首次同时成立（在任一进行中的视频结束或跳过后执行）；演出时序——①环境光 0.8 秒内降至 15%；②水面倒影与远处人形轮廓浮现 1.5 秒；③守望者快速贴近镜头 0.6 秒；④屏幕闪白 0.15 秒＋水雾冲击粒子；音频——低频轰鸣自触发帧持续 1.2 秒 → 贴近帧切高频尖啸 0.4 秒 → 静音 0.2 秒；镜头——冲击震动 0.3 秒（中幅）；演出总时长 ≤4.0 秒，期间锁玩法输入；结束后——`echo_watcher_triggered=true`、玩家控制恢复、密室壁灯组点亮（新光源）、守望者壁龛刻纹显现并在线索笔记登记「壁龛刻纹」条目（指向星穹顶图 E 佐证的观测位置）；事件每局仅触发一次；全程不产生 HP、伤害、追逐或战斗状态。
- G08 结算评级（本包冻结值）：逃脱结算按误译次数与用时给出评级表达——误译 0 且用时 ≤1800 秒＝「纯净解封」；其余完成＝「常规解封」；用时 >3000 秒＝「仓促解封」；评级只改变结算文案、灯光表现与 C04 尾帧变体，不改变通关条件（保持单逃脱结局）。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：W/A/S/D＝移动；E＝搜证/机关/存档交互；Tab＝译义板；拖拽＝赋义与道具组合；R＝回滚当前假设；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：无对应佐证的证实操作被拒；组合材料不足被拒；机关前驱未满足提示缺口且不消耗；暂停/结算/守望者演出期间输入无效。
- I03 无手柄需求；译义板（三态）、道具栏、误译计数、当前房间、线索笔记与剩余时限须常驻可查。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；面板打开时玩法键不串入；守望者演出期间锁输入（≤4.0 秒）。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：当前房间、剩余时限、误译计数、符文假设状态（三态）、线索笔记条目数、道具栏；守望者事件后新增「壁龛刻纹」线索条目；HUD 对照见 rubric。
- I07 输入延迟目标：移动按键到画面反馈 ≤ 80 毫秒；交互（E/Tab/拖拽）反馈 ≤ 100 毫秒。

## 6. 机制系统 [M01–M05]

- M01 译义假设三态（主机制）
  - input：译义板赋义／佐证交互
  - precondition：赋义＝处于译义板且符号未证实；证实＝持有对应线索且在对应房间交互
  - state_change：未知→暂定→证实；误译→机关拒绝＋可回滚→未知
  - observable：假设状态机事件（三态合法转移才通过；非法转移拒绝）；线索笔记登记事件
  - invalid_case：非法转移（未知→证实、证实→暂定不经回滚）拒绝且无副作用
  - recovery：R 回滚当前假设重置为未知
- M02 跨室证据链
  - input：线索/佐证跨室携带（系统）
  - precondition：线索已在笔记登记
  - state_change：一室线索改变另一室机关的可解性
  - observable：跨室依赖事件（前驱未满足时机关拒绝并提示缺口）
  - invalid_case：未登记线索直接机关交互 → 拒绝
  - recovery：回取证物路径即可推进
- M03 道具依赖
  - input：道具组合/使用
  - precondition：组合材料齐备；使用场景匹配（钥芯仅用于密室封印槽）
  - state_change：组合→新道具→解锁路径与槽位
  - observable：组合事件与依赖图断言
  - invalid_case：材料不足组合被拒且不消耗
  - recovery：补齐材料重试
- M04 进度保存
  - input：房间节点保存（自动/手动）
  - precondition：玩家位于存档点或译义板打开
  - state_change：保存假设/道具/机关状态/误译计数/线索笔记 → 读档恢复
  - observable：存读档前后快照 diff=0
  - invalid_case：读取损坏存档 → 拒绝并保留原文（不清空进度）
  - recovery：读档即恢复
- M05 回声守望者（气氛事件，G07）
  - input：触发条件成立（系统判定）
  - precondition：「已证实符号 ≥3」∧「位于密室」∧「本局未触发」，且无进行中视频
  - state_change：执行 G07 演出时序（环境光→倒影与轮廓→贴近→闪白）；结束后置 `echo_watcher_triggered=true`、点亮壁灯组、登记「壁龛刻纹」线索
  - observable：`echo_watcher` 事件（含触发时刻、演出阶段时间戳、结束状态）；线索笔记新增条目事件
  - invalid_case：不满足触发条件时不得触发；已触发后同局不再触发
  - recovery：演出结束自动恢复玩家控制（≤4.0 秒锁输入）；无失败态、无战斗状态

跨阶段后果表（至少 1 条显式 A→B→C 链，早期状态在后续阶段仍可观察）：

- K01 阶段A（前厅取潮汐壁画佐证并为 A 赋义「潮」暂定）→ 阶段B（内室潮汐锁由拒绝转为可解、A 经验证转证实）→ 阶段C（密室六槽封印的 A 槽按「潮」对位，最终封印解序依赖 A 的证实状态）；验证方式=跨阶段回溯探针：阶段 A 结束记录假设快照 → 阶段 B 检查潮汐锁状态翻转 → 阶段 C 检查六槽封印对位与开启。
- K02 阶段A（前厅取得铜镜）→ 阶段B（内室取得刻刀并组合出反光刻片、再合封印钥芯）→ 阶段C（密室封印槽需钥芯才能开槽，逃脱路线依赖组合链）；验证方式=道具链依赖断言（缺任一前驱则密室槽不可开）。

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：6 符号全部证实并按真实译义对位完成六槽封印 → 开启封印逃脱 → 结算（显示误译次数、用时、佐证完成度、评级）。
- V02 失败条件：3600 秒超时判负（涨潮沉没结算）；软锁为红线（应不存在——发现即 FAIL 并记录缺陷）。
- V03 恢复语义：四级恢复——①误译回滚（重置该符号假设）；②节点存读档（每室入口自动＋译义板手动）；③房间重置（当前室机关与假设状态重置、道具保留、已证实符号不回退）；④一键重开全量清空。
- V04 persistent_state：跨室持久（译义假设、道具、机关状态、误译计数、线索笔记、echo_watcher_triggered 标志跨室保留；节点存档存读档；重开全量清空）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（进度/评级素材）局内保留；跨室状态按 V04 持久；无跨局保留（重开全量清空）。
- V06 软锁与不可达处理：不设永久软锁——关键目标均可通过正常操作达成，或触发 V02 失败路径进入结算；判定不可达时按 V02 失败语义结算而非无限等待。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：架空的「汐语环礁」海域，每逢大潮退去，一座沉在潮线之下的先民遗址短暂露出；碑文学会派出驻礁学者赶在下一次涨潮前完成拓印与解封。
- W02 场景所在地：汐语环礁的月潮遗址——潮汐前厅（入口与壁画）、刻文内室（月相与灯台）、封印密室（星穹顶与六槽封印台，最深层）。
- W03 玩家身份与当前任务：玩家是碑文学者「临」；当前任务：解读六枚潮汐符文的真实译义，激活三重机关，在涨潮前解开遗址封印。
- W04 失败代价与结局表达：超时＝涨潮吞没遗址（结算文案「潮水再临，遗址重眠」）；完成则 C04 呈现封印解开的潮光升腾，评级（纯净/常规/仓促）表达解封质量。
- W05 叙事来源：六符号（潮/月/火/水/星/门）＝先民记录潮汐历法的核心语汇；三重机关＝封印仪式的三个环节；「回声守望者」＝先民刻在壁龛中的看门者传说——遗址深层用以警示闯入者的「活刻文」，它是气氛与调查机制的一部分，不是敌人。
- W06 视觉风格与色彩材质：风格化写实的第一人称遗址；主色＝冷潮青（#2E5A66 系）＋石刻灰（#8A8F8C 系）＋符文潮金（#D9B96A 发光）；材质以湿石、水光反射、青苔与发光刻纹为主；密室整体暗于前厅（守望者事件前的低照度为氛围服务）。
- W07 环境氛围与声音语言：潮声环绕的寂静遗址——常驻潮汐低频、水滴与石厅回声；音效语言为「水滴＋石刻摩擦＋符文谐鸣＋守望者低频轰鸣」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代遗址与任务 → 机关开启（C02）与深层进入（C03）承载阶段叙事 → 守望者事件（G07 演出）深化「活刻文」传说并给出新线索 → 解封结算视频（C04）按评级收束；故事只做包装，不改变机制数值。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：5 个（text-to-3D 2，image-to-3D 3）；object 任务资产为：glyph_scholar, echo_watcher, rune_tablet, seal_altar, tidal_compass。每项只允许一个物体；组合物必须拆成独立任务。
- motion：3 个；覆盖动作：idle, walk, rub_interaction。
- video/audio/mechanic/UI：分别为 4/13/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

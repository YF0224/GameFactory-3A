## 1. 定位与完整流程 [S01–S05]

- S01 类型：3D 俯视固定俯角潜行，单人单局。能力：视线/识别/警戒状态机、噪声半径与诱饵、撂倒、应急照明周期、检查点、档案获取与撤离、开场与结局视频、潜行氛围演出层。
- S02 核心循环一句话：观察守卫视锥与照明周期 → 控噪移动 → 规避或诱饵 → 抵达档案室 → 携档案撤离。
- S03 流程：标题 → 前院潜入 → 档案大厅（CP2）→ 获取机密档案（CP3）→ 撤离走廊 → 撤离舱口交互 → 结算（成功/失败）→ 重开或返回。
- S04 最低完整流程：标题、游玩、成功结算、失败结算、重开全部存在且有真实入口。
- S05 失败恢复入口：失败结算提供「从检查点重试」与「重开整局」；Esc 暂停可继续/重开/返回。

## 2. 完整核心循环与阶段 [S06–S12]

- S06 启动与标题
  - input：系统加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且资源加载完成
  - state_change：进入「标题」；首次开始前按 §10 C01 播开场视频
  - feedback：标题界面按 §9 F10
  - next_actions：进入「前院潜入」
  - outcome：无跨局状态
- S07 前院潜入
  - input：WASD/C 蹲伏/Shift 奔跑/G 诱饵/E 交互/Esc（触发方：玩家）
  - precondition：处于前院（CP1）
  - state_change：按 §6 M02–M05 结算识别度、噪声与守卫状态
  - feedback：识别度条与心跳按 §9 F05；照明周期按 M08
  - next_actions：进入档案大厅 →「大厅潜入」；被发现至 L2 →「警戒/逃脱」
  - outcome：守卫相位与警戒等级实时更新
- S08 大厅潜入
  - input：同 S07（触发方：玩家）
  - precondition：抵达档案大厅入口（CP2 快照）
  - state_change：档案室交互 3s 取得机密档案匣（CP3）
  - feedback：高掩体/低掩体视线遮挡按 M02；档案室灯光提示
  - next_actions：取得档案 →「撤离段」
  - outcome：档案持有态=true
- S09 撤离段
  - input：同 S07（触发方：玩家）
  - precondition：持有档案，抵达撤离走廊
  - state_change：走廊尽头舱口交互 2s → V01 成功
  - feedback：撤离点指引光（信息性 VFX）
  - next_actions：撤离成功 →「胜利结算」
  - outcome：按 V01 判定
- S10 警戒/逃脱（可发生于任意段）
  - input：系统驱动（触发方：系统）
  - precondition：识别度满 100（L1）或 L1 再满（L2）
  - state_change：L1=守卫前往最后目击点调查 20s；L2=全体搜索、移速 +50%、见即攻击；L2 脱离全部视线 45s → L0 恢复
  - feedback：守卫头顶指示条+心跳渐快；L1/L2 背景音乐切换+画面边缘变色（黄/红）
  - next_actions：L2 持续 120s 未恢复 →「失败结算」
  - outcome：警戒等级状态机事件流水
- S11 结算
  - input：Enter=重试/重开 / Esc=返回（触发方：玩家）
  - precondition：V01 或 V02 成立
  - state_change：成功面板（评级：未被击杀/全程未惊动/撂倒数，面板前按 §10 C04 播撤离成功视频）或失败面板（HP0 或封锁，面板前按 §10 C03 播失败视频）
  - feedback：结算面板显示评级/原因
  - next_actions：从检查点重试或重开整局
  - outcome：检查点重试按 CP 快照恢复；整局重开全量清空
- S12 暂停
  - input：Esc（触发方：玩家）
  - precondition：处于游玩状态
  - state_change：暂停覆盖层打开，守卫、识别度、照明周期计时全部冻结
  - feedback：暂停面板（继续/重开/返回/设置）
  - next_actions：恢复回到游玩
  - outcome：恢复后状态逐字段一致；窗口失焦自动暂停

## 3. 数值口径与全局规则 [G01–G08]

- G01 统一刻度：设施为三段连续空间（米制）；状态变量=玩家 HP/姿态、守卫位置与状态机相位、识别度（0–100）、警戒等级（L0/L1/L2）、诱饵库存、档案持有态、照明周期相位 t。
- G02 视线与掩体：守卫视锥半角 45°、视距 12m（应急照明亮灯期 18m，见 M08）；高掩体 2.0m 遮挡全部视线；低掩体 1.0m 仅遮挡蹲伏玩家（身高 0.9m），站立玩家（1.7m）可见。
- G03 识别度：玩家在视锥内无遮挡曝露时，站立 +40/s、蹲伏 +25/s；遮挡不累计；离开视锥 −20/s 衰减至 0。oracle：站立 2.5s（40×2.5=100）→ L1；蹲伏 4.0s；脱离视锥 5.0s（100/20）归零。识别度满 100 → L1 怀疑；L1 下再满 100 → L2 警戒。
- G04 噪声半径：蹲伏 0m、步行 4m、奔跑 12m、诱饵落点 15m；半径内守卫被吸引 → 前往声源调查 20s → 返回原路线与相位；诱饵每局 3 个、冷却 10s、投掷最大 8m。
- G05 玩家：蹲伏 1.5 / 步行 3.0 / 奔跑 5.5 m/s；HP 100；无非致命手段以外的攻击方式。
- G06 守卫：巡逻 2.0 / 调查 2.5 / L2 追击 3.5 m/s；攻击=2m 内每 1.0s 扣 20；撂倒（E）=背后 1.5m 内、动作 1.5s（玩家不可移动）、仅巡逻/调查/可疑状态守卫可撂倒、昏迷 90s（L2 搜索/追击态不可撂倒）。
- G07 暂停与模拟时间：Esc 暂停冻结守卫/识别度/照明周期/逃脱计时；失焦自动暂停；恢复无漂移。
- G08 状态转移 oracle（独立可复核）：初始识别度 0、守卫 A 巡逻态；玩家站立进入其视锥并保持 → 2.5s 时产生 `alert(L1)` 且守卫 A 转调查态前往最后目击点；任何偏离即 FAIL。

## 4. 操作与输入 [I01–I07]

- I01 键位：WASD=按相机方向移动；C=蹲伏切换（即时无延迟）；Shift（按住）=奔跑；E=撂倒/交互（档案 3s、撤离 2s）；G=投掷诱饵；Esc=暂停；Enter=结算确认。
- I02 输入语义边界：目标非背后 1.5m 内或处于 L2 态 → E 撂倒无效且无副作用；诱饵库存 0 或冷却中 → G 无效；交互被移动/受击打断 → 无副作用；面板打开时玩法键一律拒绝。
- I03 键盘为完整输入方式；鼠标仅用于 UI。
- I04 输入优先级：暂停/结算阻断玩法输入；同帧顺序=暂停 > 交互 > 移动。
- I05 焦点与失焦：点击画布捕获；失焦自动暂停。
- I06 UI 必显状态：玩家 HP、识别度条、警戒等级（L0/L1/L2）、诱饵库存、档案持有态、当前检查点。
- I07 输入延迟目标：≤100 毫秒（蹲伏/站立切换即时）。

## 6. 机制系统 [M01–M09]

- M01 守卫感知（视锥）
  - input：系统每帧驱动（触发方：系统）
  - precondition：守卫存活且非昏迷
  - state_change：视锥半角 45°、视距 12m（亮灯期 18m）；高掩体全遮挡、低掩体仅遮挡蹲伏玩家
  - observable：`spot_progress(value)` / `alert(level)` 事件
  - invalid_case：遮挡期间识别度冻结不累计
  - recovery：脱离视锥按 −20/s 衰减
- M02 识别度与警戒状态机
  - input：系统按 G03 累计（触发方：系统）
  - precondition：玩家在视锥内
  - state_change：满 100 → L1（守卫前往最后目击点调查 20s）；L1 再满 → L2（全体搜索、移速 +50%、见即攻击）；L2 脱离全部视线 45s → L0；L2 持续 120s → V02 失败
  - observable：`alert(L0/L1/L2)` 事件与守卫状态快照
  - invalid_case：L0 无搜索行为
  - recovery：L2 逃脱计时 45s 恢复
- M03 噪声与诱饵
  - input：玩家移动产生噪声；G 投掷诱饵（触发方：玩家）
  - precondition：诱饵库存 >0 且非冷却
  - state_change：按 G04 半径吸引守卫前往声源调查 20s；诱饵 −1、冷却 10s
  - observable：`noise(radius, pos)` / `decoy_throw` 事件
  - invalid_case：库存 0 或冷却中 → 拒绝无副作用
  - recovery：守卫调查后返回原路线与相位
- M04 撂倒
  - input：E（触发方：玩家）
  - precondition：目标守卫为巡逻/调查/可疑态且在背后 1.5m 内
  - state_change：动作 1.5s（玩家不可移动）→ 目标昏迷 90s
  - observable：`takedown(g)` 事件
  - invalid_case：L2 搜索/追击态守卫不可撂倒 → E 无效无副作用
  - recovery：昏迷守卫 90s 后苏醒回巡逻
- M05 玩家移动与姿态
  - input：WASD/C/Shift（触发方：玩家）
  - precondition：处于游玩状态
  - state_change：按 G05 移速切换；蹲伏降低可探测性（识别度 +25/s、低掩体遮挡）
  - observable：姿态事件与坐标流水
  - invalid_case：蹲伏下按 Shift 不奔跑（仅站立可奔跑）
  - recovery：C 即时切换（≤I07 延迟）
- M06 档案获取与撤离
  - input：E（触发方：玩家）
  - precondition：档案室 3s 交互 / 舱口 2s 交互
  - state_change：档案持有态=true；撤离交互完成 → V01
  - observable：`archive_taken` / `extracted` 事件
  - invalid_case：交互被打断 → 无副作用
  - recovery：档案持有后死亡不丢档（检查点恢复）
- M07 检查点
  - input：跨段触发（触发方：系统）
  - precondition：首次进入大厅（CP2）/取得档案（CP3）
  - state_change：快照=守卫位置与状态机相位、警戒等级回 L0、诱饵库存、档案持有态、玩家 HP
  - observable：`checkpoint(n)` 事件与快照
  - invalid_case：重复触发被拒
  - recovery：失败后从检查点恢复快照
- M08 应急照明周期（新增）
  - input：系统计时（触发方：系统）
  - precondition：本局开始即启动
  - state_change：备用电源每 30s 闪亮 5s；亮灯期守卫视距 12→18m、识别度累计 ×1.5（照明→视锥→识别度 A→B 边）；oracle：亮灯期站立 40×1.5=60/s → 100/60=5/3 秒≈1.67s 触发；蹲伏 25×1.5=37.5/s → 8/3 秒≈2.67s
  - observable：`light_on/off` 事件与场景明暗渐变
  - invalid_case：黑暗期恢复 12m 与原速率
  - recovery：暂停冻结周期相位 t
- M09 撂倒暴露（新增）
  - input：系统检测（触发方：系统）
  - precondition：场上有昏迷守卫
  - state_change：昏迷守卫被其他守卫视锥看见（无遮挡、视距内）→ 设施警戒直接升 L1
  - observable：`body_spotted` + `alert(L1)` 事件
  - invalid_case：已被 L2 覆盖时不再触发
  - recovery：警戒状态机自行管理

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：取得机密档案并完成撤离交互 → 成功结算（成功面板前按 §10 C04 播放撤离成功视频），评级显示「未被击杀/全程未惊动/撂倒守卫数」。
- V02 失败条件：玩家 HP0（被击倒）或 L2 持续 120s（设施封锁）→ 失败结算并注明原因。
- V03 恢复语义：失败后「从检查点重试」=恢复 CP 快照（守卫位置/警戒 L0/库存/档案态/HP）；「重开整局」=全量重置。
- V04 persistent_state：无跨局持久状态（评级仅为局内统计）。
- V05 persistent_state 生命周期：动作级即时；局内检查点保留本局快照；重开清空。
- V06 软锁与不可达处理：不设永久软锁——诱饵与蹲伏永远可用；被 L2 围堵可靠躲藏点脱出；120s 封锁兜底结束。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：近未来，「灰堡」档案设施——垄断财团存放敏感档案的地下库区，一次人为破坏导致全站停电。
- W02 场景所在地：灰堡前院、档案大厅、撤离走廊三段结构；备用电源的应急照明每 30 秒挣扎着亮起 5 秒。
- W03 玩家身份与当前任务动机：玩家是受雇的档案回收者，只有趁备用电源恢复、安保重启之前带走那份档案。
- W04 失败代价与结局表达：失败=被安保击倒或设施封锁；结局表达见 §10 C03——警报红光下的封锁走廊为失败意象。
- W05 叙事来源：守卫=设施私人安保；机密档案=财团罪证；停电=内部告密者的配合。全部原创。
- W06 视觉风格与色彩材质：冷色低光潜入风；主色=档案灰 #4A4E55、应急灯冷白 #C8D4DC、警戒红 #D64541、档案金 #C9A876；材质为金属格栅地面、地毯、钢制档案柜。
- W07 环境氛围与声音语言：停电低鸣环境声；关键声音分层：脚步（金属格栅/地毯两种材质可辨）、心跳、警报、撂倒闷响；关键声音不得被环境音遮挡（F07）。
- W08 故事表达方式：开场视频（C01）交代停电与潜入 → 警戒事件（C02）承载过程张力 → 双结局视频（C03 失败封锁 / C04 携档而归）收束；故事只做包装不改数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：俯视固定俯角（可缩放两档）；镜头边界=当前段空间外接矩形+8%。
- F02 关键操作镜头变化：L2 警戒时镜头轻微下沉+边缘红晕；撂倒瞬间 0.1s 顿帧；无持续震动。
- F03 输入与延迟：见 I07；蹲伏切换即时。
- F04 环境常驻效果：停电低鸣、应急灯呼吸、档案室微光。纯表现层。
- F05 事件反馈表（冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 识别度上涨 | 守卫头顶指示条渐满 | 心跳渐快 | 识别度归零或警戒触发 |
| L1 警戒 | 画面边缘黄晕 | 警戒音乐切入 | 恢复 L0 |
| L2 警戒 | 画面边缘红晕+守卫红色标记 | 警报音乐加强 | 逃脱计时或失败 |
| 撂倒 | 守卫瘫倒+0.1s 顿帧 | 短促顿挫+闷响 | 动作完成 |
| 蹲伏切换 | 姿态即时切换 | 布料摩擦轻响 | 即时 |
| 诱饵落地 | 声波圈扩散 | 落地碰撞声 | 声波消散 |
| 档案拾取 | 档案匣高亮+入包动画 | 纸张与锁扣声 | 交互完成 |
| 撤离成功 | 舱口开启光柱 | 撤离完成音 | 进入结算 |
| 失败 | 画面降饱和 | 低沉失败音 | 进入面板 |

- F06 关键音效清单（one_shot）：金属格栅脚步、地毯脚步、心跳渐快、L1 音乐切换、L2 音乐切换、撂倒闷响、蹲伏切换、档案拾取、撤离完成、诱饵落地、守卫苏醒；环境循环：停电低鸣（常驻，暂停静音）；无配音需求。
- F07 VFX 信息性与遮挡约束：识别度条、警戒边缘色、声波圈为信息性 VFX 必须可辨；金属格栅与地毯脚步声可区分（噪声半径的视听反馈）；环境音不得掩盖脚步方位、警报与心跳（关键声音优先级：警报>心跳>脚步>环境）。
- F08 音画同步：脚步声与步频同帧；撂倒音与顿帧同帧起止。
- F09 屏幕震动：仅 L2 触发瞬间 0.15s 小幅；设置可关闭。
- F10 前端界面：标题 → HUD（I06 全项）→ 成功/失败面板 → 暂停面板；关键状态图标+文字并用；失焦自动暂停。

## 10. 过场视频 [C01–C04]

- C01 停电之夜（Opening，8 秒，1280×720@24fps）
  - 触发时机：首次由标题进入前院之前，每局一次
  - 内容与角色场景：灰堡设施灯光骤然熄灭，备用电源指示灯闪烁；一名潜入者翻过庭院围栏没入阴影，应急灯在墙面投下短暂光带
  - 资产对应：潜入者、守卫、前院与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入前院；自然播完 → 进入前院
  - 状态一致：播放期间不推进任何计时
- C02 警戒拉响（Event，6 秒，1280×720@24fps）
  - 触发时机：首次进入 L2 警戒时，每局一次
  - 内容与角色场景：红色警报灯旋转扫过档案大厅，守卫们从各方向举灯汇聚；潜入者贴在档案柜阴影中屏息
  - 资产对应：守卫、大厅与游戏内同源
  - 可跳过：Esc/Enter 跳过 → 直接继续游玩；播完 → 继续游玩
  - 状态一致：播放期间警戒计时冻结，L2 状态保持
- C03 封锁之夜（Ending，8 秒，1280×720@24fps）
  - 触发时机：V02 成立、失败面板出现之前，每局一次
  - 内容与角色场景：警报红光下走廊尽头舱口缓缓闭合，守卫持灯封锁通道；潜入者视角画面渐暗
  - 资产对应：走廊、舱口、守卫与游戏内同源
  - 可跳过：Esc/Enter 跳过 → 直接进入失败面板；播完 → 进入失败面板
  - 状态一致：仅在真实 V02 后触发
- C04 携档而归（Ending，7 秒，1280×720@24fps）
  - 触发时机：V01 成立（撤离交互完成）、成功面板出现之前，每局一次
  - 内容与角色场景：潜入者从舱口跃出翻过庭院围栏，怀中档案匣紧贴胸口；身后设施应急灯仍在闪烁，远处天际透出黎明微光；潜入者没入巷影，镜头定格于围栏上留下的一个浅浅鞋印
  - 资产对应：潜入者、档案匣、围栏与游戏内模型同源
  - 可跳过：Esc/Enter 跳过 → 直接进入成功面板；播完 → 进入成功面板
  - 状态一致：仅在真实达成 V01 后触发，与真实游戏进度一致；播放期间不推进任何计时

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：5 个（text-to-3D 3，image-to-3D 2）；object 任务资产为：infiltrator, patrol_guard, archive_case, decoy_thrower, cover_cabinet_set。每项只允许一个物体；组合物必须拆成独立任务。
- motion：6 个；覆盖动作：crouch_walk, walk_stealth, vault_window, takedown_action, interact_archive, hit_react。
- video/audio/mechanic/UI：分别为 4/13/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

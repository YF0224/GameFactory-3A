## 1. 定位与完整流程 [S01–S06]

- S01 类型：3D 俯视迷你高尔夫（单人杆数制）。本测例包含的能力：三洞冻结球场、蓄力击球物理、坡面反弹摩擦、瞄准线与轨迹残影反馈、界外复位与罚杆、双镜头模式、开场/结算视频。
- S02 核心循环一句话：瞄定力度方向 → 击球 → 物理滚动 → 进洞或补杆 → 结算杆数。
- S03 流程：标题 → 球洞1 → 球洞2 → 球洞3 → 总结算（杆数对比标准杆）；每洞自动开球。
- S04 最低完整流程：标题、三洞球场、每洞 HUD（当前杆数）、总结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：界外自动复位回上一杆位＋罚 1 杆；总结算界面一键重开；Esc 暂停。
- S06 与种子卡差异：种子卡杆数为「规则化高尔夫全流程」；本包冻结为三洞切片（标准杆 12），P0 局内口径不变。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：启动与标题 → 球洞1 → 球洞2 → 球洞3 → 总结算 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且球场按 seed=1056 生成完成
  - state_change：进入「标题」状态；首次进入按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10 呈现
  - next_actions：进入「球洞1」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 球洞1（直道平地，标准杆 3）
  - input：鼠标瞄准、按住左键蓄力、松开击球、R 重打、C 镜头切换、Esc 暂停（触发方：玩家）
  - precondition：洞1 载入完成且球静止于发球点
  - state_change：击球按 G02 公式生成初速 → 物理结算
  - feedback：瞄准线/蓄力条/轨迹残影按 §9 F05 呈现
  - next_actions：入洞 →「球洞2」；8 杆上限 → 强制完成进下一洞
  - outcome：本洞杆数累计局内
- S08 球洞2（缓上坡＋单挡板折返，标准杆 4）
  - input：同 S07（触发方：玩家）
  - precondition：洞1 完成（入洞或达上限）
  - state_change：载入洞2；坡面与挡板按 L02 冻结
  - feedback：坡面瞄准线变浅提示减速
  - next_actions：入洞 →「球洞3」
  - outcome：杆数累计
- S09 球洞3（阶梯坡＋双挡板，标准杆 5）
  - input：同 S07（触发方：玩家）
  - precondition：洞2 完成
  - state_change：载入洞3；阶梯坡与双挡板生效
  - feedback：反弹火花与入洞反馈
  - next_actions：入洞或达上限 →「总结算」（先播 C02）
  - outcome：按 V01 结算
- S10 总结算
  - input：Enter＝重开 / Esc＝返回标题（触发方：玩家）
  - precondition：三洞全部完成
  - state_change：进入「总结算」状态
  - feedback：总结算面板显示总杆数、对比标准杆 12、罚杆数
  - next_actions：重开或返回
  - outcome：无跨局写入
- S11 暂停
  - input：Esc（触发方：玩家）
  - precondition：处于任一洞
  - state_change：暂停覆盖层打开；球、物理与蓄力冻结
  - feedback：暂停面板（继续/本洞重打/返回标题/设置）
  - next_actions：Esc 或「继续」→ 恢复
  - outcome：恢复后无状态漂移（G04）

## 3. 数值口径与全局规则 [G01–G05]

- G01 统一刻度：距离米制；力度为 0–100% 蓄力条（数值常显）；杆数为整数。
- G02 物理与公式（本包冻结值）：击球初速 v＝蓄力比例 × 12 米/秒；平地滚动摩擦减速度 1.5 米/秒²；坡道沿坡向加速度分量 3.0 米/秒²；碰撞恢复系数 0.6。独立 oracle 数例：平地直线满蓄力 50% 击球 v＝6 米/秒，纯滚动距离＝v²/(2×1.5)＝**12 米**；蓄力 100% 为 48 米。
- G03 杆数与罚则（本包冻结值）：三洞标准杆 3/4/5（总标准杆 12）；界外复位每次罚 1 杆；每洞杆数上限 8 杆，达上限自动按 8 杆＋累计罚杆记入并进入下一洞（无硬失败）。
- G04 暂停与随机：Esc 暂停冻结球与物理；窗口失焦自动暂停；fixed_seed=1056 冻结三洞地形布置；本作物理为确定公式，无概率判定。
- G05 瞄准与轨迹反馈（本包冻结值）：击球准备时显示瞄准虚线——长度＝按当前蓄力的预计纯滚动距离 × 60%，不显示反弹/坡面后路径，坡面段虚线透明度降低 40% 提示减速；蓄力条 0–100% 数值与当前蓄力同步；球滚动中显示轨迹残影（0.5 秒渐隐，仅保留最近一条）。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：鼠标移动＝瞄准方向；按住左键蓄力、松开击球；C＝俯视全览/击球视角切换；R＝本洞重打（罚 1 杆）；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：球滚动中击球无效；蓄力不足 5% 松开视为取消（不耗杆）；暂停/结算期间输入无效；被拒输入不产生杆数变化。
- I03 无手柄需求。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；俯视全览模式下击球无效（须切回击球视角）；同帧多输入按瞄准→蓄力→击球顺序结算。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：当前洞号、本洞已用杆数与上限、蓄力条数值、罚杆数、镜头模式提示；HUD 对照见 rubric。
- I07 输入延迟目标：蓄力/击球按键到画面反馈 ≤ 50 毫秒（手感关键）；镜头切换 ≤ 150 毫秒。

## 5. 关卡与内容清单 [L01–L04]

- L01 生成对象：高尔夫球 1、三洞（洞杯、旗杆、发球点）、坡面与挡板若干、瞄准线与蓄力条 UI、轨迹残影；花园装饰为表现层。
- L02 球洞（seed=1056 冻结地形）：洞1 直道平地 12 米（标准杆 3）；洞2 缓上坡＋单挡板折返（标准杆 4）；洞3 阶梯坡＋双挡板（标准杆 5）。
- L03 目标物/交互物/场景/UI 对象：本 spec §3–§9 引用的界面元素（标题/HUD/结算/暂停/视频播放层）与交互物逐类存在且运行时可进入；数量与属性以 L01/L02 与 G 系为准。
- L04 冻结需求 vs 实现默认 vs 生成自由度：本 spec 明确写出的数值与数量为冻结需求；§9 未冻结的花园装饰与配色为生成自由度，不得评估为缺失；实现默认值必须明确标注且符合核心机制。

## 6. 机制系统 [M01–M05]

- M01 力度方向与物理（主机制）
  - input：瞄准＋蓄力击球
  - precondition：球静止且处于击球准备状态（非俯视全览）
  - state_change：按 G02 公式生成初速向量 → 球滚动/反弹
  - observable：逐帧球位置采样与初速、距离事件（见 G02 oracle）；`stroke` 事件（含初速与角度）
  - invalid_case：滚动中击球、全览模式击球 → 拒绝且不耗杆
  - recovery：球静止即恢复击球准备
- M02 坡面反弹与摩擦
  - input：地形接触（系统）
  - precondition：球与坡面/挡板碰撞
  - state_change：坡面改变速度分量（沿坡 3.0 米/秒²）；碰撞按恢复系数 0.6 反弹
  - observable：接触/反弹事件与速度分量差分
  - invalid_case：无碰撞则纯摩擦结算
  - recovery：—
- M03 界外复位
  - input：球坠出球场边界（系统）
  - precondition：球越过 L02 边界
  - state_change：回上一杆位＋罚 1 杆；连续界外不叠加惩罚上限以外的额外状态；镜头回上一杆位
  - observable：`out_of_bounds` 事件（含罚杆字段）
  - invalid_case：贴边滚动不触发
  - recovery：复位即恢复击球
- M04 杆数判定
  - input：球入洞（系统）/ 达上限（系统）
  - precondition：球与洞杯判定重叠且速度低于阈值
  - state_change：本洞完成 → 下一洞；达 8 杆上限强制完成；三洞完成 → 总结算
  - observable：`hole_complete` 事件与杆数流水（含罚杆）
  - invalid_case：高速掠过洞杯不判入洞（速度阈值）
  - recovery：—
- M05 瞄准与轨迹反馈
  - input：瞄准移动／蓄力变化（玩家）
  - precondition：击球准备状态
  - state_change：瞄准虚线长度与坡面透明度按 G05 更新；蓄力条数值同步；击球后生成轨迹残影（0.5 秒渐隐，替换旧残影）
  - observable：虚线长度采样与预计距离的 60% 对账；残影出现/渐隐事件
  - invalid_case：全览模式不显示虚线（切回即恢复）
  - recovery：—

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：完成三洞 → 总结算（显示总杆数、对比标准杆 12 与罚杆数）。
- V02 失败条件：无硬失败态；每洞 8 杆上限强制推进（记为上限完成）。
- V03 恢复语义：界外自动复位＋罚 1 杆；R 重打本洞（罚 1 杆、回发球点）；结算后一键重开。
- V04 persistent_state：无（重开全量清空；累计杆数仅本局内保留）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（杆数/洞进度）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设永久软锁——8 杆上限保证推进；界外复位兜底；任意洞可完成。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：架空云海时代的「浮屿花园」——园艺师们在漂浮于云海的花屿上经营三洞试炼球场，庆祝春分的推杆大会今夜开杆。
- W02 场景所在地：浮屿花园的三座花洞——直道花径（洞1）、上坡藤架（洞2）、阶梯石台（洞3），云海在球场边缘流动。
- W03 玩家身份与当前任务：玩家是见习园艺师「芽衣」；当前任务：在推杆大会上以不超过标准杆的成绩完成三洞，取得正式园丁资格。
- W04 失败代价与结局表达：本作无失败态；超标准杆仅影响成绩表达；完成则 C02 呈现大会颁奖与花灯升空。
- W05 叙事来源：三洞＝园艺师资格考试的三个科目（直道基本功/坡度控球/复杂地形）；旗杆与洞杯＝试炼花器；云海边界＝浮屿边界（界外即坠云）。全部原创。
- W06 视觉风格与色彩材质：明快风格化 3D 花园；主色＝草甸绿（#7CB26B 系）＋花瓣粉（#E8A0B8 系）＋云海白蓝（#C9DCE8 系）；材质以草坪、木挡板、石台为主，光线为春日暖光。
- W07 环境氛围与声音语言：云海微风的春日花园——常驻风拂草浪与远处鸟鸣；音效语言为「击球脆响＋滚动沙沙＋碰撞闷响＋入洞清脆」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代浮屿与大会 → 三洞推进承载试炼节奏 → 结算视频（C02）收束颁奖；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头（冻结需求）：默认击球视角＝发球/停球点后方第三人称（俯角 45°，距离 5 米），瞄准方向随鼠标旋转；球滚动时镜头平滑跟随球（0.2 秒插值，速度上限 12 米/秒避免甩镜）；球静止 1 秒后镜头回击球准备位；C 键切换「俯视全览」（整洞 60° 俯视，不参与击球）；镜头边界＝球场外框外扩 10%；界外复位/换洞时镜头直接落位（无漂移）。
- F02 关键操作镜头变化：入洞瞬间镜头轻微推近洞杯 5%（0.5 秒）；出界瞬间镜头短暂拉高 10%（0.4 秒）；无慢动作。
- F03 输入与延迟：见 I07（击球手感为 S 档核心，≤50 毫秒）。
- F04 环境常驻效果：花瓣随风飘落（低频）、云海缓慢流动、旗杆旗面摆动；不遮挡瞄准线与洞杯。
- F05 事件反馈表（事件 → 表现 → 结束条件，全部为冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 蓄力开始 | 蓄力条展开＋数值跳动 | 蓄力低鸣（按住循环，音调随力度升高） | 松开或取消 |
| 击球 | 球推出＋草地小尘环＋轨迹残影启动 | 击球脆响 | 残影 0.5s 渐隐 |
| 球滚动 | 轨迹残影跟随＋草浪压痕 | 滚动沙沙（滚动中循环） | 球停 |
| 碰撞挡板 | 火花小粒子＋球体挤压回弹 | 碰撞闷响 | 回弹完成 |
| 上坡减速 | 瞄准线透明度提示（击球前）/球速渐减 | 沙沙声减弱 | 坡段结束 |
| 出界 | 球坠云＋镜头拉高＋「界外＋1 杆」提示 | 坠落风声 | 复位完成 |
| 入洞 | 球旋入洞杯＋旗杆亮灯＋花瓣迸溅 | 入洞清脆音 | 进入下一洞 |
| 达杆数上限 | 「本洞按 8 杆计」横幅 | 低提示音 | 推进下一洞 |
| 三洞完成 | 花灯升空粒子 | 结算上扬音 | 进入总结算 |

- F06 关键音效清单：蓄力低鸣、击球脆响、滚动沙沙、碰撞闷响、坠落风声、入洞清脆音、低提示音、上扬音；环境音：风拂草浪＋云海低鸣＋远处鸟鸣（常驻循环）；循环音开始/结束：滚动沙沙按滚动起止、蓄力低鸣按按住起止、环境声随球场载入开始、随结算淡出 0.5s；无配音需求。
- F07 VFX 信息性与遮挡约束：瞄准虚线与蓄力条承担击球信息；轨迹残影承担落点复盘信息；花瓣与草浪粒子单帧 ≤ 35 且不遮挡瞄准线、洞杯与 HUD。
- F08 音画同步：击球脆响与击球帧同步；碰撞闷响与接触帧同步；入洞清脆音与入洞事件帧同步。
- F09 屏幕震动：入洞 0.1 秒小幅；碰撞 0.05 秒微幅；设置界面提供「镜头震动开/关」（关闭不影响判定）。
- F10 前端界面：标题（开始/设置/退出）→ HUD（洞号、杆数/上限、蓄力条数值、罚杆、镜头模式提示）→ 总结算（总杆数/对比标准杆 12/罚杆/重开/返回）→ 暂停面板（继续/本洞重打/返回标题/设置）；关键状态附图标＋文字（镜头模式、界外提示），不只靠颜色区分；窗口失焦自动暂停。

## 10. 过场视频 [C01–C02]

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：3 个（text-to-3D 2，image-to-3D 1）；object 任务资产为：gardener_mei, golf_ball, hole_flag。每项只允许一个物体；组合物必须拆成独立任务。
- motion：2 个；覆盖动作：idle, putt_swing。
- video/audio/mechanic/UI：分别为 2/9/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

## 2. 数值口径与全局规则 [G01–G10]

- G01 统一刻度：比分、资金、招募点、训练币、碎片按整数；体力为百分比；比赛时钟自动推进（模拟时间）。
- G02 比赛奖励（本包冻结值）：胜/平/负分别获得招募点 240/140/100、训练币 300/200/150、转会资金 900/600/450；终场仅结算一次，刷新终场不重复奖励。
- G03 转会价格公式（本包冻结值）：价格＝稀有度基价（R 700、SR 1600、SSR 3600）＋基础能力均值×10＋(等级−1)×80＋星级×180，再按 10 取整。独立 oracle 数例（由公式代入）：R 稀有、基础能力均值 50、等级 3、星级 2 → 700＋500＋160＋360＝1720；出售得估值 55%＝946；回购按完整估值 1720（价差 774 防止无成本循环获利）。任何偏离即 FAIL。
- G04 抽卡与碎片（本包冻结值）：单抽消耗招募点 100、十连消耗招募点 900（团队交付口径：十连只扣 900 点）、稀有保底、SSR 第 30 抽保底；重复卡产生碎片；每 5 碎片可换 60 转会资金；初始转会资金 5000；比赛进行中锁定招募与转会；报价版本、抽卡锁与动作令牌防重复确认。
- G05 出售约束（本包冻结值）：出售得估值 55%；禁止出售首发球员、人数不足五人或最后一名门将；出售保存培养归档，签回或再抽到该球员恢复等级、星级和碎片。
- G06 比赛节奏（本包冻结值）：时钟自动推进，关键攻防暂停等待组合选择；支持暂停与 1 倍/2 倍速度；每次进攻最多六步，整个关键机会有总步数上限，不能无限重复拖延。
- G07 随机与复现：fixed_seed=1058 用于评测注入（动作概率抽样、抽卡序列）；概率项须显示概率并以固定种子或注入随机值核验，不以单次成败判定正确性。
- G08 比赛阶段与镜头（本包冻结值）：单场结构＝开场（开球动画）→ 上半场（第 1–3 个关键机会）→ 中场（换人/战术窗口）→ 下半场（第 4–6+ 个关键机会）→ 终场结算；阶段切换事件 `phase_change` 可观测；俯视镜头固定全局（沿袭 S01），进球后 2 秒定格推近（朝球门方向缩放 +8%）并显示球轨迹残影（0.6 秒渐隐），随后回全景。
- G09 球权与状态显示（本包冻结值）：持球方以持球球员脚下光环＋HUD 球权图标常驻显示——三态＝本方（绿光环＋「我方球权」）、对方（红光环＋「对方球权」）、争夺中（黄光环＋「争夺中」）；球权转换事件 `possession_change` 可观测且与动作结算严格一致（抢断/拦截/解围/失误推进受阻必触发）。
- G10 中断、暂停与重开（本包冻结值）：比赛进行中 Esc 暂停（暂停冻结模拟，1×/2× 倍速仅比赛进行中生效）；比赛中断（关闭页面/刷新）按 K03 刷新语义恢复（比分/球权/体力保留并暂停等待继续）；单场重开＝结算界面「重新比赛」（当轮重赛，seed 复现该场概率序列）；「重新开始赛季」需二次确认并清空档内赛季进度（K05 语义）。

## 4. 机制系统：17 种足球动作 [M01–M17]

全部动作都有场景限制、体力代价、概率显示、状态结果和动作/足球轨迹反馈。类别构成：进攻 9（M01–M09）、防守 4（M10–M13）、守门 1（M14）、定位球 3（M15–M17），共 17 种主要类别动作。

- M01 短传：选择接球目标，成功切换持球人、推进 8% 并增加配合；消耗执行者体力。
- M02 直塞：选择接球目标，成功推进 22%，较易被截；失误转入防守。
- M03 盘带：持球人突破推进 15%；可能因对手犯规得到任意球或点球。
- M04 冲刺：推进 24%，消耗较多体力；失误、造犯规遵循对应状态规则。
- M05 射门：进球改变比分；失误结束攻势或产生角球。距离、配合、能力、战术、疲劳影响概率。
- M06 传中：选接球目标，成功进入高球争夺，随后可头球、凌空或停球。
- M07 头球：高球场景直接攻门，成功改变比分。
- M08 凌空射门：高球直接攻门，风险和体力代价较高。
- M09 停球：卸下高球转为地面持球；失误让对方发动攻势。
- M10 抢断：成功夺回球权并转为进攻；失败让对方推进。
- M11 铲球：争回球权，另有 22% 犯规风险；对方得到任意球或点球时进入门将扑救。
- M12 拦截：成功夺回球权并创造较好的反击位置。
- M13 解围：消耗体力、安全结束本轮对手攻势。
- M14 扑救：由门将执行，成功保住比分；失败增加对方比分。对方点球比普通射门难扑救。
- M15 任意球：可直接攻门，成功/失败影响比分和后续球权。
- M16 点球：可实际罚球，成功/失败改变比分或结束攻势。
- M17 角球：开入禁区，随后选择头球、凌空或停球。

系统耦合边（玩法必需、可复现）：

- E01 from_system=传中/定位球系统（M06/M17）→ to_system=高球场景系统（M07/M08/M09）；changed_state=传中或角球成功 → 进入高球争夺 → 头球/凌空/停球三动作解锁可用；验证方式=state_before（高球未成立时三动作禁用）／state_after（高球成立后可用）对照。
- E02 from_system=比赛结果系统（G02）→ to_system=经济系统（G03/G04）；changed_state=终场胜负平直接决定招募点/训练币/资金入账 → 改变抽卡与转会可用性（资金不足时买入禁用）；验证方式=胜/平/负三档 state_before/after 资源流水与转会可用性对照。
- E03 from_system=培养持久系统（L01 新赛季保留培养/K01 存档）→ to_system=比赛能力系统（M01–M17 概率输入）；changed_state=训练升星/等级跨场跨赛季持久 → 改变后续比赛的动作概率与转会价格（G03 公式代入），早期培养投入在终局阵容与经济仍可观察；验证方式=培养前后同动作概率差分与价格公式对账（L 档跨阶段链）。

## 5. 比赛、成长与闭环 [L01–L05]

- L01 阵容与赛季：初始 8 名球员、5 人首发，可调整阵型、战术与核心；赛季六轮，结束后可进入新赛季并保留培养。
- L02 换人与恢复：中场可换人两次、调整战术；球员有体力恢复。
- L03 核心技能：每场核心技能限一次，用后提升下一次射门概率。
- L04 经济闭环：比赛/任务获得资源 → 抽卡或转会 → 训练、升星、入阵 → 下一场与新赛季；抽卡与转会可独立使用，并通过球员与碎片联动。
- L05 训练场：动作训练场不消耗正式俱乐部资源，可独立练习全部 17 种动作。

## 6. 抽卡与转会 [V01–V03]

- V01 抽卡：单抽（消耗招募点 100）、十连（消耗招募点 900，冻结值见 G04）、稀有保底、SSR 第 30 抽保底；重复卡产生碎片；训练与升星保留原流程。
- V02 转会：买入未拥有的球员，加入替补席后可安排首发；价格按 G03 公式；出售按 G05 约束与 55% 估值；回购按完整估值，不能无成本循环获利；每 5 碎片换 60 转会资金。
- V03 资源边界：全部为游戏资源，无充值、无真实交易、无付费操作。

| 进球 | 球入网定格推近＋球轨迹残影＋比分跳动 | 进球欢呼＋哨声 | 2 秒后回全景 |

| 犯规/定位球 | 犯规图标＋定位球点位高亮 | 裁判哨声（两短一长） | 定位球开出 |
| 中场窗口 | 中场横幅＋换人/战术面板 | 中场哨声 | 推进下半场 |
| 体力不足 | 球员头顶体力环变红闪烁＋动作禁用 | 低提示音 | 恢复或换人 |
| 资源入账 | 招募点/训练币/资金图标飞向资源栏 | 入账叮声 | 到位即停 |
| 抽卡/转会完成 | 卡面翻转/合同盖章动画 | 卡片翻动/盖章声 | 完成 |
| 赛季结算 | 战绩榜展开＋尾帧按夺冠变体 | 赛季终哨＋欢呼/低音 | 进入结界面板 |

- F06 关键音效清单：开场/中场/终场哨、踢球闷响分档、失误音、欢呼、扑救掌声、切换音、确认音、入账叮、翻卡、盖章、低提示音；环境音：看台环境声（常驻循环，比赛期间）；循环音开始/结束：环境声随比赛载入开始、随结算淡出 0.5s、暂停低音量；无配音需求。
- F07 VFX 信息性与遮挡约束：球权三态光环、概率条与体力环承担玩法信息（光环同时附图标＋文字，不只靠颜色）；球轨迹线与欢呼粒子单帧 ≤ 30 且不遮挡动作按钮、比分栏与球场中圈。
- F08 音画同步：踢球声与动作结算帧同步；哨声与阶段事件帧同步（`phase_change`/犯规/进球）；欢呼与进球帧同步。
- F09 屏幕震动：扑救成功 0.15 秒小幅；设置界面提供「画面震动开/关」（关闭不影响判定）。
- F10 前端界面：标题与主菜单（赛季/训练场/抽卡/转会/训练/阵容/存档）→ 比赛 HUD（比分、球权图标、体力环、当前阶段、步数提示、概率条）→ 中场面板（换人两次/战术）→ 结算面板（奖励/重赛/推进）→ 暂停面板（继续/倍速/重赛/设置）；关键状态附图标＋文字（球权三态、犯规、体力），不只靠颜色区分；窄屏无横向溢出（I03）；窗口失焦自动暂停。

## 10. 过场视频 [C01–C04]

- C01 赛季开幕（Opening，10 秒，1280×720@24fps）
  - 触发时机：首次由主菜单进入赛季时，每局一次
  - 内容与角色场景：俯瞰青藤镇社区球场，绿茵俱乐部球员列队入场，六支对手队旗依次升起，赛季首轮开球哨响
  - 资产对应：球场、球员色块队服、队旗与游戏内一致（程序化风格）
  - 可跳过：Esc/Enter 跳过 → 直接进入首轮比赛；自然播完 → 同
  - 状态一致：播放期间不推进比赛时钟；进入状态＝赛季第 1 轮
- C02 关键攻防·进球（Event，6 秒，1280×720@24fps）
  - 触发时机：本方赛季首个进球事件后的下一帧短暂插入（每局一次）
  - 内容与角色场景：射门入网的慢镜定格俯视回放，球轨迹残影拉出弧线，看台浪涌起
  - 资产对应：球场、球、球员与游戏内一致
  - 可跳过：Esc 跳过 → 回到比赛继续；自然播完 → 同
  - 状态一致：仅在真实进球后触发，比分与球权不变
- C03 赛季决战阶段（Transition，8 秒，1280×720@24fps）
  - 触发时机：第六轮开赛时短暂插入，每局一次
  - 内容与角色场景：战绩榜定格在最后一轮，冲甲对手队旗与绿茵队旗并列，球场灯光亮起夜赛氛围
  - 资产对应：战绩榜、球场、队旗与游戏内一致
  - 可跳过：Esc 跳过 → 直接进入第六轮比赛；自然播完 → 同
  - 状态一致：仅在真实推进至第六轮后触发
- C04 赛季结束（Ending，12 秒，1280×720@24fps，尾帧按夺冠变体）
  - 触发时机：第六轮终场结算后、赛季结界面板之前，每局一次
  - 内容与角色场景：赛季战绩榜展开；尾帧按分支——夺冠（绿茵队旗升上冠军联赛榜、「冲甲成功」字样）/留级（球员围圈致意看台、「来年再战」字样）
  - 资产对应：战绩榜、队旗、球员与游戏内一致
  - 可跳过：Esc/Enter 跳过 → 直接进入结界面板；自然播完 → 同
  - 状态一致：尾帧与真实赛季战绩一致

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：0 个（text-to-3D 0，image-to-3D 0）；object 任务资产为：（本测例为 scene-only；不强行添加 object）。每项只允许一个物体；组合物必须拆成独立任务。
- motion：1 个；覆盖动作：pass_and_shoot。
- video/audio/mechanic/UI：分别为 4/10/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

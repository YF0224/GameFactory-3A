## 1. 范围、优先级与完整流程 [S01–S09]

- S01 完整对局验收 2–8 人，允许真人与电脑混合。原始规则不规定人数上限；当前服务上限 64 是实现限制，不是规则定律；64 人只检查布局，完整对局与性能承诺以 2–8 人为准。
- S02 采用俯视/斜俯视小院 3D＋文字状态与操作。手机可操作，渲染不可用时可退回文字视图；移动以指令提交与结果演算表达，无需自由 WASD 碰撞战斗。
- S03 暂按四位角色纳入设计：002 GG大师、007 大资本家、012 电磁炮、023 闪电法师。角色只影响外观，不改变属性/出拳/步数/耗时；技能未定义，按冻结口径交付。
- S04 本轮交付聚焦：同时行动猜拳淘汰主循环（G02–G06）、五种基础行动（A01–A09）、四位冻结角色（V02–V05）、统一小院场景（V09）与 2–8 人房间流程（N01–N03）；范围收敛口径由 §11 正向清单 P06 承载。
- S05 新的用户确认 > 本需求中的确定规则 > 标明的实现约定 > 历史文档和参考图。参考图不赋予技能或改变数值。发现冲突先列出，不静默选择。
- S06 类型定位：2–8 人同时行动猜拳淘汰竞技（L-Regular，服务端权威结算）；G003 槽位要求 2 个真实客户端，其余席位由大厅电脑补足。玩法聚焦于猜拳—行动—淘汰闭环，叙事与氛围由 §8 世界设定与 §10 视频做包装。
- S07 核心循环：隐藏出拳 → 同时揭晓 → 赢家得步 → 行动/队列执行（拿刀/穿裤/移动/脱裤/割）→ 淘汰 → 下一轮 → 最后存活者获胜。
- S08 最低完整流程：建房/加入 → 大厅加电脑与选角 → 房主开始 → 开场视频 C01 → 出拳全屏（首轮出拳前播 C02 遭遇视频）→ 结果展示 → 行动阶段 → 终局结算（结算面板前播 C04）→ 重开；桌面与手机保留退出入口（N01/V10）。
- S09 失败恢复入口：断连宽限（房主 15/45 秒、成员 75 秒）内重连恢复身份与公开状态；刷新恢复身份且命令不重复执行；真正退出撤销身份、对局中视为出局；对局结束可再开局（N02/N03）。

## 2. 核心循环、猜拳与全局数值口径 [G01–G10]

- G01 每人开局在自己的家，1 条裤子、上限 3 条，没有刀。裤子为计数防护，不是 HP；0 条仍存活。最后一名存活者获胜。
- G02 所有存活玩家隐藏出拳，全部收齐后同时揭晓。一种或三种手势为平局；两种手势按石头胜剪刀、剪刀胜布、布胜石头判定，可以有多个赢家。
- G03 每位赢家各得输家人数的步数；普通输家 0 步。
- G04 连输 7 次获得 3 步保底。平局不累计也不打断连败，获胜清零；触发保底后清零，多个玩家可同时触发。
- G05 出拳独立全屏；有胜负后结果独立展示 5 秒，显示每人拳型、输赢、步数及保底；平局只展示 1 秒后全部重猜，不进入行动。未揭晓的拳型不能向其他玩家或电脑泄露。
- G06 步数不跨轮保存。没有全局行动者或座位顺序，有步数的人同时操作。所有存活玩家步数耗尽且行动/队列结束后进入下一轮猜拳；当前实现另有 1.1 秒轮间过渡，仅为可配置表现约定。
- G07 统一刻度：步数、裤子条数（0–3）、连败计数、角色与动作 ID 均为整数；时间为游戏模拟秒；结果展示 5 秒、平局展示 1 秒、轮间过渡 1.1 秒均为可配置表现约定，不改变结算语义（G05/G06）。
- G08 步数判定 oracle（独立可复核数例）：2 石头对 1 剪刀＝两位赢家各得 1 步；1 布对 3 石头＝赢家得 3 步；一人或三种手势＝平局，无人得步、不进入行动；连败第 7 次＝该玩家获 3 步保底且连败清零，期间平局不打断连败计数。任何偏离即 FAIL。
- G09 双端与权威：服务端为唯一权威，客户端只提交输入意图；真实双客户端对同一对局事实的观测摘要差分＝0（身份/裤子/持刀/步数/队列/出局/回合阶段）。单机双客户端模拟仅作开发诊断与证据预检，不得据此产生正式评测 PASS。
- G10 seed 与复现：fixed_seed=1003 用于评测对局注入（电脑行为与超时随机代出的随机流；代出分布的精确边界见 N09）；同 seed 同操作序列可复现；历史战绩与排行榜不进入评测分母。

## 3. 动作与结算 [A01–A09]

- A01 每个动作只花 1 步：拿刀 1 秒、穿裤子 1 秒、移动 2 秒、脱裤子 3 秒、割 3 秒。耗时替代旧的行动后 1 秒冷却，不额外叠加冷却。
- A02 拿刀、穿裤子可在任意地点进行。刀永久持有；每次穿/脱只增减 1 条，范围 0–3。满裤/已持刀等非法提交拒绝且不扣步。
- A03 移动可从任意家到任意家，距离不改变步数和耗时。开始瞬间进入独立户外，2 秒后抵达；户外不与任何人同地点，包括其他移动者。淘汰者的家仍是地点。
- A04 脱和割需要双方同地点。割要求自己持刀、对手 0 裤；成功后对手出局，清空其动作、队列和步数，不能继续出拳/行动。没有伤害数值或多段 HP。
- A05 每人一次执行一个动作；忙时新指令进入自己的 FIFO 队列，其他玩家不被锁住，目标也不被锁住，执行者仍能被偷袭。
- A06 提交时预留 1 步，入队和启动不重复扣费；不提供已提交操作取消。允许依据自己已有队列预排拿刀→移动→脱→割，其他玩家未来状态不作保证。
- A07 动作在结束瞬间按真实状态结算。对手移动、穿上裤子或已出局等导致已接受动作失效，仍耗步和时间，不产生成功统计。例：割完成前目标穿好裤子，割无效。
- A08 同时完成依次结算：拿刀＞移动＞穿裤子＞脱裤子＞割。同类同刻按服务端接收序列；整批结算后才启动下一项队列。不同完成时刻不得因同一渲染帧而合并。动画不能决定状态。
- A09 终局清空所有未完成动作。先后击杀由 A08 决定，不能在已出局后继续完成自己的攻击。
- 同刻结算 oracle（独立可复核数例，源自 A07/A08）：同一时刻完成的拿刀与割必按拿刀＞割次序结算——割完成前目标已持刀或已穿裤时割无效、仍耗步耗时；两个动作不同完成时刻不得因同一渲染帧合并。任何偏离即 FAIL。

## 4. 房间、电脑与战绩 [N01–N09]

- N01 建房/加入、大厅加电脑、房主开始、返回和退出入口。房主只可在大厅移除其他成员，对局中不可踢人；被踢身份不能重连。
- N02 房主主动退出立即结束房间；断连采用当前宽限：检测到断开后 15 秒可重连，心跳失联 45 秒兜底，两者取先到期限。普通成员意外断线宽限 75 秒；真正退出立即撤销身份，对局中视为出局。
- N03 刷新恢复自己的身份与公开状态；命令重复不重复执行。服务端绑定操作者身份，不接受客户端伪造玩家、时间或结算。电脑只能读取公开状态。
- N04 战绩记录真人游玩次数、胜场/胜率、成功击杀数、成功穿裤子数；人机局真人同样统计，电脑不进排行榜。开局自带裤子、失败或取消动作不计穿裤子。
- N05 用户名去首尾空白后聚合，无账号认证；同名席位分别计参赛。结束/中途关闭的参赛局计次数；正常结束只有最终幸存者计胜场，房主关闭进行中房间不产生胜者。已完成击杀/穿裤子即使退房也保留。每局只记录一次。
- N06 排行榜约定：胜场降序、游玩次数升序、用户名排序，前 50 名并支持完整用户名查询。公开榜显示游戏身份，不宣称账号唯一性。
- N07 每次猜拳开始时统一启动 20 秒倒计时，平局重猜重新计时。全部存活玩家提前出拳则立即揭晓；到期仅为仍未出拳的存活玩家由服务器随机代出石头/剪刀/布，已提交的选择不覆盖。仍按 G02–G05 结算，超时玩家按正常胜负结算继续参与。
- N08 行动阶段每位玩家独立累计闲置时间，仅在存活、有剩余步数、无执行中动作且队列为空时计时，满 15 秒丢弃本轮剩余步数；不影响已执行/排队动作，也不直接淘汰。重新进入闲置条件时开始新的 15 秒窗口；丢步后按 G06 检查能否进入下一轮。
- N09 以下为待确认的实现边界，不伪称已获用户确认：随机代出采用三个手势等概率且不读取他人隐藏拳型；无效点击不重置闲置时间；刷新/断线不重置服务端截止时间；恰好截止时命令与超时事件的先后顺序尚需冻结。

## 5. 角色、动作与场景设计 [V01–V11]

- V01 统一日式动画风（商业画风基准方向记录于 G003 种子卡 reference_policy.R，不进入本文件正文）；历史约五头身方向可作为比例起点，但不将旧偏写实参考当最终统一画风。近景五官清楚，游戏视角剪影可辨，材质与场景协调。
- V02 GG大师：棕色短发，绿色短唐装/外套、米白内搭、红色腰带、三枚石剪布主题腰饰、深色宽裤与棕靴。`images/002_anime_front.png` 是新版正面参考，不保证背面/绑定/动作。
- V03 大资本家：富态成年人，卷须、高礼帽、短礼服、怀表链与条纹裤；厚重轮廓。旧参考只约束身份/服装，需统一到 V01 画风。
- V04 电磁炮：茶色短发与侧发夹、米色针织背心、白短袖衬衫、深灰百褶裙、棕鞋、露腿和白色堆堆袜；无黑裤袜，保留底层运动短裤。没有电击技能。（商业形象参考方向见 G003 种子卡 reference_policy.R）
- V05 闪电法师：黑色竖发、胡须、蓝金服装。电光不烘焙成身体几何，不因外观赋予伤害技能。旧参考只约束身份，画风以 V01 为准。（商业形象参考方向见 G003 种子卡 reference_policy.R）
- V06 永久身份服装始终保留；裤子 0–3 变化只通过独立外层标记及数字表达。角色选择在大厅，开局锁定；可重复选择，不能靠角色外观区分同名玩家，保留玩家标签/选中提示。
- V07 动作目标集合：待机、移动、拿刀、穿裤子、脱裤子、割、出局、获胜。每位角色均需覆盖；动作可有个性但语义和耗时相同。用明确动作 ID 关联状态/事件，未来增加技能动作无需重写五种基础规则；已定义技能在后续轮次按冻结口径加入动作分母。
- V08 待机不持续低头耸肩；移动步态与脚底接触自然、循环/切换平顺；衣料不拉伸开裂、手腕不过折。穿/脱表现操作外层标记，不剥离原服装；拿刀后道具保持，割表现为明确的非血腥淘汰。动作完整性不能靠播放同一待机冒充。
- V09 每个玩家有独立可识别小院，地板可选作移动目的地；院子、道路、矮墙、长凳/花植构成统一场景。家之间的视觉距离不增加移动代价，墙和装饰不引入门规则。户外轨迹只作表现，不创造共用攻击地点。
- V10 支持全景、旋转、缩放和找自己；姓名/裤子/持刀/动作进度/队列/出局信息清楚。同院多人标签避免重叠，选目标和移动目的地区分。桌面和手机保留退出入口。
- V11 胜负和行动结算有可静音短音效；失败反馈不能误报成功。音效清晰与视听同步属 Quality，事件绑定正确属 Gameness。出拳和结果阶段独立占屏。

## 6. 操作与输入 [I01–I03]

- I01 双端键鼠/触屏：建房/加入、出拳（石头/剪刀/布）、五种行动指令（拿刀/穿裤/移动/脱/割）、目标与移动目的地选取、找自己、全景/旋转/缩放、返回/退出（N01/V10）。
- I02 输入语义边界：满裤/已持刀/无刀割/非 0 裤目标等非法提交拒绝且不扣步（A02/A04）；已提交操作进入队列后按 A05/A06 口径执行；手机可操作、渲染不可用退回文字视图（S02）。
- I03 HUD 须常驻可查：姓名、裤子数、持刀、动作进度、队列、出局信息、出拳倒计时（20 秒）与闲置丢步提示（15 秒）（V10/N07/N08）。

## 7. 机制系统与验收映射 [M01–M03]

- M01 机制族覆盖（静态层）
  - input：固定脚本与双端操作驱动（触发方：玩家/评测脚本）
  - precondition：构建可启动、房间可建立（D03/D04 边界除外）
  - state_change：按 §1–§5 冻结规则运行——猜拳（G01–G06）、动作与结算（A01–A09）、房间与战绩（N01–N06）、超时（N07–N09）、角色/动作/场景（V01–V11）
  - observable：逐条规则 ID 的运行时事件与状态流水；文件存在/静态代码不算证据（D03）
  - invalid_case：非法提交按 A02/A04 拒绝且不扣步；伪造结算按 N03 拒绝
  - recovery：断连宽限内重连/刷新恢复公开状态（N02/N03）；对局结束可再开局
- M02 完整对局（动态层）
  - input：2–8 人对局（≥2 真实客户端＋大厅电脑补席）（触发方：玩家）
  - precondition：房间满员且房主已开始
  - state_change：出拳→得步→行动→淘汰→终局的完整链路自然演化
  - observable：多轮完整对局流水（含多赢家、保底、偷袭、闲置丢步、代出）；正常对局证明可达，状态夹具用于精确边界
  - invalid_case：已出局者继续行动被拒绝（A04/A09）
  - recovery：断线宽限内重连恢复（N02）
- M03 跨客户端一致性与信息边界（本题独有复杂度来源）
  - input：双端同时操作＋网络扰动（触发方：玩家）
  - precondition：真实双端会话建立
  - observable：双端对局状态摘要差分＝0；未揭晓拳型不向任何端/电脑泄露；断连宽限语义正确
  - state_change：服务端权威状态 → 各端观测同步
  - invalid_case：客户端伪造玩家/时间/结算被权威拒绝（N03）
  - recovery：宽限内重连恢复公开状态（正式 multiplayer contract 未绑定时按 rubric 记 local diagnostic / UNKNOWN）

**复杂度结构声明**（L-Regular 档）：①多人同时行动结算——隐藏出拳同时揭晓、服务端权威、多端状态一致；②实时并发——多人 FIFO 队列并行、同刻动作按固定优先级依次结算、忙时被偷袭；③组合状态——裤子 0–3、持刀、队列、出局、连败、闲置计时叠加。**双情境**：情境一＝2–8 人完整对局（真机混合）；情境二＝同刻冲突局面（同刻多动作完成、双端并发提交、断连重连，可同局不同局面）。

**跨阶段后果表**（L-Regular 档复杂度主来源，至少一条显式 A→B→C 链，早期状态在后续阶段仍可观察；2026-10-08 严格复核后重写——「战绩→排行→赛程」经复核为外围系统，不再作为主要依据，复核记录见 rubric ambiguities）：

- K01 局内轮次资产链（核心必经流程）：阶段A（轮 N 猜拳分胜负：赢家按 G03 得步 → 行动阶段执行穿裤/拿刀/移动/脱裤/割，A01–A09）→ 阶段B（轮 N+1 起始状态：裤子 0–3、持刀、所在位置、存活者集合按轮 N 行动结果更新——G06 只清步数，资产与存活集跨轮保留）→ 阶段C（后续轮的可用行动与胜负改变：持刀者才可割（A04）、仅 0 裤目标可被割、同地点判定由轮 N 移动结果决定（A03/A04）→ 最终存活者获胜（G01））；重试保留＝断连宽限内重连/刷新恢复公开状态且轮间资产不回滚（N02/N03）；新局清空＝对局结束全量清空（§14）；验证方式＝跨轮回溯探针——轮 N 结束记录资产快照（裤子/持刀/位置/存活集）→ 轮 N+1 开始与行动阶段逐项对照，并按「持刀＋0 裤＋同地点」构造割的成功与失败两侧用例（A09 oracle）。
- K02 连败保底链（核心必经流程，局内轮间）：阶段A（轮 N 猜拳落败：局内连败计数 +1（G04）；平局不累计不打断、获胜清零）→ 阶段B（第 7 次落败触发保底：得 3 步、计数清零）→ 阶段C（该轮行动阶段可用行动改变：保底步数允许执行 1 步动作（A01），影响本轮攻防与后续存活格局）；重试保留＝断连宽限内重连计数不重置（N02）；新局清空＝对局结束清零（N04 战绩不含连败项）；验证方式＝连续构造 7 轮落败局面，保底触发前后双快照（步数 0→3）与行动能力对照（G08 oracle）。
- 战绩与排行榜（N04–N06）为跨局持久化的**外围统计**：仅排序展示（N06）、不影响任何对局条件与胜负、按 G10 不进入评测分母；作为 P2 的附加持久化来源记录，不承担 L-Regular 资格。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：「裁拳巷」——一座闹中取静的四合小院街区，街坊间流传着以猜拳定输赢、赢家得步数、持刀者可「割」掉输家裤子的传统游戏；GGgame 工作室把这项传统办成了小院联赛。
- W02 场景所在地：裁拳巷中央的四合院赛场——每位玩家一间可识别的独立小院，青砖矮墙、石板路相连，院子之间有长凳与花植；中央设揭晓台。
- W03 玩家身份与当前任务动机：玩家扮演四名参赛者之一（GG大师/大资本家/电磁炮/闪电法师）参赛，以淘汰其余对手、成为本巷「拳王」为动机；角色只影响外观与出拳个性演出，不改变规则数值（V06）。
- W04 失败代价与结局表达：被「割」出局者当场触发出局演出（抖动＋裤子抛物线飞出的喜剧化表现）；胜者登台接受全场欢呼（§10 C04）。
- W05 叙事来源：裤子＝巷内规矩的计数防护（输家掉裤、0 裤仍存活）；刀＝淘汰权（持刀且对手 0 裤方可割，A04）；连败保底＝巷口老人们对连败者的照顾（G04）；电脑席位＝观赛的街坊临时上场补位（N01）。全部原创，不使用商业作品命名或造型。
- W06 视觉风格与色彩材质：统一日式动画风（V01）；主色=砖红 #B3574A、青瓦灰 #6E7B8A、院落绿 #7FA46B、揭示金 #E8C559；材质为青砖、木凳、布幔与花植。
- W07 环境氛围与声音语言：午后小院的闲适与揭晓时刻的紧张反差——常驻巷院环境声（风拂花植＋远处街坊人声衬底）；出拳、揭晓、割、淘汰与胜利配专属短音效，全部按 §9 F06 冻结清单交付；失败反馈与胜利反馈听感明确区分（V11）。
- W08 故事表达方式：开场视频（C01）交代联赛与角色登场 → 遭遇视频（C02）与技能演出视频（C03）承载过程节奏 → 结算视频（C04）收束；故事只做包装与节奏，不改变任何机制数值。

- F01 视角与镜头：俯视/斜俯视固定机位；支持全景、旋转、缩放与「找自己」（V10）；镜头边界＝所有小院与道路外接矩形 +5% 余量。

|---|---|---|---|

## 10. 过场视频 [C01–C04]

- C01 巷口开赛（Opening，8 秒，1280×720@24fps）
  - 触发时机：房主开始对局、首轮出拳窗口开启之前，每局一次
  - 内容与角色场景：午后裁拳巷全景，布幔拉开、灯笼摇曳；四名参赛者（GG大师/大资本家/电磁炮/闪电法师）依次步入各自小院亮相，揭晓台上的石剪布图腾转动

  - 内容与角色场景：出拳全屏界面展开，各院参赛者剪影对峙、拳型图标在指尖酝酿；倒计时数字落下，镜头快速掠过每间小院
  - 资产对应：角色剪影、小院与游戏内同源
  - 可跳过：跳过 → 直接进入出拳操作（倒计时照常）；自然播完 → 进入出拳操作
  - 状态一致：播放期间倒计时冻结，播放结束后 20 秒倒计时启动
- C03 一刀定胜负（Event，5 秒，1280×720@24fps）

  - 内容与角色场景：持刀者踏步逼近、刀光一闪定格；被割者惊愕抖动，裤子划出抛物线飞出院墙（喜剧化）；全场镜头短促定格后恢复
  - 资产对应：持刀者、被割者、裤子外层标记与游戏内同源
  - 可跳过：跳过 → 直接继续行动阶段（出局结算已生效）；自然播完 → 继续行动阶段
  - 状态一致：仅在真实割命中后触发；播放期间队列计时冻结、出局状态保持，播放结束瞬间恢复结算序列
- C04 拳王诞生（Ending，8 秒，1280×720@24fps，胜负共用双意象）
  - 触发时机：终局（最后存活者产生）、结算面板出现之前，每局一次
  - 内容与角色场景：胜利意象=拳王登上揭晓台高举双拳，彩带落下、全体欢呼，镜头拉远至巷院全景；失败侧=各出局者灰溜溜夹着排队离院、布幔合拢
  - 资产对应：胜者、四角色、揭晓台与游戏内同源
  - 可跳过：跳过 → 直接进入终局结算面板；自然播完 → 进入终局结算面板
  - 状态一致：仅在真实终局后触发；播放期间不推进任何计时

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：6 个（text-to-3D 4，image-to-3D 2）；object 任务资产为：gg_master, rail_tycoon, rail_gunner, storm_mage, duel_knife, pants_layer_marker。每项只允许一个物体；组合物必须拆成独立任务。
- motion：6 个；覆盖动作：rps_throw, grab_knife, eliminated_stagger, rps_throw, cut_slash, victory_cheer。
- video/audio/mechanic/UI：分别为 4/14/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

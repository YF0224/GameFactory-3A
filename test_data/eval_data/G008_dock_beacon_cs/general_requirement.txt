## 0. 档位与历史定位声明

本题为 **L-Regular** 档团队战术 FPS：复杂度主来源为跨回合/换边的跨阶段后果（K01/K02），实时事件链与多人并发为附加复杂度来源。来源稿与 `RTS_versus.md` 的对齐原则与三题正交性讨论见**附录 A**（仅迁移记录，不构成验收需求）。

### 0.1 交付预算（冻结）

- 至少 **12 个可选战术干员原型**，每个原型有独立的侦察、控区、突破或支援机制；
- 一张多区域地图，包含 3 个目标点、至少 5 个可进入区域、可破坏/可穿透材质和多条攻防路线；
- 两队各 3 名角色：两名真实客户端各控制一名角色，其余角色由确定性 AI 控制；
- 至少 6 条跨系统链路：购买 → 装备 → 移动/侦察 → 射击 → 命中/伤害 → 死亡/观战 → 目标结算 → 经济变化；
- 至少 4 种有效策略：强攻、默认控图、绕后、诱导转点/保存经济；
- 至少 5 个回合，至少一次攻守换边；
- 至少 6 类武器、4 类战术装备、护甲/穿透/弹药和换弹逻辑；
- 所有关键事件必须有可重放或可核对证据，不能只靠录屏中“看起来像命中”；
- 完整逻辑比赛建议 10–18 分钟；benchmark 运行切片为 6–10 分钟，采用固定 bot 行为和加速回合节奏（切片冻结口径见 0.2）。

### 0.2 切片与平衡口径（冻结）

**主轴（唯一）**：实时事件链的**顺序确定性** ——
`输入 → 移动/视线 → 命中（部位×材质×穿透×距离） → 伤害/死亡 → 信息（声音/视野） → 目标物状态 → 回合经济 → 换边继承`。
链上任一环缺失或顺序漂移，本切片即不达标；所有切片必测机制都必须落在这条链上，不落链的机制降为切片外存在性要求。

**机制→轴映射（必测机制的出处可回溯，防止场景退化为"随便挑一段能跑的"）**

| 链段 | 承载机制（出处） |
|---|---|
| 输入/移动 | 移速、精度与声音状态（2.5） |
| 命中 | 射线、部位系数、材质穿透、距离衰减（2.1 / 2.4） |
| 伤害 | 比例减伤、白值护盾（2.1 / 2.6） |
| 死亡 | 倒地窗口、救援、观战（5.3 O07 / 8.2） |
| 信息 | 声学半径、三态视野、诱饵/伪装（3.4 / 7.2 / 7.3） |
| 目标物 | 安装/拆除/打断、接口过载（3.2 / 5.3 O09） |

| 回合/换边 | 回合胜负、换边继承、加赛（3.3 / 4.4） |

**切片冻结口径（0.1 的 6–10 分钟在此收口为确定值）**

- 切片 = **一场完整 5 回合比赛**（3.3 规则），逻辑加速 ×1.5，全程 ≈ 7~8 分钟；
- 固定 bot 脚本必须使比分打到 ≥4 回合（保证换边与经济继承被触发），并各出现 ≥1 次保存局、半买局、全买局、安装、拆除或打断；
- **切片强制干员组（8/12）**：O01 破门手、O02 侦察员、O04 闪击手、O05 守点工程师、O06 诱饵专家、O07 医疗支援、O09 反电子专家、O12 指挥支援 —— 覆盖 5.2 全部四个威胁分层，11 克制矩阵 ≥5 行可在组内闭环；

- 8 个链段在切片内各 ≥1 次可观测发生，缺一不得标记切片完成。

**切片资源配额（人/物/景/动/音/影 六类互斥计数，只计切片覆盖实体）**

**合计 ≈ 64（校准带宽 ±10；roster 其余 4 名干员不计入）**

**平衡约束冻结（每题必测数值平衡的约束组，全部可从本稿回溯）**

1. 4.5 五个经济决策点全部成立（保存/半买/强买/全买/翻盘红线）；

## 1. 生成目标与边界

生成一个 3v3 回合制团队战术 FPS：

- 两个真实客户端各控制一名干员；每队第三名干员由确定性 AI 控制；
- 攻击方通过安装目标物或完成数据窃取获胜；防守方通过击杀、拆除或拖延时间获胜；
- 一局至少 5 个回合，第三回合后攻守换边；
- 单回合结束后，死亡角色不可在该回合复活，下一回合重置；
- 购买阶段允许购买武器、护甲和战术装备；
- 目标点 A/B/C 均可成为主目标，但每回合只激活其中一个；
- 地图必须支持至少两条接近路线和一条风险绕后路线；
- 目标点、炸弹/数据核心、击杀、经济和回合结果必须在运行时可见。

### 1.1 交付范围口径（正向）

本轮验收按以下口径交付：3v3 席位（2 真实客户端＋4 确定性 AI）、一张冻结的多区域地图、六类武器与四类战术装备、12 干员 roster 全量实现（可被固定 probe 独立触发，O03/O08/O10/O11 按存在性要求触发）；匹配、账号、排行榜、语音、反作弊与社交系统为生成自由补充，不进入验收分母（N06 承载）。

## 2. 数值口径 [G01–G06]

### 2.1 命中与伤害 [G01]

沿用 `RTS_versus.md` 的比例减伤原则作为护甲基础：

```text
实际伤害 = 武器基础伤害 × 命中部位系数 × 穿透系数 × 100 / (100 + 护甲)
```

初始部位系数：

| 部位 | 系数 |
|---|---:|
| 头部 | 2.0 |
| 胸腹 | 1.0 |
| 四肢 | 0.7 |

规则：

- 命中点必须来自真实射线/弹道或引擎碰撞结果；
- 不允许用“准星碰到敌人”直接判定命中；
- 穿透材质必须有厚度、穿透次数和伤害衰减；
- 爆炸伤害按距离衰减，并记录遮挡；
- 真实伤害/特殊技能必须明确绕过哪一层公式；
- 所有伤害事件必须包含射手、目标、武器、部位、材质、距离和最终伤害。

### 2.2 生存性和 EHP [G02]

```text
基础 EHP = 生命值 × (100 + 护甲) / 100
```

头部一击、爆炸、穿透和护盾不能简单折算进裸 HP，必须在测试报告中分别记录：

- 裸 HP；
- 护甲类型；
- 头部/身体命中窗口；
- 护盾或临时防护；
- 被击倒/救援状态；
- 回合内是否允许复活。

### 2.3 时间口径 [G03]

- 单回合准备阶段：20 秒；
- 单回合行动阶段：120 秒；
- 安装目标物：5 秒；
- 拆除目标物：7 秒；
- 安装后倒计时：35 秒；
- 逻辑加速必须同步加速回合计时、炸弹计时和冷却，但不能改变命中判定顺序。

### 2.4 距离衰减与材质穿透 [G04]

把 2.1 的「穿透系数」展开为材质表，并补入距离系数。伤害计算全管线：

```text
最终伤害 = 基础伤害 × 距离系数 × 穿透衰减（每层材质连乘） × 部位系数 × 100 / (100 + 护甲)
```

距离衰减带（地图最长交战距离约 60m）：

| 武器 | 满伤区 | 衰减终点 | 终点伤害 |
|---|---:|---:|---:|
| 手枪 | 0–15m | 40m | 70% |
| 冲锋枪 | 0–8m | 30m | 55% |
| 步枪 | 0–25m | 60m | 70% |
| 霰弹枪 | 0–6m | 20m | 30%（超出后弹丸散布脱离命中框） |
| 狙击枪 | 0–40m | 80m | 85% |
| 轻机枪 | 0–20m | 50m | 60% |

材质穿透表：

| 材质 | 厚度等效 | 每层衰减 | 最大穿透层数 |
|---|---:|---:|---:|
| 木板/石膏 | 20 | −15% | 3 |
| 防弹玻璃 | 15 | −10% | 1（被打穿后变为透明） |
| 薄金属板 | 30 | −25% | 2 |
| 混凝土薄墙 | 60 | −40% | 1 |

武器自身穿透上限：手枪 1 / 冲锋枪 1 / 步枪 2 / 霰弹枪 0 / 狙击枪 3 / 轻机枪 2。
实际可穿层数 = min(武器上限，路径上各材质允许层数)；穿透衰减发生在部位与护甲计算之前。

### 2.5 移速、精度与声音状态 [G05]

移速 = 干员基准（6.1 表）＋ 武器修正（加算）：

| 武器 | 移速修正 |
|---|---:|
| 手枪 | +0 |
| 冲锋枪 | +0.3 |
| 霰弹枪 | +0.1 |
| 步枪 | −0.2 |
| 狙击枪 | −0.3 |
| 轻机枪 | −0.6（架设时移速为 0） |

| 移动状态 | 速度倍率 | 脚步声 |
|---|---:|---|
| 跑动 | 100% | 有 |
| 静步 | 55% | 无 |
| 蹲伏移动 | 50% | 无 |

移动射击散布惩罚：冲锋枪 ×1.1 / 手枪 ×1.15 / 步枪 ×1.4 / 霰弹枪（弹丸天然散布，不另算）/ 狙击枪 ×4（等效禁止移动狙）/ 轻机枪未架设 ×2.5。静止蹲伏时首发散布 ×0.8。

### 2.6 临时增益叠加规则 [G06]

与 `RTS_versus.md` 的「乘算叠加禁令」同源。6.5 的 TTK 校验只在增益不复合乘算时成立：

- 同一干员同一时刻**最多一层白值护盾**（如闪击手·突进护盾），后到覆盖先到；
- 白值护盾先于 HP 承伤，且**享受护甲减免**——护盾不引入第二条伤害公式；
- 移速加成同刻最多一层：医疗、技能、装备来源互斥，取绝对值最大者；
- 伤害加成一律**加算百分比**（猎杀本能 +15% 与背刺 +30% 相加 = +45%），禁止复合乘算；
- 爆发状态（装填、架设）只增白值或改散布，不改伤害公式。

## 3. 地图、目标与信息规则 [L01–L04]

### 3.1 地图结构 [L01]

固定一张室内/室外混合地图：

- 攻击方出生区；
- 防守方出生区；
- 目标区 A/B/C；
- 中央连接区；
- 左右两条主攻路线；
- 一条高风险绕后路线；
- 至少两个可穿透掩体区；
- 至少一个可破坏门/窗/薄墙；
- 至少两个能改变声音传播或视野的区域。

### 3.2 目标系统 [L02]

| 目标 | 类型 | 攻击方动作 | 防守方动作 |
|---|---|---|---|
| A/B/C 目标点 | 每回合随机激活 1 个 | 安装数据核心并守住 | 阻止安装或拆除 |
| 数据核心 | 可携带目标物 | 携带、放置、安装 | 击杀携带者、拾取或拆除 |
| 备用终端 | 低概率替代目标 | 6 秒持续交互 | 打断交互 |

- 目标物只能有一个真实归属；
- 携带者死亡后目标物落地；
- 目标物状态必须在所有客户端一致；
- 安装、拆除、交互可以被伤害/控制打断；
- 回合结束后目标物和交互进度必须重置，不得泄漏上一回合状态。

### 3.3 回合胜负 [L03]

攻击方在以下任一条件满足时赢得回合：

1. 成功安装目标物且防守方未在倒计时内拆除；
2. 消灭全部防守方且目标物已被安装或防守方失去可阻止路径；
3. 完成备用终端交互。

防守方在以下任一条件满足时赢得回合：

1. 回合时间结束且目标物未安装；
2. 拆除已安装目标物；
3. 消灭全部攻击方且目标物未安装。

比赛胜负：先获得 3 个回合胜利的一方获胜；第三回合结束后攻守换边。若总分相同，进入加赛回合，双方经济重置为冻结值。

### 3.4 地图时序与声学半径 [L04]

| 路线 | 跑动耗时（基准 4.0 m/s） |
|---|---:|
| 攻方出生区 → A / B / C | 12s / 15s / 12s |
| 守方出生区 → A / B / C | 9s / 11s / 9s |
| A ↔ B、B ↔ C（横向支援） | 8s / 8s |
| A ↔ C（中央连接区） | 11s |
| 绕后路线（全程无己方观察点） | 20s |

声学半径（超出半径不可听；每穿过一层不可穿透材质衰减 50%）：

| 声源 | 半径 |
|---|---:|
| 跑动脚步 | 24m |
| 静步 / 蹲伏移动 | 无声 |
| 换弹 | 10m |
| 手枪 / 冲锋枪（无消音） | 60m |
| 步枪 / 霰弹枪 / 轻机枪 | 80m |
| 狙击枪 | 120m |
| 消音武器（手枪/冲锋枪可装，+$200） | 25m |
| 安装 / 拆除目标物 | 30m |

**时序含义**（回合设计的硬约束，全部可从上表推导）：

- 安装后倒计时 35s、拆除 7s → 防守方最迟在剩余 8s 时开始拆除（守点工程师为 5s，即剩余 6s）；
- 横向支援 8s → "假打 A 真打 B"的可信窗口 = 侦察确认 + 转点 ≈ 10~15s，诱饵类干员的数值全部围绕该窗口设计；
- 绕后 20s → 绕后必须在行动阶段开始后尽早决策；消音/静步装备可以把声学风险降为零，但不能缩短时间。

## 5. 12 个异构战术干员原型 [O01–O12]

> 12 个原型对应 `RTS_versus.md` 的异构族群压力。它们不是换皮角色，而是改变侦察、进攻、守点、撤退或目标处理方式的不同战术包。

| 编号 | 原型 | 核心机制 | 主要策略 |
|---|---|---|---|
| O01 | 破门手 | 定向破坏薄墙/门，改变路线 | 强攻、开新入口 |
| O02 | 侦察员 | 可部署扫描器，短时共享敌方位置 | 控图、预判 |
| O03 | 烟幕师 | 可编排烟幕形状和持续时间 | 切割视线、转点 |
| O04 | 闪击手 | 短距离冲刺和一次性突破护盾 | 首杀、突破 |
| O05 | 守点工程师 | 放置炮台/警报/延迟装置 | 拖延、反拆 |
| O06 | 诱饵专家 | 生成脚步、枪声和假目标 | 欺骗、假打 |
| O07 | 医疗支援 | 回合内一次救援/稳定倒地队友 | 续航、残局 |
| O08 | 追踪猎手 | 根据弹道/脚印/受伤痕迹追踪 | 反绕后、清点 |
| O09 | 反电子专家 | 干扰扫描、关闭装置和目标接口 | 反信息、反守点 |
| O10 | 重装压制 | 可架设重武器，但移动和转身变慢 | 架枪、封锁 |
| O11 | 伪装渗透 | 短时改变识别标记，不能伪造友军伤害 | 潜入、偷点 |
| O12 | 指挥支援 | 以团队情报换取一次全队预警或空投 | 运营、终局决策 |

### 5.1 原型实现红线

- 每个原型至少有 2 个战术能力和 1 个被动/限制；
- 每个能力必须影响路线、视野、声音、命中、装备、目标交互或时间之一；
- 至少 4 个原型能改变地图可通行性或区域控制；
- 至少 4 个原型能改变信息状态；
- 至少 3 个原型能直接改变目标物交互；
- 伪装、扫描和诱饵必须有可验证的可见/可听差异；
- 不允许永久隐身、无声射击、无限扫描、不可拆除装置或全图必杀。

### 5.2 干员威胁分层（跨干员校验用）

与 `RTS_versus.md` 的「战力分层」同构：**不按 HP/护甲排序，按其对战场状态的改变方式分层**。
所有干员裸 HP 相同（100），分层完全由机制决定 —— 这是本题"异构玩法包"的核心。

| 层级 | 判据 | 成员 |
|---|---|---|
| 结构改变层 | 能永久改变地图可通行性或可交互面 | 破门手、守点工程师、反电子专家（加固） |
| 信息支配层 | 能改变"谁知道谁在哪" | 侦察员、追踪猎手、诱饵专家、伪装渗透、指挥支援 |
| 节奏控制层 | 能改变交战时机与视线 | 烟幕师、闪击手、重装压制、反电子专家 |
| 存续恢复层 | 能改变单位存活与经济回收 | 医疗支援 |

> 分层的用途：任一队伍若同时缺失两个层级，策略空间塌缩为纯枪法对决；
> 生成系统必须保证 12 干员在 probe 中全部可用，不允许某层缺失。

### 6.6 武器生态位校验 [V06]

| 校验点 | 结果 |
|---|---|
| 步枪 25m 内身体 TTK 0.36s 全场最优、$2,700 中价 → 通用主力成立 | ✓ |
| 冲锋枪 TTK 全面劣于步枪（0.45 vs 0.36），但移速 +0.3、价格 $1,200、移动散布惩罚最小 → 生态位 = 经济局 + 高机动转点 | ✓ |
| 霰弹枪 0~6m 全弹丸 80 伤：身体两枪 0.9s、贴脸头部一枪；>6m 断崖衰减 + 弹匣 6 → 贴脸专精 | ✓ |
| 狙击枪身体两枪 1.6s、头部恒一枪 → "远距 + 爆头"专精；身体惩罚防止全能 | ✓ |
| 轻机枪架设 TTK 0.42s + 载弹 45 → 封锁窗口专精；未架设 0.84s + 散布 ×2.5 + 移速 −0.6 | ✓ |

> "单个武器不能在所有距离、所有护甲和所有目标上最优"红线。

## 7. 实时操作、声音和信息状态 [P01–P03]

### 7.1 输入和移动 [P01]

- WASD/摇杆移动必须影响真实角色位置；
- 视角和准星必须独立于角色移动；
- 射击不能穿过不可穿透材质；
- 角色速度、蹲伏、冲刺和重装状态必须写入状态日志；
- 客户端只提交输入和瞄准意图，命中与伤害由权威运行时判定。

### 7.2 声音信息 [P02]

至少实现三类可定位声音：

- 脚步；
- 枪声/换弹；
- 目标物安装/拆除。

声音必须有来源坐标、半径和可被遮挡/衰减的规则。若生成版本暂时没有空间音频，必须提供同步的视觉辅助，但不能把声音机制标记为完整实现。

### 7.3 视野和信息 [P03]

- 不在视野内的敌人位置为未知；
- 侦察、脚步、枪声和目标状态可产生不完整信息；
- 假目标不能直接被当作真实敌人；
- 伪装不能绕过伤害归属和友伤规则；
- HUD 必须区分：确认敌人、最后已知位置、推测位置和未知。

## 8. 多人同步、死亡和换边 [H01–H03]

### 8.1 权威状态 [H01]

- 权威运行时负责位置采样、射线命中、伤害、死亡、目标物、经济和回合结算；
- 客户端不能提交最终命中、伤害、金币或胜负结果；
- 每个事件包含 `tick`、`actor_id`、`target_id`、`weapon_id`、`hit_part`、`material`、`source_client`；
- 两个真实客户端必须能导出一致的：回合状态、存活列表、目标物状态、比分、经济、攻守方和最终结果。

### 8.2 死亡和观战 [H02]

- 回合内死亡后不可重新控制该干员；
- 可在队友视角之间切换观战；
- 观战视角不能显示不应获得的敌方信息；
- 医疗支援只有在明确倒地窗口内才能救援；
- 回合结束后所有干员复位，装备和经济按规则结算。

### 8.3 客户端缺失与失败归因 [H03]

- 缺少第二真实客户端：`UNKNOWN + EVALUATOR_FAIL`，不能静默用本地假玩家冒充；
- 游戏没有第二玩家入口：`FAIL + GAME_FAIL`；
- 运行时无法记录命中/目标/回合事件：`UNKNOWN + EVALUATOR_FAIL`；
- 目标物状态在客户端之间不一致：`FAIL + GAME_FAIL`；
- 评测工具自身崩溃但游戏状态可正常运行：`UNKNOWN + EVALUATOR_FAIL`。

## 9. 冻结必测场景 [S01–S06]

### S01：房间、选人和购买

- 两客户端进入同一私有房间；
- 双方选择不同干员；
- 购买不同武器/护甲/装备；
- 双方看到一致的队伍、回合、资金和装备状态；
- 第二客户端缺失时产生明确错误，不得伪造成功。

### S02：移动、射线、命中和伤害

使用固定靶位和脚本化 bot 行为，至少验证：

- 身体命中；
- 头部命中；
- 掩体遮挡；
- 穿透材质；
- 距离衰减；
- 护甲减伤；
- 击杀和击杀归属；
- 双客户端观察一致。

### S03：信息与战术装备

依次触发烟雾、闪光、破片、侦察装置、诱饵和伪装：

- 可观察范围改变；
- 真实声音和假声音可区分；
- 装置可被触发、失效、破坏或关闭；
- 不能出现永久遮挡、永久致盲或无限扫描。

### S04：目标物安装/拆除

- 攻击方携带数据核心到 A/B/C 中的激活点；
- 安装可被伤害和控制打断；
- 防守方可拆除；
- 安装后的倒计时、提示音和 UI 在双方一致；
- 目标物掉落、拾取和回合结束重置正确。

### S05：死亡、观战和经济

- 角色被击杀后退出当前回合控制；
- 进入合法观战视角；
- 队友不能看到非法敌方信息；
- 回合奖励、失败补偿、装备保留/损失正确；
- 至少出现一次强攻失败后的保存或半购买决策。

### S06：攻守换边和完整结算

- 至少进行 5 个回合；
- 第三回合后攻守交换；
- 目标点激活、回合时间、比分和经济状态清零/继承符合规则；
- 先到 3 分的一方获胜；
- 双客户端得到相同的最终结果和摘要。

## 10. 公平性红线（正向口径）[R01–R09]

- R01 命中必须来自真实射线/弹道判定：部位、材质、穿透、距离逐项写入结构化事件日志；准星画面接触敌人本身不构成命中。
- R02 伤害必须通过部位×材质×穿透×距离与比例减伤公式结算并以结构化伤害事件表达；血条直减可以同步显示，但以事件日志为判定证据。
- R03 12 个干员必须在机制字段（充能/CD/反制/威胁分层）上真实可区分；仅名称或外观差异的换皮实现按同构处理。
- R04 每件武器必须保持排他生态位（距离带×价格×移速三维，6.6 校验成立）；出现全能最优即约束失败。
- R05 全部装置、烟幕、闪光、隐身与目标交互必须限时且可反制（可拆除、可干扰、可识破）。
- R06 胜负必须保留经济、换边与翻盘窗口（12.1 校验全部成立）。
- R07 观战信息必须与观战者可见性口径一致（8.2）：观战端只能看到规则允许的信息。
- R08 双端验收必须基于真实双客户端会话；本地 AI 与单机双客户端模拟仅作诊断预检（H01）。
- R09 评测证据必须以结构化事件日志为准；录屏仅作辅助证据。

## 11. 跨干员克制与反制矩阵

与 `RTS_versus.md` 的「天敌互攻克制表」同构。信息与结构类能力的克制不是数值倍率，
而是**机制失效**；每行都必须能从运行时事件链验证。

| 克制方 | 被克制方 | 失效原理 |
|---|---|---|
| 反电子专家 | 侦察员 / 守点工程师 / 指挥支援 | EMP 禁用扫描器、炮台与空投落点 |
| 反电子专家·加固 | 破门手 | 聚能切割需 2 充能才能切开加固面 |
| 追踪猎手 | 诱饵专家 | 假声源无脚印、假人无开火记录，回溯与痕迹直接判假 |
| 伪装渗透 | 侦察员 | 主动扫描将伪装者标为友军，目标数据库失效 |
| 守点工程师 | 伪装渗透 / 绕后路线 | 警报绊线是机械触发，与视觉标识无关 |
| 烟幕师 | 重装压制 / 狙击枪 | 烟幕切割视线后，架设火力与远距压制整体作废 |
| 破门手 | 守点工程师 | 新入口绕开原布防面，绊线/炮台朝向失效 |
| 闪击手 | 守点工程师 | 装置 DPS 40 追不上冲刺，近身 ×2 拔除 |
| 医疗支援 | 经济压制打法 | 救回倒地使对方"击杀 $300 ＋ 掉落"落空，专克滚雪球 |
| 指挥支援 | 诱饵专家 | 预警可交叉验证真假声源（代价：消耗情报） |
| 诱饵专家 | 重装压制 / 追踪猎手 | 假声源浪费架设窗口与回溯 CD |
| 重装压制 | 强攻正面 | 架设窗口封锁主通道，正面强攻代价最大化 |

> 矩阵的用法：3v3 中每队 2 名真实玩家 + 1 AI，克制通过**选人**实现的赛前博弈 ——
> 对方锁侦察员，则反电子专家价值立即上升。这正是"策略路径"压力轴的来源。

## 12. 关键校验点与设计原则回顾

### 12.1 经济校验点 [J01]

| 校验点 | 结果 |
|---|---|
| 连败 2 回合累计收入 $1,900 vs 半买 $1,850 | ✓ 半买在连败第 2 回合恰好可达 |
| 败方补偿上限 $3,400 ＋ 一胜 $3,000 = $6,400 vs 全买 $4,600 | ✓ 不存在数学上无法翻盘的落后 |
| 歼灭胜利总收入 $3,000 ＋ 6×$300 = $4,800 vs 全买 $4,600 | ✓ 歼灭胜正好够一次全买 |
| 狙击枪 $4,750 vs 败方单回合收入上限 $3,400 | ✓ 狙击是"赢过一回合"的武器，天然控稀缺 |

### 12.2 状态与信息校验点 [J02]

| 校验点 | 结果 |
|---|---|
| 烟幕 15s vs 横向支援 8s | ✓ 一次烟幕不足以掩护完整转点，须双烟接力或配合假打（烟幕接力为此设计） |
| 安装后 35s − 拆除 7s → 最迟剩余 8s 开始拆除 | ✓ 工程师 5s 拆除使其成为反拆核心，接口过载是对位反制 |
| 侦察装置 8s 扫描 vs 转点 8~11s | ✓ 信息半衰期 ≈ 机动窗口，侦察与机动互为镜像 |
| 伪装 8s vs 攻方出生→目标 12~15s | ✓ 伪装只能覆盖半程，后半程必须靠静步或烟幕 |
| 倒地窗口 12s vs 医疗救援 4s | ✓ 救援必须在火线掩护下完成，不可白嫖 |

### 12.3 设计原则回顾（实现时务必遵守）[J03]

1. **命中必须来自真实射线**：部位、材质、穿透、距离逐项入日志，不允许"准星即命中"；
2. **比例减伤 + 部位系数**，不用固定减伤，护甲永不把伤害归零；
3. **同一干员同一时刻最多一层护盾/移速/伤害加成层**：爆发只增白值，不改公式；
4. **每件武器必须有排他生态位**（距离带 × 价格 × 移速三维），不允许全能最优；
5. **每个能力必须有可执行反制**，且反制必须比能力本身便宜或更快；
6. **信息类机制必须三态可验证**：确认 / 最后已知 / 未知 —— 假目标、伪装、扫描在日志中的字段必须可区分。

## 13. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：飓风季的滨海旧城「锚湾」——走私航线上的暴雨码头；七号泊位之下埋着上一代航运时代的数据中枢，两支雇佣小队在每个雨夜为它的密钥信标开战。
- W02 场景所在地：七区域码头地图——攻守双方出生区、目标区 A/B/C、中央连接区、两条主攻路线与一条绕后水道；暴雨夜、积水反光与集装箱迷宫构成主要攻防空间（3.1）。
- W03 玩家身份与当前任务动机：玩家扮演两支雇佣队之一——「信标队」（进攻方：护送数据核心、安装信标引爆）或「锚卫队」（防守方：拆除信标、清剿来敌）；每回合的目标争夺决定泊位控制权与赏金分成。
- W04 失败代价与结局表达：败方失去泊位赏金分成与装备预算；胜方领取赏金并在结算中确立泊位控制权（回合经济的叙事包装，C04 收束）。
- W05 叙事来源：数据核心=旧中枢的密钥信标（3.2 目标物）；购买阶段=两队军械商的回合补给（4.2）；暴雨与金属码头天然放大脚步与枪声（3.4 声学半径的世界理由）；12 干员=两队的异构雇佣分工（5.2 威胁分层）。全部原创，不使用商业作品命名或造型。
- W06 视觉风格与色彩材质：暴雨夜写实战术风；主色=雨夜蓝 #2E3A4E、集装箱锈橙 #C4622D、警戒黄 #E4B33C、信标青 #35C4C9、混凝土灰 #6B7280；材质为湿钢波纹板、防滑栅格、积水镜面与油渍。
- W07 环境氛围与声音语言：暴雨环境为底（雨幕、闷雷、水滴敲击），脚步、枪声、警报与安装/拆除音为关键信息源；混音铁律=暴雨环境声恒不得盖过脚步声的方位判断（F07）；音效语言=枪械机械+金属碰撞+雨幕衬底，全部音效按 §14 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代雨夜两队登场 → 遭遇争夺视频（C02）与回合胜负视频（C03）承载回合节奏 → 终局结算视频（C04）收束；故事只做包装与节奏，不改变任何机制数值。

## 14. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：第一人称；FOV 80（可调 70–90）；狙击开镜有呼吸晃动（±0.3°，屏息 3 秒内稳定）；镜头边界=地图包围盒。
- F02 关键操作镜头变化：开火后坐按武器独立曲线（手枪 0.5°、冲锋枪 0.8° 连发累积、步枪 1.2°、霰弹 2.5°、狙击 1.5°、轻机枪 1.0° 且架设后 −70%）；被击中受伤方向指示＋镜头抖动 0.15 秒；闪光弹致盲=全屏白闪 1.5 秒→2.5 秒渐退（仅被致盲方可见）；击杀确认镜头短促顿挫。设置提供「镜头震动开/关」（关闭不影响判定与数值）。
- F03 输入与延迟：双端输入到开火反馈 ≤100 毫秒；后坐与扩散属于表现层，不改变命中判定。
- F04 环境常驻效果：暴雨雨幕与积水涟漪、闪电偶发照亮、远处货轮剪影、吊机吱嘎。纯表现层，不参与判定。
- F05 事件反馈表（事件 → 画面表现 → 音效 → 结束条件，全部冻结需求）：

| 事件 | 画面表现 | 音效 | 结束条件 |
|---|---|---|---|
| 开火 | 枪口火光＋武器独立后坐曲线＋准星扩散 | 六类武器枪声各自可辨（含弹壳落地尾音） | 射击帧结束 |
| 命中（身体） | 白色 hit marker | 命中确认音 | 0.15 秒 |
| 爆头命中 | 红色 hit marker＋击杀爆点 | 爆头高亮音（与身体命中可区分） | 0.15 秒 |

- F07 VFX 信息性与遮挡约束：hit marker、受伤方向指示、信标进度环与警报为信息类 VFX，必须清晰可辨；雨幕与粒子不得遮挡 hit marker、准星与目标物；闪光白屏仅对被致盲方生效；烟幕不得向烟雾外玩家泄露烟内信息（7.3 三态口径）。

- F09 屏幕震动：被击中 0.15 秒方向抖动；霰弹命中侧小幅震动；设置可关闭（关闭不影响判定与数值）。
- F10 前端界面：主菜单 → 房间/选人 → 购买菜单 → 战斗 HUD（资金、比分、回合与安装倒计时、装备栏、弹药、观战视角）→ 回合结算 → 终局结算 → 重开；关键状态图标+文字并用（比分、安装倒计时、干员充能），不只靠颜色区分；双端会话按回合制时间统一推进。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：9 个（text-to-3D 6，image-to-3D 3）；object 任务资产为：attacker_operator, defender_operator, data_core_beacon, pistol_sidearm, smg_carbine, rifle_standard, shotgun_breacher, sniper_rifle, lmg_sustained。每项只允许一个物体；组合物必须拆成独立任务。
- motion：7 个；覆盖动作：run_tactical, reload_rifle, plant_beacon, breach_sprint, walk_silent, defuse_beacon, downed_reach。
- video/audio/mechanic/UI：分别为 4/17/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

## 1. 定位与完整流程 [S01–S05]

- S01 类型：2.5D 侧视重力反转平台，单人单局，3 段垂直矿井。本测例包含的能力：重力二态反转与上下接触面行走、定向陷阱与周期规避、地面/顶面双锚点检查点、坠落计数与判负、终点装置交互、开场/反转事件/结算视频、重力手感演出层。
- S02 核心循环一句话：观察陷阱周期与重力方向 → 在正确接触面反转 → 落到对侧安全面 → 通过三段抵达终点。
- S03 流程：开始界面 → 进入矿井（首次进入前播 C01）→ 段1 教学 → 段2 长竖井 → 段3 精密段 → 终点装置交互 → 结算（面板前播 C03）→ 重开或返回。
- S04 最低完整流程：开始界面、可操作矿井、结算界面、重开必须全部存在且有真实入口。
- S05 失败恢复入口：坠落回最近检查点对应锚点继续（计数保留）；第 6 次坠落判负；结算界面一键重开；游玩中 Esc 暂停。

  - outcome：恢复后状态逐字段一致

## 3. 数值口径与全局规则 [G01–G06]

- G01 统一刻度：米制；时间用游戏模拟秒（暂停冻结）；坠落计数为非负整数。
- G02 数值（本包冻结值）：跑速 4.0 米/秒；反转后重力加速度 12 米/秒²；无跳跃键——反转即唯一腾空手段；反转键冷却 0.5 秒且滞空中不可再按（仅接触合法支撑面且冷却到期可反转，AUD12）；检查点 3 个（每段起点）；坠落次数上限 5 次（第 6 次判负）。
- G03 状态转移 oracle：初始「正常重力·立于地面」，输入序列〔跑动 2 秒 → 按反转 → 滞空 → 落到顶部〕必然产生事件流 `flip(dir: normal→inverted)`、`airborne_enter`、`land(surface=ceiling, orientation=inverted)`、角色行走朝向翻转；任何偏离即 FAIL。
- G04 关卡与接触面（zkx 裁决冻结）：三段推进距离 40/60/50 米；上下接触面间距 **6 米**（上下两面均为可行走接触面）；三段结构与陷阱布置由 seed=1012 冻结并导出相位。
- G05 陷阱周期（zkx 裁决冻结）：压锤 4 秒周期＝前 3 秒收起、后 1 秒危险；蒸汽 3 秒周期＝前 2 秒关闭、后 1 秒喷射；尖刺常驻；生效重力态按 M02 判定表；相位由 seed 固定并随 layout_manifest 导出。
- G06 暂停与复位裁决：Esc 冻结移动、重力与陷阱计时；窗口失焦自动暂停。检查点双锚点（AUD10）：每个检查点记录一对安全地面/顶面锚点；坠落复位保留重力方向并选对应锚点，速度归零、动作解除、翻转冷却就绪；锚点不得与陷阱重叠。坠落与终点交互同帧 → 判负优先。

## 4. 操作与输入 [I01–I07]

- I01 键位：A/D 或 ←/→＝移动；Space 或 W＝重力反转；Esc＝暂停；Enter＝结算界面重开；终点装置交互由抵达触发（无独立按键）。
- I02 输入语义边界：冷却中/滞空中按反转无效且无副作用；暂停/结算期间玩法键无效；被拒输入不产生事件。
- I03 键盘为完整输入方式；菜单可仅用键盘操作。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；同帧互斥动作按 I01 列举顺序取首个。
- I05 焦点与失焦：点击画布捕获输入焦点；窗口失焦自动暂停。
- I06 UI 必显状态：当前重力方向（正常/反转）、朝向、坠落计数（0–5）、当前检查点编号、已用时间。
- I07 输入延迟目标：按键到画面反馈 ≤100 毫秒（P95，≥30 次采样/类别）。

## 6. 机制系统 [M01–M04]

- M01 重力切换与接触面（主机制）
  - input：反转键（触发方：玩家）
  - precondition：接触合法支撑面（地面或顶面）且 0.5 秒冷却已到期（AUD12）
  - state_change：重力方向二态翻转 → 离地滞空（重力加速度 12 m/s²）→ 落到原「对侧」接触面并更新行走朝向（角色在 0.2 秒内旋转朝向，镜头保持水平，AUD12）
  - observable：重力向量状态、朝向事件、落点事件（见 G03 oracle）
  - invalid_case：滞空中或冷却中按反转 → 拒绝且无副作用
  - recovery：坠落走 M03 复位
- M02 定向陷阱
  - input：接触判定（触发方：系统）
  - precondition：处于游玩状态且陷阱相位按 G05 周期运行
  - state_change：按判定表（本包冻结值）——尖刺组 A 仅对「正常重力·立地面」生效；顶部压锤组 B 仅对「反转重力·立顶面」生效（危险窗为 4 秒周期的后 1 秒）；侧向蒸汽组 C 两态均生效（仅段3，喷射窗为 3 秒周期的后 1 秒）；错误状态接触陷阱造成坠落（计 M03）
  - observable：陷阱命中事件含重力方向与陷阱类型字段、周期相位时间戳
  - invalid_case：收起/关闭相位接触不造成坠落
  - recovery：坠落后回检查点锚点复位
- M03 坠落复位
  - input：掉出安全区或陷阱命中（触发方：系统）
  - precondition：处于游玩状态
  - state_change：回最近检查点对应重力方向的锚点（保留重力方向并选对应锚点，速度归零、动作解除、翻转冷却就绪，AUD10）、坠落计数 +1；第 6 次判负结算
  - observable：reset 事件（含检查点 ID 与锚点面）、fall_count 流水
  - invalid_case：结算后坠落不再触发复位
  - recovery：判负走 V02；结算界面重开为最终出路
- M04 胜负与重开
  - input：终点装置交互完成 / 第 6 次坠落 / 结算界面（触发方：系统判定/玩家）
  - precondition：处于游玩状态或结算状态
  - state_change：终点交互完成 → 胜利结算（显示用时与坠落次数）；第 6 次坠落 → 失败结算（注明原因）；结算后玩法冻结；同帧裁决按 G06（判负优先）
  - observable：win / lose(reason) 事件与结算面板
  - invalid_case：结算后再触发判定被拒绝（每局一次）
  - recovery：重开=全量重置（重力回正常、计数清零、相位按 seed 复现）

## 7. 成功、失败与恢复 [V01–V06]

- V01 成功条件：按序通过三段并完成终点装置交互 → 结算（显示用时与坠落次数）。
- V02 失败条件：坠落计数达 6 次（超上限 5）→ 判负结算（注明「坠落超限」）；与终点同帧按 G06 判负优先。
- V03 恢复语义：单次坠落回最近检查点对应重力方向锚点继续（计数保留、重力方向保留）；判负后一键重开。
- V04 persistent_state：无（重开全量清空；检查点仅记录双锚点位置）。
- V05 persistent_state 生命周期：动作级即时结算；局内状态（计数/时间）局内保留、重开清空；无跨局保留。
- V06 软锁与不可达处理：不设永久软锁——陷阱周期与双锚点保证任一重力方向均有复位出路；判定不可达时按 V02 失败语义结算而非无限等待。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：矿井里的反向救援——深井中央的主重力核失控，矿道上下两面翻转不定，矿井濒临坍缩。
- W02 场景所在地：一座三段垂直矿井（教学巷道 40 米、长竖井 60 米、精密检修段 50 米），上下两面均可行走，尽头是失稳的主重力核终点装置。
- W03 玩家身份与当前任务动机：玩家是重力维修工，携带着反转扳手下井；动机是在矿道彻底坍缩前重启主重力核，让矿井恢复秩序。
- W04 失败代价与结局表达：失败=第六次坠落，维修工被矿井引力乱流卷回井口（C03 失败意象）；胜利=主重力核重启、矿井灯光逐层亮起（C03 胜利意象）。
- W05 叙事来源：重力反转=维修扳手的二态扳动（唯一腾空手段）；定向陷阱=失控引力对不同接触面的定向反噬（尖刺咬地面、压锤咬顶面、蒸汽两态皆险）；双锚点检查点=维修工安装的双面安全栓。全部原创。
- W06 视觉风格与色彩材质：深矿井工业风＋暖色灯光点缀；主色=岩黑 #2B2F36、铜金 #C9A876、危险红 #C43B2F、重力青 #4FC3C9、灯暖橙 #E8A25C；材质为湿岩、锈铁、蒸汽铜管。
- W07 环境氛围与声音语言：矿井低鸣与滴水为底；音效语言为「重力反转嗡鸣+金属陷阱+落面闷响」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代下井与失控主核 → 反转事件视频（C02）承载重力机制的过程叙事 → 结算视频（C03）收束；叙事提示不阻断控制、不改变数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：2.5D 侧视固定水平镜头（不随重力旋转）；前视安全区 ≥ 屏宽 30%；镜头仅位移不旋转；镜头重置仅在明确切场/复位时。

- F06 关键音效清单（one_shot 8 条，全部冻结需求）：重力反转嗡鸣、失重风切、落面闷响、陷阱命中锐响、坠落复位音、压锤机械预警音、蒸汽喷射音、胜利/失败结算音（胜利上扬/失败低沉各一）。混音优先级：陷阱与压锤/蒸汽预警 ＞ 反转/落面 ＞ 其余；环境循环：矿井低鸣（常驻，暂停静音、结算淡出 0.5 秒，接缝无爆音；恒低于预警音）。无配音需求。震动事件到调度日志 ≤50ms（含 source_event_id/单调时间/amplitude/duration_ms/channel/device_available），无硬件时验证调度与禁用行为。
- F07 VFX 信息性与遮挡约束：双锚点检查点基座与陷阱危险相位为信息类 VFX，必须清晰可辨（压锤收起/危险、蒸汽关闭/喷射可辨）；反转光圈不遮挡陷阱轮廓与 HUD；闪红 ≤0.1 秒不遮挡后续判定输入；隐藏状态（陷阱下一相位）不得被特效泄露。
- F08 音画同步：反转嗡鸣与光圈同帧；落面闷响与尘土同帧；预警音与危险窗起始同帧。
- F09 屏幕震动：仅陷阱命中 0.08 秒轻微抖动；暂停/结算/重开取消未结束的震动与特效；设置可关闭（关闭不影响判定与数值）。
- F10 前端界面：标题（开始/设置/退出）→ 矿井 HUD（I06 全项）→ 结算面板（用时/坠落次数/原因/重开/返回）→ 暂停面板（继续/重开/返回/设置）；关键状态图标+文字并用（重力方向、坠落计数）；窗口失焦自动暂停；叙事节拍提示不阻断控制。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：6 个（text-to-3D 4，image-to-3D 2）；object 任务资产为：mine_mechanic, spike_trap, ceiling_hammer, steam_vent, dual_anchor_checkpoint, gravity_core_console。每项只允许一个物体；组合物必须拆成独立任务。
- motion：4 个；覆盖动作：run, gravity_flip, trap_react, fall_reset。
- video/audio/mechanic/UI：分别为 3/10/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

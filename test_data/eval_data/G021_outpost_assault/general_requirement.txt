## 1. 定位与完整流程 [S01–S06]

- S01 类型：单屏幕俯视攻防（布防＋出征两阶段单循环），单人单局。本测例包含的能力：布防预算建造、陷阱消耗、编组出征与登陆点选择、兵种克制、来袭波脚本、战利品经济与升级、撤回中间结算、主堡被毁局败、胜利/失败/撤回三种结算结果、开场/波次/结算视频、攻防手感演出层。
- S02 核心循环一句话：布置防御 → 编组出征小队 → 选登陆点 → 摧毁目标工事带回战利品 → 升级布防 → 再出征，直至摧毁敌方核心。
- S03 流程：标题 → 布防态（首次进入前播 C01）→ 编组出征（选编组＋登陆点）→ 进攻态（敌方目标岛，含 2 次来袭波）→ 撤回结算（中间结算，布局/战利品/升级保留）→ 回布防态升级 → 循环 → 摧毁敌方核心=通关 或 主堡被毁=局败 → 结算（面板前播 C03）→ 重开或返回。
- S04 最低完整流程：布防界面、编组界面、进攻战斗、撤回结算、升级入口、通关/局败结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：出征小队全灭或 180 秒超时 → 撤回中间结算（布局/战利品/升级保留，免费重编组再出征）；主堡被毁 → 局败结算（Enter 重开清空全局）；结算界面一键重开。
- S06 本局耦合边速览：E01 布防系统→来袭损耗系统（布局改变敌方来袭损耗）；E02 战利品系统→升级系统（战利品再投入改变下次出征战力）——均限本局循环内（P1）。

## 2. 完整核心循环与阶段 [S07–S13]

- S07 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且资源加载完成
  - state_change：进入「标题」状态；首次开始时按 §10 C01 播放开场视频
  - feedback：标题界面按 §9 F10 呈现
  - next_actions：进入「布防态」
  - outcome：无跨局状态写入
- S08 布防态（建造与升级）
  - input：点击放置/出售建筑与陷阱、升级点击（触发方：玩家）
  - precondition：处于布防态且预算/战利品满足（M01/M04 口径）
  - state_change：塔/陷阱落位（扣布防预算）或出售（全额返还，出征前）；升级按 AUD12 公式扣 100 战利品；布防预算局内保留、已损毁塔/已消耗陷阱不退款（AUD14）
  - feedback：按 §9 F05（放置网格、塔射程圈、升级脉冲）
  - next_actions：编组出征 →「进攻态」
  - outcome：出征开始锁定布防快照（AUD11）
- S09 编组出征
  - input：编组界面点选兵种数量、点选登陆点（触发方：玩家）
  - precondition：编组 ≤20 单位（免费重编组，AUD11/14）
  - state_change：小队编成、登陆点确定（东滩/南崖/西湾）；出征开始锁定布防快照、180 秒计时与两波脚本重置（AUD13）
  - feedback：编组面板（三类兵种/上限/克制提示）
  - next_actions：进入「进攻态」
  - outcome：出征小队状态独立于布防
- S10 进攻态（目标岛）
  - input：点选目标点移动（单位自动交战）（触发方：玩家）；来袭波按脚本触发（触发方：系统）
  - precondition：处于进攻态且非暂停/结算
  - state_change：按 §6 M02/M03 结算交战与克制；摧毁工事/核心计战利品；来袭两波（t=30/90 秒各 4 单位：2 枪兵 1 装甲 1 破甲）沿最近可达路线攻击主堡（AUD11）；首次波次触发按 §10 C02 播放波次视频
  - feedback：按 §9 F05（命中闪烁、战利品弹字、波次警报、核心受击震动）
  - next_actions：摧毁敌方核心 →「通关结算」；小队全灭/超时 →「撤回结算」；主堡被毁 →「局败结算」
  - outcome：按 §7 V01/V02/V03 判定，同帧局败优先（G06）
- S11 撤回结算（中间结算）
  - input：Enter=返回布防态（触发方：玩家）
  - precondition：V03 成立（小队全灭或 180 秒超时）
  - state_change：布局、战利品、升级、敌工事/核心伤害与一次性奖励状态保留；下一次出征 180 秒与两波脚本重置（AUD13）；不播 C03（撤回非终局）
  - feedback：撤回面板显示原因（全灭/超时）与保留状态摘要
  - next_actions：回布防态免费重编组再出征
  - outcome：中间结算不清空全局
- S12 通关/局败结算
  - input：Enter=重开 / Esc=返回（触发方：玩家）
  - precondition：V01（敌核心被毁）或 V02（主堡被毁）成立
  - state_change：进入对应终局结算；面板出现前按 §10 C03 播放结算视频（每局一次，三意象）
  - feedback：通关面板（战利品/战损比/用时）；局败面板注明「主堡被毁」
  - next_actions：Enter 重开清空全局或返回标题
  - outcome：只有通关/局败后的 Enter 重开才清空全局（AUD13）
- S13 暂停
  - input：Esc（触发方：玩家）；窗口失焦自动触发（触发方：系统）
  - precondition：处于布防态或进攻态
  - state_change：暂停覆盖层打开，战斗与计时（含 180 秒与波次脚本）冻结
  - feedback：暂停面板（继续/重开/返回/设置）
  - next_actions：继续 → 回到原状态
  - outcome：恢复后状态逐字段一致

## 3. 数值口径与全局规则 [G01–G07]

- G01 统一刻度：兵种单位数、建筑数、战利品、布防预算、时间（秒）均为整数；格为逻辑坐标。
- G02 兵种与克制（本包冻结值）：三类兵种——沙枪手（基础攻 10、HP 40）、岩甲车（攻 40、HP 120）、破壁手（攻 25、HP 60）。两两克制：岩甲车克沙枪手、沙枪手克破壁手、破壁手克岩甲车，克制系数 ×1.5、被克 ×0.75、同类 ×1.0。伤害结算（AUD14）：**先计算升级后的基础攻，再乘克制系数，最后 floor(x+0.5) 取整，每击至少 1**。独立 oracle 数例：岩甲车对沙枪手单发 40×1.5＝**60**；沙枪手对岩甲车单发 10×0.75＝floor(7.5+0.5)＝**8**；未升级沙枪手对己方无克制目标 10×1.0＝**10**。
- G03 布防与建筑（zkx 裁决冻结，AUD10/14）：布防预算 **300**（独立于战利品；战利品初始 **100**）；建造费用：塔 **50**、地面陷阱 **25**；出征前出售建筑**全额返还**布防预算；塔 HP 300、攻击 20、间隔 1 秒、射程 **6 格**、自动选敌（射程内最近敌人优先，同距按实体 ID 破序，AUD14）；地面陷阱对触发单位一次造成 **50 无甲伤害**后消耗（不退款）；主堡 HP **1000**；敌方核心 HP **1200**、外围工事 HP **200**；建造位不超 8 建筑/6 陷阱位。布防预算在局内保留，已损毁塔/已消耗陷阱不退款（AUD14）。
- G04 出征与波次（zkx 裁决冻结，AUD11）：每次出征最多 **20 单位**，编组与重编组免费；三类兵种移速 2 格/秒、攻击间隔 1 秒；沙枪手/岩甲车/破壁手射程 **6/3/4 格**；本例无护甲层，对建筑伤害系数 **1.0**；出征开始锁定布防快照；来袭两波在出征模拟 **t=30/90 秒**各 4 单位（2 枪兵 1 装甲 1 破甲），沿最近可达路线攻击主堡；无目标时单位走向指令点，被建筑阻挡时攻击可破坏阻挡体（AUD14）。
- G05 战利品与升级（zkx 裁决冻结，AUD12）：摧毁敌方核心 **+200**；每摧毁一个敌方外围工事 **+20**；己方建筑被毁 **−10**（战利品可为负）；升级仅两种：兵种基础攻 +10%（第 k 级攻＝基础×(1+0.1k)）、己方建筑最大 HP +20%（第 k 级最大 HP＝基础×(1+0.2k)），每次 **100 战利品**、升级时必须 ≥100；升级效果按基础值加算、**不自动补满已损失 HP**、仅本局有效；工事奖励**按对象 ID 每局仅一次**（幂等，重复摧毁不重复发放）。
- G06 计时、裁决与同帧优先（zkx 裁决冻结，AUD13）：单次出征限时 **180 秒**（超时按全灭撤回）；fixed_seed=1021 冻结敌方岛工事布位与来袭波脚本，同 seed 同操作序列事件可复现；主堡被毁与敌方核心被毁同帧 → **局败优先**；结算只触发一次并锁定玩法；先检查失败再检查成功（AUD01）。Esc 暂停冻结战斗与计时；布防/编组/结算界面不推进战斗时间。
- G07 建造经济 oracle（AUD14 口径）：独立数例——初始布防预算 300 建 4 塔（200）＋4 陷阱（100）＝恰用尽，出售 1 塔返还 50；升级一次 100 战利品（初始 100 → 0）；塔对来袭枪兵单发 20×1.0=20（对建筑系数同 1.0），枪兵 HP 40 → 2 击消灭；任何偏离即 FAIL。

## 6. 机制系统 [M01–M04]

- M01 防御布防（主机制）
  - input：布防态放置/出售/升级指令（触发方：玩家）
  - precondition：建造需布防预算 ≥50（塔）/≥25（陷阱）且对应空位；升级需战利品 ≥100；出售仅出征前全额返还
  - state_change：塔/陷阱落位（扣预算）→ 改变敌方来袭单位的路径与损耗；升级按 AUD12 公式提升基础攻/最大 HP（不补满已损 HP）；已损毁塔/已消耗陷阱不退款（AUD14）
  - observable：布防快照（塔/陷阱/位）与敌方来袭损耗流水对账；预算/战利品流水
  - invalid_case：预算/战利品不足、位满时点击无效且无副作用
  - recovery：出售返还可重新布防；撤回中间结算保留布局（AUD13）
- M02 登陆点与交战（主机制）
  - input：出征界面点选登陆点；进攻态点选目标点（触发方：玩家）
  - precondition：编组 ≤20 单位且处于进攻态
  - state_change：不同登陆点 → 接触敌方不同防线序列 → 战损差分；交战优先射程内最近敌人、同距按实体 ID 破序；被建筑阻挡时攻击可破坏阻挡体（AUD14）
  - observable：登陆事件与逐单位战损流水（含空间分布与克制字段）
  - invalid_case：超编/无效目标点击拒绝且无副作用
  - recovery：小队全灭/超时走 M03 撤回
- M03 兵种克制与三种结算（主机制）
  - input：编组配置＋交战判定；终局判定（触发方：系统）
  - precondition：处于进攻态
  - state_change：按 G02 克制表与 AUD14 取整公式结算伤害；敌核心被毁 → 通关结算；出征小队全灭/180 秒超时 → 撤回中间结算（保留布局/战利品/升级/敌工事伤害/一次性奖励状态）；主堡被毁 → 局败结算；主堡毁与核心毁同帧局败优先（AUD13）
  - observable：克制命中伤害差分（含双方类型字段）、三种结算事件（win/lose/retreat）
  - invalid_case：结算后再触发判定被拒绝（每局每种一次）
  - recovery：撤回后免费重编组再出征；通关/局败后 Enter 重开清空全局
- M04 战利品经济与幂等（主机制）
  - input：摧毁敌方对象（触发方：系统）；升级点击（触发方：玩家）
  - precondition：战利品 ≥100 才可升级（AUD12）
  - state_change：核心 +200/工事 +20/己方建筑被毁 −10；工事奖励按对象 ID 每局仅一次（幂等）；升级消耗 100、按基础值加算（第 k 级攻=基础×(1+0.1k)、最大 HP=基础×(1+0.2k)）
  - observable：战利品流水（含对象 ID 与幂等标记）、升级事件与属性差分（升级前后快照）
  - invalid_case：重复摧毁同一工事 ID 不重复发放；负战利品时升级拒绝
  - recovery：撤回中间结算保留战利品与升级（AUD13）

系统耦合边（玩法必需、可复现）：

- E01 from_system=布防系统 → to_system=来袭损耗系统；changed_state=塔/陷阱布局改变敌方来袭单位的路径与损耗（陷阱 50 伤害消耗、塔 20/秒射程 6 格）；验证方式=同 seed 同波次下不同布防快照的来袭损耗流水 state_before/after 对照。
- E02 from_system=战利品系统 → to_system=升级系统；changed_state=战利品再投入改变下次出征兵种攻/建筑最大 HP（AUD12 公式）；验证方式=升级前后对小队战力快照对照（第 1 级攻 10→11、最大 HP 300→360）。

## 7. 成功、失败与恢复 [V01–V06]

- V01 成功条件（通关）：摧毁敌方目标核心 → 终局胜利结算（显示战利品、战损比、用时）。
- V02 失败条件（局败）：己方前哨主堡被毁 → 局败结算（注明「主堡被毁」）；与核心被毁同帧局败优先（AUD13）。
- V03 撤回（中间结算）：出征小队全灭或 180 秒超时 → 撤回结算；布局、战利品、升级、敌工事/核心伤害与一次性奖励状态保留；下一次出征 180 秒与两波脚本重置（AUD13）——与通关/局败的终局语义不同，三者必须区分。
- V04 persistent_state：局内循环保留（布防布局/预算、战利品、升级、敌工事伤害、一次性奖励状态）；无跨局存档，通关/局败后 Enter 重开全量清空（AUD13）。
- V05 persistent_state 生命周期：动作级即时结算；局级状态局内保留；只有通关/局败后的 Enter 重开才清空全局；跨局不保留。
- V06 软锁与不可达处理：不设永久软锁——关键目标均可通过正常操作达成（免费重编组、出售返还）；主堡被毁/核心被毁提供明确终局而非无限等待；结算界面重开为最终恢复出路；不得把恢复入口缺失解释为正常失败。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：荒漠海岸的前哨第二道命令——风沙纪元的海岸防线吃紧，前哨是大陆桥头的最后支点。
- W02 场景所在地：荒漠海岸两张俯视地图（己方前哨：主堡＋建造位＋陷阱位；敌方目标岛：核心、外围工事、两段防线、三处登陆点）。
- W03 玩家身份与当前任务动机：玩家是前哨指挥官；动机是在来袭波逼近下布置第一道防线、组织出征并摧毁敌方海岸核心，把战利品投入后续作战。
- W04 失败代价与结局表达：敌核心摧毁=胜利（C03 胜利意象）；主堡被毁=局败（C03 局败意象）；小队全灭/超时=撤回（C03 撤回意象，非终局）；三种结果结算界面区分原因。
- W05 叙事来源：塔=前哨速射哨塔；陷阱=荒漠陷坑；三类兵种=沙枪手/岩甲车/破壁手（海岸戍卫编制）；战利品=缴获军资；登陆点=东滩/南崖/西湾三处抢滩口。全部原创。
- W06 视觉风格与色彩材质：荒漠海岸军事风；主色=沙金 #D8B96A、岩褐 #8A7A66、军绿 #6E8F5A、警示橙 #E4762C、海雾蓝 #7FA3B8；材质为风化岩、帆布工事、金属塔架。
- W07 环境氛围与声音语言：海岸风沙为底；音效语言为「建造落位＋塔击发＋命中闪烁＋战利品弹字＋波次警报＋升级脉冲」，全部音效按 §9 F06 冻结清单交付；混音优先级：波次/主堡警报 ＞ 战斗命中 ＞ 建造/升级 ＞ 环境风沙。
- W08 故事表达方式：开场视频（C01）交代前哨与敌方核心目标 → 波次视频（C02）承载敌袭升级的过程叙事 → 结算视频（C03）三意象收束；叙事提示不阻断控制、不改变数值；提前失败允许直接进入失败结局。

  - 可跳过：Esc/Enter 跳过 → 直接进入对应结算面板；自然播完 → 进入对应结算面板

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：8 个（text-to-3D 4，image-to-3D 4）；object 任务资产为：outpost_keep, sentry_tower, ground_trap, enemy_core, outer_bastion, rock_armor_car, sand_gunner, wall_breaker。每项只允许一个物体；组合物必须拆成独立任务。
- motion：8 个；覆盖动作：move, attack, hit, death, move, attack, hit, death。
- video/audio/mechanic/UI：分别为 3/13/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

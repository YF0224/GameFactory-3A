## 1. 定位与完整流程 [S01–S07]

- S01 类型：三日循环的基地生存管理。本测例包含的能力：昼夜循环与任务分配、搜集风险脚本、制作取舍、五级伤员状态机、士气与共餐、夜袭防御、三结局判定、日结与日内两级恢复、开场/两段日转换/结局视频。
- S02 核心循环一句话：昼间防御与整备 → 夜间外出搜集 → 制作补给 → 伤员分配护理 → 次日资源结算 → 第 3 日救援结局。
- S03 流程：第一日（立足：修工事、囤食物、分工试探）→ 第二日（危机：夜袭加强、外出遭遇伤病）→ 第三日（救援判定：按存活/资源/伤情出结局）。
- S04 最低完整流程：任务分配面板、搜集、制作、护理、夜袭结算、结局判定、重开必须全部存在且有真实入口。
- S05 失败恢复入口：每日晨自动存档可读档；日内任意时刻可「回到本日晨」（G09）；一键重开；Esc 暂停。
- S06 本局耦合边速览：搜集系统→伤员系统（外出带回资源同时承受伤病）；工事系统→夜袭损耗系统（防御强度改变夜袭损耗）；士气系统→夜袭损耗（士气 ≥2 免除夜袭伤情项）。
- S07 跨阶段结构与状态保留：三日昼夜循环推进；基地资源、工事强度、居民状态（伤情）、士气、库存全量跨日持久；日结自动存档，读档全量恢复。

## 2. 完整核心循环与阶段 [S06–S10]

完整循环：启动与第一日 → 第一夜 → 第二日 → 第二夜 → 第三日与结局 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与第一日
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且基地按 seed=1050 生成完成
  - state_change：进入「第一日昼间」状态；首次进入按 §10 C01 触发开场视频
  - feedback：第一日目标提示（修工事/囤食物）按 §9 F10 呈现
  - next_actions：分配任务并推进昼夜 →「第一夜」
  - outcome：第一日快照落盘（日晨存档）
- S07 第一夜
  - input：昼间已确认分配（触发方：系统接管；玩家仅查看夜袭结算）
  - precondition：昼间 120 秒结束且分配已锁
  - state_change：外出结算（资源＋伤病脚本）→ 夜袭结算（工事差分）→ 日结推进至第二日晨
  - feedback：夜袭警报、结算面板（§9 F05）
  - next_actions：按 Enter 推进 →「第二日」（播 C02）
  - outcome：资源/伤情/士气跨日持久
- S08 第二日与第二夜
  - input：玩家昼间分配（触发方：玩家）；夜间接管（触发方：系统）
  - precondition：第一夜日结完成
  - state_change：第二日夜袭强度 2、外出者必遭劫掠受伤（seed 脚本）；士气与共餐可用
  - feedback：第二日危机提示与共餐反馈
  - next_actions：日结 →「第三日」（播 C03）
  - outcome：第二日快照落盘
- S09 第三日与结局
  - input：昼间整备（触发方：玩家）；救援判定（触发方：系统）
  - precondition：第二夜日结完成
  - state_change：第三日晨按 G07 结局条件判定 → 出「全员撤离/艰难撤离/社区失守」结局
  - feedback：结局面板与 C04（尾帧按结局变体）
  - next_actions：重开或返回
  - outcome：按 V01/V02 结算
- S10 暂停与日内恢复
  - input：Esc 暂停（触发方：玩家）；「回到本日晨」（触发方：玩家）
  - precondition：处于三日任意阶段
  - state_change：暂停冻结昼夜倒计时与夜袭流程；「回到本日晨」读当日晨存档全量恢复
  - feedback：恢复面板注明回到日与状态摘要
  - next_actions：继续或重开
  - outcome：日内恢复为检查点语义（G09）

## 3. 数值口径与全局规则 [G01–G09]

- G01 统一刻度：资源按件、伤情按级（0 健康/1 受伤/2 恶化/3 垂危/死亡）、工事按级 0–3、士气按点 0–2；时间用游戏模拟秒（昼 120 秒、夜 90 秒，暂停冻结）。
- G02 居民与基地（本包冻结值）：居民 4 名（原创造型：老周/阿岚/小满/程奶奶）；基地两层小楼（床位 4、储物间、工作台、门禁工事位）；居民每日消耗食物 1 件/人，断食日伤情 +1。
- G03 搜集与风险（本包冻结值）：夜间可派 0–2 人外出；每次外出带回食物 2 件＋材料 2 件（50% 追加药品 1，由 seed 序列决定）；外出承受伤病风险——seed 脚本冻结：第 2 夜外出者必遭劫掠者受伤（伤情 +1）；留守者承担夜袭风险。
- G04 制作与取舍（本包冻结值）：材料 2 件 → 工事加固 1 级或床位维修 1 张；食物 1＋材料 1 → 干粮（次日起可囤）；药品 1 由护理消耗不可制作；同一材料不可同时用于两种用途（冲突取舍表导出事件）。
- G05 伤员状态机（本包冻结值）：健康→受伤→恶化→垂危→死亡为单向恶化（断食或夜袭致伤各 +1 级）；护理（1 药品）→ 回退 1 级；垂危未护理过夜 → 死亡（永久移除并计入结局扣分）。
- G06 夜袭与防御（本包冻结值）：夜袭强度——第 1 夜 1、第 2 夜 2、第 3 夜 3；工事级 ≥ 夜袭强度 → 无损失；每低 1 级 → 被抢食物 2 件＋随机 1 名留守居民伤情 +1（seed 决定目标）。
- G07 判定与独立 oracle（本包冻结值）：夜袭 oracle——工事 2 对夜袭 2 必无损失、工事 1 对夜袭 2 必失食物 2 件＋1 人受伤；伤员 oracle——垂危未护理过夜必死亡、用药必回退 1 级；结局 oracle——第 3 日晨判定：存活 ≥3 且食物 ≥2 → 「全员撤离」好结局；存活 2 或（存活 ≥3 但食物 <2）→ 「艰难撤离」结局；存活 <2 → 「社区失守」失败结局（≥2 结局分支）。存读档 oracle——日结存档后读档全量状态快照 diff＝0。任何偏离即 FAIL。fixed_seed=1050 冻结夜袭目标序列与搜获得率序列。
- G08 士气与共餐（本包冻结值）：士气 0–2，初始 1；昼间可执行 1 次「共餐」（消耗食物 1，每日限 1 次）→ 士气 +1（上限 2）；断食日 → 士气 −1（下限 0）；士气 ≥2 时，夜袭结算中「居民伤情 +1」项免除（被抢食物仍按规则执行）；士气状态跨日持久并显示于 HUD。
- G09 日内恢复与阶段重开（本包冻结值）：每日晨自动存档（day_start 快照，含资源/伤情/士气/工事/库存）；昼间与夜间任意时刻可从暂停菜单「回到本日晨」（读当日晨存档，全量恢复）；日结后自动推进至次日晨存档；一键重开全量清空（seed 复现）。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：点击居民＋任务卡＝分配（整备/外出/留守/护理）；点击工作台＝制作；点击门禁＝加固；点击餐桌＝共餐；Esc＝暂停；日结界面 Enter＝推进；结局界面 R＝重开。
- I02 输入语义边界：材料/药品/食物不足的指令被拒；夜外期间不可再改派（分配锁）；共餐每日限 1 次重复被拒；暂停/结算期间输入无效。
- I03 无手柄需求；居民伤情、士气、库存、工事级、昼夜倒计时、夜袭预告须常驻显示。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；同帧多输入按分配→制作→加固→共餐顺序结算。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：4 名居民伤情与任务、士气（数字＋图标）、库存（食物/材料/药品）、工事级、昼夜倒计时、夜袭预告、共餐可用状态；HUD 对照见 rubric。
- I07 输入延迟目标：面板点击到反馈 ≤ 100 毫秒。

## 6. 机制系统 [M01–M07]

- M01 昼夜循环（主机制）
  - input：系统计时
  - precondition：处于三日流程内
  - state_change：昼＝防御窗口（可整备）；夜＝搜集窗口（留守/外出分配锁）
  - observable：昼夜切换事件与角色任务分配记录
  - invalid_case：入夜后改派被拒（分配锁）
  - recovery：G09 日内恢复
- M02 搜集与风险
  - input：外出指令
  - precondition：昼间已确认 0–2 人外出名单
  - state_change：外出 → 带回资源但承受伤病风险（seed 脚本）
  - observable：搜集结算与伤病事件
  - invalid_case：夜外期间改派被拒
  - recovery：护理或次日重试
- M03 制作与资源取舍
  - input：制作指令
  - precondition：材料/食物满足对应配方
  - state_change：材料匮乏 → 道具/食物/药三分取舍（冲突表）
  - observable：取舍决策事件与库存对账
  - invalid_case：材料不足拒绝且不部分消耗
  - recovery：次日搜集补充
- M04 伤员状态机
  - input：伤病/护理
  - precondition：护理需药品 ≥1 且目标伤情 ≥1 级
  - state_change：健康→受伤→恶化→康复回退；死亡 → 结局扣分
  - observable：伤员状态转移事件（合法转移断言）
  - invalid_case：垂危未护理过夜 → 死亡（合法终态）
  - recovery：用药回退 1 级
- M05 基地防守
  - input：夜袭事件
  - precondition：夜段开始（夜袭强度按日 1/2/3）
  - state_change：防御工事强度 → 夜袭损耗差分（士气 ≥2 免除伤情项，G08）
  - observable：夜袭结算与工事差分
  - invalid_case：工事 ≥ 强度 → 无损失
  - recovery：日结后昼间修复
- M06 救援结局
  - input：第 3 日判定（系统）
  - precondition：第二夜日结完成
  - state_change：按存活/资源/伤情汇总 → 结局分支
  - observable：结局触发事件与条件快照
  - invalid_case：第 3 日前全员死亡提前终止并按失守结算
  - recovery：重开全量清空
- M07 士气与共餐
  - input：共餐指令（昼间）
  - precondition：食物 ≥1 且当日未共餐
  - state_change：食物 −1 → 士气 +1（上限 2）；断食日士气 −1；士气 ≥2 → 当夜夜袭伤情项免除
  - observable：`morale_change` 事件（含原因字段）与夜袭豁免标记
  - invalid_case：重复共餐或食物不足被拒
  - recovery：无副作用回退

跨阶段后果表（至少 1 条显式 A→B→C 链，早期状态在后续阶段仍可观察）：

- K01 阶段A（第一日修工事与囤食物，库存与工事级落盘）→ 阶段B（第二日夜袭损耗与外出伤病由工事级与派单决定）→ 阶段C（第三日结局分支完全由前两日累计的存活名单、食物与伤情汇总决定）；验证方式=跨阶段回溯探针：第一日库存/工事快照 → 第二日夜袭/伤病流水 → 第三日结局条件对照。
- K02 阶段A（第一日将药品护理分配给甲并记录）→ 阶段B（甲康复可承担第二夜外出，乙因未护理而恶化）→ 阶段C（第三日存活名单与结局分支依赖护理分配记录，早期药给谁在终局名单仍可观察）；验证方式=护理分配流水 → 伤情轨迹 → 存活名单对照。

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：第 3 日晨达成救援结局——「全员撤离」（存活 ≥3 且食物 ≥2）为最佳；「艰难撤离」（存活 2 或食物不足）亦计达成但结算注明。
- V02 失败条件：「社区失守」结局（存活 <2）；或第 3 日前全员死亡提前终止。
- V03 恢复语义：每日晨自动存档可读档（回该日晨全量状态）；日内任意时刻「回到本日晨」（G09）；一键重开全量清空（seed 复现夜袭与搜获序列）。
- V04 persistent_state：跨日持久（基地资源、工事强度、居民伤情、士气、库存全量跨日保留；日结存档；重开全量清空）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（三日进度）局内保留；跨日状态按 V04 持久；无跨局保留（重开全量清空）。
- V06 软锁与不可达处理：不设永久软锁——日内恢复与读档双出路；任意状态可推进至日结或结局。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：近未来的内陆地震灾后第三天，「霁后巷」社区在断水断电中等待外部救援队抵达；余震与劫掠者威胁着最后的存粮。
- W02 场景所在地：霁后巷社区的两层小楼基地——床位、储物间、工作台、门禁工事位与餐桌；周边三个搜集点（药铺废墟/便利店/工棚）。
- W03 玩家身份与当前任务：玩家是社区互助组组长；当前任务：在三日窗口内分配居民整备、搜集与护理，守住社区等到第三日救援判定。
- W04 失败代价与结局表达：社区失守＝救援抵达时已无人可救（失守文案）；全员撤离＝C04 呈现救援车队驶入、全员登车的场面；艰难撤离则呈现满目疮痍的离别。
- W05 叙事来源：4 名居民各有分工来源——老周（工事手艺）、阿岚（夜行搜集）、小满（年轻劳力）、程奶奶（护理经验）；劫掠者＝灾后失序的外来威胁；餐桌＝社区共餐传统的具象。全部原创。
- W06 视觉风格与色彩材质：风格化写实的灾后社区；主色＝尘灰（#7A7468 系）＋火堆暖橙（#D98A4A 系）＋警戒灯红（#C43B3B 系）；材质以砖瓦残垣、防水布、木箱为主，雨夜反光明显。
- W07 环境氛围与声音语言：灾后社区的紧张与守望——常驻余风与远处犬吠；音效语言为「锤击加固＋脚步搜刮＋夜袭警报＋共餐碗筷」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代震后抵达与任务 → 两段日转换视频（C02/C03）承载「第二日危机」「第三日黎明」节奏 → 结局视频（C04）按分支收束；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：固定俯视 45° 基地全景（三档缩放：全景/基地/室内），鼠标拖拽平移（边界＝社区外框）；无跟随镜头；夜袭结算时镜头轻微推近门禁 5%。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：1 个（text-to-3D 0，image-to-3D 1）；object 任务资产为：gate_barricade。每项只允许一个物体；组合物必须拆成独立任务。
- motion：4 个；覆盖动作：hammer_work, walk, carry_crate, nurse_idle。
- video/audio/mechanic/UI：分别为 4/9/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

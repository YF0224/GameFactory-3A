## 1. 定位与完整流程 [S01–S06]

- S01 类型：单区域轻任务 RPG（对话接取→寻物→交付）。本测例包含的能力：三线并行委托、线索链与方向提示、条件交付与确认框、一次性奖励、委托后叙事状态、开场/寻获/结算视频。
- S02 核心循环一句话：对话接取 → 寻找/拾取 → 条件判定 → 交付 → 奖励 → 完成状态。
- S03 流程：山村区域自由探索 → 与委托 NPC 对话接取 → 寻找目标物 → 返回交付 → 领奖；三条委托顺序自由，全部完成后出完成结算。
- S04 最低完整流程：可探索区域、委托对话、拾取交互、交付对话、奖励发放、完成结算、重开必须全部存在且有真实入口。
- S05 失败恢复入口：无硬失败态；软锁不可存在（红线：任何时刻可通过正常操作继续推进或重开）；结算界面一键重开。
- S06 与种子卡差异：种子卡 persistent_state 为「任务完成标记（区域内持久）」；本包冻结为仅当前会话/局内保留，重开全量清空（P0），不要求跨会话存档。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：启动与标题 → 山村自由探索 → 委托接取 → 寻找目标物 → 返回交付 → 完成结算 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始」
  - precondition：构建可启动且区域按 seed=1051 生成完成
  - state_change：进入「标题」状态；首次进入按 §10 C01 触发开场视频
  - feedback：标题界面按 §9 F10 呈现
  - next_actions：进入「山村自由探索」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 山村自由探索
  - input：WASD 移动、E 对话/拾取/线索交互、Tab 任务面板、Esc 暂停（触发方：玩家）
  - precondition：标题已完成
  - state_change：进入可操作探索状态；三条委托可自由接取
  - feedback：交互高亮与线索登记反馈按 §9 F05 呈现
  - next_actions：与委托 NPC 对话 →「委托接取」
  - outcome：任务状态与线索局内记录
- S08 委托接取
  - input：E 对话＋选择「接下委托」（触发方：玩家）
  - precondition：与委托 NPC 处于对话距离
  - state_change：任务未接→已接；对话线索自动登记入任务面板
  - feedback：任务卡飞入面板＋接取确认音
  - next_actions：按线索指引「寻找目标物」
  - outcome：G04 状态机进入已接/进行中
- S09 寻找目标物
  - input：E 拾取目标物/交互环境线索（触发方：玩家）
  - precondition：任务已接取（未接取时拾取被拒并提示）
  - state_change：目标物入任务背包；环境线索登记（HUD 出现方向提示）；鹅为活体跟随
  - feedback：寻获弹窗与方向提示按 §9 F05
  - next_actions：携目标物返回 →「返回交付」
  - outcome：可交付条件逐步满足
- S10 返回交付
  - input：E 对话＋交付确认框「确认/取消」（触发方：玩家）
  - precondition：条件满足（持有目标物/集齐邮戳/鹅跟随到位）
  - state_change：进行中→可交付→已完成；一次性奖励发放；委托 NPC 致谢分支解锁
  - feedback：交付动画、奖励入账、感谢图标
  - next_actions：三委托全完成 →「完成结算」（先播 C03）
  - outcome：按 V01 结算
- S11 完成结算
  - input：Enter＝重开 / Esc＝返回标题（触发方：玩家）
  - precondition：三条委托全部已完成
  - state_change：进入「结算」状态；区域交互冻结
  - feedback：结算面板显示邮票总数与用时；村口集会装饰呈现
  - next_actions：重开（全量清空）或返回
  - outcome：无跨局写入

## 3. 数值口径与全局规则 [G01–G08]

- G01 统一刻度：任务状态枚举（未接/已接/进行中/可交付/已完成）；物品与奖励计数为整数；线索状态枚举（未发现/已发现）。
- G02 委托与奖励（本包冻结值）：三条委托——①《祖母的旧顶针》（寻 1 件遗失物，奖 50 邮票）；②《走失的鹅群》（寻回 3 只鹅，奖 80 邮票）；③《远行的包裹》（集齐 2 枚邮戳后交付，奖 100 邮票）。奖励一次性发放；集邮册仅记录，不另计分。
- G03 时限带宽（本包冻结值）：单条委托从接取起 10 分钟为提示带宽（超时仅界面提示，不判负、不中断任务）。
- G04 状态转移 oracle：给定输入序列〔与 NPC1 对话接取→拾取顶针→返回对话交付→再次对话请求交付〕，任务状态流唯一确定为 未接→已接→进行中→可交付→已完成，且第二次交付请求被拒绝、不重复发奖；任何偏离即 FAIL。
- G05 线索链（本包冻结值）：每条委托 2 条线索——①对话线索（接取时委托 NPC 给出，自动登记）；②环境线索（区域内固定提示物：顶针线索＝河岸洗衣盆、鹅线索＝河滩羽毛痕、包裹线索＝集市邮戳印台；E 交互登记）；发现环境线索后 HUD 显示该委托目标物方向提示（未发现则无提示）；线索仅引导，不阻塞拾取判定。
- G06 交付边界（本包冻结值）：误交＝将目标物交予非委托 NPC → 该 NPC 摆手拒绝（提示「这不是我托付的东西」），物品不消耗、无状态变化；重复交付＝已完成任务的再次交付被拒（G04）；撤回＝交付确认后不可撤回（一次性）；确认框＝交付前弹出「交付 X？」确认/取消。
- G07 目标物唯一性（本包冻结值）：顶针 1、鹅 3、邮戳 2 全场唯一（不可复制、不可丢弃销毁）；鹅为活体目标（靠近后自动跟随玩家，交付给委托人后停止跟随）。
- G08 委托后叙事状态（本包冻结值，局内叙事层）：每条委托完成后其委托 NPC 对话分支切换为致谢台词并在头顶显示感谢图标（图标＋文字）；全部完成时村口出现「邮局答谢集会」装饰（结算前演出）；叙事状态不改变任何机制数值与奖励。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：WASD＝移动；E 或左键＝对话/拾取/线索/交付交互；Tab＝任务面板；Esc＝暂停；结算界面 Enter＝重开。
- I02 输入语义边界：未接取任务时目标物不可拾取（提示先接取）；已完成后重复交付被拒绝且无奖励变化；误交被拒且不消耗；暂停/结算期间输入无效。
- I03 无手柄需求。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；对话/确认框打开时玩法键不串入。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：任务列表与状态、各委托线索条目（未发现/已发现）、邮票计数、目标物方向提示（发现环境线索后）；HUD 对照见 rubric。
- I07 输入延迟目标：移动按键到画面反馈 ≤ 100 毫秒（WebGL/HTML5 ≤ 150 毫秒）；交互反馈 ≤ 100 毫秒。

## 6. 机制系统 [M01–M04]

- M01 任务状态机（主机制）
  - input：对话接取/拾取/交付
  - precondition：状态机当前态允许该操作（未接不可拾取、已完成不可回退）
  - state_change：未接→已接→进行中→可交付→已完成 按序流转；非法跳转一律拒绝且不产生状态变化
  - observable：每次状态变化产生 task_state 事件（含任务 ID 与前后状态）
  - invalid_case：未接直接交付、已完成回退、误交 → 拒绝
  - recovery：放弃当前委托重接（状态回已接）
- M02 条件交付
  - input：交付对话＋确认框
  - precondition：条件满足（持有目标物/集齐邮戳/鹅跟随到位）
  - state_change：条件满足 → 完成并发奖；不满足 → 拒绝并提示缺项；确认后不可撤回
  - observable：交付判定事件（含条件字段与结果）
  - invalid_case：条件缺项拒绝且不消耗
  - recovery：补齐条件重试
- M03 一次性奖励
  - input：首次完成交付（系统）
  - precondition：该任务从未发放过奖励
  - state_change：奖励发放一次并记账；此后重复交付不可再得
  - observable：奖励流水（同任务仅一条发放记录）
  - invalid_case：重复交付无奖励变化
  - recovery：无
- M04 线索与叙事状态
  - input：环境线索交互（E）／委托完成（系统）
  - precondition：对应委托已接取（线索交互）；任务已完成（致谢分支）
  - state_change：线索未发现→已发现并启用 HUD 方向提示；委托 NPC 对话分支切换致谢＋感谢图标
  - observable：`clue_found` 事件（含委托 ID 与线索类型）、`npc_thanks` 事件
  - invalid_case：未接取时交互环境线索无效（提示先接取）
  - recovery：无副作用

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：三条委托全部完成 → 完成结算（显示邮票总数与用时）。
- V02 失败条件：无硬失败态（时限仅提示；红线为不可出现软锁）。
- V03 恢复语义：任何时候可放弃当前委托重接（状态回已接，线索保留）；结算界面一键重开。
- V04 persistent_state：无（重开全量清空；任务完成标记、线索与奖励仅局内保留，见 §1 与种子卡差异）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（任务/线索/邮票）局内保留、重开清空；无跨局保留状态。
- V06 软锁与不可达处理：不设永久软锁——目标物唯一且位置冻结、不可销毁，任意时刻可完成或放弃重接；关键目标均可正常操作达成。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：现代山乡的慢生活时代；云雾缭绕的「青溪村」只有一座老邮局，新邮差到任的第一天正逢秋收农忙。
- W02 场景所在地：青溪村——邮局、村道、河岸洗衣石、后山小径与晒谷集市场景连贯成单一可探索区域。
- W03 玩家身份与当前任务：玩家是新上任的年轻邮差「阿驿」；当前任务：受理三位村民的遗失物委托，集齐邮票印花的答谢，赶在傍晚集会前全部办妥。
- W04 失败代价与结局表达：本作无失败态；放弃或超时仅表达为委托推迟（提示文案）；全部完成则 C03 呈现村口答谢集会。
- W05 叙事来源：三委托各有来源——祖母的顶针（洗衣时遗落河岸）、站长的鹅群（受惊散入河滩）、远行客的包裹（需集齐两枚邮戳回执才能寄出）；环境线索物即村民生活痕迹。全部原创。
- W06 视觉风格与色彩材质：手绘水彩风格化村落；主色＝暖秋黄（#E8C46B 系）＋溪水青（#6FA8A0 系）＋邮局墨绿（#3F6B4F 系）；材质以木质、晒布、卵石为主，光线为午后暖阳。
- W07 环境氛围与声音语言：蝉鸣渐弱的秋日山乡——常驻溪水与风拂晒谷声；音效语言为「纸页翻动＋脚步碎石＋鹅鸣＋确认印章」，全部音效按 §9 F06 冻结清单交付。
- W08 故事表达方式：开场视频（C01）交代邮差到任 → 首件寻获视频（C02）作为正反馈 → 集会结算视频（C03）收束；故事只做包装，不改变机制数值。

## 9. 演出、镜头与反馈 [F01–F10]

- F01 视角与镜头：第三人称斜后方跟随（距离 3.5 米、高度 2 米），平滑插值 0.1 秒，鼠标水平旋转；镜头边界＝村界围墙；对话时镜头轻微推近 NPC 5%。
- F02 关键操作镜头变化：寻获关键目标物时镜头轻微推近 5%（0.5 秒）＋目标物高亮；无震动类镜头变化。
- F03 输入与延迟：见 I07。
- F04 环境常驻效果：溪水流动与落叶飘落、晒谷布飘动、鹅群在河滩踱步（未接取时）；不遮挡交互高亮与 HUD。

- F06 关键音效清单：纸页翻动、接取确认、线索叮、拾取、鹅鸣、提示、印章落款、轻快音、否定音、入账叮、集会欢快音；环境音：溪水＋秋叶风声（常驻循环）＋远处犬吠（偶发）；循环音开始/结束：环境声随区域载入开始、随结算淡出 0.5s；无配音需求（对白以文本呈现）。
- F07 VFX 信息性与遮挡约束：任务卡与线索状态承担任务信息；方向提示箭头承担寻物信息；落叶粒子单帧 ≤ 30 且不遮挡 NPC 对话气泡与交互高亮。

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：6 个（text-to-3D 4，image-to-3D 2）；object 任务资产为：young_postman, granny_lin, postmaster, traveler_wen, goose_flock, silver_thimble。每项只允许一个物体；组合物必须拆成独立任务。
- motion：4 个；覆盖动作：idle, walk, run, hand_over。
- video/audio/mechanic/UI：分别为 3/8/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

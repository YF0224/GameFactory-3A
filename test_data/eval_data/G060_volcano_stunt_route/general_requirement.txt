## 1. 定位与完整流程 [S01–S07]

- S01 类型：分段目标制的特技运动路线。本测例包含的能力：三段冻结路线与检查点、6 动作空中连招、落地平衡 QTE、双路线分岔、路面与熔岩地貌规则、段落达标与总评评级、四级视频（训练/高风险/恢复/结算）。
- S02 核心循环一句话：加速起跳 → 空中连段动作 → 落地平衡判定 → 连招结算 → 分段推进 → 总评。
- S03 流程：分段一（火山缓坡：基础连招，达标 3000 分）→ 分段二（熔岩跳台：高风险连段，达标 6000 分）→ 分段三（火山口极限：总评冲刺，达标 10000 分）→ 三段总评结算。
- S04 最低完整流程：起跳、动作指令、平衡判定、连招链显示、分段结算、总评、重开必须全部存在且有真实入口。
- S05 失败恢复入口：摔倒回分段检查点（连招清零、分段分保留）；分段未达标可重开该段；总评后一键重开全路线；Esc 暂停。
- S06 本局耦合边速览：连招链系统→计分系统（链倍率改变动作分值）；落地平衡系统→连招链系统（摔倒使链清零）；路面系统→滑行系统（火山灰摩擦与熔岩摔倒改变推进与风险）。
- S07 跨阶段结构与状态保留：三段顺序推进；各段得分、最长链、摔倒次数跨段累计并保留至总评；分段检查点推进后不可回退段内分。

## 2. 完整核心循环与阶段 [S06–S11]

完整循环：启动与标题 → 分段一 → 分段二 → 分段三 → 三段总评 → 重开/返回。每阶段六要素如下（引用本 spec §3–§7 与 §9 对应规则）：

- S06 启动与标题
  - input：系统启动加载完成（触发方：系统）；玩家按 Enter/点击「开始训练」
  - precondition：构建可启动且路线按 seed=1060 冻结
  - state_change：进入「标题」状态；首次进入按 §10 C01 触发训练视频
  - feedback：标题界面按 §9 F10 呈现（三段目标与评级说明）
  - next_actions：进入「分段一」
  - outcome：无跨局状态写入（见 §7 V04）
- S07 分段一（火山缓坡）
  - input：WASD 移动、Space 起跳、J/K/L 空中动作、R 摔倒后复位、Esc 暂停（触发方：玩家）
  - precondition：分段一载入完成
  - state_change：基础连招与平衡判定按 G02–G04 结算；草雪混合路面摩擦为基准值
  - feedback：雪痕、连招链与落地反馈按 §9 F05 呈现
  - next_actions：段末结算 ≥3000 →「分段二」（低于则段重开入口）
  - outcome：段分与摔倒计数跨段累计
- S08 分段二（熔岩跳台）
  - input：同 S07＋分岔路线选择（触发方：玩家）
  - precondition：分段一达标
  - state_change：火山灰路面摩擦 ×0.85；主路大跳台 vs 支路机关带分岔生效；熔岩池踏入即摔倒
  - feedback：熔岩溅射、灰痕与高风险路线提示
  - next_actions：段末结算 ≥6000 →「分段三」
  - outcome：段分累计；检查点登记
- S09 分段三（火山口极限）
  - input：同 S08（触发方：玩家）
  - precondition：分段二达标
  - state_change：熔岩带更宽、风速扰动更强；总评冲刺结算
  - feedback：熔岩红光与极限氛围
  - next_actions：段末结算 ≥10000 →「三段总评」（先播 C04）
  - outcome：按 G05 评级
- S10 三段总评
  - input：Enter＝重开全路线 / Esc＝返回标题（触发方：玩家）
  - precondition：三段全部达标
  - state_change：进入「总评」状态；模拟冻结
  - feedback：总评面板显示各段分、总分、最长链、摔倒次数与评级（金/银/铜/未达标）
  - next_actions：重开（全量清空）或返回
  - outcome：按 V01 结算
- S11 暂停与检查点恢复
  - input：Esc 暂停（触发方：玩家）；R 摔倒后复位（触发方：玩家）
  - precondition：处于分段滑行中
  - state_change：暂停冻结滑行、QTE 窗口与计时；摔倒后 R 立即回最近检查点（或 2 秒自动）
  - feedback：暂停面板（继续/段重开/全路线重开/设置）；恢复时按 §10 C03 触发检查点恢复视频（每次恢复均可触发但每段每局一次）
  - next_actions：继续滑行
  - outcome：检查点语义（段内分保留）

## 3. 数值口径与全局规则 [G01–G08]

- G01 统一刻度：分数按点、角度按度、时间用游戏模拟秒（暂停冻结）。
- G02 动作库与分值（本包冻结值）：6 个空中动作——豚跳 200、抓板 300、转体 360 计 400、空翻 500、转体 540 计 600、组合转体 720 计 800；动作指令：J/K/L 对应三组（J 豚跳/抓板轮替、K 转体 360/540 递进、L 空翻/720 按蓄力）。
- G03 连招与倍率（本包冻结值）：空中串联动作形成连招链；链长 1＝倍率 1.0、2＝1.2、3＝1.5、4 及以上＝2.0（上限 2.0 防发散）；连招分＝Σ动作分×链倍率；着地间隔 ≤2 秒且站稳 → 链保持；摔倒或超时 → 链断裂清零。
- G04 落地平衡（本包冻结值）：落地姿态偏差 <20° 自动站稳；≥20° 触发平衡 QTE（1 秒窗口 3 键序列，seed 预生成）；QTE 全对站稳、错 1 次即摔倒；摔倒 → 倒地 2 秒 → 分段检查点恢复且连招链清零。
- G05 分段目标与总评（本包冻结值）：分段达标线 3000/6000/10000 分，达标才解锁下一段；总评评级——三段总分 ≥30000 金、≥20000 银、≥12000 铜、否则未达标（≥2 评级分支）；总评含修正显示：摔倒次数与最长链作为评级修正项展示（不改变总分）。
- G06 路线与检查点（本包冻结值）：每段 400 m、每 100 m 检查点 1 个；每段 1 处分岔——主路大跳台（高风险高分窗口）vs 支路机关带（稳分低风险）；分段成绩独立累计，段内摔倒回最近检查点继续。
- G07 判定与独立 oracle（本包冻结值）：连招 oracle——豚跳＋转体 360 两连必得 (200＋400)×1.2＝720 分；三连加抓板必得 (200＋400＋300)×1.5＝1350 分；平衡 oracle——偏差 19° 必自动站稳、21° 必触发 QTE；存档 oracle——分段结算后重开该段不保留已得分、全路线状态与前段得分不变；任何偏离即 FAIL。fixed_seed=1060 冻结 QTE 序列与跳台风速扰动。
- G08 路面与地貌（本包冻结值）：三段路面材质与规则——分段一草雪混合（摩擦基准 1.0，滑行留雪痕）；分段二火山灰地面（摩擦 ×0.85，滑行更远、落地打滑时 HUD 提示「地面湿滑」并留灰痕）；分段三熔岩带（踏入熔岩池判定＝立即摔倒回检查点，伴随熔岩溅射与热浪反馈；熔岩池位置由 seed 冻结并在地面有红光警示标记）；雪痕/灰痕为表现层（45 秒渐隐），不参与判定。

## 4. 操作与输入 [I01–I07]

- I01 键鼠：W/A/S/D＝移动；Space＝起跳；J/K/L＝空中动作；QTE 窗口内按提示键；R＝摔倒后立即回检查点；Esc＝暂停；结算界面 Enter＝继续，R＝重开。
- I02 输入语义边界：非空中时动作指令无效；QTE 窗口外按键无效；暂停/结算期间输入无效；摔倒倒地期 2 秒内输入无效。
- I03 无手柄需求；当前连招链、链倍率、分段得分、检查点、姿态偏差提示、路面状态须常驻显示。
- I04 输入优先级：暂停与结算状态阻断全部玩法输入；QTE 窗口内 QTE 键优先；同帧多输入按起跳→动作→QTE 顺序结算。
- I05 焦点与失焦规则：点击画布捕获输入焦点；面板层阻断点击穿透；窗口失焦自动暂停。
- I06 UI 必须显示的状态：连招链与倍率、分段得分与达标线、检查点进度、姿态偏差提示、路面状态（雪/灰/熔岩警示）、摔倒计数；HUD 对照见 rubric。
- I07 输入延迟目标：起跳/动作按键到画面反馈 ≤ 50 毫秒（动作手感关键）；QTE 键采样 ≤ 30 毫秒。

## 6. 机制系统 [M01–M06]

- M01 空中动作与连招（主机制）
  - input：动作指令串
  - precondition：处于空中（起跳后落地前）
  - state_change：空中串联动作 → 连招链延长 → 分值累乘（上限 2.0）
  - observable：连招链事件与串接时序（EVENT_SEQUENCE）
  - invalid_case：非空中动作指令拒绝且无副作用
  - recovery：落地或摔倒结束链
- M02 连招衰减
  - input：着地间隔（系统）
  - precondition：已落地站稳
  - state_change：着地间隔 >2 秒或摔倒 → 链断裂衰减清零
  - observable：链断事件与衰减系数
  - invalid_case：2 秒内站稳链保持
  - recovery：重新起跳建链
- M03 落地平衡
  - input：落地姿态（系统）＋QTE 输入
  - precondition：落地瞬间
  - state_change：偏差小自动站稳；偏差大 QTE → 站稳或摔倒
  - observable：平衡判定事件与结果差分
  - invalid_case：QTE 窗口外按键无效
  - recovery：摔倒走 M04
- M04 摔倒复位
  - input：摔倒（系统）／R（玩家）
  - precondition：摔倒成立或倒地中
  - state_change：短时倒地 2 秒（或按 R 立即）→ 分段检查点恢复 → 连招清零、段分保留
  - observable：复位事件与链清断言
  - invalid_case：倒地期 2 秒内输入无效
  - recovery：检查点即恢复
- M05 分段目标与总评
  - input：分段终点（系统）
  - precondition：抵达段末结算线
  - state_change：分段达标 → 解锁下一段 → 三段总分结算评级
  - observable：分段结算事件与评级分支
  - invalid_case：未达标出段重开入口
  - recovery：段重开清该段分保留前段
- M06 路面与地貌
  - input：滑行接触面变化（系统）
  - precondition：滑行中
  - state_change：按 G08 切换摩擦（1.0/×0.85）；熔岩池接触 → 立即摔倒；灰面落地打滑提示
  - observable：`surface_change` 事件（含路面类型与摩擦系数）、`lava_hit` 摔倒事件
  - invalid_case：非熔岩接触不误判
  - recovery：摔倒回检查点

跨阶段后果表（至少 1 条显式 A→B→C 链，早期状态在后续阶段仍可观察）：

- K01 阶段A（分段一累计基础分与最长链，分段结算落盘）→ 阶段B（分段二高风险连段在既有动作熟练度上放大分数，段分独立累计）→ 阶段C（总评由三段累计总分与评级修正项共同决定，分段一得分在终局仍可观察）；验证方式=跨阶段回溯探针：分段一结算快照 → 分段二得分流水 → 总评对账。
- K02 阶段A（分段一摔倒 2 次与链清零记录落盘）→ 阶段B（分段二平衡 QTE 容限 −20%（高风险段）且长链维持要求提高）→ 阶段C（总评修正显示累计摔倒次数与最长链，最终评级呈现早期记录）；验证方式=摔倒计数流水 → 分段二容限对照 → 总评修正项对照。

系统耦合边（玩法必需、可复现）：

- E01 from_system=连招链系统 → to_system=计分系统；changed_state=链长改变倍率（1.0/1.2/1.5/2.0）使同动作分值不同；验证方式=链长事件→倍率→计分流水三联对照。
- E02 from_system=落地平衡系统 → to_system=连招链系统；changed_state=摔倒使链清零、站稳维持链；验证方式=摔倒/站稳两态链状态对照。
- E03 from_system=路面系统 → to_system=滑行与风险系统；changed_state=火山灰摩擦 ×0.85 改变滑行距离与落地打滑提示、熔岩接触直接摔倒改变推进与路线选择；验证方式=两路面滑行距离差分与熔岩摔倒事件对照。

## 7. 成功、失败与恢复 [V01–V05]

- V01 成功条件：三段全部达标且总分 ≥12000 → 至少铜级总评结算（显示各段分、总分、最长链、摔倒次数与评级）。
- V02 失败条件：任一分段未达标且用尽段内检查点继续权（连摔 5 次强制段结算）→ 该段重开；总分 <12000 → 未达标结算。
- V03 恢复语义：摔倒回最近检查点（连招清零、段分保留）；分段未达标重开该段（该段分清零、前段得分保留）；总评后一键重开全路线（全量清空、seed 复现）。
- V04 persistent_state：跨段持久（分段成绩与总评跨段保留；检查点推进不回退段内分；重开全路线全量清空）。
- V05 persistent_state 生命周期：当前动作级状态即时结算；当前局级状态（段分/摔倒数/最长链）局内保留；跨段状态按 V04 持久；无跨局保留（重开全量清空）。
- V06 软锁与不可达处理：不设软锁——检查点复位、段重开、全路线重开三级恢复；熔岩摔倒必回检查点。

## 8. 世界设定与创作基线 [W01–W08]

- W01 世界与时代背景：架空的极限运动时代；「烬峰」是刚进入休眠期的活火山，灰烬滑降联盟在它的三段地貌上开设了特技运动认证路线。
- W02 场景所在地：烬峰三段路线——火山缓坡（草雪混合坡）、熔岩跳台（火山灰地带与熔岩池）、火山口极限（宽熔岩带与强风扰动）。
- W03 玩家身份与当前任务：玩家是考取「烬峰认证滑手」的运动员；当前任务：在三段路线上完成空中连招与落地平衡，以总分冲击金级认证。
- W04 失败代价与结局表达：段未达标＝该段重开（认证中止文案）；三段完成则 C04 呈现评级授证场面（金/银/铜分支）。
- W05 叙事来源：6 个动作＝联盟认证动作库；检查点＝联盟护坡员设立的哨位；机关带＝稳定评分的训练装置；熔岩池＝烬峰未冷的心跳。全部原创。

## 10. 过场视频 [C01–C04]

- C01 路线训练（Opening，10 秒，1280×720@24fps）

  - 状态一致：评级变体与真实总评一致

## 生成任务明确性补充（2026-10-12）

> 本补充只约束游戏生成输入，不引用 rubric。所有生成器必须以本文件规则和下列 JSONL 任务为准；未列出的装饰细节可以自由发挥，但不得省略已列资产或生命周期。

### 故事与流程最低合同
- **玩家身份与当前冲突**：以 §1、§8 的角色/世界/冲突为唯一叙事入口；开局必须让玩家知道“我是谁、现在要解决什么问题”。
- **阶段性目标**：必须有可操作的阶段目标、至少一次状态变化/升级，并在 §7 的胜利、失败、重开入口中闭环；不能只生成一个无结果的场景演示。
- **结果承接**：胜利/失败都要有明确结果文案或演出，并回到可重开、暂停或标题入口；视频、音频和 VFX 不得推进未完成的玩法状态。

### 生成任务清单（JSONL 冻结口径）
- scene：1 个；必须生成连贯可游玩的空间，不得出现下半部文字、拼贴面板、物体 lineup 或 UI。
- object：3 个（text-to-3D 2，image-to-3D 1）；object 任务资产为：stunt_rider_yan, big_launch_ramp, steadiness_gantry。每项只允许一个物体；组合物必须拆成独立任务。
- motion：3 个；覆盖动作：ride_idle, jump_tuck, sp_trick。
- video/audio/mechanic/UI：分别为 4/13/1/1 个任务；若某项为 0，只能是本案例明确的 N/A，不得默默遗漏。

### Video / motion / audio 生命周期
- Video 每项必须写清 `trigger`、`start_condition`、`duration_sec`、`skippable`、`skip_behavior`、`end_condition` 和进入的下一个游戏状态；播放期间不得偷偷消耗计时或改变战斗/任务数值。
- Motion 每项必须写清 `source_asset`、`trigger`、`start_condition`、`duration_sec`、`loop`、`end_condition` 和 `cancel_behavior`；动作要与对应输入/机制事件绑定，不可只写“walk animation”。
- Audio 每项必须写清触发事件、时长、`loop`、`stop_condition`、优先级和 ducking；关键命中/提示音必须与事件帧同步，暂停/结算时按 §9 处理。

### Mechanic / UI / 游玩手感
- Mechanic JSON 与 §1–§7 配对：每个输入都要有 precondition、state_change、feedback、next_state；必须说明失败/禁用分支。
- UI JSON 与 §9/F10 配对：HUD、菜单、结算、暂停、错误/禁用态要有 state binding；关键状态不能只用颜色表达。
- 手感冻结：相机跟随/构图、FOV、碰撞/遮挡、镜头调整与镜头震动必须在 §9 说明；震动反馈必须写明触发、强度和持续时间，并提供关闭设置且不改变判定。

### VFX 时机合同
每个特效必须写清 `trigger event`、预备/前摇、active window、持续时间、结束条件、被打断/取消条件，以及和相机震动、音效、UI 的同步关系；命中特效、失败特效、胜利特效不能只写“有粒子”。

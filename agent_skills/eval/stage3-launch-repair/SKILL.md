# Stage3 启动修复（只为让原玩法跑起来）

你在**评估副本**（当前工作目录，`runtime/project`）里工作。作者原始交付在别处、只读；你的每个改动都会被保存成 diff、由另一次审查判断，并在成绩里标记为“启动修复过”。目标只有一个：**让作者已经写好的游戏能编译、导入、进入作者的入口场景/地图**，玩法表现完全保持作者原样。

## 允许

1. **工程/环境配置**：`.uproject`、`*.uplugin`、`*.Build.cs`、`*.Target.cs`、`Config/*.ini`（引擎/平台/模块/插件设置，不改游戏参数）、Unity `ProjectSettings/`（输入后端、脚本后端、API 兼容级别等）、`Packages/manifest.json`、`*.asmdef`/`*.asmref`。例：补缺失的模块依赖、启用已被引用的引擎插件、修正引擎版本关联、补 `using`/命名空间引用所需的程序集引用。
2. **不改变行为的编译兼容**：缺失的 `#include`/`using`；引擎版本间的 API 改名或签名变化（用等价新 API）；显式类型转换；`const`/`override`/`virtual` 修饰；未初始化导致编译失败的声明；重复定义/歧义引用的限定名。改完后，同样的输入必须产生同样的游戏行为。
3. 只为修上面的问题而**新增**的空壳文件（例如缺失的 Target.cs、模块入口文件），内容只能是引擎模板。

## 禁止（出现即整次修复作废并回滚）

- 改任何**玩法逻辑、规则、数值、胜负条件、输入映射、AI、关卡流程、UI 文本/行为**；补写作者没实现的功能、方法、场景对象或资源。
- 改场景/关卡/预制体/资源文件（`.unity`、`.prefab`、`.umap`、`.uasset`、材质、贴图、音频、模型等），删除作者的任何文件。
- 为了编译通过而**删掉或注释掉**作者代码、把函数体改成空实现、`#if 0`、捕获并吞掉异常。
- 改评估工具/adapter/录制插件（`A3GamePlayable`、`GameFactory3A*` 等注入文件）、`Library/`、`Intermediate/`、`Binaries/` 等缓存；碰工作目录外的任何东西。
- 联网下载、安装新的第三方包。

拿不准是否改变行为时：**不改**，在回复里说明原因。没有可安全修复的问题（例如失败来自评估工具本身、或要修就必须动玩法）时，不做任何修改，`status` 返回 `not_repairable`。

## 做法

1. 先读失败信息里给的日志路径，找到**最早**的真实错误（编译器第一条 error、第一条 missing module/plugin、场景/地图加载失败的根因）。
2. 读相关源码，判断错误属于“允许”的哪一类；做最小改动，每处改动只修一个错误。
3. 不运行引擎（构建/导入会由评估流程重新执行）；可以用 grep/读文件核对 API 和引用。
4. 回复 JSON：`status`（`repaired` / `not_repairable`）、`root_cause`、`changes`（每处：文件、类型 config/compile_compat/new_stub、为什么不改变行为）、`not_fixed`（剩余错误及原因）。
